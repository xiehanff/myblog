# 安全基础

上线前照着清单加几个响应头，把一条宽泛的 CSP 当成“安全做完了”；或者在客户端校验输入，认为界面拦住了非法请求；又或者觉得“上了 HTTPS 就没事了”。这些做法的共同问题，是把攻击名和防护手段当成了同一类东西：XSS、CSRF、注入、拒绝服务描述的其实是三种不同的越界，越界位置不同，防护点就不同——输出编码管不了资源耗尽，限速管不了 SQL 注入，`HttpOnly` 也消化不掉 CSRF。

本板块把安全当作“威胁模型 + 越界条件 + 防护组合”来学，而不是一张需要背下来的名词表。目前只有一篇唯一正文，它先建立资产、信任边界与攻击者能力的模型，再分别讲清四类攻击的成立条件、机制、失败边界与防护配合，最后回答客户端能做与不能做，并给出可以逐项核对的服务端检查清单。浏览器专属机制（CSP、SameSite、同源策略、CORS）在文中显式标注适用范围；本板块不扩展成 Web 前端开发教程，也刻意只保留理解防护所需的最小攻击细节。

前置知识：安全问题的成立条件大多建立在协议机制之上，建议先读完网络板块的[HTTP 语义、缓存与版本演进](../04-计算机网络/07-HTTP语义、缓存与版本演进.md)、[HTTPS 与 TLS](../04-计算机网络/08-HTTPS与TLS.md)与[身份认证：Cookie、Session 与 JWT](../04-计算机网络/09-身份认证：Cookie、Session与JWT.md)；否则 Cookie 属性、同源策略与凭证传递讲不清。

## 前置知识与学习顺序

网络安全的基础概念分散在网络板块，按下面的顺序建立地图，再进入攻击与防护：

1. [HTTP 语义、缓存与版本演进](../04-计算机网络/07-HTTP语义、缓存与版本演进.md)：请求/响应语义、方法的安全与幂等、同源策略与 CORS 的边界——CSRF 与 XSS 的判断都依赖它。
2. [HTTPS 与 TLS](../04-计算机网络/08-HTTPS与TLS.md)：TLS 保护传输过程的什么、不修复什么；证书与信任链。
3. [身份认证：Cookie、Session 与 JWT](../04-计算机网络/09-身份认证：Cookie、Session与JWT.md)：凭证如何存储与发送、`HttpOnly`/`Secure`/`SameSite` 的作用、会话被偷走之后的处理。
4. [常见应用攻击与防护](./01-常见应用攻击与防护.md)：本板块唯一正文，把攻击拆成越界条件与防护组合。

完成标准：对任意一个防护手段，能说出它挡的是哪条越界线、挡不住什么；能写出一份在服务端重新执行（而非依赖客户端）的检查清单，并知道哪些条目属于传输保护、哪些属于应用层。

> HTTPS 只保护传输过程；“客户端已经校验过”不构成服务端跳过校验的理由。两句话的完整论证见正文[客户端能做与不能做](./01-常见应用攻击与防护.md#客户端能做与不能做)。
