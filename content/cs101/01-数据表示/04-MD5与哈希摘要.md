# 数据表示｜04-MD5 与哈希摘要

下载文件后看到一串 32 个十六进制字符，或者旧系统用 MD5 保存文件“校验值”，这些都来自哈希函数：把任意长度的输入映射成固定长度摘要。要正确使用它，关键不只是会计算摘要，还要分清摘要、编码、加密与消息认证码的边界。

本文以 MD5 为例说明摘要的含义、典型用途与安全限制，并演示对文本和文件计算摘要。MD5 适合帮助理解哈希，但已不适合安全用途；新系统应根据目的选择 SHA-256、HMAC 或现代密码哈希方案。

## 哈希摘要是什么

哈希函数接收任意长度的字节序列，输出固定长度的摘要（digest）。MD5 的摘要长度为 128 位，也就是 16 字节；通常以 32 个十六进制字符显示：

```text
输入字节：任意长度
MD5 摘要：128 位 = 16 字节 = 32 个十六进制字符
```

摘要不是原文的另一种可逆编码。计算摘要时信息被压缩到固定长度，无法通过摘要还原输入；不同输入理论上可能得到相同摘要，这称为碰撞。对文本求摘要时，算法处理的是字节，因此必须先约定字符编码：同一文本用 UTF-8 与其他编码得到的字节不同，摘要也会不同。

哈希函数的性质也不是“绝不碰撞”。对于理想的 n 位摘要，两个相互独立、随机选取的输入，其摘要碰撞概率约为 `2^-n`。如果比较大量随机输入，可能碰撞的输入对数量会随输入数平方增长，出现生日效应；约有 `2^(n/2)` 个输入时，发生至少一次碰撞的概率已达到显著水平。实际安全性还取决于算法能否抵抗针对性的攻击。MD5 已能被实际构造碰撞，因此不能再把它的 128 位长度当作安全保证。

## MD5 的输出与计算

MD5 会先对输入进行填充，使消息长度满足分组处理要求，再按 512 位（64 字节）分组迭代更新内部状态，最终输出 128 位摘要。实现细节可以查阅 RFC 1321；日常使用应调用经过维护的标准库或系统工具，不要自行实现密码算法。

同一字节序列总会得到同一个 MD5 摘要，因此它具有确定性：

```text
MD5("abc") = 900150983cd24fb0d6963f7d28e17f72
```

这个结果针对 ASCII/UTF-8 字节 `61 62 63`。输入多一个换行、空格，或使用不同编码，结果都会变化。摘要“雪崩效应”意味着输入哪怕只改一个 bit，输出通常也会显著不同；但雪崩效应不等于抗碰撞能力。

## MD5 能做什么、不能做什么

MD5 在非对抗环境下仍可能用于非安全性的内容指纹，例如快速发现文件是否意外损坏或重复。如果攻击者可以同时替换文件和摘要，那么无论使用何种摘要算法，验证都无法提供保证：期望摘要必须通过可信渠道获得。即使 MD5 摘要本身可信，MD5 已可被实际构造碰撞，因此也不宜用于对抗性场景中的内容完整性验证。这里的碰撞攻击不意味着可以轻易为任意给定的 MD5 摘要找出另一个匹配输入；应改用 SHA-256 等安全哈希，并通过可信渠道分发摘要，或使用数字签名验证发布者身份。

| 机制 | 是否可逆 | 是否需要密钥 | 主要用途 |
| --- | --- | --- | --- |
| 编码（如 Base64） | 可以还原 | 否 | 改变表示形式、适配文本通道 |
| 加密 | 持密钥可还原 | 是 | 保密 |
| 普通哈希（如 SHA-256） | 不可还原 | 否 | 摘要、内容指纹 |
| HMAC | 不可还原 | 是 | 带密钥的消息认证 |
| 数字签名 | 不可还原（签名本身不含原文） | 私钥签名、公钥验证 | 验证来源与完整性 |

不能用 `MD5(password)` 安全地保存密码。MD5 速度快，攻击者可高速尝试大量候选；应使用 Argon2id、scrypt、bcrypt 或 PBKDF2 等专门的密码哈希方案，配合每个账户独立的随机盐和适当成本参数。也不要把 `MD5(message + secret)` 当成 MAC，应使用标准 HMAC，例如 HMAC-SHA-256。

> **面试高频：** MD5 是加密吗？
> **答题脉络：** 不是，MD5 是不可逆的固定长度摘要 → 不提供保密，也不带密钥认证 → 已存在实用碰撞攻击 → 密码存储用慢速密码哈希，消息认证用 HMAC，来源验证用数字签名。
> **追问方向：** 为什么文件摘要必须通过可信渠道分发；为什么“输出看起来不同”不能证明抗碰撞。

## 计算文本与文件的 MD5

在 Unix-like 系统中可使用 `md5sum`；macOS 常用 `md5`。计算文本时可将内容通过管道传给命令；`printf` 不会像 `echo` 那样默认追加换行，因此下面计算的是 `abc` 三个字节的摘要：

```bash
printf 'abc' | md5sum
# macOS
printf 'abc' | md5
```

计算文件时，命令读取文件内容；不要把文件名或终端显示文本误认为输入内容：

```bash
md5sum archive.zip
# macOS
md5 archive.zip
```

Dart 标准库不内置 MD5。若业务仅为兼容旧格式而确实需要 MD5，应选择维护良好且明确支持该算法的密码学库；用于安全设计时则应优先换成安全方案。文本计算还必须固定 UTF-8 等字节编码，不要对“字符”直接求摘要。

## 安全场景应该选什么

- **发布文件防篡改**：用 SHA-256 或更强的安全哈希，并通过 HTTPS、签名等可信渠道分发期望值；只有摘要来源可信才有验证意义。
- **消息认证**：使用 HMAC-SHA-256 等标准 MAC；不要拼接密钥后直接做普通哈希。
- **密码存储**：使用 Argon2id、scrypt、bcrypt 或 PBKDF2，采用独立随机盐和合适的计算成本；不要使用 MD5 或普通 SHA-256 直接哈希密码。
- **数字签名**：使用成熟签名算法与经过验证的密钥管理流程；签名验证才可以把内容与发布者身份关联起来。

## 小结

MD5 把任意输入字节映射为 128 位摘要，常用作历史格式兼容或非对抗场景的指纹；它不是加密，不能还原原文，也已不具备抗碰撞安全性。根据目标分别选择安全哈希、HMAC、密码哈希或数字签名，并明确文本转字节时使用的编码。
