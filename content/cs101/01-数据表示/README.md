# 数据表示

接口返回的中文变成“涓枃”，图片字段的 Base64 末尾多出几个 `=`，同一句 `1 << 31` 在 Dart 与 Java 里结果相反——这些问题看起来分属不同的 bug，根因却都在同一处：机器里只有位和字节，“字符”与“文本”都是约定之上的解释。不把整数位宽、字符编码和文本通道这三层分开，就只能靠试错改代码。

本板块用三篇正文建立从位到文本的完整层次：先看整数如何占用固定宽度的位模式，再看字符如何变成字节，最后看任意二进制如何伪装成纯文本。三篇可以独立阅读，按 01 → 02 → 03 的顺序则能一路复用前一篇的模型；要把位运算用于算法题时，再转到[算法知识体系的位运算技巧](../02-算法与数据结构/01-算法基础/14-位运算技巧.md)。

## 学习顺序与依赖

前置知识只有一项：会用任意一门语言读写字节序列（如 Dart 的 `Uint8List`、C 的 `unsigned char`）。不需要数字电路或硬件背景。

推荐顺序与依赖关系：

1. [二进制表示与位运算](./01-二进制表示与位运算.md)：建立“整数是固定宽度的位模式”这一底座，补齐补码、移位与掩码。
2. [字符编码与乱码](./02-字符编码与乱码.md)：把字节解释为字符，依赖第 1 篇的十六进制与位宽概念。
3. [Base64 编码](./03-Base64编码.md)：把任意字节送进纯文本通道，依赖第 1 篇的 6 位分组和第 2 篇的“字节与文本”边界。

读完本板块后，可以继续：

- 算法方向：[位运算技巧](../02-算法与数据结构/01-算法基础/14-位运算技巧.md) 把位模式翻译成算法恒等式，入口依赖第 1 篇。
- 网络方向：[身份认证：Cookie、Session 与 JWT](../04-计算机网络/09-身份认证：Cookie、Session与JWT.md) 中的 Base64URL 是第 3 篇的变体应用。
- 安全方向：编码本身不提供机密性，攻击面与防护见[常见应用攻击与防护](../06-安全基础/01-常见应用攻击与防护.md)。

## 完成标准

- 能画出“整数位模式 → 字节序列 → 字符编码 → 文本通道编码”四层模型，并说出每一层负责的转换。
- 不查资料解释补码与 `~x + 1`，并能指出有符号移位在各语言中的确定性差异。
- 拿到一段乱码或一组未知字节，能按“确认原始字节 → 确认编码声明 → 只在已知源编码时转换”的顺序排查。
- 能解释 Base64 的 6 位分组、padding、膨胀比例与 URL-safe 变体，并明确它既不是加密也不是压缩。
