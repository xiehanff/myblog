# 程序设计与软件设计

代码能编译、能跑通，不代表改动便宜。客户端项目里最难改的部分通常不在算法上，而在边界上：同一份业务规则散落在多个文件，某个 `set` 方法允许外部写进非法状态，两个页面共享同一个可变对象，改一处、崩一片。再往后是展示层问题——换个页面结构就要重写全部状态流转；以及协作问题——知道一堆模式名字，却说不清什么时候该用、用了要付出什么代价。

本板块按“对象 → 复制 → 分层 → 模式”四步推进：先用面向对象与 SOLID 建立判断准则，再理解对象复制、所有权与深浅拷贝如何决定改动的影响范围，然后看 MVC、MVP、MVVM 与单向数据流如何组织展示层，最后用 25 篇设计模式给反复出现的设计约束命名。示例以 Dart 为主；MVC 一篇从 Flutter 用户页入门，其他代码按正文说明使用纯 Dart 或 Flutter。原则、架构与模式处于不同层级，索引只负责定位，机制与权衡以对应正文为准。

前置知识：能读 Dart 的类、继承、泛型与空安全，用过至少一种状态管理方案。若对 `implements`、`with`、`sealed` 的差别不熟，先读第 1 步。只想准备面试，可从[面试高频入口](#面试高频入口)反向进入。

## 推荐学习路线

四步存在依赖关系，按顺序读成本最低；每一步附一两句完成标准。

1. **面向对象与设计原则** — [01-面向对象与设计原则](./01-面向对象与设计原则.md)。先建立“对象是不变量边界”的模型，再逐条拆开封装、抽象、继承、多态、SOLID 与依赖注入。完成标准：能对一段代码指出变化轴与依赖方向，并用判据而非口号解释“该组合还是继承”“抽象类还是接口”。
2. **对象复制、所有权与深浅拷贝** — [02-对象复制、所有权与深浅拷贝](./02-对象复制、所有权与深浅拷贝.md)。从对象图与别名出发，分清浅拷贝、领域深拷贝、JSON 往返、不可变集合与 isolate 消息的边界。完成标准：能画出复制后的对象图，指出哪些对象仍共享；知道“复制一次”不等于“线程安全”；能说明 `copyWith`、`List.from`、`final` 为什么都不是深拷贝。
3. **MVC、MVP、MVVM 与单向数据流** — [03-MVC、MVVM与单向数据流](./03-MVC、MVVM与单向数据流.md)。先从 Flutter 用户页认识三种分工，再深入依赖方向与不可变快照。完成标准：能用示例说清 MVC、MVP、MVVM 的更新路径，解释 Flutter 中为什么要把复杂页面状态从 Widget 拆开，以及什么时候暂时不需要 ViewModel。
4. **设计模式** — [04-设计模式](./04-设计模式/README.md)。依赖第 1 步的抽象边界。先按创建型、结构型、行为型通读一遍建立词汇，之后按问题反查。

面试复习的反向路径：先读 01 的[常见误区与面试答题路径](./01-面向对象与设计原则.md#常见误区与面试答题路径)和 03 的[常见误区：六种失败形态](./03-MVC、MVVM与单向数据流.md#常见误区六种失败形态)，再用设计模式目录的成对辨析检查自己是否只会背名字。

## 如何阅读设计模式

模式是对反复出现的设计约束的命名，不是可以照抄的类图模板，也不是“用得越多越专业”的清单。每篇模式正文都按固定结构组织：意图、结构、实现、适用条件与代价、Dart 标准库与生态映射、面试追问。

读每一篇时至少回答六个问题：它封装的是哪个变化轴；参与者各自承担什么职责与协作；不用模式的最简替代是什么；引入抽象后的间接层、生命周期与并发代价是什么；Dart 语言特性是否已经提供了更轻的等价物；当前需求是否真的需要它。分类导航与按问题选择的入口见[设计模式目录](./04-设计模式/README.md)。
