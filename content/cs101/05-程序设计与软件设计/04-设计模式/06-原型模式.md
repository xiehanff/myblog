## 意图（Intent）

用原型实例指定要创建对象的类型，通过复制这个原型来创建新对象。

动机：有些对象的创建过程比复制贵得多——它可能来自一次解析、一系列配置，或者一份手工调好的模板。让调用方拿着“样板”复制一份出去改，比重新走一遍创建流程更直接。但“复制”要看复制什么：外层容器换了，内层对象还是共享的，改动就会互相牵连。原型模式真正要定的，是**复制深度、身份和资源语义由谁负责**。

## 结构（Structure）

```text
Client ──▶ Prototype（copy() / copyWith() / 拷贝构造器）
             │
             ├── 浅拷贝：新外壳，内层对象仍共享
             └── 深拷贝：逐层重建，副本与原样互不影响

原型注册表：Client ──name──▶ Registry ──copy()──▶ 新对象
```

- **Prototype**：定义复制自身的方法；复制语义由领域对象自己实现。
- **ConcretePrototype**：决定哪些字段复制、哪些重建、哪些禁止复制。
- **Client**：向原型或注册表要副本，不重新走完整创建流程。
- **Registry**（可选）：按名字保存一批原型，取用时复制，保护模板不被使用方修改。

依赖方向：客户端依赖复制协议，不依赖原型的构造细节。

## 实现（Implementation）

先看复制深度的差别。`List.of`/`List.from` 都是浅拷贝：只换外层列表，元素仍是同一批对象，所以嵌套的 `tags` 依然共享。深拷贝必须逐层重建内层集合。

以下代码合起来是完整文件 `prototype_copy.dart`。验证环境：Dart 3.12.2；`dart analyze` 无问题，`dart run --enable-asserts` 通过。

```dart
// 前置条件：Dart 3.x；纯 Dart；无第三方依赖。

/// 复制语义由领域对象自己定义。
final class Track {
  Track(this.title, this.tags);

  final String title;
  final List<String> tags;

  /// 元素自身可变，深拷贝必须重建内层集合。
  Track deepCopy() => Track(title, List<String>.of(tags));

  @override
  String toString() => 'Track($title, tags=$tags)';
}

final class Playlist {
  Playlist(this.name, this.tracks);

  final String name;
  final List<Track> tracks;

  // 1. 浅拷贝：新外层列表，元素仍是同一批对象。
  Playlist shallowCopy() => Playlist(name, List<Track>.of(tracks));

  // 2. 深拷贝：元素也复制，两份对象完全隔离。
  Playlist deepCopy() =>
      Playlist(name, <Track>[for (final track in tracks) track.deepCopy()]);

  // 3. copyWith 只换字段，集合的深度由调用方决定。
  Playlist copyWith({String? name, List<Track>? tracks}) =>
      Playlist(name ?? this.name, tracks ?? this.tracks);

  @override
  String toString() => 'Playlist($name, $tracks)';
}

void main() {
  final original = Playlist('通勤', <Track>[
    Track('A', <String>['work']),
    Track('B', <String>['calm']),
  ]);

  final shallow = original.shallowCopy();
  final deep = original.deepCopy();

  // 4. 两个副本的外层列表都是新对象。
  assert(!identical(shallow.tracks, original.tracks));
  assert(!identical(deep.tracks, original.tracks));

  // 5. 差别在内层：浅拷贝共享元素，深拷贝不共享。
  assert(identical(shallow.tracks.first, original.tracks.first));
  assert(!identical(deep.tracks.first, original.tracks.first));

  // 6. 改原型的嵌套集合，只有浅拷贝被牵连。
  original.tracks.first.tags.add('urgent');
  assert(shallow.tracks.first.tags.contains('urgent'));
  assert(!deep.tracks.first.tags.contains('urgent'));

  print('original=$original');
  print('deep=$deep');
}
```

副本的新旧是可以用 `identical` 精确断言的——这正是区分“换了外壳”和“真正复制”的判据。接着把原型放进注册表：模板只属于注册表，取用者拿到的是副本，改坏了也污染不到模板。

以下代码合起来是完整文件 `prototype_registry.dart`。验证环境同上。

```dart
// 前置条件：Dart 3.x；纯 Dart；无第三方依赖。

/// 原型注册表：模板只属于注册表，取用者拿到的是模板的副本。
final class ThemeTemplate {
  ThemeTemplate(this.name, List<String> palette)
    : palette = List<String>.of(palette);

  final String name;
  final List<String> palette;

  ThemeTemplate copy() => ThemeTemplate(name, palette);

  @override
  String toString() => 'ThemeTemplate($name, $palette)';
}

final class ThemeLibrary {
  final Map<String, ThemeTemplate> _templates = <String, ThemeTemplate>{};

  void register(ThemeTemplate template) =>
      _templates[template.name] = template.copy();

  // 1. 按名字取原型并复制；不存在时显式失败。
  ThemeTemplate newTheme(String name) {
    final template = _templates[name];
    if (template == null) {
      throw ArgumentError.value(name, 'name', '未注册的主题模板');
    }
    return template.copy();
  }
}

void main() {
  final library = ThemeLibrary()
    ..register(ThemeTemplate('base', <String>['#ffffff', '#000000']));

  final dark = library.newTheme('base');
  final light = library.newTheme('base');

  // 2. 两次取用得到不同对象；改一份不影响另一份和模板。
  assert(!identical(dark, light));
  dark.palette.add('#0f62fe');
  assert(light.palette.length == 2);
  assert(library.newTheme('base').palette.length == 2);

  // 3. 未注册的名字显式失败。
  try {
    library.newTheme('missing');
    assert(false, '未注册的模板必须抛错');
  } on ArgumentError catch (error) {
    print('未注册模板被拒绝：$error');
  }
  print('dark=$dark');
}
```

要点：

- `ThemeTemplate` 在构造器和 `copy()` 里都用 `List.of` 重建调色板，注册时再次复制，确保调用方持有的模板与注册表内的模板互不共享同一层集合。
- 复制后如果只改外层（加一个 `Track`），浅拷贝与深拷贝看起来一样；只有修改共享的内层对象时差异才会显现。测试要针对内层身份断言。
- 原型和工厂都能“产出对象”：工厂从零创建，原型从一个已有实例复制。复制能保留运行期才具备的状态，代价是复制语义更难泛化。

## 适用条件与代价

- 适用：创建成本高、需要保留某个运行期配置作为样板、需要按名字批量产出相似对象；对象结构相对简单，可以讲清复制深度。
- 代价：复制语义容易失控——对象图里出现共享节点或环时，朴素递归深拷贝会重复复制或无限递归，需要按 identity 做 memo；`File`、连接、流这类资源句柄通常不能复制，只能禁止复制或显式重建。
- 不可变对象通常不需要复制：直接共享即可，“复制”出来再改反而破坏了不可变性。

## Dart 标准库与生态映射

- Dart 没有 Java 的 `Cloneable`/`Object.clone()`：不存在能对所有对象生效的统一克隆入口。复制语义必须由领域对象显式提供，常见命名是拷贝构造器、`copyWith` 或 `clone`。
- `List.of`、`Map.of`、`[...source]`、`{...source}` 都只复制一层；代码生成（如 freezed）的 `copyWith` 同样不自动深拷贝。想准确判断一个拷贝是深是浅，看它是否重建了内层可变对象。
- 完整的跨语言复制模型、JSON 往返技巧与 isolate 消息传递见[对象复制、所有权与深浅拷贝](../02-对象复制、所有权与深浅拷贝.md)，本篇不重复展开。

## 面试追问

- 原型和[工厂](03-工厂方法.md)的区别？（工厂从头创建；原型复制已有实例，能带走运行期状态）
- 为什么 `clone` 不能做成万能的反射操作？（字段语义、共享节点、资源句柄都要领域知识才能决定怎么复制）
- 循环引用和共享节点怎么处理？（深拷贝按 identity memo：优先查表复用已复制节点）
- 不可变对象还需要 clone 吗？（不需要，共享即可；复制反而增加成本）
- `copyWith` 是深拷贝吗？（不是，默认只换字段或复制一层，深度由实现者决定）

## 一句话总结

> 原型模式用复制代替重建，核心不在“能复制”，而在于明确复制深度、对象身份和资源句柄各自由谁负责。
