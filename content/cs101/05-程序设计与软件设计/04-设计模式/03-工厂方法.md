## 意图（Intent）

定义创建对象的接口，但让子类决定实例化哪个类，把实例化推迟到子类。

动机：数据来源会不断增加，而“逐条创建、再统一处理”的流程始终不变。如果创建代码写死在流程里，每加一种来源就得复制整段流程；工厂方法把流程留在父类，只把“造哪种记录”这个变化点下放给子类。

## 结构（Structure）

```text
Client ──▶ Creator ──createRecord(raw)【子类覆写】──▶ Record（KeyValue / Json）
             importAll()/summarize() 由父类固定
```

- **Creator / ConcreteCreator**：父类声明工厂方法并在模板流程中使用它的产物，子类覆写决定具体产品。
- 依赖方向：客户端依赖 Creator 与 Record，不认识具体产品。

## 实现（Implementation）

以下代码合起来是完整文件 `factory_method.dart`。验证环境：Dart 3.12.2；`dart analyze` 无问题，`dart run --enable-asserts` 通过。

```dart
// 前置条件：Dart 3.x；纯 Dart；无第三方依赖。
import 'dart:convert' show jsonDecode;

/// 产品协议：一行导入数据。
abstract interface class Record {
  String get name;

  String get value;
}

final class KeyValueRecord implements Record {
  KeyValueRecord(this.name, this.value);

  @override
  final String name;

  @override
  final String value;
}

final class JsonRecord implements Record {
  JsonRecord(this.name, this.value);

  @override
  final String name;

  @override
  final String value;
}

/// Creator：导入流程固定，唯一的变化点「造哪种记录」交给子类覆写。
abstract class Importer {
  // 1. 工厂方法：只声明创建契约，不给实现。
  Record createRecord(String raw);

  // 2. 模板流程：先创建再使用，子类替换的是被创建的类型。
  List<Record> importAll(List<String> raws) => <Record>[
    for (final raw in raws) createRecord(raw),
  ];

  String summarize(List<String> raws) => importAll(
    raws,
  ).map((Record record) => '${record.name}=${record.value}').join(', ');
}

final class KeyValueImporter extends Importer {
  @override
  Record createRecord(String raw) {
    final separator = raw.indexOf('=');
    if (separator <= 0) throw FormatException('不是 name=value 形式', raw);
    return KeyValueRecord(
      raw.substring(0, separator),
      raw.substring(separator + 1),
    );
  }
}

final class JsonImporter extends Importer {
  @override
  Record createRecord(String raw) {
    final decoded = jsonDecode(raw);
    if (decoded is! Map<String, dynamic> || decoded.length != 1) {
      throw FormatException('期望单字段 JSON 对象', raw);
    }
    return JsonRecord(decoded.keys.first, '${decoded.values.first}');
  }
}

void main() {
  // 3. 运行期只依赖 Importer，具体产品由子类决定。
  final Importer keyValue = KeyValueImporter();
  final Importer json = JsonImporter();

  assert(
    keyValue.summarize(<String>['singleton=单例', 'prototype=原型']) ==
        'singleton=单例, prototype=原型',
  );
  assert(json.summarize(<String>['{"factory": "工厂"}']) == 'factory=工厂');

  // 4. 解析失败由具体 creator 负责，模板流程不掺入格式细节。
  try {
    keyValue.createRecord('broken');
    assert(false, '缺失分隔符必须抛错');
  } on FormatException catch (error) {
    print('解析失败：${error.message}');
  }
  print('json -> ${json.summarize(<String>['{"builder": "生成器"}'])}');
}
```

模板流程只在父类写一次，子类无法“忘记调用创建步骤”。只有一条创建行为、没有额外状态时，直接传函数就不必建子类——以下是完整文件 `factory_method_closure.dart`，验证环境同上：

```dart
// 前置条件：Dart 3.x；纯 Dart；无第三方依赖。
import 'dart:convert' show jsonDecode;

/// 只有一条创建行为、没有额外状态时，直接传函数就不必建子类。
typedef PairRecord = ({String name, String value});

PairRecord fromKeyValue(String raw) {
  final separator = raw.indexOf('=');
  if (separator <= 0) throw FormatException('不是 name=value 形式', raw);
  return (
    name: raw.substring(0, separator),
    value: raw.substring(separator + 1),
  );
}

PairRecord fromJson(String raw) {
  final decoded = jsonDecode(raw);
  if (decoded is! Map<String, dynamic> || decoded.length != 1) {
    throw FormatException('期望单字段 JSON 对象', raw);
  }
  return (name: decoded.keys.first, value: '${decoded.values.first}');
}

typedef RecordFactory = PairRecord Function(String raw);

// 1. 创建步骤作为函数参数注入：调用方直接决定实例化哪个产品。
String summarize(List<String> raws, RecordFactory createRecord) => <PairRecord>[
  for (final raw in raws) createRecord(raw),
].map((PairRecord record) => '${record.name}=${record.value}').join(', ');

void main() {
  // 2. 同一套流程，两行调用就换了创建策略，没有新增任何类型。
  assert(summarize(<String>['a=1', 'b=2'], fromKeyValue) == 'a=1, b=2');
  assert(summarize(<String>['{"a": 1}'], fromJson) == 'a=1');

  // 3. 创建器需要外部参数时用闭包补上。
  const prefix = 'imported-';
  assert(
    summarize(<String>['a=1'], (String raw) {
      final pair = fromKeyValue(raw);
      return (name: '$prefix${pair.name}', value: pair.value);
    }) ==
        'imported-a=1',
  );

  print('keyValue=${summarize(<String>['a=1', 'b=2'], fromKeyValue)}');
  print('json=${summarize(<String>['{"a": 1}'], fromJson)}');
}
```

## 适用条件与代价

- 适用：流程固定、创建哪种产品由子类决定；框架提供扩展点，让使用者替换产品实现。
- 代价：每加一种产品就要新增子类；继承层级加深后流程与创建耦合，只为一次创建引入子类并不划算。函数形态更轻（多个创建器还能用 record 分组），但会丢掉 creator 的子类结构，无法在创建前后插入状态逻辑。

## Dart 标准库与生态映射

- 严格意义的工厂方法要求“子类覆写延迟实例化”。Dart 标准库里找不到官方 API 的严格案例，本篇示例即最小实现；`factory` 构造器能返回子类型，但它不是子类覆写。
- 不要把所有命名构造器都叫工厂方法：`DateTime.utc()`、`Uri.parse` 只是命名构造语法的便利入口，没有 Creator/ConcreteCreator 结构。

## 面试追问

- 与[简单工厂](02-简单工厂.md)、[抽象工厂](04-抽象工厂.md)的差别？（简单工厂一处集中选择；工厂方法把选择下放到子类；抽象工厂一次创建一族相关产品）
- 为什么函数参数可能比子类更简单？什么时候必须保留 creator？（只变化创建行为、无额外状态时注入函数即可；创建需要状态、依赖或框架扩展点时才值得用子类）
- 模板流程被意外覆写的风险怎么控制？（把流程方法固定住，只开放工厂方法一个变化点）

## 一句话总结

> 工厂方法把创建时机推迟到子类覆写，流程留在父类；当创建只有一个行为且没有额外状态时，注入函数比新建子类更轻。
