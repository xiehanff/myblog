## 意图（Intent）

把一个请求封装成对象，从而可以：用命令参数化其它对象、把命令排队、记录日志，以及支持撤销。

动机：遥控器按下“开灯”时，它不应该知道灯怎么亮，更不该直接调用 `Light.on()`——那样按钮和灯就绑死了。把“动作”本身变成可传递的值后，按钮才有统一形态：可以随便换绑、可以批量触发、可以记下来反悔。

## 结构（Structure）

```text
Client ──创建并装配──▶ Invoker ──execute()──▶ Command ──▶ Receiver
                                                    │
                     ConcreteCommand 持有 Receiver 引用，
                     execute() 内部转发到 receiver 的某个动作
```

- **Command**：请求的封装形态；最小实现就是 `void Function()`。
- **Receiver**：真正执行动作的对象。
- **Invoker**：触发命令的对象，不认识 Receiver。
- **Client**：装配 Invoker、Command 和 Receiver。

## 实现（Implementation）

Dart 里命令的天然形态是函数：`typedef Command = void Function()`。实例方法 tear-off（如 `light.on`）、闭包、宏命令都自动满足这个协议，不需要为一次性动作建单方法类。只有需要撤销、排队、日志、身份或依赖注入时，才值得把命令升级成有 `execute()` 的类型。

以下代码合起来是完整文件 `command.dart`。验证环境：Dart 3.12.2；`dart analyze` 无问题，`dart run --enable-asserts` 通过。

```dart
// 前置条件：Dart 3.x；纯 Dart；无第三方依赖。
typedef Command = void Function();

/// Receiver：真正被操作的设备。
final class Light {
  String _state = 'off';

  String get state => _state;

  void on() => _state = 'on';

  void off() => _state = 'off';
}

/// Invoker：不关心命令做什么，只负责触发、记录逆命令。
final class RemoteControl {
  RemoteControl({int slotCount = 7})
    : _onCommands = List<Command?>.filled(slotCount, null),
      _offCommands = List<Command?>.filled(slotCount, null);

  final List<Command?> _onCommands;
  final List<Command?> _offCommands;
  final List<Command> _history = [];

  int get undoDepth => _history.length;

  void setSlot(int slot, {required Command on, required Command off}) {
    // 1. 命令在装配阶段注入，Invoker 不认识 Light。
    _onCommands[slot] = on;
    _offCommands[slot] = off;
  }

  void pressOn(int slot) {
    // 2. 先取齐一对命令再执行，避免执行一半才发现槽位为空。
    final onCommand = _require(_onCommands, slot);
    final inverse = _require(_offCommands, slot);
    onCommand();
    _history.add(inverse); // 3. 记下逆命令，供撤销使用
  }

  void pressOff(int slot) {
    final offCommand = _require(_offCommands, slot);
    final inverse = _require(_onCommands, slot);
    offCommand();
    _history.add(inverse);
  }

  /// 撤销最近一次按键；撤销本身也是一次命令。
  void undo() {
    if (_history.isEmpty) return;
    _history.removeLast()();
  }

  Command _require(List<Command?> commands, int slot) {
    final command = commands[slot];
    if (command == null) {
      throw StateError('slot $slot 还没有绑定命令');
    }
    return command;
  }
}
```

```dart
/// 宏命令：把多个命令组合成一个命令。
Command macro(List<Command> commands) => () {
  for (final command in commands) {
    command();
  }
};

void main() {
  final livingRoom = Light();
  final bedroom = Light();
  final remote = RemoteControl();

  // 4. 方法 tear-off 本身就是 Command，不需要包装类。
  remote.setSlot(0, on: livingRoom.on, off: livingRoom.off);
  remote.setSlot(1, on: bedroom.on, off: bedroom.off);
  remote.setSlot(
    2,
    on: macro([livingRoom.on, bedroom.on]),
    off: macro([livingRoom.off, bedroom.off]),
  );

  // 5. 单灯开关与撤销。
  remote.pressOn(0);
  assert(livingRoom.state == 'on');
  remote.undo();
  assert(livingRoom.state == 'off');

  // 6. 宏命令一次触发多个接收者。
  remote.pressOn(2);
  assert(livingRoom.state == 'on' && bedroom.state == 'on');
  remote.pressOff(2);
  assert(livingRoom.state == 'off' && bedroom.state == 'off');
  assert(remote.undoDepth == 2);

  // 7. 未绑定的槽位显式失败，而不是悄悄忽略。
  try {
    remote.pressOn(5);
    assert(false, '未绑定槽位应当抛错');
  } on StateError catch (error) {
    print(error.message);
  }
}
```

要点：

- `_history` 里存的是逆命令而不是“上一次的 Receiver 状态”：执行 `on` 时记下 `off`，撤销就是把栈顶命令执行一次。这正是命令模式区别于普通回调的地方——它把“能反悔”也建模出来了。
- 逆命令只在操作可逆且期间没有外部状态干扰时可靠；真实编辑器通常还要保存版本号或快照，避免“撤销”把已经被别的操作修改过的接收者恢复到错误状态。
- 宏命令 `macro([...])` 只是又一个 `Command`，对 Invoker 完全透明，可以继续放进槽位、入队或撤销。
- 逆命令必须是成对的。如果一次按键只绑定了一半（比如只有 on 没有 off），这里选择在装配后最早的时刻用 `StateError` 失败，而不是默默执行一半。

## 适用条件与代价

- 适用：需要撤销/重做、排队执行、宏命令、操作日志，或者把“谁发起”和“何时执行”分离。
- 不适用：只是同步调用一次动作。此时直接调用函数就是最短路径，为每个动作建类只会增加间接层。
- 代价：命令对象/闭包会形成额外一层引用；撤销要求每个操作都有可执行的逆操作（随机数、发送邮件这类不可逆操作只能存状态或干脆不撤销）；历史记录要限制深度，否则内存持续增长。

## Dart 标准库与生态映射

- Dart 没有 `Command` 标准类型；`void Function()` 就是最小命令协议，UI 回调（如 `onPressed`）是把命令参数化的常见形态。
- 需要排队时用 `dart:collection` 的 `Queue<Command>`；`Timer`、`Future` 只负责在什么时机执行，不负责命令语义。
- 需要成对的 do/undo 时，可以让命令类型升级为 Dart 3 record：`typedef Reversible = ({Command execute, Command undo});`，依然不必建类。
- 语言机制与模式不是一回事：把函数当值传递是函数式特性；命令模式真正的增量价值在撤销、排队、日志这些额外职责。

## 面试追问

- 命令和[策略](./22-策略.md)的区别？两者都是“行为对象”，策略换的是算法，命令封装的是请求，并且可以带 Receiver、可撤销、可排队。
- 命令和普通闭包的区别？闭包没有撤销、日志和身份语义，接口只能靠约定。
- 撤销应该存逆操作还是存快照？（小额状态存快照，代价是内存；不可逆操作存逆命令无从谈起）
- 宏命令在 GoF 结构里扮演谁的角色？（它本身就是一个 ConcreteCommand，组合了其它命令）
- 命令如何支持事务和日志恢复？

## 一句话总结

> 命令把请求变成可传递、可排队或可记录的值；只有在这些额外语义有价值时，才需要超出一个普通函数。
