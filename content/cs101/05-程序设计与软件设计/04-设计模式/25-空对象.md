## 意图（Intent）

用一个什么都不做的对象代替 `null`，让调用方在不做分支判断的情况下完成一次“无操作”调用。

动机：日志、缓存、通知这类依赖常常是可选的。方法返回 `null` 时，每个调用点都要检查返回值，漏掉一处就是运行时错误。空对象把这个检查提前到装配阶段：调用方拿到的永远是一个满足协议的对象，只是它什么都不做。

## 结构（Structure）

```text
Client ──▶ AbstractOperation（协议）
                   ├── RealOperation   做真实的事
                   └── NullOperation   什么都不做，但遵守同一契约
```

- **AbstractOperation**：调用方依赖的协议。
- **RealOperation**：真实实现。
- **NullOperation**：合法实现，方法体为空。

## 实现（Implementation）

以下代码是完整文件 `null_object_audit.dart`。验证环境：Dart 3.12.2；`dart analyze` 无问题，`dart run --enable-asserts` 通过。

```dart
// 前置条件：Dart 3.12；纯 Dart；无第三方依赖。
// 审计日志：真实实现记录内容，空对象满足同一契约但不做任何事。

/// 协议：只声明“记录一条审计消息”。
abstract interface class AuditLog {
  void write(String message);
}

/// 真实实现：写入内存缓冲，便于断言。
final class MemoryLog implements AuditLog {
  final List<String> entries = [];

  @override
  void write(String message) => entries.add(message);
}

/// 空对象：契约不变，行为是无操作。
final class NullLog implements AuditLog {
  const NullLog();

  @override
  void write(String message) {}
}

/// 业务代码只依赖非空协议，调用时不需要 null 检查。
final class PaymentService {
  PaymentService(this.log);

  final AuditLog log;

  void pay(String orderId, double amount) {
    if (amount <= 0) {
      throw ArgumentError.value(amount, 'amount', '支付金额必须为正');
    }
    log.write('支付 $orderId: $amount');
  }
}

bool auditConfigured() => false;

void main() {
  // 1. 正常环境：注入真实实现。
  final memory = MemoryLog();
  PaymentService(memory).pay('A-1001', 99.5);
  assert(memory.entries.single == '支付 A-1001: 99.5');

  // 2. 未配置审计的环境：注入空对象，调用方代码一模一样。
  PaymentService(const NullLog()).pay('A-1002', 10);
  assert(memory.entries.length == 1); // 空对象没有写进任何地方

  // 3. 空对象是 const 实例：跨调用点共享同一个对象。
  assert(identical(const NullLog(), const NullLog()));

  // 4. 可空替代：缺失本身必须由调用方显式处理。
  final AuditLog? maybeLog = auditConfigured() ? MemoryLog() : null;
  maybeLog?.write('这条不会记录');
  final effective = maybeLog ?? const NullLog();
  effective.write('仍然安全');
  assert(maybeLog == null);

  print(memory.entries.join('\n'));
}
```

要点：

- `PaymentService` 里的 `log` 类型是非空的 `AuditLog`，调用 `log.write(...)` 之前不需要任何判断。
- `NullLog` 用 `const` 构造器：所有 `const NullLog()` 是同一个规范化实例，等于语言帮你实现了“每 isolate 一个”的单例，不需要额外写静态字段。
- 空对象只在“无操作确实是正确语义”时成立。如果“没有日志”意味着配置缺失、必须有人发现，注入空对象就是在吞故障——这时应让依赖不可空并在启动时失败。

## 可空类型是更直接的替代

Dart 的空安全让“缺失”必须写成显式的可空类型，很多场景不需要空对象，只需要可空类型加 `?.`、`??`。示例文件第 4 步就是这样消费同一个协议：入口返回 `AuditLog?`，`maybeLog?.write(...)` 表示“有才调用”，`maybeLog ?? const NullLog()` 表示“在边界处补默认值”。

- 可空替代适合“缺失本身需要被处理或上报”的场景，类型会强迫每个调用点表态。
- 空对象适合“缺失是正常的、调用方不关心”的场景，装配时注入一次，之后所有调用点零分支。
- 两者也可以结合：入口用可空类型表达“未配置”，在组合根处用 `?? NullLog()` 收敛成非空依赖。

## 适用条件与代价

- 适用：协议已存在，且“什么都不做”是合法行为；有多个调用点、不想重复判空。
- 代价：空对象会静默吞掉调用；如果它掩盖的是必须配置的依赖，故障会推迟到最难看懂的地方；协议方法很多时，空对象要为每个方法写空实现。
- 与[责任链](./14-责任链.md)的联系：链尾的 `null` 表示“没人处理”，如果“没人处理”是正常情况，也可以换成 no-op 的链尾处理器；区别在于责任链要表达“请求是否被处理”，空对象要表达“这个依赖可以不存在”。

## Dart 标准库与生态映射

- 空安全、`?.`、`??`、模式匹配是语言级替代机制；它们和空对象不是竞争关系：可空类型描述“可能没有”，空对象描述“没有时也有合法行为”。
- Dart 标准库没有 Null Object 命名类型；`NullLog` 这类对象按协议自己实现即可。

> 空对象把“缺失依赖”收敛成一个合法的无操作实现；只有在无操作确实是业务语义时，才不算吞掉故障。
