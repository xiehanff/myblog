## 意图（Intent）

提供一种方法顺序访问一个聚合对象中的各个元素，而又不暴露该对象的内部表示。

动机：树、图、分页结果这些结构，调用方通常只关心"按某种顺序拿到每个元素"，不关心游标存在哪里、下一步怎么算。如果让调用方自己维护下标或递归状态，容器的内部表示就泄漏了；想换一种遍历顺序（中序、前序、广度优先），调用代码也得跟着改。迭代器把"聚合"和"游走"分开：容器只承诺能给出一个游标，游标负责顺序、前进与终止条件。

## 结构（Structure）

```text
Iterable<T>                          Iterator<T>
  │  iterator ────────────────────▶   moveNext() → bool
  │                                   current    → T
  │
for-in / map / where / take / fold ── 都建立在这两个方法之上

Aggregate          → Iterable<T>（可重复遍历的承诺）
ConcreteAggregate  → TreeNode / Countdown
Iterator           → Iterator<T>（一次性游标）
ConcreteIterator   → CountdownIterator，或 sync* 生成器保存的遍历状态
```

- **Aggregate / Iterable**：暴露 `iterator`，每次调用都返回一个新的游标。
- **Iterator**：保存遍历位置，`moveNext()` 前进并报告是否还有元素，`current` 读取当前元素。
- **Client**：用 `for-in` 或 `Iterable` 的扩展方法消费，不接触容器内部。

依赖方向：客户端只依赖 `Iterable<T>`；容器自己决定如何构造游标，游标自己保存遍历状态，容器表示和遍历状态互不泄漏。

## 实现（Implementation）

Dart 已经把迭代协议内建在语言里，不需要再定义一个 `hasNext/next` 接口，也不用为普通集合重写迭代器。下面用两种方式给自定义结构提供遍历：树的中序遍历用 `sync*` 生成器，倒计时用手写 `Iterator` 看清协议的责任边界。

以下三段合起来是完整文件 `iterator.dart`。验证环境：Dart 3.12.2；`dart analyze` 无问题，`dart run --enable-asserts` 通过。

```dart
// 前置条件：Dart 3.x；纯 Dart；无第三方依赖。
// 迭代器：sync* 惰性遍历，以及手写 Iterator 的契约。

/// 树节点：left/right 保持私有，遍历只通过 inOrder() 暴露。
final class TreeNode {
  TreeNode(this.value, {TreeNode? left, TreeNode? right})
    : _left = left,
      _right = right;

  final int value;
  final TreeNode? _left;
  final TreeNode? _right;

  /// 中序遍历：sync* 把递归写成惰性序列，被消费时才向下走。
  Iterable<int> inOrder() sync* {
    final left = _left;
    if (left != null) yield* left.inOrder();
    yield value;
    final right = _right;
    if (right != null) yield* right.inOrder();
  }
}

/// 自然数：惰性序列必须有上限消费者，否则永不结束。
Iterable<int> naturals() sync* {
  var value = 0;
  while (true) {
    yield value++;
  }
}

```

```dart
/// 手写 Iterator：游标状态由对象保存，moveNext 成功后才能读 current。
final class CountdownIterator implements Iterator<int> {
  CountdownIterator(this._remaining);

  int _remaining;
  int? _current;

  @override
  int get current {
    final current = _current;
    if (current == null) {
      throw StateError('moveNext() 返回 true 之前没有 current');
    }
    return current;
  }

  @override
  bool moveNext() {
    if (_remaining <= 0) {
      _current = null;
      return false;
    }
    _current = _remaining--;
    return true;
  }
}

/// Aggregate：对外只承诺“可重复遍历”，游标实现不暴露。
final class Countdown extends Iterable<int> {
  Countdown(this.start);

  final int start;

  @override
  Iterator<int> get iterator => CountdownIterator(start);
}

```

```dart
void main() {
  // 1. 构造 5 / 3 7 / 1 9 的二叉搜索树。
  final root = TreeNode(
    5,
    left: TreeNode(3, left: TreeNode(1)),
    right: TreeNode(7, right: TreeNode(9)),
  );

  // 2. Iterable 可重复遍历：每次取到的 iterator 都是新游标。
  assert(root.inOrder().toList().toString() == '[1, 3, 5, 7, 9]');
  assert(root.inOrder().toList().toString() == '[1, 3, 5, 7, 9]');
  assert(root.inOrder().where((value) => value >= 5).length == 3);

  // 3. 惰性：无限序列可以被 take 截断，不必先算完。
  assert(naturals().take(3).toList().toString() == '[0, 1, 2]');

  // 4. for-in 背后就是 moveNext/current 协议。
  final seen = <int>[];
  for (final value in Countdown(3)) {
    seen.add(value);
  }
  assert(seen.toString() == '[3, 2, 1]');

  print(root.inOrder().toList());
}
```

要点：

- `Iterable` 和 `Iterator` 不是一回事。`root.inOrder()` 是一个方法调用，每次都会得到一个新的 `Iterable`，再次遍历时从 `_left` 重新开始；`Iterator` 则是一次性游标，只能向前。`for-in` 的展开就是先取 `iterator`，再循环 `moveNext()`，成功时读 `current`。
- `sync*` 让递归写法变成惰性序列：`yield*` 把子树产生的元素接进来，函数在每次 `yield` 处挂起，消费方要一个才走一步。遍历状态由运行时的生成器状态机保存，不需要为它写游标类；`naturals()` 能表示无限序列，正是因为序列在 `take(3)` 之前根本没有被算出来。
- 惰性不等于缓存。每个新 `Iterable` 都重新执行生成器；如果同一批结果要反复遍历，先 `toList()` 缓存成列表再复用。
- 手写 `Iterator` 的契约只有两条：`moveNext()` 返回 `false` 表示正常结束，不能拿它当异常；`current` 只在 `moveNext()` 返回 `true` 之后有效。本示例用一个 `_current == null` 检查把误用立刻变成 `StateError`，比依赖某个集合实现的兜底行为更清楚。

## 适用条件与代价

- 适用：容器内部表示需要封装、同一数据需要多种遍历顺序、希望惰性消费（只取前几个元素或序列无限）、把遍历逻辑从业务代码里抽出来复用。
- 代价：每次遍历多一层对象或生成器状态；`current` 的有效期是常见错误来源；在遍历过程中修改可变集合，Dart 集合迭代器会抛 `ConcurrentModificationError`（本示例的树不可变，不存在这个问题，换成可变容器时要先想清规则）。
- 如果只是对一个 `List` 做一次 `for` 循环，直接用 `for-in` 就是最短路径。只有确实要隐藏表示、复用遍历逻辑或惰性求值时，才值得定义新类型。

## Dart 标准库与生态映射

- `Iterable<T>` / `Iterator<T>` 就是 Dart 的迭代协议，`for-in`、`map`、`where`、`expand`、`take`、`fold` 都建立在它之上，这是强对应。
- `sync*` 生成器是语言机制层面的等价物：用同步惰性写法产出 `Iterable`；对应的 `async*` 产出 `Stream`，语义从同步拉取变成异步推送。
- `Stream` 不是"异步 Iterator 的简单同义词"：`Stream` 有独立的错误通道和 done 事件、支持取消订阅、区分 single-subscription 与 broadcast，事件何时到达由生产者决定；`Iterable` 是同步拉模型，消费方决定何时取下一个元素。`await for` 只是语法上与 `for-in` 相似。
- Dart 只有一套迭代协议：`Iterable` / `Iterator` 就是唯一入口，不需要再维护两套并行的遗留遍历 API。

## 面试追问

- `Iterable` 和 `Iterator` 各自负责什么？前者是可重复遍历的抽象，后者是一次性游标；`Iterable.iterator` 每次返回新游标。
- 惰性遍历的状态存在哪里？`sync*` 生成器里存在运行时的生成器状态机中；手写 `Iterator` 时存在游标对象的字段里。
- 为什么 `Stream` 不能直接当成异步版 `Iterator`？错误通道、取消、广播、事件到达时机与背压语义都不同。
- 遍历中删除元素会怎样？Dart 的集合迭代器会检测到并发修改并抛错；要删除应使用 `removeWhere`，或先收集要删的元素再统一处理。

## 一句话总结

> 迭代器把“如何走过集合”从集合表示中分离出来；`Iterable` 提供可重复遍历入口，`Iterator` 保存一次遍历的游标状态。
