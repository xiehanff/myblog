## 意图（Intent）

允许一个对象在内部状态改变时改变它的行为，看起来就像换了一个类。动机：订单、播放器、售货机这类对象的操作是否合法，几乎完全由“当前处于哪一步”决定；用布尔字段加 `if/else` 堆逻辑时，每加一个状态就要回到每个方法里补分支，“哪些转移合法”也散落在各处。状态模式把每个状态的行为装进独立对象，并把转移规则也交给状态自己。

## 结构（Structure）

```text
Context ──事件委托──▶ State（协议）
   │ state 字段          ├── ConcreteStateA ──处理事件时决定下一个状态
   │ 对外方法只转发      └── ConcreteStateB ──处理事件时决定下一个状态

糖果机状态转移：
未投币 ──投币──▶ 已投币 ──退币──▶ 未投币
                    │
                    └──转动曲柄──▶ 出货：还有糖 -> 未投币
                                    没糖了 -> 售罄
售罄：投币 / 退币 / 转动 全部拒绝（留在售罄）
```

- **Context**：持有当前状态，把每个事件转给状态对象处理，本身不写条件分支。
- **State**：为每个事件声明一个处理方法；**ConcreteState** 定义该状态下的行为，并在需要时把 Context 转移到下一个状态。

关键点：**转移的决策权在状态对象，不在 Context**。Context 只提供事件入口和可观察的转移结果。

## 实现（Implementation）

以下两段代码合起来是完整文件 `state_gumball_machine.dart`（第一段到 `SoldOutState` 结束，第二段从 `main` 开始）。验证环境：Dart 3.12.2；`dart analyze` 无问题，`dart run --enable-asserts` 通过。

```dart
// 前置条件：Dart 3.12；纯 Dart；无第三方依赖。
// 糖果机：每个状态的行为和转移封装成对象，Context 只做委托。

abstract interface class GumballState {
  void insertQuarter(GumballMachine machine);

  void ejectQuarter(GumballMachine machine);

  void turnCrank(GumballMachine machine);
}

final class GumballMachine {
  GumballMachine(int count)
    : _count = _requireNonNegative(count),
      _state = count > 0 ? const NoQuarterState() : const SoldOutState();

  static int _requireNonNegative(int value) {
    if (value < 0) throw ArgumentError.value(value, 'count', '库存不能为负');
    return value;
  }

  int _count;
  GumballState _state;
  final List<String> _log = [];

  int get count => _count;

  GumballState get state => _state;

  List<String> get log => List.unmodifiable(_log);

  // 状态类通过库级私有方法改变 Context，调用方不能直接写出非法状态。
  void _setState(GumballState next) => _state = next;

  void _record(String message) => _log.add(message);

  void _dispense() {
    if (_count <= 0) throw StateError('库存已经为空');
    _count--;
  }

  void insertQuarter() => _state.insertQuarter(this);

  void ejectQuarter() => _state.ejectQuarter(this);

  void turnCrank() => _state.turnCrank(this);
}

final class NoQuarterState implements GumballState {
  const NoQuarterState();

  @override
  void insertQuarter(GumballMachine machine) {
    machine._record('投入硬币');
    machine._setState(const HasQuarterState());
  }

  @override
  void ejectQuarter(GumballMachine machine) => machine._record('没有硬币可退');

  @override
  void turnCrank(GumballMachine machine) => machine._record('请先投币');
}

final class HasQuarterState implements GumballState {
  const HasQuarterState();

  @override
  void insertQuarter(GumballMachine machine) =>
      machine._record('已有硬币，不能重复投入');

  @override
  void ejectQuarter(GumballMachine machine) {
    machine._record('退回硬币');
    machine._setState(const NoQuarterState());
  }

  @override
  void turnCrank(GumballMachine machine) {
    // 1. 出货后转移到哪里，由当前状态在事件处理中决定。
    machine._dispense();
    machine._record('发放糖果，剩余 ${machine.count}');
    machine._setState(machine.count > 0
        ? const NoQuarterState()
        : const SoldOutState());
  }
}

final class SoldOutState implements GumballState {
  const SoldOutState();

  @override
  void insertQuarter(GumballMachine machine) => machine._record('售罄：不能投币');

  @override
  void ejectQuarter(GumballMachine machine) =>
      machine._record('售罄：没有硬币可退');

  @override
  void turnCrank(GumballMachine machine) => machine._record('售罄：无法转动');
}

```

```dart
void main() {
  final machine = GumballMachine(2);

  machine.insertQuarter(); // 未投币 -> 已投币
  machine.insertQuarter(); // 重复投币被拒绝
  machine.turnCrank(); // 出货 -> 未投币，剩余 1
  machine.turnCrank(); // 未投币，拒绝
  machine.ejectQuarter(); // 没有硬币可退
  machine.insertQuarter(); // 未投币 -> 已投币
  machine.ejectQuarter(); // 退币 -> 未投币
  machine.insertQuarter(); // 未投币 -> 已投币
  machine.turnCrank(); // 出货 -> 售罄，剩余 0
  machine.insertQuarter(); // 售罄，拒绝

  assert(machine.count == 0);
  assert(machine.state is SoldOutState);
  assert(machine.log.length == 10);
  assert(machine.log.first == '投入硬币');

  print(machine.log.join('\n'));
}
```

要点：

- 三个事件在三个状态下全部有定义，拒绝也留下一条可观察的记录，不存在“忘了处理”的组合。
- 状态对象不持有 Context 的引用，而是把 Context 作为参数传入。这样状态可以是 `const` 单例，也不会和 Context 互相持有；示例里 `state` 是公开字段，真实代码应封装转移方法。

### sealed 替代版本

如果状态和事件都是封闭集合，用 `sealed class` 加穷尽 `switch` 可以把整张转移表写在一个函数里：

```dart
// 前置条件：Dart 3.12；纯 Dart；无第三方依赖。
// 糖果机的 sealed 替代：状态和事件都是封闭类型，转移写成穷尽 switch。

sealed class MachineState {
  const MachineState();
}

final class Idle extends MachineState {
  const Idle();
}

final class Ready extends MachineState {
  const Ready();
}

final class Empty extends MachineState {
  const Empty();
}

sealed class MachineEvent {
  const MachineEvent();
}

final class InsertQuarter extends MachineEvent {
  const InsertQuarter();
}

final class EjectQuarter extends MachineEvent {
  const EjectQuarter();
}

final class TurnCrank extends MachineEvent {
  const TurnCrank();
}

/// 转移规则集中在一个函数里；返回新状态和一句可观测的说明。
({MachineState state, String message}) handle(
  MachineState state,
  MachineEvent event,
  int stock,
) => switch ((state, event)) {
  (Empty(), _) => (state: state, message: '售罄：拒绝所有事件'),
  (Idle(), InsertQuarter()) => (state: const Ready(), message: '投入硬币'),
  (Idle(), EjectQuarter()) => (state: state, message: '没有硬币可退'),
  (Idle(), TurnCrank()) => (state: state, message: '请先投币'),
  (Ready(), InsertQuarter()) => (state: state, message: '已有硬币，不能重复投入'),
  (Ready(), EjectQuarter()) => (state: const Idle(), message: '退回硬币'),
  (Ready(), TurnCrank()) => (
    state: stock > 1 ? const Idle() : const Empty(),
    message: '发放糖果，剩余 ${stock - 1}',
  ),
};

```

```dart
void main() {
  MachineState state = const Idle();
  final log = <String>[];

  const events = <MachineEvent>[InsertQuarter(), TurnCrank(), InsertQuarter()];
  for (final event in events) {
    final result = handle(state, event, 1);
    state = result.state;
    log.add(result.message);
  }

  assert(state is Empty);
  assert(log.join(' -> ') == '投入硬币 -> 发放糖果，剩余 0 -> 售罄：拒绝所有事件');
  print(log.join('\n'));
}
```

两种写法的取舍：

- 多态版本：新增状态 = 新增一个类；但新增事件要改所有状态类。
- sealed + switch 版本：转移规则集中在一处，读起来像一张表；代价是新增状态或事件都会让 `switch` 编译报错，所有用到的地方都要补分支——这正是穷尽检查想要的破坏性变更。

## 适用条件与代价

- 适用：行为随少量状态切换；状态转移规则需要显式管理；希望消掉大段 `if/else` 或 `switch`。
- 代价：每个状态一个类，状态多时会膨胀；转移规则分散在各状态里，整体流程要靠转移图补全理解。
- 状态和[策略](./22-策略.md)的区别：策略由 Context 或调用方选择、替换，策略自己不决定下一个策略；状态转移由状态在处理事件时触发。

## Dart 标准库与生态映射

- Dart 没有 `State` 标准类型；`sealed class`（或 `enum`）加模式匹配是表达状态机最直接的语言机制。状态恰好是简单枚举值时，`enum` 加穷尽 `switch` 比 sealed 类层级更省；一旦不同状态要携带不同数据，再升级为 sealed 类。

## 一句话总结

> 状态模式把“当前状态下怎么响应事件”和状态转移放进状态对象；状态集合封闭时，`sealed` + 穷尽 `switch` 往往是更轻的替代。
