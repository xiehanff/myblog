# 算法与数据结构｜07-堆与优先队列

日志系统要从百万行记录里实时挑出耗时最高的 10 条；调度器每一刻都要找出优先级最高的任务；一个数据流不断追加整数，却要随时回答"当前中位数是多少"。这些问题的共同点是：元素在动态变化，而查询只关心极值或前几个极值。

最朴素的做法是每次查询都重看所有元素（O(n)），或者每次插入后重新排序（O(n log n)）。这两种做法都做了大量不需要的工作——查询只问"谁最紧急"，从来没有要求"所有人都按顺序站好"。

本文先说明为什么"部分有序"就够用，再给出优先队列的抽象契约；然后拆开二叉堆，看它如何用数组同时维持形状与堆序两个不变量、如何用上浮与下沉修复、如何 O(n) 建堆；接着给出一个可直接复用的 Dart `BinaryHeap`，用它解决 Top K、流式中位数与多路归并；最后集中处理常见坑与面试追问。

## 为什么不必每次都全量排序

问题可以统一成一句话：维护一个会插入、会删除的动态集合，并反复询问"当前的最小值/最大值是谁"。如果只关心极值，维护"全序"就是超量工作。

先用最直接的几种结构对照一次代价：

| 结构 | 查看极值 | 插入 | 删除极值 | 额外空间 | 主要代价 |
| --- | --- | --- | --- | --- | --- |
| 无序数组 | O(n) 扫描 | O(1) | O(n) | O(1) | 每次取极值都要看全部元素 |
| 有序数组 | O(1) | O(n) 搬移 | O(n) 搬移 | O(1) | 插入要维持全序 |
| 自适应搜索树（如 Dart `SplayTreeSet`） | 均摊 O(log n) | 均摊 O(log n) | 均摊 O(log n) | 每节点指针与对象开销 | 常数更大，指针跳跃多 |
| 二叉堆 | O(1) | O(log n) | O(log n) | O(n) 数组 | 不支持任意查找与有序迭代 |

前两行把"访问快"和"插入快"摆在了对立面：数组很擅长顺序访问，却无法廉价地腾出中间位置。搜索树能同时做到对数级，但为每个元素维护了左右指针，常数和内存开销都更高。各操作的复杂度口径（最坏与均摊）沿用[复杂度分析与算法思想](./01-复杂度分析与算法思想.md)的约定。

二叉堆走了第三条路：它只维持一种弱得多的秩序——"每个父节点不劣于自己的孩子"。这个条件足以把最值一直顶到根上，于是查看极值 O(1)，插入和删除极值只需沿一条路径调整，O(log n)。它放弃的是全局顺序：既不能按序迭代，也不能快速查找任意元素。

极值查询只需要元素之间的偏序，不需要全序；堆用"只维护偏序"换来了 O(1) 取极值与 O(log n) 更新，代价是失去排序、查找与范围能力。

流式场景进一步放大了这个差异。求 100 万条日志里最慢的 10 条，排序要读完整个数组并 O(n log n) 比较；而一个大小为 10 的堆可以一边读一边淘汰，只保留 10 个候选，额外空间 O(k)，数据来不完也能先给出当前答案。这在数据量超过内存或持续到达时不是优化，而是唯一可行的路线。

## 优先队列 ADT

优先队列（priority queue）的名字容易误导：它和"先进先出"的队列（queue）不是同一种结构。队列按到达顺序出队，优先队列按优先级出队。它的抽象契约只有三件事：

1. `insert(e)`：把元素放进去；
2. `peek()`：查看当前优先级最高的元素，但不取出；
3. `removeMin()`（或 `removeMax()`）：取出优先级最高的元素。

"优先级"由调用方给出的比较器定义：比较器认为更小（或更大）的元素先出队。按这个方向分，就有最小堆（min-heap）与最大堆（max-heap）两套习惯。二者不是两种数据结构——翻转比较器就能互相转换。

ADT 规定了可观察行为，不规定实现。它没有承诺的东西同样重要：

- 它不承诺元素有序。`peek` 只保证看得到当次最值，不保证第二个元素就是次小值；
- 它不承诺相同优先级元素的出队顺序。三个优先级相同的元素放入本文实现后，出队顺序是 `[a, c, b]`，与入队的 `[a, b, c]` 不同；这是实现细节，不属于契约。需要稳定出队时，必须自己给优先级加一个递增序号作为次级键。

优先队列是"可反复取最值"的抽象契约，二叉堆只是兑现该契约的常用实现；契约不承诺全序，也不承诺相同优先级的先后关系。

Dart 生态里有一个值得记住的事实：核心库 `dart:collection` 提供了 `Queue`、`SplayTreeSet` 等容器，但没有优先队列；需要使用时，通用选择是 `package:collection` 的 `PriorityQueue`。

> **时效信息（核查日期：2026-09-22）：** 在 Dart 3.12.2 的 `dart:collection` 库中未发现优先队列类型；`package:collection` 提供 `PriorityQueue` 与 `HeapPriorityQueue`，本文核查时为 1.19.1。其文档约定"比较结果更小的元素优先级更高"，并明确"比较返回 0 的元素之间没有指定顺序"；`add`/`removeFirst` 均摊 O(log n)（容量扩张时偶发线性），`first` O(1)，而 `contains`/`remove` 需要 O(n) 查找、移除时用 `Object.==` 判等。它是工程选项，不是本文代码的前提。

## 二叉堆的两个不变量

二叉堆（binary heap）首先是一棵完全二叉树（complete binary tree）：除最后一层外每层都填满，最后一层的节点从左到右连续排列，中间没有空洞。这个"形状不变量"带来了一个决定性好处——它可以原样装进数组：从上到下、从左到右编号后，第 i 个节点的孩子和父亲都能用下标算出来，不需要任何指针。

第二个不变量是堆序（heap order）：以最小堆为例，每个父节点的值都不大于它的两个孩子；最大堆则相反。注意它的作用范围：

- 堆序只约束"父与子"这条边，不约束兄弟之间，也不约束堂兄弟之间；
- 沿任意一条从根向下的路径，值单调不降（最小堆），这就是"最值在根上"的全部依据。

0-based 数组中的下标关系如下（`~/` 是 Dart 的整除）：

```text
数组（下标从 0 开始）：  [1, 3, 2, 7, 5, 4]
下标：                    0  1  2  3  4  5

                 index 0: 1
                 /        \
        index 1: 3          index 2: 2
        /      \          /
index 3: 7   index 4: 5  index 5: 4

parent(i)    = (i - 1) ~/ 2
leftChild(i) = 2 * i + 1
rightChild(i)= 2 * i + 2
最后一个内部节点下标 = n ~/ 2 - 1     // n = 6 时是 2
叶子下标范围         = n ~/ 2 .. n - 1 // n = 6 时是 3..5
```

堆的高度是 ⌊log₂n⌋，因此"沿一条路径走到底"的步数是 O(log n)。这张图还顺带说明了一个容易误解的事实：上面这个数组满足最小堆序，却不是有序数组（`1, 3, 2, 7, 5, 4`）。堆的内部数组只能保证根是极值。

二叉堆由"完全二叉树的形状"与"父不劣于子的堆序"两个不变量共同定义；堆数组不是有序数组，它只保证每条根到叶的路径单调。

很多教材与旧代码采用 1-based 下标（根放在 `a[1]`），公式是 `parent(i) = i ~/ 2`、`children = 2i, 2i + 1`。两套公式各自成立，但绝不能混用：同一份代码里同时出现两种约定的位移，就会出现"下标算到了另一个节点的孩子"这种难查的 bug。本文与 Dart 的 `List` 一致，全部采用 0-based。

> **面试高频：** 堆和二叉搜索树的区别是什么？
> **答题脉络：** 堆只维护父子偏序、用数组实现，擅长取极值；BST 维护全序，支持查找、rank 与有序迭代；两者的操作上界相同量级，但堆常数更小、内存更紧凑。
> **追问方向：** 堆为什么不能有序迭代；BST 为什么通常不用数组表示；为什么堆更常出现在调度与最短路算法里。

## 上浮与下沉

有了两个不变量，插入和删除就变成"小心地破坏其中一个，再花一条路径把它修回来"。

插入操作把新元素直接追加到数组末尾。形状不变量天然保持（最后一层又多了一个靠左的节点），但堆序可能被破坏，而且只可能发生在从新元素到根的这条路径上。修复叫上浮（sift up / swim）：不断与父节点比较，若比父节点更优先就交换，直到不再优先或到达根。

删除堆顶时，堆顶必须被拿走，但直接删掉会在形状上留下一个空洞。做法是先把最后一个元素删下来，把它放到根的位置——形状恢复，堆序可能被破坏。修复叫下沉（sift down / sink）：与两个孩子中"更优先"的那个交换（最小堆取更小的孩子），直到不劣于两个孩子或到达叶子。

为什么必须挑选更小的那个孩子？假设当前节点比两个孩子都大，若与较大的孩子交换，较大的孩子坐上去仍然比另一个（更小的）孩子大，堆序立刻再次被破坏。所以正确次序是先选出孩子中的更优先者，再与它比较。

下面三段轨迹来自真实实现的逐帧打印（验证文件 `trace_sift.dart` 对每一步数组状态都有断言）：

```text
在 [1, 3, 2, 7, 5, 4] 中插入 0：
  1, 3, 2, 7, 5, 4        -- 追加到末尾 --> 1, 3, 2, 7, 5, 4, 0
  1, 3, 2, 7, 5, 4, 0     -- 0 < 父 a[2]=2，交换 --> 1, 3, 0, 7, 5, 4, 2
  1, 3, 0, 7, 5, 4, 2     -- 0 < 父 a[0]=1，交换 --> 0, 3, 1, 7, 5, 4, 2

从 [1, 3, 2, 7, 5, 4] 删除堆顶：
  1, 3, 2, 7, 5, 4        -- 删 1，末尾 4 补到根 --> 4, 3, 2, 7, 5
  4, 3, 2, 7, 5           -- 与更小的孩子 a[2]=2 交换 --> 2, 3, 4, 7, 5

从三层堆 [1, 3, 2, 7, 5, 4, 6] 删除堆顶，尾元素 6 连沉两层：
  6, 3, 2, 7, 5, 4        -- 与更小的孩子 a[2]=2 交换 --> 2, 3, 6, 7, 5, 4
  2, 3, 6, 7, 5, 4        -- 与更小的孩子 a[5]=4 交换 --> 2, 3, 4, 7, 5, 6
```

两个操作都只在一条路径上反复比较与交换，步数不超过树高，因此插入与删除堆顶都是 O(log n)；`peek` 直接返回 `a[0]`，O(1)。用伪代码固定这两个循环（`text` 块为伪代码，不可直接运行，本文的 Dart 版本在下节）：

```text
siftUp(i):                          # 最小堆；i 是刚插入元素的下标
    while i > 0:
        parent = (i - 1) // 2
        if a[parent] <= a[i]: break
        swap(a[parent], a[i]); i = parent

siftDown(i):
    while leftChild(i) < n:
        child = leftChild(i)                       # 默认取左孩子
        if rightChild(i) < n and a[rightChild(i)] < a[child]:
            child = rightChild(i)                  # 右孩子更优先则改取它
        if a[i] <= a[child]: break
        swap(a[i], a[child]); i = child
```

插入与删除只会破坏从某个节点到根或到叶的一条路径上的堆序；上浮与下沉沿这一条路径反复修正，这就是堆操作是对数级而不是线性级的根本原因。

## 自底向上建堆

已经有一整个无序数组时，把一个元素一个元素地 `add` 进去，需要 n 次上浮，最坏情况下合计 O(n log n)。但没有必要从空堆开始：数组里的每个叶子节点本身就是一个大小为 1 的合法堆，只要从最后一个内部节点起，倒着对每个节点执行一次下沉，就能在 O(n) 内完成。

正确性来自一个简单事实：处理某个节点时，它的两棵子树已经是合法堆，因此对根做一次下沉即可让整棵子树合法。处理顺序从右下角向左上角推进，正好保证这个前提。

代价为什么是 O(n)，而不是 n 次 O(log n)？关键是每个节点下沉的最大步数等于它的高度，而越靠近底部的节点越多、高度越小：

```text
高度为 h 的节点最多有 ⌈n / 2^(h+1)⌉ 个
总代价 ≤ Σ(h = 0..⌊log₂n⌋) h × 节点数(h)
       = O(n × Σ(h ≥ 0) h / 2^(h+1))    # 取整与有限项只影响低阶项
       = O(n)                            # 因为 Σ(h ≥ 0) h / 2^(h+1) = 1
```

直观地说，一半节点在叶子层（下沉 0 步），四分之一节点在高度 1（最多 1 步），高度 2 的最多 2 步……把"节点数量乘以高度"加起来，级数收敛到常数倍 n。这一论证可见 [CLRS 第 6 章](https://mitpress.mit.edu/9780262033848/introduction-to-algorithms/)；[algs4 §2.4](https://algs4.cs.princeton.edu/24pq/) 还给出了更具体的常数：基于下沉的建堆至多 n 次交换、2n 次比较（该结论也是其练习题的参考答案）。

用一个具体程序核对建堆的代价。下面这段函数来自验证文件，它对建堆过程中的交换与比较计数，并顺带证明"逐个插入"在降序输入下代价大得多：

```dart
// 前置条件：Dart 3.12.2；纯 Dart，无第三方依赖；Dart VM。
// 运行：dart run --enable-asserts .work/verify/A07/build_heap_cost.dart

/// 自底向上建堆（最小堆），返回（交换次数, 比较次数），并原数组就地修改。
(int, int) buildHeapCost(List<int> a) {
  var swaps = 0;
  var comparisons = 0;

  void siftDown(int index) {
    while (true) {
      final left = 2 * index + 1;
      if (left >= a.length) break; // 没有孩子，到达叶子
      final right = left + 1;
      var preferred = left;
      if (right < a.length) {
        comparisons++;
        if (a[right] < a[left]) preferred = right;
      }
      comparisons++;
      if (a[preferred] >= a[index]) break; // 已满足堆序
      final temporary = a[index];
      a[index] = a[preferred];
      a[preferred] = temporary;
      swaps++;
      index = preferred;
    }
  }

  // 从最后一个内部节点起依次下沉；叶子天然是大小为 1 的堆。
  for (var index = a.length ~/ 2 - 1; index >= 0; index--) {
    siftDown(index);
  }
  return (swaps, comparisons);
}
```

真实运行输出（同样的验证程序还对 500 组随机输入检查了堆序与线性上界）：

```text
n=31：交换 26 次，比较 52 次
n=1023：交换 1013 次，比较 2026 次
n=4095：交换 4083 次，比较 8166 次
n=1024 降序输入：自底向上 1015 次交换，逐个插入 8204 次
```

三个规模上，交换次数都略小于 n（符合"至多 n 次"的常数界），而不是 n log n 的量级；同样是 1024 个元素的降序输入，自底向上只需 1015 次交换，逐个插入却要 8204 次。验证程序对降序输入与 500 组随机输入断言了这条界限：交换数 ≤ n、比较数 ≤ 2n。

O(n) 建堆依赖"叶子天然是堆、从最后一个内部节点倒序下沉"这一顺序；它不代表每次下沉是 O(1)，更不代表建完堆数组就有序。逐个插入建堆仍然是 O(n log n)，两个结论的前提不同。

顺带说明：建完堆后连续删除 k 次堆顶是 O(n + k log n)。这与"大小为 k 的堆保留 Top K"是两条不同的路线，后面会对照。

## Dart 最小可运行 BinaryHeap

下面是一个完整、可运行的最小二叉堆实现（验证环境 Dart 3.12.2，纯 Dart，无第三方依赖）。设计上有三个约定：

- 比较器语义统一为 `compare(a, b) < 0` 表示 `a` 先出队。于是升序比较器得到最小堆，降序比较器得到最大堆，同一个类同时支持两种堆；
- 空堆上的 `first` 与 `removeFirst` 抛出 `StateError`，而不是返回 `null`。把"误用空堆"变成一个立刻可见的错误；
- 构造函数接受一个现成集合，内部用上节的 O(n) 建堆初始化。

先看对外接口：

```dart
// 前置条件：Dart 3.12.2；纯 Dart，无第三方依赖；Dart VM（原生 64 位 int）。
// 运行：dart run --enable-asserts .work/verify/A07/binary_heap.dart

/// 升序比较器：较小者优先级更高，用作最小堆。
int ascendingCompare<T extends Comparable<T>>(T a, T b) => a.compareTo(b);

/// 降序比较器：较大者优先级更高，用作最大堆。
int descendingCompare<T extends Comparable<T>>(T a, T b) => b.compareTo(a);

/// 二叉堆实现的优先队列：compare(a, b) < 0 表示 a 先出队。
class BinaryHeap<E> {
  BinaryHeap(this._compare, [Iterable<E> items = const []]) {
    _data.addAll(items);
    // 1. 自底向上建堆：从最后一个内部节点起逐个下沉。
    for (var index = _data.length ~/ 2 - 1; index >= 0; index--) {
      _siftDown(index);
    }
  }

  final Comparator<E> _compare;
  final List<E> _data = [];

  int get length => _data.length;
  bool get isEmpty => _data.isEmpty;

  /// 查看堆顶（当前优先级最高的元素）；空堆抛 [StateError]。
  E get first {
    if (_data.isEmpty) throw StateError('空堆没有堆顶');
    return _data.first;
  }

  /// 插入一个元素。
  void add(E value) {
    _data.add(value);
    _siftUp(_data.length - 1); // 2. 新元素只可能破坏它到根这一条路径
  }

  /// 删除并返回堆顶；空堆抛 [StateError]。
  E removeFirst() {
    if (_data.isEmpty) throw StateError('空堆不能删堆顶');
    final result = _data.first;
    final last = _data.removeLast();
    if (_data.isNotEmpty) {
      _data[0] = last; // 3. 用最后一个元素补位，再沿一条路径下沉
      _siftDown(0);
    }
    return result;
  }
```

私有部分就是上节的两个循环，加一个用于观察内部数组的只读快照：

```dart
  void _siftUp(int index) {
    while (index > 0) {
      final parent = (index - 1) ~/ 2;
      if (_compare(_data[index], _data[parent]) >= 0) break;
      _swap(index, parent);
      index = parent;
    }
  }

  void _siftDown(int index) {
    while (true) {
      final left = 2 * index + 1;
      if (left >= _data.length) break; // 没有孩子，到达叶子
      final right = left + 1;
      var preferred = left;
      if (right < _data.length && _compare(_data[right], _data[left]) < 0) {
        preferred = right; // 4. 先选出两个孩子中更优先的那个
      }
      if (_compare(_data[preferred], _data[index]) >= 0) break;
      _swap(index, preferred);
      index = preferred;
    }
  }

  void _swap(int i, int j) {
    final temporary = _data[i];
    _data[i] = _data[j];
    _data[j] = temporary;
  }

  /// 内部数组快照：只保证堆序，不保证全局有序；用于观察与调试。
  List<E> get unorderedElements => List.unmodifiable(_data);
}
```

验证文件的 `main()` 覆盖了这些行为：最小堆按升序出队、最大堆按降序出队；一次性建堆与逐个插入结果一致；随机数据与 `List.sort` 对拍；重复值全部保留；空堆两种操作都抛 `StateError`；单元素堆删除后回到空。它还用三个相同优先级的元素演示了前文说的"顺序不受契约保证"：出队顺序是 `[a, c, b]`。内部数组的例子则是 `[1, 3, 2, 5, 9, 8]`——根是极值，但整体不是有序数组。

比较器方向决定最小堆还是最大堆，类本身不变；比较器必须是传递自洽的严格弱序，且不要用 `a - b` 之类的差值实现（原生 64 位 `int` 相减会溢出，`double` 相减会丢精度），用 `compareTo` 或显式分支。

## 常见应用模式

**固定大小 k 的堆求 Top K。** 求最小的 k 个元素时，反而维护一个大小为 k 的最大堆。原因是堆顶要充当"当前答案集中最差的元素"：新元素一旦不比堆顶更优，它就注定进不了前 k，直接丢弃；比堆顶更优才替换堆顶并下沉。每一步只有一次 O(1) 的堆顶比较和至多一次 O(log k) 的替换，总时间 O(n log k)，额外空间 O(k)，而且单遍扫描、支持流式输入。求最大的 k 个元素则是镜像：大小为 k 的最小堆。

顺带对照另一条路线：如果数据已经全部在内存、只查询一次，先把 n 个元素整体建堆再连续弹出 k 次，时间是 O(n + k log n)、空间 O(n)。两者时间同数量级，固定大小 k 的堆赢在 O(k) 空间与流式能力；当 k 接近 n 时，直接排序或快速选择反而更省事（详见[排序](./09-排序.md#排序之外的选择问题)）。

**双堆维护中位数。** 把数据流对半切开：左半部分用一个最大堆（堆顶是左半最大值），右半部分用一个最小堆（堆顶是右半最小值），并维护两个不变量——左堆大小等于右堆或比它多 1；左顶不大于右顶。插入时先入左堆、把左堆最大值转给右堆，再按大小需要把右堆最小值送回左堆；中位数只会是左顶（奇数个）或两个堆顶的平均（偶数个）。每次插入 O(log n)，查询 O(1)。

**多路归并。** k 个各自有序的序列合成一个有序序列时，堆里只需要放 k 个"当前队首"：每次弹出全局最小者，再从它所属的序列补入下一个。堆的大小是 k 而不是元素总数 N，所以总时间 O(N log k)，空间 O(k)。这是外部排序（内存装不下全部数据）与"合并 k 个有序流"的标准做法，也是[归并排序](./09-排序.md#归并排序)在多路情形下的自然推广。

**惰性删除。** 二叉堆没有为"删除任意元素"或"修改优先级"设计接口：堆里只有下标关系，没有记录元素所在位置的索引。需要这类操作时有两种常见做法：给每个元素维护位置索引，实现 O(log n) 的 decrease-key；或者采用惰性删除——把新版本连同有效性信息一起入堆，弹出时丢弃已经过期的条目。Dijkstra 的优先队列就是后者的典型场景，细节见[图](./08-图.md)。

## 什么时候用，什么时候别用

适合用堆：

- 数据动态到来，且只关心当前极值或前 k 个（调度、流式 Top K、事件模拟）；
- 需要 O(k) 额外空间处理内存放不下的数据——内存内排序与快速选择都要求随机访问全部数据，只有堆能单遍扫描、边读边淘汰；
- 需要反复"取出最小/最大并继续推进"的算法：Dijkstra、Prim、[哈夫曼编码](./13-贪心.md#哈夫曼编码)、多路归并；
- 双堆这类"维护两个动态分位边界"的结构。

不适合用堆：

- 数据不变、只需要一次全序：直接排序更简单，常数也通常更小（排序算法见[排序](./09-排序.md)）；
- 需要按下标或键随机查找、删除任意元素、按序遍历、求 rank 或范围查询：这些都是全序结构（哈希表、搜索树、有序数组）的领域，树见[树与二叉树](./06-树与二叉树.md)；
- 要求相同优先级的元素严格按入队顺序出队：堆不承诺稳定，要么在比较器里加递增序号，要么换用别的方式；
- 只需要"全部数据一起排序后的第 k 个"：快速选择平均 O(n)，可能比堆更快（对照见[排序](./09-排序.md#排序之外的选择问题)）。

工程上，如果要直接用现成实现，`package:collection` 的 `PriorityQueue` 覆盖了本文实现大部分场景；但要在堆中间删除元素，它只提供 O(n) 的按值删除（`remove`）；修改优先级与稳定出队则不在支持之列——这些限制来自二叉堆本身，而不是某个库的取舍。

## 常见坑与边界

- **0-based 与 1-based 混用。** 父下标写成 `i ~/ 2`、子下标写成 `2 * i + 2` 这类"半套公式"是最常见的 off-by-one 来源。本文统一 0-based：`parent = (i - 1) ~/ 2`，`children = 2i + 1 / 2i + 2`。另外要用整除 `~/` 而不是 `/`，后者返回 `double`，无法作为下标。
- **比较器方向写反。** 约定"更小者先出队"时，最大堆必须用降序比较器；忘记取反会让 Top K 悄悄变错但不报错。还要避免差值比较器：`(a, b) => a - b` 在 `int` 接近 64 位边界时溢出、在 `double` 上丢精度，也会破坏比较器的传递性。
- **删除堆顶后忘记下沉，或下沉范围算错。** `removeFirst` 的顺序必须是"取出根 → 删掉末尾 → 末尾补到根 → 下沉到合法位置"；补位后如果忘了下沉，堆就只是被洗乱了一次。若把这段逻辑改写成堆排序，还要注意"已排好序的尾部不能参与下沉"，收缩边界写错会把刚放到末尾的最大值又换回来。
- **k 越界与空输入。** 固定大小 k 的堆必须先处理 `k <= 0`（返回空）与 `k >= n`（返回整个集合的副本），否则会在"堆还没满就淘汰"或"下标越界"上翻车。
- **双堆的大小或边界值失平衡。** 常见错误是只保证"左堆尺寸不小于右堆"，却在偶数个元素时取错堆顶；或者忘记"左顶不大于右顶"这个顺序不变量，导致中位数落在错误一侧。偶数个元素求平均时，注意 Dart 的 `/` 返回 `double`，`(a + b) / 2` 不会像某些语言的整型除法那样截断；只有接近 64 位上限的整数相加才需要改成 `a + (b - a) / 2` 之类的溢出安全写法。
- **误称建堆是 O(n log n)。** O(n log n) 是"逐个插入建堆"或"建完堆后逐个弹出"的代价；自底向上建堆是 O(n)。

### 常见误区

- ❌ "堆的内部数组差不多就是有序数组。" ✅ 堆只保证父子偏序与"根是极值"；`[1, 3, 2, 5, 9, 8]` 是合法最小堆，但不是有序数组。
- ❌ "求最小的 k 个数应该用最小堆。" ✅ 堆顶要充当"当前答案中最差的那个"，求最小 k 用最大堆，求最大 k 用最小堆——方向恰好相反。
- ❌ "相同优先级的元素一定先来先出。" ✅ 标准契约不承诺这一点；需要稳定时自己加序号做 tie-break。

### 例题 1：347. Top K Frequent Elements

问题匹配点：先做频次统计（哈希计数，见[哈希表](./05-哈希表.md)），再用大小为 k 的最小堆保留"当前频次最高的 k 个"。堆顶是当前答案里频次最低的元素，一旦它被更频繁的元素挤出，答案集就更新。频次相同的情况下题目保证答案唯一，这里仍用值做次级比较，使输出确定。

```dart
/// 返回出现频率最高的 k 个元素；顺序不限，元素集与题面接受的一组答案一致。
List<int> topKFrequent(List<int> nums, int k) {
  // 1. 频次表：值 -> 出现次数。
  final countByValue = <int, int>{};
  for (final num in nums) {
    countByValue[num] = (countByValue[num] ?? 0) + 1;
  }

  // 2. 大小 k 的最小堆：堆顶是当前保留集合里频次最低的元素。
  //    比较器用 compareTo 而不是相减；频次相同时按值做次级比较，保证结果确定。
  final heap = BinaryHeap<(int, int)>((a, b) {
    final byCount = a.$2.compareTo(b.$2);
    return byCount != 0 ? byCount : a.$1.compareTo(b.$1);
  });
  countByValue.forEach((value, count) {
    heap.add((value, count));
    if (heap.length > k) heap.removeFirst(); // 3. 淘汰当前最弱的一个
  });

  // 4. 弹出堆内元素；题目不要求顺序。
  return drainSorted(heap).map((entry) => entry.$1).toList();
}
```

<!-- verify: .work/verify/A07/top_k_frequent.dart -->

- 复杂度：时间 O(n + u log k)（u 是不同元素个数），空间 O(u) 频次表 + O(k) 堆；
- 边界用例：k 等于不同元素个数（返回全部）、只有一种元素、单元素数组、频次并列，验证文件另用"排序后取前 k"对拍全部 k 值；
- 旧题解分类：排序；当前题目页见 [R6]。

### 例题 2：LCR 159. 库存管理 III（原剑指 Offer 40. 最小的 K 个数）

问题匹配点：返回最小的 `cnt` 个数，且题面明确"返回顺序不限"，正是固定大小堆的用武之地。与上一题相反，这里用大小为 `cnt` 的最大堆，堆顶是当前候选里的最大值。

```dart
/// 返回最小的 cnt 个元素；顺序不限。cnt <= 0 返回空表，cnt >= 长度返回整个数组的副本。
List<int> leastKNumbers(List<int> stock, int cnt) {
  if (cnt <= 0) return const [];
  if (cnt >= stock.length) return List.of(stock);

  // 大小 cnt 的最大堆：堆顶是当前保留集合中的最大值，越界就淘汰它。
  final heap = BinaryHeap<int>(descendingCompare);
  for (final value in stock) {
    heap.add(value);
    if (heap.length > cnt) heap.removeFirst();
  }
  return drainSorted(heap);
}
```

<!-- verify: .work/verify/A07/least_k_numbers.dart -->

- 复杂度：时间 O(n log cnt)，空间 O(cnt)；
- 边界用例：`cnt = 0` 返回空、`cnt = n` 返回全部、重复值必须全部保留（不能按不同值去重）、单元素数组；验证文件对每个样例遍历所有 `cnt` 与排序结果做多重集对拍；
- 旧题解题名：剑指 Offer 40「最小的 K 个数」；当前题目页见 [R7]。

### 例题 3：LCR 160. 数据流中的中位数（原剑指 Offer 41）

问题匹配点：数据流需要"边追加边查询"，且中位数由中间两个数决定；两个堆顶恰好就是这两个数。与 LCR 159 的思路互补：那里的两个堆是"候选集 + 淘汰"，这里则是"较小的一半 + 较大的一半"。

```dart
/// 用两个堆维护数据流中位数。
/// 不变量 1：左堆（最大堆）存较小的一半，右堆（最小堆）存较大的一半，左顶 <= 右顶。
/// 不变量 2：左堆大小等于右堆，或比右堆多 1；因此中位数只可能来自两个堆顶。
class MedianFinder {
  final _left = BinaryHeap<int>(descendingCompare); // 较小的一半，堆顶是其中最大者
  final _right = BinaryHeap<int>(ascendingCompare); // 较大的一半，堆顶是其中最小者

  void addNum(int num) {
    // 1. 先放入左堆，再把左堆最大者交给右堆，保证左堆元素都较小。
    _left.add(num);
    _right.add(_left.removeFirst());

    // 2. 右堆不得超过左堆，否则把右堆最小者还回去，恢复大小不变量。
    if (_right.length > _left.length) {
      _left.add(_right.removeFirst());
    }
  }

  double findMedian() {
    if (_left.isEmpty) throw StateError('数据流还没有元素');
    if (_left.length > _right.length) return _left.first.toDouble();
    // Dart 的 '/' 对 int 返回 double，不会截断；极大整数相加才需要溢出保护。
    return (_left.first + _right.first) / 2;
  }
}
```

<!-- verify: .work/verify/A07/median_finder.dart -->

- 复杂度：`addNum` O(log n)，`findMedian` O(1)，空间 O(n)；
- 边界用例：两组题面样例、空数据流读取抛 `StateError`、负数、重复值、极端值（±10⁹）；验证文件在每步插入后检查两个不变量，并与"重新排序求中位数"对拍；
- 旧题解题名：剑指 Offer 41「数据流中的中位数」；当前题目页见 [R8]。

## 面试考点与追问

> **面试高频：** 建堆为什么能做到 O(n)？
> **答题脉络：** 叶子天然是堆 → 从最后一个内部节点倒序下沉 → 每个节点代价等于其高度 → 高度 h 的节点约 n / 2^(h+1) 个 → Σ h · n / 2^(h+1) 收敛到常数倍 n。
> **追问方向：** 逐个插入建堆为什么是 O(n log n)；为什么"建完再弹出 k 次"是 O(n + k log n)；常数项大概是多少（可用本文验证程序计算）。

> **面试高频：** 求最小的 k 个数用大顶堆还是小顶堆？
> **答题脉络：** 先明确堆顶要代表"当前答案里最差的元素"→ 求最小 k 用最大堆（堆顶是候选最大值）→ 新元素与堆顶比较、必要时替换 → 复杂度 O(n log k)、空间 O(k)、可流式。
> **追问方向：** k 接近 n 时改用什么；数据能否全部放进内存；能否修改输入数组（快速选择，见[排序](./09-排序.md#排序之外的选择问题)）。

> **面试高频：** 为什么堆数组不是有序数组？取出全序要多少代价？
> **答题脉络：** 堆只维持父子偏序与"根是最值" → 内部数组不单调（如 `[1, 3, 2, 5, 9, 8]`）→ 要全序只能连续弹出 n 次，每次 O(log n)，总 O(n log n)，这正是堆排序（见[排序](./09-排序.md#堆排序)）。
> **追问方向：** 为什么构建堆不能顺便产生全序；堆序与 BST 中序有序的差别；堆数组里如何找到"第二小"。

> **面试高频：** 双堆中位数的两个不变量是什么？
> **答题脉络：** 大小不变量（左堆等于右堆或比右堆多 1）与顺序不变量（左顶 ≤ 右顶）→ 插入时先入左、转最大值到右、必要时还回来 → 中位数只取两个堆顶。
> **追问方向：** 奇数/偶数个元素分别怎么取；重复值与负数是否影响；如果要求"随时拿走一个任意元素"该怎么改。

> **面试高频：** 想修改某个元素的优先级（decrease-key）怎么办？
> **答题脉络：** 二叉堆本身不知道元素在数组的哪个位置 → 标准 `PriorityQueue` 不提供 decrease-key → 要么额外维护"元素 → 下标"索引实现真正的 decrease-key，要么用惰性删除：重复入堆、弹出时跳过过期条目。
> **追问方向：** Dijkstra 里过期条目怎么判断（比对当前最短距离，见[图](./08-图.md)）；堆内存会不会持续增长；带索引的堆如何维护交换时的下标表。

## 小结

二叉堆的用法可以压缩成四句话：数组按层序存放一棵完全二叉树；每个父节点不劣于孩子；`peek` O(1)、`add`/`removeFirst` O(log n)、整体建堆 O(n)；只承诺偏序，不承诺有序。凡是"动态数据 + 只关心极值或前 k 个"的问题（Top K、流式中位数、多路归并、Dijkstra），先想堆；凡是需要全序、任意查找或稳定顺序的问题，去别处找工具。
