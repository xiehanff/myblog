# 算法与数据结构｜12-动态规划

爬楼梯、找零、编辑距离、背包——这些问题的输入一旦变大，朴素递归就会卡住：同一个子问题被不同分支反复展开，指数级的重复计算把几十个状态的问题变成几百万次调用。动态规划（Dynamic Programming，DP）就是为这种重复工作准备的折叠术：把"同一类子问题"的结果存下来，让每个状态只被计算一次。

难的地方不在代码。转移方程大多只有几行，真正容易出错的是它前面的三件事：状态含义有没有写清楚、初始与非法状态有没有区分、遍历顺序有没有满足依赖关系。多数"换了数据就错"的 DP，问题都出在这三件事上，而不是方程本身。

本文按"为什么朴素递归会重复工作 → 适用条件 → 状态设计五步法 → 记忆化与制表 → 三类典型模型 → 空间优化与方案恢复 → 使用边界 → 四道例题"推进；写不出转移时先回到状态定义，而不是继续搜题干对应哪个模板。

## 为什么朴素递归会重复工作

从最熟悉的斐波那契看重复从哪来。爬楼梯问题与它同型：每一步可以走 1 级或 2 级，求到达第 n 级的方法数，方法数的递推恰好是 `f(n) = f(n-1) + f(n-2)`。把朴素递归的调用过程画成树：`f(5)` 展开出 `f(4)` 和 `f(3)`，`f(4)` 又展开出 `f(3)` 和 `f(2)`——`f(3)` 被两个父节点各求一次，越靠近基线的子问题被到达的次数越多。

下面的代码不打印树，而是给每个子问题加一个进入计数器，直接观察重复次数：

```dart
void main() {
  const n = 10;
  final calls = List<int>.filled(n + 1, 0); // calls[i] 统计 fib(i) 被进入的次数

  int fib(int k) {
    calls[k]++;
    if (k <= 1) {
      return k;
    }
    return fib(k - 1) + fib(k - 2);
  }

  // 1. 直接递归计算 fib(10)。
  final value = fib(n);

  // 2. 汇总每个子问题被进入的次数。
  var total = 0;
  for (final count in calls) {
    total += count;
  }

  print('fib($n) = $value，函数共被进入 $total 次');
  print('其中 fib(1) 被计算 ${calls[1]} 次，而不同输入只有 ${n + 1} 个');
  assert(value == 55);
  assert(total == 177);
  assert(calls[1] == 55);
}
```
<!-- verify: .work/verify/A12/naive_fib.dart -->

在 Dart 3.12.2（Windows x64）上运行的结果是：`fib(10)` 的函数体一共被进入 **177** 次，其中 `fib(1)` 被计算了 **55** 次，而不同的输入（状态）只有 **11** 个。调用树节点数随 n 指数增长，状态数只有 n+1 个，这中间的差额就是重复劳动。

朴素递归的浪费来自重叠子问题——不同的决策路径到达了同一个状态，各算一遍；动态规划的第一步就是把重复的子树折叠成"查表"，让每个状态只计算一次。

> **面试高频：** 为什么朴素递归计算斐波那契是指数级的？
> **答题脉络：** 写出调用树的形态或递归式 `T(n) = T(n-1) + T(n-2)` → 说明子问题重叠（不同路径到达同一 n）→ 对比"路径数"与"状态数"的增长速度 → 缓存或递推把每条路径的重复展开换成一次查表。
> **追问方向：** 记忆化的缓存键怎么确定；哪些递归不能这样折叠；递归式求解与状态数计算的区别。

## 动态规划的适用条件

"看到最值就用 DP"是最常见的错误起点。判断能不能用动态规划，要做三项检查：子问题是否重叠、是否有最优子结构、状态是否无后效性；前两项决定"值不值得折叠"，第三项决定"折叠得对不对"。

### 重叠子问题

重叠子问题的含义是：**同一个子问题在不同的决策路径下被反复需要**。判据不是"函数调用了自己"，而是"调用树去重后节点数显著变小"——不同路径数远大于不同状态数。

对照两个例子：归并排序把数组分成两半，两半的子问题互不相交，调用树去重后没有变化，这是分治；斐波那契的调用树去重后只剩 n+1 个节点，这是重叠子问题。前者不需要缓存，后者的缓存收益就是全部重复次数。

### 最优子结构

最优子结构指：**整问题的最优解可以由子问题的最优解组装出来**。求最短路时，最短路径的每一段本身也是最短的，所以可以用子问题的距离递推；而一般图中的最长简单路径是 NP-hard 问题，同样的"求最长"却没有这样的结构，说明"最值"字样并不能保证最优子结构。

动态规划与贪心共享最优子结构这个前提，分野在于如何处理"选哪个"：动态规划保留每一类子问题的最优值供比较，贪心则断言某个局部选择一定出现在某个最优解里，于是不需要保留分支（证明与反例见[贪心](./13-贪心.md#贪心与动态规划)，两组思想不重复展开）。

### 无后效性

无后效性（no aftereffect）的通常表述是"未来的决策只依赖当前状态，不依赖到达它的历史"。它更准确的用法是当作状态定义的检验标准：

无后效性是对状态定义的要求：状态里必须包含决定未来的全部信息，这一点并非问题本身自带。检验方法是把状态含义写成一句话，然后问"做后续决策时还需要历史上的什么信息"；还需要什么，就说明状态漏了什么。

两个最小例子：背包问题里，剩余容量必须进状态，否则无法判断还能不能装下一件；带冷冻期的股票问题里，"今天是否处于冷冻期"必须进状态，否则无法判断明天能不能买。反过来，斐波那契的 `f(n)` 与"它是被谁调用的"无关，所以缓存键只写 `n` 就够了。

从依赖视角看，把每个状态当作图上的一个点、每条转移当作一条指向依赖状态的有向边，动态规划要求这张**状态依赖图无环**：有环说明两个状态互相依赖，计算顺序无法确定。自底向上的遍历顺序就是这张图的一个拓扑序；与图算法的分工是：无权图的最短路径交给 BFS（见[图](./08-图.md#无权图最短路)），动态规划处理的是带权、带决策、要比较目标值的最优化与计数。状态是集合类信息时，可以用位掩码把"已经选过哪些元素"编码进状态，代价是状态数变成 `2^n`（表示方法见[位运算技巧](./14-位运算技巧.md#位掩码表示小集合)）。

## 状态设计五步法

转移方程不是背来的，它是状态定义的推论。下面五步把"定义状态"拆成可以逐项检查的动作：

1. **写下目标口径**：求最值、方案数还是可行性；返回值类型是什么；答案在整张表的哪个格子。计数问题要额外回答"顺序不同算不算不同方案"。
2. **用一句话写状态含义**：例如"`dp[i]` 表示前 i 个元素能获得的最大值"或"`dp[i]` 表示以第 i 个元素结尾的最长递增子序列长度"。含义写不清，边界和答案位置一定跟着错。
3. **找最后一步决策，写出转移**：当前状态由哪些更小的状态、加上什么代价得到；所有前驱情况是否覆盖完整、计数时有没有重复或遗漏。
4. **确定初始与非法状态**：基线状态（`dp[0]`、首行、首列）直接给出正确答案；"不可达"的状态要显式区分——求最大值时用 `0` 冒充不可达，会让它伪装成合法解。
5. **确定遍历顺序和答案位置**：顺序由状态依赖图决定（见下一节）；逐个检查每个转移依赖的格子是否已经算好，同时记录哪些状态其实用不到，这是空间优化的入口。

第 2 步的两个常见口径——"前 i 个"与"以 i 结尾"——值得单独区分。前缀口径的答案常是 `dp[n]`；结尾口径的答案要对所有 i 取极值，因为最优解可能不以最后一个元素结尾。最长递增子序列（LIS）正好演示了定义如何反过来决定转移能否写出：

- 定义成"`dp[i]` = 前 i 个元素的最长递增子序列长度"时，这个数字不携带"结尾值是多少"，看到 `nums[i+1]` 无法判断能不能接上，转移写不出来。
- 定义成"`dp[i]` = 以 `nums[i]` 结尾的最长长度"后，结尾值就是 `nums[i]` 本身，只需枚举 `j < i` 且 `nums[j] < nums[i]`，转移自然成立。

写不出转移方程时，问题通常出在状态信息不足：状态没有携带未来需要的信息，任何方程都补不回来，技巧也帮不上忙。

> **面试高频：** 面试里如何一步步定义出 DP 状态？
> **答题脉络：** 先说目标口径（最值/计数/可行性）→ 用一句话写状态含义 → 找最后一步决策列前驱 → 明确初始值与不可达 → 由依赖方向定顺序与答案位置 → 用小样例手推两格验证边界。
> **追问方向：** 状态维度怎么判断（有几个独立进度就需要几维）；维度增加是不是总更好；无后效性如何检验。

## 自顶向下记忆化

记忆化（memoization）是最小改动：保留递归的契约和基线，只在入口先查缓存，未命中再展开，算完写回。因为展开顺序与朴素递归一致，基线正确性通常可以原样沿用：

```dart
void main() {
  final memo = <int, int>{};

  // 1. 函数契约不变，只在入口先查缓存。
  int fib(int k) {
    final cached = memo[k];
    if (cached != null) {
      return cached;
    }

    // 2. 只有缓存未命中时才递归计算，并把结果写回缓存。
    final result = k <= 1 ? k : fib(k - 1) + fib(k - 2);
    memo[k] = result;
    return result;
  }

  final value = fib(10);
  print('fib(10) = $value，共缓存 ${memo.length} 个状态');
  assert(value == 55);
  assert(memo.length == 11);
}
```
<!-- verify: .work/verify/A12/memo_fib.dart -->

`fib(10)` 只缓存了 **11** 个状态，函数进入 19 次（11 次未命中、8 次命中），而朴素版本是 177 次。缓存键必须包含决定未来的全部信息，它和状态定义是同一件事：斐波那契的键是 `k`，编辑距离的键是 `(i, j)`，0-1 背包的键是 `(物品下标, 剩余容量)`。键少一项，就会出现"两个不同状态共用一份答案"的错误复用。

两种方向的取舍：

- **记忆化**：只计算真正被用到的状态，适合状态稀疏、依赖跳跃的场景；代价是递归栈深度为状态依赖链的长度，加上字典的常数与内存开销。
- **制表**：从最小状态按序填到答案，没有递归栈，顺序固定后可以做空间压缩；代价是可能计算题目用不到的状态。

空间口径也不同：记忆化的空间是"缓存 + 递归栈"，制表是"状态表（可压缩）"。

记忆化不改变递归的逻辑，只是把它从"按路径求值"改成"按状态求值"；时间从路径数降到"状态数 × 每状态转移数"，这也是动态规划复杂度的统一算法。

> **面试高频：** 记忆化和制表怎么选？
> **答题脉络：** 先说明两者共享同一套状态与转移 → 记忆化按需计算但受栈深限制，制表顺序固定、方便压空间但可能算无用状态 → 结合状态稠密度和是否需要滚动压缩给结论。
> **追问方向：** 同一个递归式改成制表时顺序怎么定；缓存键写哪些参数；递归栈溢出时怎么办。

## 自底向上制表

制表（tabulation）把递归关系翻译成循环：先给基线状态赋值，再按依赖顺序填完剩下的格子，最后返回答案状态。斐波那契的例子还顺带展示了边界处理——`n = 0` 时不能去写 `dp[1]`（验证文件的 `main` 断言 `fib(0) = 0`、`fib(1) = 1`、`fib(10) = 55`）：

```dart
int fib(int n) {
  // dp[i] 只依赖 dp[i-1] 与 dp[i-2]，因此从最小边界开始按序填表。
  final dp = List<int>.filled(n + 1, 0);
  if (n >= 1) {
    dp[1] = 1;
  }
  for (var i = 2; i <= n; i++) {
    dp[i] = dp[i - 1] + dp[i - 2];
  }
  return dp[n];
}
```
<!-- verify: .work/verify/A12/tab_fib.dart -->

**遍历顺序由状态依赖图决定，不是风格问题。** 三种典型结构：

- **一维顺序**：`dp[i]` 依赖 `dp[i-1]`、`dp[i-2]`，i 从小到大。斐波那契、打家劫舍都属于这一类。
- **一维逆序**：0-1 背包中 `dp[j]` 依赖"上一轮"的 `dp[j-w]`，必须让 j 从大到小，否则会读到本轮刚写入的值；具体反例见"典型模型二"。
- **二维逐行**：`dp[i][j]` 依赖上方 `dp[i-1][j]`、左方 `dp[i][j-1]`、左上方 `dp[i-1][j-1]` 时，外层 i 递增、内层 j 递增即可（编辑距离）；区间型状态 `dp[i][j]` 依赖更小的区间时，则要按区间长度从小到大填。

复杂度统一按"状态数 × 每状态转移数"计算，而不是把"DP 都当 O(n²)"：斐波那契是 O(n) 个状态、O(1) 转移；0-1 背包是 O(n·V) 个状态；编辑距离是 O(mn) 个状态、每个只做常数次比较。转移里嵌套枚举（如 LIS 的 O(n²) 版本）会把每状态转移数抬高到 O(n)。

> 遍历顺序必须满足依赖图规定的先后关系；顺序写反的典型现象是把"本轮新值"当成"上一轮旧值"，代码照样运行，结果却悄悄允许了不该发生的重复使用。

## 典型模型一：线性与网格

线性模型的状态只有一个下标，按口径分成两族：

- **前缀族**：`dp[i]` 表示前 i 个元素的答案，转移来自 `dp[i-1]` 或 `dp[i-2]`，答案通常是 `dp[n]`。爬楼梯（计数）、打家劫舍（选或不选）都是这一族。它与前缀和的形式相近但目标不同：前缀和把区间查询预处理成 O(1)，是"信息变换"；前缀族 DP 求的是"每种决策下的最优值或方案数"（见[数组与字符串](./02-数组与字符串.md#前缀和与差分)）。
- **结尾族**：`dp[i]` 表示以第 i 个元素结尾的答案，枚举所有 `j < i` 拼接，最终答案要在所有 i 中取极值。LIS、最大子数组和都属于这一类；后者的状态不带长度，只带"以 i 结尾的最大和"。

网格模型再引入一个维度。以"从左上角走到右下角、每次只能向右或向下"为例，二维状态可以压成一行滚动数组：`dp[j]` 表示到达当前行第 j 列的方法数，逐行刷新：

```dart
int uniquePaths(int m, int n) {
  // dp[j]：到达"当前行"第 j 列的方法数（逐行滚动，初始化为第一行）。
  final dp = List<int>.filled(n, 1);
  for (var i = 1; i < m; i++) {
    for (var j = 1; j < n; j++) {
      // 1. dp[j] 来自上方，dp[j-1] 已被本行更新为左侧。
      dp[j] = dp[j] + dp[j - 1];
    }
  }
  return dp[n - 1];
}
```
<!-- verify: .work/verify/A12/unique_paths.dart -->

更新顺序是这段代码的关键：从左到右扫描时，`dp[j - 1]` 已经被本行更新成"左侧来"的新值，`dp[j]` 还是上一行留下的"上方来"的旧值，两者相加正好就是当前格的方法数；第一行全部初始化为 1，因为只能一路向右。验证文件断言 `uniquePaths(3, 7) = 28`、`uniquePaths(3, 2) = 3`、`uniquePaths(1, 1) = 1`。复杂度是 O(m·n) 时间、O(n) 额外空间。

区间模型记作 `dp[i][j]`，表示区间 `[i, j]` 上的答案，依赖 `dp[i+1][j]`、`dp[i][j-1]`、`dp[i+1][j-1]` 这些更短的区间，所以要先算小区间（按长度递增，或按 i 递减、j 递增）。最长回文子序列、石子合并是常见代表；回文串的字符串侧算法见[字符串算法](./15-字符串算法.md)。

线性与网格 DP 的第一道分岔是状态选"前 i 个"还是"以 i 结尾"，它决定答案位置；第二道分岔是行列更新方向，它同时决定初始化方式与能否滚动压缩。

## 典型模型二：背包

背包问题的模型是：若干物品各有重量与价值，给一个容量上限，求最大价值、方案数或可行性。状态 `dp[j]` 表示"消耗容量 j 时达到的目标"，外层维度是"已考虑的物品"，容量维度表示"消耗的额度"。

**0-1 背包**（每件至多一次）用一维数组时必须**逆序**遍历容量：逆序时 `dp[j - w]` 还没被当前这件物品更新，读到的就是"未考虑当前物品"的旧状态；如果正序，`dp[j - w]` 可能刚被当前物品写入，等价于允许同一件物品被重复使用。这个差别不是形式问题——下面的反例函数对 `[2, 2, 3, 5]` 会给出错误的 `true`：正序让当前这个 2 先写入 `dp[2]`，再被传播到 `dp[4]` 和 `dp[6]`，等于把一个 2 用成了三个。

```dart
// 反例演示：正序遍历会允许同一个数被重复使用。
bool canPartitionForwardBug(List<int> nums) {
  var sum = 0;
  for (final num in nums) {
    sum += num;
  }
  if (sum.isOdd) {
    return false;
  }
  final target = sum ~/ 2;
  final dp = List<bool>.filled(target + 1, false);
  dp[0] = true;
  for (final num in nums) {
    for (var j = num; j <= target; j++) {
      if (dp[j - num]) {
        dp[j] = true;
      }
    }
  }
  return dp[target];
}
```
<!-- verify: .work/verify/A12/partition_subset.dart -->

**完全背包**（物品可重复使用）则使用正序——正序读到的 `dp[j - w]` 正是"本件物品刚更新过"的新值，语义上就是可以再拿一件。一维数组里 `dp[j - w]` 同时承担"旧值/新值"两种语义，遍历方向就是在为它选一种。

**计数问题**还要额外确定"顺序算不算不同方案"。同样的硬币与金额，把物品循环放在外层得到**组合数**（1+2 与 2+1 视为同一方案），把金额循环放在外层得到**排列数**（两者视为不同）。代码只有两层循环的位置之差，含义完全不同：

```dart
// 组合数：1+2 与 2+1 视为同一方案（外层物品，内层金额）。
int countCombinations(List<int> coins, int amount) {
  final dp = List<int>.filled(amount + 1, 0);
  dp[0] = 1;
  for (final coin in coins) {
    for (var j = coin; j <= amount; j++) {
      dp[j] += dp[j - coin];
    }
  }
  return dp[amount];
}

// 排列数：1+2 与 2+1 视为不同方案（外层金额，内层物品）。
int countPermutations(List<int> coins, int amount) {
  final dp = List<int>.filled(amount + 1, 0);
  dp[0] = 1;
  for (var j = 1; j <= amount; j++) {
    for (final coin in coins) {
      if (coin <= j) {
        dp[j] += dp[j - coin];
      }
    }
  }
  return dp[amount];
}
```
<!-- verify: .work/verify/A12/coin_orders.dart -->

验证文件断言：`coins = [1, 2]`、`amount = 3` 时组合数为 **2**（1+1+1、1+2），排列数为 **3**（1+1+1、1+2、2+1）。

容量很大而价值之和很小时，可以把"容量做下标、价值做答案"换成"价值做下标、容量做答案"，让状态空间去乘更小的那一维。计数结果增长很快，还要留意 64 位 `int` 的边界（见"常见坑与边界"）。

> 0-1 与完全背包的差别只体现在容量维的遍历方向：逆序读到"上一件物品的旧值"，正序读到"本件物品刚更新的新值"；"组合还是排列"则由物品与容量哪一层在外决定构造顺序。

> **面试高频：** 0-1 背包为什么容量要倒着遍历？
> **答题脉络：** 先说明一维数组里 `dp[j-w]` 的旧值/新值二义性 → 逆序保证读旧值（每件物品只被用一次）→ 正序等价于完全背包 → 用 `[2, 2, 3, 5]` 的正序反例说明后果。
> **追问方向：** 完全背包为什么正序；计数问题的循环顺序；二维写法为什么不需要考虑方向。

## 典型模型三：子序列与字符串编辑

子序列类问题的状态通常比线性模型多一个维度，因为"进度"有多个：第一个串走到哪、第二个串走到哪。三个经典模型的状态差异可以放在一张表里对照：

| 问题 | 状态含义 | 转移来源 | 答案位置 |
| --- | --- | --- | --- |
| 最长递增子序列 | `dp[i]`：以 `nums[i]` 结尾的最长长度 | 满足 `nums[j] < nums[i]` 的 `dp[j]` | 所有 i 的最大值 |
| 最长公共子序列 | `dp[i][j]`：前 i 个与前 j 个字符的 LCS 长度 | 相等取 `dp[i-1][j-1]+1`；否则取上、左的较大者 | `dp[m][n]` |
| 编辑距离 | `dp[i][j]`：把前 i 个字符变为前 j 个字符的最少操作数 | 相等取 `dp[i-1][j-1]`；否则取替换、删除、插入的最小值 | `dp[m][n]` |

两条规律从这个对照里显形：

- **"可以不连续"意味着不需要检查相邻位置**，状态是"前缀对"，转移把所有"跳过"的可能压缩成上、左两个前驱；而子数组、子串要求连续，状态一般要选"以 i 结尾"，或者改用[滑动窗口](./02-数组与字符串.md#滑动窗口)。
- **编辑距离的三种操作恰好对应三个前驱**：替换来自左上 `dp[i-1][j-1]`，删除来自上方 `dp[i-1][j]`，插入来自左方 `dp[i][j-1]`。能说清"每个前驱代表哪个操作"，就不会背错转移。

边界行列的初始化也由状态含义直接读出：`dp[0][j] = j`（从空串变出前 j 个字符，只有插入）、`dp[i][0] = i`（删到空串）。LIS 的 O(n²) 到 O(n log n) 优化、编辑距离的完整实现和边界用例都在"知识点应用"中演示。

状态维度对应"问题里有几个相互独立的进度"；子序列类问题用"前缀对 (i, j)"，连续子数组/子串类问题用"以 i 结尾"，两者不能互换。

## 空间优化与方案恢复

压缩空间的动作可以分三个层次，检查方法都一样：**写下每个状态依赖哪些格子，确认被覆盖的旧值在后续计算中确实不再被读取。**

- **常数变量**：打家劫舍的 `dp[i]` 只依赖 `dp[i-1]` 与 `dp[i-2]`，用两个变量滚动即可（见例题一）；代价是丢掉历史，无法直接回答"具体选了哪些房间"。
- **一维滚动**：网格路径把行维度压掉，只留一行；`dp[j-1]` 是新值、`dp[j]` 是旧值的读取顺序必须与转移含义一致。
- **两行/逆序压维**：编辑距离依赖上一行与左上方，可以只保留两行；0-1 背包靠逆序遍历把二维压成一维。压缩后建议用小规模对拍验证：例题三的验证文件就同时实现了正序与逆序两个版本，用同一组输入对比结果。

**恢复方案与压缩空间往往冲突。** 只求最优值时，压缩掉的历史不需要保留；一旦要输出具体选择或路径，通常有三种做法：

1. **保留完整表，从终点回推**：比较当前值是否等于某个前驱加对应代价，成立就记录该决策并移动过去（编辑距离的回推就是逐格判断三个前驱）。
2. **额外维护 parent/predecessor 数组**：在填表时同步记录"这个状态是从哪个状态来的"，空间是 O(状态数)。
3. **重新计算**：保存少量关键点后重放区间；计数问题用它恢复"某一条方案"并不总是可行，因为压缩后信息已经丢掉。

空间压缩的前提是"被覆盖的值之后不再被读取"；一旦还需要恢复方案，被丢掉的历史往往正是需要的信息——先决定输出口径，再决定空间策略。

## 什么时候用，什么时候别用

可以优先考虑动态规划的信号：

- **不同决策路径反复到达同一有限状态**，目标是最优值、方案数或可行性；用"状态数 × 转移数"估算的复杂度在可接受范围内。
- **能写出状态含义并解释无后效性**：状态携带的信息足够让未来决策只依赖状态。
- **状态依赖无环**：自底向上能排出拓扑序，或自顶向下递归收敛。

遇到下列情况就不该用动态规划：

- **可以证明的安全贪心**：区间调度、哈夫曼编码用交换论证一旦成立，排序加扫描就比状态表更省（判定方法与两类背包的分界见[贪心](./13-贪心.md#贪心与动态规划)）。
- **无权图最短路径**：BFS 直接给出最早到达的层数，不需要比较多个候选策略（见[图](./08-图.md#无权图最短路)）。
- **要输出所有方案**：此时输出规模本身就是复杂度下界，应该用回溯（见[递归、分治与回溯](./11-递归、分治与回溯.md#回溯是决策树上的-dfs)）。
- **状态必须保存完整历史，或状态数本身不可接受**：前者要重新设计状态或改用搜索剪枝；后者的典型是 n = 30 的子集类问题（2³⁰ 个状态，位压缩只改变表示、不改变指数规模，见[位运算技巧](./14-位运算技巧.md#位掩码表示小集合)）。
- **存在更匹配的结构**：单调性可以二分答案、数学公式可以直接推导时，不必引入状态表（见[查找与二分查找](./10-查找与二分查找.md#在答案空间上二分)）。

实用流程：先尝试证明贪心；证明不出来，再检查"状态有限 + 转移无环 + 状态信息完整"；都不满足时回到搜索加剪枝。

## 常见坑与边界

- **状态含义没写清楚**：`dp[i]` 在脑内从"前 i 个"漂移到"第 i 个"，边界与答案位置跟着全错。先写一句话，再动键盘。
- **初值污染不可达状态**：求最大值时用 `0` 初始化"做不到"的状态，会让不可行解伪装成合法解；"恰好达到"类问题需要 -∞ 或额外的布尔标记，求最小值时还要小心哨兵加代价后的溢出。
- **遍历方向反**：0-1 背包正序会重复使用物品；`[2, 2, 3, 5]` 的反例见"典型模型二"。同样的错误会出现在任何"本轮新值可能覆盖旧值"的一维压缩里。
- **滚动数组读出错误的一侧**：网格路径中 `dp[j-1]` 必须先被更新成本行新值、`dp[j]` 必须还是上一行旧值；换扫描方向后转移含义就变了。
- **二维表的行别名**：`List<List<int>>.filled(m, List<int>.filled(n, 0))` 会让所有行共享同一个列表对象，改一行等于改所有行；官方文档明确"All elements of the created list share the same fill value"，应改用 `List.generate(m, (_) => List<int>.filled(n, 0))`（编辑距离的建表写法）。
- **计数溢出**：Dart Native 的 `int` 是 64 位有符号整数，路径数与方案数增长很快；题面要求取模时按题面取模，否则考虑 `BigInt` 或重新核对约束（位宽依据见[Dart 内置类型](https://dart.dev/language/built-in-types)）。
- **子数组与子序列混淆**："连续"约束会改变状态定义：子序列用前缀对，子数组用"以 i 结尾"，两者的转移和去重方式都不同。
- **把记忆化当万灵药**：状态里包含完整路径时，缓存键的取值空间没有变小，缓存只增加内存，不改变复杂度。

### 常见误区

- ❌ "看到求最值就用动态规划。" ✅ 先用交换论证尝试贪心，再用状态数估算 DP 的规模；贪心可证明时，DP 是更差的方案。
- ❌ "DP 就是二维表格加两层循环。" ✅ 维度由"有几个独立进度"决定：两个变量（斐波那契、打家劫舍）、一维（0-1 背包）、二维（编辑距离）都可能；表格只是其中一种形态。
- ❌ "空间压缩后还能轻松还原方案。" ✅ 压缩丢掉的往往正是恢复路径需要的历史；先确定输出口径，再决定是否压缩。
- ❌ "记忆化是在递归上随便加个 Map。" ✅ 缓存键必须等于状态定义，少一项就会跨状态错误复用答案。

### 打家劫舍（LeetCode 198）

[题目](https://leetcode.com/problems/house-robber/)｜归档：[../02-LeetCode题解/07-动态规划.md](../02-LeetCode题解/07-动态规划.md)

- **问题匹配点**：每一步"偷或不偷"只影响相邻的下一个决策，可以压缩成"上一间是否被偷"的两个状态，属于线性 DP 加空间压缩。
- **状态与不变量**：`dp[i]` 表示前 i 间房能偷到的最高金额；不偷第 i 间取 `dp[i-1]`，偷第 i 间取 `dp[i-2] + nums[i]`。滚动变量版本的不变量是：每轮循环结束，`prev1` 等于前 i 间的最优值、`prev2` 等于前 i-1 间的最优值。
- **边界用例**：题面保证 `n >= 1`，代码额外约定空数组返回 0；单元素直接返回它；相邻两间只能取较大者。验证文件对 `[1, 2, 3, 1]`（4）、`[2, 7, 9, 3, 1]`（12）、`[5]` 与空数组逐一断言。

```dart
int rob(List<int> nums) {
  // dp[i]：前 i 间房能偷到的最高金额；dp[i] 只依赖前两个状态，用两个变量滚动。
  var prev2 = 0; // dp[i-2]
  var prev1 = 0; // dp[i-1]
  for (final num in nums) {
    // 1. 不偷当前房取 dp[i-1]，偷当前房取 dp[i-2] + num。
    final current = prev1 > prev2 + num ? prev1 : prev2 + num;
    prev2 = prev1;
    prev1 = current;
  }
  return prev1;
}
```

### 最长递增子序列（LeetCode 300）

[题目](https://leetcode.com/problems/longest-increasing-subsequence/)｜归档：[../02-LeetCode题解/07-动态规划.md](../02-LeetCode题解/07-动态规划.md)

- **问题匹配点**：子序列可以不连续但必须保序，判断"能不能接上"需要知道结尾值，因此状态选择"以 i 结尾"而不是"前 i 个"；题目还要求把 O(n²) 优化到 O(n log n)。
- **状态与不变量**：O(n²) 版本里 `dp[i]` 是以 `nums[i]` 结尾的最长严格递增子序列长度，答案要对所有 i 取最大值，不能只看 `dp[n-1]`。O(n log n) 版本维护 `tails[l]`：长度为 l+1 的递增子序列中最小的结尾值；不变量是 `tails` 严格递增，每个元素二分"第一个 >= num"的位置替换，越界则追加长度。
- **边界用例**：全相等的数组返回 1；单元素返回 1；严格递增要求用 `<` 比较，不下降子序列要改用 `<=`。

```dart
// O(n^2)：dp[i] 表示"以 nums[i] 结尾"的最长严格递增子序列长度。
int lengthOfLIS(List<int> nums) {
  var best = 0;
  final dp = List<int>.filled(nums.length, 1);
  for (var i = 0; i < nums.length; i++) {
    for (var j = 0; j < i; j++) {
      if (nums[j] < nums[i] && dp[j] + 1 > dp[i]) {
        dp[i] = dp[j] + 1;
      }
    }
    if (dp[i] > best) {
      best = dp[i];
    }
  }
  return best;
}
```

```dart
// O(n log n)：tails[l] 是长度为 l+1 的递增子序列中最小的结尾值。
List<int> tailsOf(List<int> nums) {
  final tails = <int>[];
  for (final num in nums) {
    // 1. 在 tails 中找第一个 >= num 的位置。
    var lo = 0;
    var hi = tails.length;
    while (lo < hi) {
      final mid = lo + (hi - lo) ~/ 2;
      if (tails[mid] < num) {
        lo = mid + 1;
      } else {
        hi = mid;
      }
    }

    // 2. 越界则追加长度，否则把该位置的结尾值改小。
    if (lo == tails.length) {
      tails.add(num);
    } else {
      tails[lo] = num;
    }
  }
  return tails;
}

bool isSubsequence(List<int> source, List<int> candidate) {
  var index = 0;
  for (final value in candidate) {
    while (index < source.length && source[index] != value) {
      index++;
    }
    if (index == source.length) {
      return false;
    }
    index++;
  }
  return true;
}
```

`tails` 的告警值得单独记住：它只记录"每个长度的最小结尾"，**本身不一定是原序列的子序列**。验证文件里用 `isSubsequence` 断言了这一点：`[2, 3, 1, 4]` 得到的 `tails` 是 `[1, 3, 4]`，而 `1, 3, 4` 并不是原序列的子序列；`tails` 的长度仍然等于答案。二分下界（lower bound）的模板见[查找与二分查找](./10-查找与二分查找.md#lower-bound-与-upper-bound)。

复杂度：O(n²) 版本时间 O(n²)、空间 O(n)；`tails` 版本时间 O(n log n)、空间 O(n)。当前约束 `1 <= n <= 2500`、`-10^4 <= nums[i] <= 10^4`，整数比较不涉及溢出风险；比较必须用 `compareTo` 语义的 `<`/`>`，不能改成相减。

### 分割等和子集（LeetCode 416）

[题目](https://leetcode.com/problems/partition-equal-subset-sum/)｜归档：[../02-LeetCode题解/07-动态规划.md](../02-LeetCode题解/07-动态规划.md)

- **问题匹配点**：判断能否选出一些数、每个数至多用一次、使和恰好为总和的一半——0-1 背包的布尔版。
- **状态与不变量**：`dp[j]` 表示能否用已处理的数凑出恰好 j；`dp[0] = true`；外层物品、内层容量逆序。不变量是：处理当前 `num` 的整个内层循环里，`dp[j - num]` 始终是"未使用当前 num"的旧值。
- **边界用例**：总和为奇数直接返回 `false`；`[2, 2, 3, 5]` 无法平分（正序版本会错误地返回 true，反例见"典型模型二"）；`[1, 5, 11, 5]` 可以分成 11 和 11。

```dart
bool canPartition(List<int> nums) {
  var sum = 0;
  for (final num in nums) {
    sum += num;
  }
  if (sum.isOdd) {
    return false;
  }
  final target = sum ~/ 2;
  // dp[j]：能否用已处理的数凑出恰好 j（每个数至多用一次）。
  final dp = List<bool>.filled(target + 1, false);
  dp[0] = true;
  for (final num in nums) {
    // 1. 逆序遍历：保证 dp[j-num] 还是"未使用当前 num"的旧值。
    for (var j = target; j >= num; j--) {
      if (dp[j - num]) {
        dp[j] = true;
      }
    }
  }
  return dp[target];
}
```

复杂度：时间 O(n · target)、额外空间 O(target)，其中 `target = sum ~/ 2`；当前约束 `1 <= n <= 200`、`1 <= nums[i] <= 100`，所以 `target <= 10^4`，空间与时间都可控。

### 编辑距离（LeetCode 72）

[题目](https://leetcode.com/problems/edit-distance/)｜归档：[../02-LeetCode题解/07-动态规划.md](../02-LeetCode题解/07-动态规划.md)

- **问题匹配点**：两个字符串的"处理进度"彼此独立，属于二维前缀状态；三种编辑操作恰好对应三个前驱状态，是"状态定义决定转移"的典型。
- **状态与不变量**：`dp[i][j]` 表示把 `word1` 的前 i 个字符变成 `word2` 的前 j 个字符的最少操作数。末尾字符相同时直接继承 `dp[i-1][j-1]`；不同时取三者最小——替换来自 `dp[i-1][j-1]`、删除来自 `dp[i-1][j]`、插入来自 `dp[i][j-1]`，各加一次代价。
- **边界用例**：空串对空串为 0；空串对长度为 n 的串等于 n（只做插入）；长度为 m 的串对空串等于 m（只做删除）。验证文件断言 `horse → ros` 为 3、`intention → execution` 为 5。

```dart
int minDistance(String word1, String word2) {
  final m = word1.length;
  final n = word2.length;
  // dp[i][j]：把 word1 的前 i 个字符变成 word2 的前 j 个字符的最少操作数。
  final dp = List.generate(m + 1, (_) => List<int>.filled(n + 1, 0));
  for (var i = 0; i <= m; i++) {
    dp[i][0] = i; // 只有删除
  }
  for (var j = 0; j <= n; j++) {
    dp[0][j] = j; // 只有插入
  }
  for (var i = 1; i <= m; i++) {
    for (var j = 1; j <= n; j++) {
      if (word1[i - 1] == word2[j - 1]) {
        dp[i][j] = dp[i - 1][j - 1]; // 末尾相同，不需要操作
        continue;
      }

      // 1. 三个前驱分别对应替换、删除、插入。
      final replace = dp[i - 1][j - 1] + 1;
      final delete = dp[i - 1][j] + 1;
      final insert = dp[i][j - 1] + 1;
      dp[i][j] = replace < delete ? replace : delete;
      if (insert < dp[i][j]) {
        dp[i][j] = insert;
      }
    }
  }
  return dp[m][n];
}
```

复杂度：时间 O(m · n)、空间 O(m · n)；依赖只有上一行与当前行，因此可压缩到两行、O(min(m, n)) 额外空间（思路见"空间优化与方案恢复"，这里保留完整二维表以便直观看到三个前驱）。当前约束两个串长度都不超过 500，建表必须用 `List.generate` 避免行别名；字符按 UTF-16 code unit 比较，本题限定小写英文字母，不存在多码元字符问题。

## 面试考点与追问

- **如何判断一道题能不能用 DP**：把"重叠子问题 + 最优子结构 + 状态无后效性"三件事逐一说明；能写交换论证就先试贪心。
- **状态与转移的定义**：用五步法复述，强调"状态含义一句话，转移是它的推论"；LIS 的"前缀/结尾"对照是最小反例。
- **记忆化与制表的取舍**：状态稀疏、依赖跳跃选记忆化；需要压空间或顺序固定选制表；空间口径分别是"缓存 + 递归栈"与"状态表"。
- **0-1 背包逆序**：一维数组里 `dp[j-w]` 的旧值/新值二义性，逆序保证每件只用一次；完全背包正序。
- **空间压缩条件**：被覆盖的旧值之后不再被读取；恢复方案与压缩常冲突。
- **LIS 与编辑距离的追问**：LIS 从 O(n²) 到 `tails` + lower bound 的 O(n log n)，注意 `tails` 不是 LIS 本身；编辑距离要能说清首行/首列是插入/删除的累积，以及三个前驱与三种操作的对应。
- **恢复方案**：完整表回推、parent 数组或重新计算；计数问题压缩后通常无法恢复。

> **面试高频：** 如何恢复一个 DP 的最优方案？
> **答题脉络：** 先明确"求值"和"恢复方案"是两个步骤 → 选择保留决策来源（完整表回推或 parent 数组）→ 指出压缩空间的版本会丢掉历史 → 用编辑距离逐格判断三个前驱举例。
> **追问方向：** 内存上限很紧时怎么恢复；计数问题能否恢复；滚动数组下有哪些替代做法。

## 小结

先定义状态和依赖，再写方程和代码：状态回答"我需要记住什么"，依赖图回答"按什么顺序算"，方程只是这两者的翻译；初始、非法状态和答案位置都要按同一条状态含义检查，模板自然就不再需要背。
