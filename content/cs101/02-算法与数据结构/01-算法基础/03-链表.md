# 算法与数据结构｜链表

事实核查日期：2026-09-22。Dart 语义按 Dart 3.12.2 核对；题目编号、题名与在线链接按当天可访问状态核对。

在数组里往中间插入一个元素时，代码只有一行 `list.insert(0, x)`，机器做的事情却是把插入点之后的元素整体后移一位。链表想省掉这次搬移：让新节点记住“我的后面是谁”，再让前一个节点记住新节点，插入就变成了两次引用赋值。

代价随之而来。“下一个元素在哪里”不再能由下标算出来，只能顺着引用一层层走；节点也不再挨着存放，遍历时缓存帮不上忙。所以数组与链表的选择从来不是“谁更快”，而是三个前提的组合：你是否已经持有要改动的位置、你是否需要按下标随机访问、以及遍历时数据是否还想连续存放。

于是链表真正的难点不在“插入很快”这个结论，而在引用图的安全修改：改哪几个引用、改之前必须先保存什么、头节点变了怎么返回、以及空表、单节点、环这些边界如何不崩溃。本文的路线是：先看清连续存储在中间插删时的代价，再建立节点与引用的模型；然后把“已知位置 O(1) 插删”的前提、哨兵、反转、快慢指针、多链表协同逐个拆开；最后回到取舍与常见坑，并用四道题把重连、身份、环与归并串起来。

本文所有 Dart 代码块的前置条件相同：Dart 3.12.2、纯 Dart、无第三方依赖；每个代码块后的 `<!-- verify: … -->` 给出它所在的完整可运行文件，文件顶部带有 `dart run --enable-asserts …` 命令与断言，正文只摘录与结论相关的函数或类。全文共用的 `ListNode`、`buildList`、`toValues` 等辅助定义在“节点模型与基本术语”一节的代码块与 `A03/list_node.dart` 中给出。

## 为什么需要非连续存储

数组模型的全部便利都来自一个公式：第 $i$ 个元素的地址等于起始地址加 $i \times$ 元素大小。正因为位置可以算，按下标读写才是 $O(1)$；也正因为位置必须连续，插入点之后的元素都要整体后移。Dart 的 `List.insert` 文档把这个契约写得很直白：它“增加长度并把 index 及其后的所有对象向尾部移动”（见 [R1]），移动的个数与插入点之后还剩多少元素成正比。文档没有承诺具体复杂度，但按契约，把头插做到 $O(1)$ 是不可能的。

链表换掉的正是这个契约：元素不再连续，位置也不可计算，但“插到某个节点之后”只改两个引用。用最小实验对比一下同样做 $n$ 次头插的两条路：

```dart
// 前置条件：Dart 3.12.2；纯 Dart，无第三方依赖。
// 运行：dart run --enable-asserts .work/verify/A03/index_cost.dart
/// 数组头插：每次插入都要移动已有的全部元素。
void insertAtFrontOfList(int count) {
  final list = <int>[];
  for (var index = 0; index < count; index++) {
    list.insert(0, index);
  }
}

/// 链表头插：每次插入只改一个引用。
ListNode<int>? insertAtFrontOfLinked(int count) {
  ListNode<int>? head;
  for (var index = 0; index < count; index++) {
    // 1. 新节点的 next 指向当前头。
    // 2. 头指针换成新节点。
    head = ListNode<int>(index, next: head);
  }
  return head;
}
```

<!-- verify: .work/verify/A03/index_cost.dart -->

$n = 10000$ 时，数组头插要搬移 $n(n-1)/2 = 49995000$ 个元素；同一台机器上同一份 Dart 运行时里的耗时观察值如下（仅代表本环境，不作为语言或实现保证；其中的数组尾插是同样 $10^4$ 次追加，用于排除“数组本身慢”的误解）：

```text
数组头插：理论搬移 49995000 个元素，耗时 73112 us
数组尾插：耗时 288 us
链表头插：耗时 320 us
```

注意对照组：数组尾插同样是 $O(1)$。慢的不是“数组”，而是“在头部或中部插入”——位置越靠前，要搬的元素越多。链表的代价则出现在另一侧：按下标取第 $k$ 个元素必须从头走 $k$ 步，这项成本在数组里是 $O(1)$。数组侧的存储模型、`List` 与 `String` 的下标语义见[数组与字符串](./02-数组与字符串.md)。

> **关键认知：** 链表不是“更快的数组”，它用“放弃按下标定位”换来了“不搬移已有元素”；插入删除的 $O(1)$ 永远附带着“已经持有位置”这个前提。

> **面试高频：** 数组和链表怎么选？
> **答题脉络：** 先问三个前提（要不要随机访问、有没有持有节点、遍历是否密集）→ 再比已知位置插删 $O(1)$ 与按下标插删 $O(n)$ → 最后补内存开销与缓存局部性 → 结论是“按主导操作选”，不是背结论。
> **追问方向：** 动态扩容的均摊成本（见[复杂度分析与算法思想](./01-复杂度分析与算法思想.md)）；双链表多一个引用换到什么；LRU 为什么两者都要（见[哈希表](./05-哈希表.md)）。

## 节点模型与基本术语

把“链”写成类型，只需要一个数据字段和一个指向同类节点的引用。Dart 的空安全让两件原本容易混淆的事变成两个不同的类型：值本身是否可空是 `T` 的事，链接是否可空是 `ListNode<T>?` 的事；验证文件里的 `buildList<int?>(const [1, null, 3])` 就是“值可空”的链表。

```dart
// 前置条件：Dart 3.12.2；纯 Dart，无第三方依赖。
// 运行：dart run --enable-asserts .work/verify/A03/list_node.dart
/// 单链表节点：值类型由 T 决定，链接是否可空由 `?` 单独表达。
final class ListNode<T> {
  ListNode(this.value, {this.next});

  T value;
  ListNode<T>? next;
}
```

<!-- verify: .work/verify/A03/list_node.dart -->

约定与术语先钉死，后面的推导才不会串：

- **头节点（head）** 是链条的入口；**尾节点** 的 `next` 为 `null`。空表就是 `head == null`。
- 某个节点的 **后继（successor）** 是 `next`，**前驱（predecessor）** 指向它的节点；单链表只有后继，双链表两个都有。
- **单链表** 每个节点一个链接；**双链表** 每个节点另有 `previous`；**循环链表** 把尾节点的 `next` 接回某个节点，形成环，此时“尾节点”不再有 `null` 作为天然终点。
- 用于简化边界、本身不存业务数据的节点叫 **哨兵（sentinel）** 或虚拟头结点，下一节单独讨论。

> **关键认知：** “链接为空”和“值为空”是两件不同的事：`next == null` 表示链到此结束，`value == null` 只表示这个节点的数据是空值；前者影响终止条件，后者影响业务语义，类型上分别是 `ListNode<T>?` 与 `T?`。

### 节点的身份不是节点的值

链表题目里最常出错的一类判断，是把“值相等”当成“同一个节点”。判断两个引用是否指向同一个对象要用 `identical`（见 [R2]）：

```dart
/// 身份判断演示：节点是新对象，而整数、字符串字面量与 const 对象会被同一化。
List<bool> identityChecks() {
  final first = ListNode(1);
  final second = ListNode(1);
  return [
    identical(first, second), // false：两个新节点不是同一对象
    identical(1, 1), // true：整数相等即同一
    identical('环', '环'), // true：字符串字面量同一化
    identical(const [1], const [1]), // true：const 对象同一化
    identical(1, 1.0), // false：int 与 double 是不同的值
  ];
}
```

<!-- verify: .work/verify/A03/list_node.dart -->

返回值依次是 `false`、`true`、`true`、`true`、`false`：普通构造器创建的节点不会与任何已有对象相同，而整数、字符串字面量和 const 字面量在“相等”时本来就可能指向同一个对象。把二者混为一谈，就会出现“用 `identical` 判断两个坐标是否相等”这类误用。

但不要把 `identical` 反过来当成“值不相等”的判据：整数、字符串字面量和 const 对象在相等时也可能返回 `true`。它的语义只有一条——“没有别的办法区分这两个参数”。因此链表算法里要用它比较**节点对象**，而不是用它区分值。

> **关键认知：** `identical(a, b) == true` 意味着两个引用指向同一个对象；它不承诺“值相等就一定 `false`”，所以“节点身份”的判断必须作用于节点本身，不能靠值来代替。

## 操作与复杂度

把两种结构放在同一组维度上对比，可以看清各自的胜负区间：

| 操作 | 数组（连续存储） | 单链表 | 备注 |
|---|---|---|---|
| 按下标读写 | $O(1)$ | $O(n)$ | 链表必须从头走 |
| 在头部插入/删除 | $O(n)$ | $O(1)$ | 数组要整体后移或前移 |
| 在已知节点之后插入 | $O(1)$ | $O(1)$ | 数组要移动 $n - i$ 个元素 |
| 删除已知节点（单链表） | $O(1)$ | $O(n)$ 或 $O(1)^*$ | $^*$ 见下文的复制后继法 |
| 遍历局部性 | 连续、可预取 | 逐节点跳转 | 见[什么时候用，什么时候别用](#什么时候用什么时候别用) |

### 已知位置：插入与删除

“已知位置”是链表 $O(1)$ 的全部前提：已经持有节点引用，就不需要再从头找它。

```dart
// 前置条件：Dart 3.12.2；纯 Dart，无第三方依赖。
// 运行：dart run --enable-asserts .work/verify/A03/insert_delete.dart
/// 在 node 之后插入一个新节点：只要已经持有 node，就是常数次引用赋值。
ListNode<T> insertAfter<T>(ListNode<T> node, T value) {
  // 1. 新节点先接上 node 原来的后继。
  final inserted = ListNode<T>(value, next: node.next);
  // 2. 再让 node 指向新节点。
  node.next = inserted;
  return inserted;
}

/// 删除 node 的后继：只要已经持有前驱，就是常数次引用赋值。
ListNode<T>? removeAfter<T>(ListNode<T> node) {
  final removed = node.next;
  node.next = removed?.next;
  return removed;
}
```

<!-- verify: .work/verify/A03/insert_delete.dart -->

两个函数都只有两个动作，但顺序不能反：先把新节点或新链接接到旧结构上，再切断/改指原引用。反过来写就会丢掉后半条链。若改成“在 `node` 之前插入”，单链表必须知道前驱，只能从头找，代价退回 $O(n)$；这正是双链表存在的理由。

### 只有待删节点：复制后继的代价

如果手上只有待删除节点本身（没有前驱），单链表有一种常见的 $O(1)$ 手法：把后继的值复制过来，然后摘掉后继节点。

```dart
/// 只持有待删除节点时的常见手法：把后继节点的值复制过来，再摘掉后继节点。
/// 返回 false 表示待删除节点是尾节点，这条路径需要 O(n) 找前驱。
/// 副作用：node 之后那个节点对象被摘除，外部如果还持有它就会看到“值搬家”。
bool removeNodeByCopyingNext<T>(ListNode<T> node) {
  final next = node.next;
  if (next == null) return false;
  node.value = next.value; // 1. 值覆盖到当前节点
  node.next = next.next; // 2. 跳过并摘除后继节点
  return true;
}
```

<!-- verify: .work/verify/A03/insert_delete.dart -->

它有两个不能忽略的边界。第一，**尾节点上没有后继可复制**：单链表只能用 $O(n)$ 找前驱，所以“删除指定节点 $O(1)$”平均成立、最坏不成立（LeetCode 237 直接在题面里排除了尾节点，见 [R12]）。第二，**节点身份被交换了**：被摘掉的是原来的后继对象，留在原位置的是原来的节点对象，值换了主人。一旦外部还持有这两个节点（做索引、做缓存、做并发标记），这个“障眼法”就会产生难以定位的 bug。

### 双链表为什么能删在 O(1)

双链表每个节点多存一个 `previous`，于是“只有自己”也足够把自己摘出来：拿到 `previous` 与 `next`，把它们互相接上，再把自己的两个引用置空。代价是每次插入和删除要维护的边从两条变成四条，写错任何一条都会造成“单向可见”的破损结构；换来的是“不需要前驱就能删”。LRU 缓存正是用“哈希表定位 + 双链表 $O(1)$ 摘除/搬到头部”组合出来的（结构分工见[哈希表](./05-哈希表.md)，完整验证代码见 `A03/insert_delete.dart` 中的 `DoublyListNode`）。

> **关键认知：** “删除是 $O(1)$”说的从来不是“知道下标就能删”，而是“已经持有前驱（单链表）或持有自身（双链表）”；缺少这个前提时，定位成本是 $O(n)$。

> **面试高频：** 链表删除什么时候是 $O(1)$，什么时候退化？
> **答题脉络：** 先声明前提（持有前驱或持有自身）→ 说明单链表只有待删节点时用复制后继法，平均 $O(1)$、尾节点 $O(n)$ → 补充身份被更换的副作用 → 结论按场景给出。
> **追问方向：** 复制后继法在什么场景下不可用（值不可变、外部持有节点、并发）；双链表维护的边数；Linux 内核式“侵入式链表”与本题的关系。

## 哨兵节点与统一边界

删除“值等于 target”的节点时，头节点可能被删掉，头指针必须改变。不引入哨兵的写法要给头节点单独开一段逻辑：

```dart
// 前置条件：Dart 3.12.2；纯 Dart，无第三方依赖。
// 运行：dart run --enable-asserts .work/verify/A03/dummy_head.dart
/// 手工处理头节点的版本：头节点可能被删掉，需要一次专门的分支。
ListNode<T>? removeValueManual<T>(ListNode<T>? head, T target) {
  // 1. 头节点可能连续多个都要删，所以用循环而不是 if。
  while (head != null && head.value == target) {
    head = head.next;
  }
  // 2. 此后头节点不会再变，只需要删除“当前节点的后继”。
  var previous = head;
  while (previous != null) {
    final current = previous.next;
    if (current != null && current.value == target) {
      previous.next = current.next;
    } else {
      previous = current;
    }
  }
  return head;
}
```

<!-- verify: .work/verify/A03/dummy_head.dart -->

哨兵的思路是凭空加一个“前驱”，让头节点也变成“被删除的后继”，于是循环里只剩一个分支：

```dart
/// 带哨兵的版本：哨兵是不参与业务语义的虚拟前驱。
/// 注意：这里能直接写 `ListNode<int>(0)`，是因为 int 有可用的占位值；
/// 换成可能不可空的泛型 T 就必须另行设计（见正文说明）。
ListNode<int>? removeValueWithDummy(ListNode<int>? head, int target) {
  final dummy = ListNode<int>(0)..next = head;
  var previous = dummy;
  var current = head;
  while (current != null) {
    if (current.value == target) {
      previous.next = current.next; // 1. 跳过 current，previous 不动
    } else {
      previous = current; // 2. 保留 current
    }
    current = current.next; // 3. 无论删没删，都继续扫描下一个节点
  }
  return dummy.next;
}
```

<!-- verify: .work/verify/A03/dummy_head.dart -->

这段代码里有个 Dart 特有的坑：`ListNode<int>(0)` 中的 `0` 只是占位，**不能被读取**；而换成泛型 `T` 时，`T` 可能不可空（例如 `T = int`），根本造不出一个“空值哨兵”。所以在 Dart 里写哨兵有两种落地方式：像上面那样把类型缩到有占位值的具体类型；或者保留泛型，把“首个节点”单独处理一次（本文的归并与验证文件里的两两交换用的就是后者）。后者不是拒绝哨兵，而是用一次分支换掉了一个难以通用的占位节点。

> **关键认知：** 哨兵的价值是把“头节点可能改变”变成“头节点不再变化”，从而消掉循环里的特判；它的成本是一个额外节点和一次分配，在只读遍历、一次性操作或内存敏感的场景里并不划算。

> **面试高频：** 什么时候该引入哨兵（虚拟头结点）？
> **答题脉络：** 先看操作是否可能改变头节点（删除、插入到头部、归并、分段反转）→ 再看循环内是否因此出现重复特判 → 最后说明成本与 Dart 泛型下的替代写法。
> **追问方向：** 不加哨兵时返回新头有哪几种写法；哨兵值被业务读取会造成什么后果；循环链表里的哨兵与普通虚拟头的区别。

## 反转与局部重连

反转是“改引用”类问题的母题：每个节点都要改一次指向，而改指向之前必须先记住原来的后继，否则剩下的链就再也找不到了。

### 迭代反转的循环不变量

```dart
// 前置条件：Dart 3.12.2；纯 Dart，无第三方依赖。
// 运行：dart run --enable-asserts .work/verify/A03/reverse_list.dart
/// 迭代反转。
/// 不变量：previous 是“已经反转完成的子链”的头节点，
///        current 是“尚未处理的原链表”的头节点。
ListNode<T>? reverseIterative<T>(ListNode<T>? head) {
  ListNode<T>? previous;
  var current = head;
  while (current != null) {
    final next = current.next; // 1. 先保存后继，否则改完指针就找不回来了
    current.next = previous; // 2. 让当前节点指向已反转部分
    previous = current; // 3. 已反转部分扩大一个节点
    current = next; // 4. 继续处理原链表剩下的部分
  }
  return previous; // 5. current 为 null 时，previous 就是新头
}
```

<!-- verify: .work/verify/A03/reverse_list.dart -->

循环不变量的说法可以更具体：每轮开始时，`previous` 指向的链已经反序，`current` 指向的链仍是原来的顺序，两条链拼接起来覆盖原链的全部节点，且没有任何节点被复制。结束时 `current == null`，`previous` 就是新头。空表与单节点不需要特判，循环直接给出正确答案；`previous` 初始为 `null` 正是“新尾节点的 `next` 应为 `null`”。

> **关键认知：** 局部重连的统一节奏是“先保存后继 → 再改指向 → 最后推进指针”；任何一步换序，轻则丢链，重则把链表改成环（把 `next` 指回已经走过的节点）。

> **面试高频：** 反转链表为什么不会丢节点？
> **答题脉络：** 说出循环不变量与两条链的划分 → 解释必须先取 `next` 再改 `next` → 用空表、单节点、两节点三个边界说明不需要特判。
> **追问方向：** 区间反转（`left`、`right`）怎么复用这套不变量；每 k 个一组反转；为什么“改 `next` 之前先保存”是通用规则。

### 递归反转与调用栈

```dart
/// 递归反转：先反转 head 之后的子链，再把 head 接到子链的尾部。
ListNode<T>? reverseRecursive<T>(ListNode<T>? head) {
  if (head == null) return null;
  final current = head; // 空安全收窄：以下 current 都是非空类型
  final next = current.next;
  if (next == null) return current; // 单节点就是答案
  final reversedHead = reverseRecursive(next);
  next.next = current; // 让后继反过来指向自己
  current.next = null; // 原来的头变成新链的尾
  return reversedHead;
}
```

<!-- verify: .work/verify/A03/reverse_list.dart -->

递归版代码更短，但它不是“常数空间”：每层调用都要等到子链反转完成后再修改两个引用，因此调用栈深度与链表长度成正比，额外空间是 $O(n)$——递归栈计入额外空间的口径见[复杂度分析与算法思想](./01-复杂度分析与算法思想.md#空间复杂度)。递归的通用拆解方式（子问题 + 边界条件）见[递归、分治与回溯](./11-递归、分治与回溯.md)。Dart 也不承诺尾调用消除，所以长链表上的递归是真实风险：

> **时效信息（核查日期：2026-09）：** 在 Dart 3.12.2（Native，Windows x64）上，本文验证文件用 20 万个节点调用递归反转会抛出 `StackOverflowError`，而同样规模的迭代反转正常完成；探针测试显示触发区间大致在数万节点量级且不随长度单调（取决于运行时栈与编译状态）。这不是语言规范给出的阈值，只是提醒：递归深度不能当作与 $n$ 无关的常数。

### 局部重连：两两交换

相邻两节点一组交换（[LeetCode 24](https://leetcode.cn/problems/swap-nodes-in-pairs/)，题面要求只改节点、不改值）是“局部重连”的典型形状：每处理一对要改三条边，而且必须有一个锚点指向这一对的前驱。第一对没有前驱，单独处理一次；之后循环以“上一对的左节点”为锚点，把右节点接到锚点后、再让左节点接上右节点的后继。它和反转共享同一个节奏：先保存后继、再改指向、最后推进锚点。验证文件覆盖了 0 到 5 个节点的六种长度，输出的值序列分别是空、`1`、`2,1`、`2,1,3`、`2,1,4,3`、`2,1,4,3,5`（奇数长度的最后一个节点保持原位是任务语义，不是疏漏）。

## 快慢指针

两个指针在**同一条**链上以不同速度前进，可以只用 $O(1)$ 额外空间换取“相对位置”信息：快指针到尾部时慢指针在中点，两个指针相隔 $k$ 步时慢指针在倒数第 $k$ 个，而速度差可以用来发现环。

### 中点与倒数第 k 个

```dart
// 前置条件：Dart 3.12.2；纯 Dart，无第三方依赖。
// 运行：dart run --enable-asserts .work/verify/A03/middle_node.dart
/// 找中点：快指针每次走两步，慢指针每次走一步。
/// 偶数长度时停在靠后的中点（4 个节点时停在第 3 个）。
ListNode<T>? middleNode<T>(ListNode<T>? head) {
  var slow = head;
  var fast = head;
  while (fast != null && fast.next != null) {
    slow = slow!.next; // 慢指针在快指针后面，不会先走到尾部
    fast = fast.next!.next; // 循环条件已确认 fast.next 非空
  }
  return slow;
}

/// 找倒数第 k 个节点（k >= 1）；节点数不足 k 个时返回 null。
ListNode<T>? kthFromEnd<T>(ListNode<T>? head, int k) {
  if (k < 1) return null;

  // 1. 快指针先走 k 步，与慢指针拉开 k 个节点的距离。
  var fast = head;
  var advanced = 0;
  while (advanced < k && fast != null) {
    fast = fast.next;
    advanced++;
  }
  if (advanced < k) return null; // 节点数不足 k 个

  // 2. 两条指针同速前进；快指针走完时，慢指针正好在倒数第 k 个。
  var slow = head;
  while (fast != null) {
    fast = fast.next;
    slow = slow?.next;
  }
  return slow;
}
```

<!-- verify: .work/verify/A03/middle_node.dart -->

这里有两处 $O(1)$ 约束下的细节容易被忽略。第一，**偶数长度取哪个中点**取决于写法：上面这套停在靠后的中点（0 到 6 个节点的验证结果依次是空、`1`、`2`、`2`、`3`、`3`、`4`），换成 `fast = head.next` 起步就会停在靠前的一个；写之前先确定题目要的是哪一半，别靠感觉。第二，**`k` 不合法时要能返回空**：`k` 超过长度、`k < 1`、空表都是真实出现的输入，`kthFromEnd` 用“先走 k 步但记录走了多少步”的方式统一处理，避免先跳再判造成的空指针。

### 判环与相遇位置

设头到环入口的距离为 $\mu$，环长为 $\lambda$。把节点序列写成 $x_0, x_1, \dots$，则当 $i \ge \mu$ 时 $x_{i+\lambda} = x_i$（进入环后每 $\lambda$ 步回到同一节点）。慢指针每步走 1、快指针每步走 2，所以第 $k$ 步时两者分别在 $x_k$ 与 $x_{2k}$。相遇意味着 $x_k = x_{2k}$，即 $k \ge \mu$ 且 $2k \equiv k \pmod{\lambda}$，也就是 $k \equiv 0 \pmod{\lambda}$。**因此第一次相遇发生在“不小于 $\mu$ 的最小正 $\lambda$ 倍数”这一步**，相遇步数 $j \le \mu + \lambda$（$\mu = 0$ 时 $j = \lambda$）；这个结论的严格版本可以在 Brent 的论文里找到，他给出的相遇下标上界是 $m + n$（$m$ 为尾长、$n$ 为环长，见 [R6]）。

```dart
// 前置条件：Dart 3.12.2；纯 Dart，无第三方依赖。
// 运行：dart run --enable-asserts .work/verify/A03/floyd_cycle.dart
/// 返回 (慢指针走过的步数, 相遇节点)；无环时相遇节点为 null。
(int, ListNode<T>?) meeting<T>(ListNode<T>? head) {
  var slow = head;
  var fast = head;
  var steps = 0;
  while (fast != null && fast.next != null) {
    final nextFast = fast.next!; // 循环条件已确认 fast.next 非空
    slow = slow!.next; // 慢指针走在快指针后面，不会先到链尾
    fast = nextFast.next; // 第二跳允许为 null，此时下一轮退出
    steps++;
    if (identical(slow, fast)) return (steps, slow);
  }
  return (steps, null);
}
```

<!-- verify: .work/verify/A03/floyd_cycle.dart -->

终止安全条件就是循环条件本身：`fast != null && fast.next != null`。快指针一次走两步，所以必须同时检查“下一步存在”和“下两步存在”；写成 `fast.next.next != null` 会在尾部提前解引用。两个 `!` 都写在已经由循环条件或位置关系保证非空的位置：`fast.next!` 由循环条件保证，`slow!.next` 由“慢指针永远走在快指针后面”保证。第二跳 `nextFast.next` 则**不能**加 `!`——它本来就允许为 `null`，而 `fast.next!.next!` 这类写法正是无环输入上最常见的崩溃来源。

### 从相遇点找回入口

第一阶段只保证“相遇节点在环上”。第二阶段把一条指针放回头部、另一条留在相遇点，同速前进，相遇处就是入口：

```dart
/// 第二阶段：一个指针从头出发，一个从相遇点出发，同速前进，相遇处就是入口。
ListNode<T>? cycleEntry<T>(ListNode<T>? head) {
  final meeting = meetingNode(head);
  if (meeting == null) return null; // 无环

  var fromHead = head!; // 有相遇点说明 head 非空
  var fromMeeting = meeting;
  while (!identical(fromHead, fromMeeting)) {
    fromHead = fromHead.next!; // 两者都不会走到 null：一个在尾巴上，一个在环上
    fromMeeting = fromMeeting.next!;
  }
  return fromHead;
}
```

<!-- verify: .work/verify/A03/floyd_cycle.dart -->

为什么成立？第一阶段的相遇下标 $j$ 满足 $j \equiv 0 \pmod{\lambda}$，也就是 $j$ 是环长的整数倍。第二阶段两条指针同速前进 $s$ 步后，从头出发的指针在下标 $s$（只要 $s \le \mu$），从相遇点出发的指针在下标 $j + s$。因为 $j \equiv 0 \pmod{\lambda}$，两者恒有 $j + s \equiv s \pmod{\lambda}$，即始终落在“环上相对偏移相同”的位置；当 $s = \mu$ 时，从头出发的指针正好走到入口，另一条指针也必然在入口。$s < \mu$ 时前者还在尾巴上、后者已在环内，不可能是同一个节点，所以 $s = \mu$ 是第一次相遇。$\mu = 0$（头节点就在环上）时两者一开始就相同，函数直接返回头部。

> **关键认知：** 第二阶段成立的前提是“相遇下标是环长 $\lambda$ 的整数倍”，这个性质来自快慢指针 1:2 的速度比；它不是一个可以随意更换步长仍然成立的巧合。

> **面试高频：** Floyd 判圈为什么能找到环入口，怎么保证不空指针？
> **答题脉络：** 先写清 $\mu$ 与 $\lambda$ 的定义与“相遇下标是 $\lambda$ 的整数倍”→ 说明第二阶段两条指针的相对偏移恒定 → 给出终止条件 `fast != null && fast.next != null` → 最后说明无环返回 `null`、自环与整链是环的退化情形。
> **追问方向：** 快指针一次走 3 步时“相遇下标的倍数性质”是否还成立；为什么必须检查两步而不是一步；环入口与“链表长度 $2\mu + \lambda$ 段”的拆分。

## 多链表协同

两条链表一起处理时，难度不在指针数量，而在两件事：**合并要复用节点还是复制值**，以及**“两条链共享某部分”到底意味着什么**。

### 归并：复用节点还是复制值

LeetCode 21 的题干明确要求“结果由前两条链表的节点拼接而成”（见 [R8]），也就是复用节点、不新建节点。归并时先定下新头，之后循环只做一件事：把较小的那个节点接到尾部。

```dart
// 前置条件：Dart 3.12.2；纯 Dart，无第三方依赖。
// 运行：dart run --enable-asserts .work/verify/A03/merge_intersection.dart
/// LeetCode 21：合并两条有序链表，复用原有节点（不复制值）。
/// compare 返回负数表示第一个参数应排在前面。
ListNode<T>? mergeTwoSorted<T>(
  ListNode<T>? left,
  ListNode<T>? right,
  int Function(T a, T b) compare,
) {
  if (left == null) return right;
  if (right == null) return left;

  // 1. 先确定结果的头节点：这一步只需要比较一次。
  final takeLeft = compare(left.value, right.value) <= 0;
  final first = takeLeft ? left : right;
  if (takeLeft) {
    left = left.next;
  } else {
    right = right.next;
  }

  // 2. 之后 tail 一定非空，循环里只需接上较小的那一个。
  var tail = first;
  while (left != null && right != null) {
    final pickLeft = compare(left.value, right.value) <= 0;
    final chosen = pickLeft ? left : right;
    if (pickLeft) {
      left = left.next;
    } else {
      right = right.next;
    }
    tail.next = chosen;
    tail = chosen;
  }

  // 3. 剩下的整段直接接上，不需要逐个复制。
  tail.next = left ?? right;
  return first;
}
```

<!-- verify: .work/verify/A03/merge_intersection.dart -->

时间 $O(m + n)$（每条链的每个节点被接一次），额外空间 $O(1)$——如果不把输出链算作额外空间。验证文件还确认了“复用”的含义：合并结果里的每个节点都在输入的节点集合里（按身份去重），没有新节点。若题面要求不修改输入，就必须复制节点，空间随之变成 $O(m+n)$；这是需求差异，不是实现技巧。

### 相交看身份，不看值

两条链表相交，指的是**它们从某个节点起共享同一段尾巴**（节点对象相同），而不是“值恰好相等”。因此判断相交必须比身份：

```dart
/// LeetCode 160：两条链表的第一个公共节点；没有公共节点返回 null。
/// 走到尾部就换到另一条链的头，两条指针走过 a+c+b 与 b+c+a 步后必然对齐。
ListNode<T>? firstCommonNode<T>(ListNode<T>? headA, ListNode<T>? headB) {
  var left = headA;
  var right = headB;
  while (!identical(left, right)) {
    left = left == null ? headB : left.next;
    right = right == null ? headA : right.next;
  }
  return left; // 无公共节点时两个指针同时走到 null
}
```

<!-- verify: .work/verify/A03/merge_intersection.dart -->

为什么“换头”能对齐？设两条链的长度分别为 $a + c$ 与 $b + c$，其中 $c$ 是共享尾部长度（不相交时 $c = 0$）。左边指针走 $a + c + b$ 步，右边指针走 $b + c + a$ 步，两者相等，所以它们会在走完同样多的步数后同时抵达交点；不相交时两者同时变成 `null`，循环自然结束。等价的做法是先量长度差、让长的先走差值步，见验证文件里的 `firstCommonNodeByLength`。验证文件里还有一个反例：两条链的值序列完全相同（`7,8,9` 与 `1,2,7,8,9`）但没有任何共享节点，身份判断返回 `null`，而“按值找第一个相同值”的实现会返回一个并不公共的节点——它把“值相等”错当成了“相交”。

> **关键认知：** 相交是“共享同一段节点对象”，不是“共享相同的值”；判断相交必须用身份（`identical`），因为两条独立构造的链即使值全等也不相交。

> **面试高频：** 判断两条链表是否相交，为什么换头双指针可行？
> **答题脉络：** 先定义相交 = 共享尾部节点 → 用 $a+c+b = b+c+a$ 说明同步 → 说明无交点时同时为 `null` → 补充“只问是否相交”时比较尾节点（或把一条链的尾接到另一条头，转成判环）也可以。
> **追问方向：** 有环链表相交怎么判；长度差法与大数 $c$ 的等价性；为什么“值相等”不能作为判据。

## 什么时候用，什么时候别用

**适合用链表的信号**：元素数量增减频繁；算法以“局部插删”为主；必须在原位置 $O(1)$ 摘除某个元素（双链表）；或者需要**引用稳定**——插入/删除时不移动其他元素，外部保存的节点引用继续有效。LRU 缓存、邻接表的边表、内核里挂在不同队列上的同一批对象（侵入式链表）都属于这一类。

**不该用链表的信号**：需要频繁按下标访问或二分；遍历是主要操作；数据量小而简单，额外引用和对象头让内存占用翻倍；以及需要高吞吐的顺序扫描——链表遍历是逐节点跳转，处理器难以预取，节点又往往分散在不同缓存行（局部性原理见 [R9]）。Stroustrup 的结论是“默认用连续表示，除非有充分理由不用”（见 [R7]），他列举的三条原则是：不要存多余的数据、让数据紧凑、以可预测的顺序访问内存。需要相反取舍的一端是“只需要两端操作”的容器：用数组栈还是链式栈，见[栈与队列](./04-栈与队列.md)。

Dart 的标准库里也有链表，它需要的前提与上面一致：链接存在元素自己身上（侵入式），元素必须继承 `LinkedListEntry`，因此持有元素就等价于持有位置。

```dart
// 前置条件：Dart 3.12.2；纯 Dart，无第三方依赖。
// 运行：dart run --enable-asserts .work/verify/A03/dart_linked_list.dart
/// 元素必须继承 LinkedListEntry；而 LinkedListEntry 是 base 类，
/// 因此子类必须声明为 base / final / sealed。
final class Entry extends LinkedListEntry<Entry> {
  Entry(this.value);

  final int value;

  // 故意重写 ==：LinkedList 的 remove/contains 仍然按身份判断。
  @override
  bool operator ==(Object other) => other is Entry && other.value == value;

  @override
  int get hashCode => value.hashCode;
}
```

<!-- verify: .work/verify/A03/dart_linked_list.dart -->

验证文件里的用法是 `list.addAll([...])` 建表、`first.insertAfter(inserted)` 插入、`inserted.unlink()` 摘除自己。几点与官方文档一致、且值得记住的限制（见 [R3]、[R4]、[R5]）：`LinkedList` **不是** `List`，不支持按下标 $O(1)$ 访问；元素同一时刻只能属于一个链表（链接存在元素身上，所以同一元素无法同时进入两个表），重复入表会抛 `StateError`；`remove` 与 `contains` 按身份判断，即使元素重写了 `==`；`insertAfter`、`insertBefore`、`unlink` 在持有元素时是常数时间。

> **时效信息（核查日期：2026-09）：** 本文验证环境（Dart 3.12.2）中 `dart:collection` 仍提供 `LinkedList` / `LinkedListEntry`，未标注 `@Deprecated`；`LinkedListEntry` 的声明是 `abstract base mixin class`，因此元素子类必须写成 `base`/`final`/`sealed`，否则编译报 `must be 'base', 'final' or 'sealed'`。`Queue()` 的默认实现是 `ListQueue`（见 [R5]），需要双链表实现的两端队列时用 `DoubleLinkedQueue`。

> **关键认知：** 链表买到的是“引用稳定 + 已知位置的 $O(1)$ 重连”，付出的是“定位成本 $O(n)$ + 每节点额外引用 + 差的缓存局部性”；只有在业务主导操作是前者时才值得选它。

## 常见坑与边界

- ❌ 改 `current.next` 之前没有保存原来的 `next`。✅ 顺序固定为“保存 `next` → 改 `next` → 推进”，如[迭代反转](#迭代反转的循环不变量)。
- ❌ 反转后返回原来的 `head`，或删掉头节点后不更新头指针。✅ 让“头可能改变”的地方显式返回并接回新头：一次特判或哨兵。
- ❌ 把“删除指定节点 $O(1)$”当成无条件结论。✅ 单链表只有待删节点时用复制后继法，尾节点退化为 $O(n)$，且会更换节点身份。
- ❌ 用 `==` 或值判断相交、判断“是不是同一个节点”。✅ 用 `identical` 比较节点对象；反过来也别把 `identical` 当成“值不相等”的判据。
- ❌ 在判环里写 `fast.next!.next!`、用递归处理长链表、忽略空表与越界。✅ 循环条件写成 `fast != null && fast.next != null`；长链表用迭代（本文环境数万节点即可能 `StackOverflowError`，且不承诺尾调用消除）；每个函数至少覆盖空表、单节点、两节点、目标在尾部四类边界。
- ❌ 认为摘下节点后内存立刻归还。✅ Dart 由运行时管理内存，解除引用后能否、何时回收不作保证，不能依赖回收时机做同步。
- 泛型可空性：`T` 可以是可空类型（`ListNode<int?>`），链接可空性是另一维（`ListNode<T>?`）；写通用容器时不要假设 `T` 一定有可用的占位值。

## 面试考点与追问

> **面试高频：** 让你实现一个 LRU 缓存，为什么是“哈希表 + 双链表”而不是单链表？
> **答题脉络：** 哈希表给出键到节点位置的 $O(1)$ 定位 → 双链表让“持有节点即可 $O(1)$ 摘除并搬到头部” → 单链表缺少前驱，摘除退化为 $O(n)$ → 容量满时删尾节点也要能 $O(1)$。
> **追问方向：** 是否必须用双链表（用单链表加保存前驱的额外结构也可以但更复杂）；哈希表与链表的职责划分见[哈希表](./05-哈希表.md)。

> **面试高频：** 一条链表上让你找环、找中点、找倒数第 k 个，怎么统一解释？
> **答题脉络：** 统一到“两个指针的相对位置” → 速度差 1:2 决定相遇位置的性质 → 距离差决定中点和倒数第 k 个 → 终止条件都是快指针走不动。
> **追问方向：** 为什么中点要处理偶数长度；快指针第三步长时第二阶段为什么可能失效；能否用“先求长度再定位”的方式替代。

## 小结

遇到链表题时按这个顺序检查：先写清节点身份与边界（空表、单节点、尾节点、环），再把“已经持有哪个节点、需要改哪几条边”写出来，然后按“保存后继 → 改指向 → 推进”落实每一步，最后用不变量解释为什么不会丢链、不会成环。选容器时反过来问：主导操作是按位置定位还是按位置重连？
