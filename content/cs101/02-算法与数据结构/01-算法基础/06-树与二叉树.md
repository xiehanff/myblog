# 算法与数据结构｜06-树与二叉树

把数据放进数组，按下标访问很快；放进链表，插入删除很快。但很多数据的形状不是一条线：文件系统有目录层级，HTML 是嵌套标签，分类体系有父子关系，一个算术表达式可以画成一层层的括号结构。这些数据的共同点是“包含”和“分层”。

用线性容器硬凑层级，只能靠额外约定，比如让数组元素再存一个“父节点下标”。这种表示在只读、只找父节点的场景下能用（并查集就是这种思路），但一旦要“列出某个目录下的所有内容”“按层打印”“动态插入子树”，就得手工维护一堆下标关系。树把这种层级关系直接编码进数据结构本身。

第二类动机来自**决策空间**：下棋的每一步、表达式求值的每一步，都可以看成一棵树——节点是当前状态，孩子是下一步选择，线性结构只能表示其中一条路径。第三类动机是**动态有序集合**：既要按键查找，又要“比 5 小的最大键”“第 k 小的键”，而且键会不断插入删除；数组加二分查得快但插入要搬移（见[查找与二分查找](./10-查找与二分查找.md)），哈希表等值查找快却丢掉顺序（见[哈希表](./05-哈希表.md)），BST 正是为这类需求准备的。

本文的路线是：先统一术语与度量口径，再用 Dart 建立节点模型；然后依次学习深度优先与广度优先两种访问顺序；接着用二叉搜索树（Binary Search Tree，BST）说明“不变量如何支撑有序操作”；再用“平衡”回答最坏复杂度问题；最后用自底向上的返回值和四道题，把遍历顺序与递归返回值统一起来。

## 为什么线性结构不够

先分清两种“查找”。数组按位置查，`a[3]` 直接得到第 4 个元素；哈希表按键查，`map[key]` 直接得到值。层级数据要回答的是第三类问题：**包含关系**——这个节点下面有哪些节点，从根到它经过哪些节点，它和另一个节点最近的共同祖先是谁。位置和键都不能表达“谁包含谁”。

> **关键认知：** 树不是“更高级的数组”，而是把“包含/分层”直接写进引用关系的不变量；用线性结构表达层级时，层级一旦变化，额外约定的维护成本会迅速超过数据结构本身的收益。

## 树的术语与度量

### 基本术语

一棵树是递归定义的：它要么是**空树**，要么由一个**根节点（root）**和若干棵互不相交的**子树（subtree）**组成。子树有唯一的**父节点（parent）**，父节点可以有零个或多个**孩子（child）**；没有孩子的节点叫**叶子（leaf）**。二叉树（binary tree）每个节点最多两个孩子，并且左、右**有序**——交换左右子树是另一棵树，这也是三种遍历顺序有意义的前提。节点数和边数之间有一条恒等式：含 n 个节点的树恰好有 n−1 条边（删根得到若干子树，把子树边数相加再加根到各子树根的边即可归纳）；含 k 个连通分量的森林则有 n−k 条边。树本身就是一种特殊的图（连通且无环），图的遍历与最短路见[图](./08-图.md)。

### 深度与高度：先把口径说死

**深度（depth）**：从根往下数，根节点深度为 0，某节点的深度是它到根的边数；**高度（height）**：从叶往上数，叶节点高度为 0，某节点的高度是它到最深后代叶子的边数，整棵树的高度就是根的高度。

同一棵树在这套“边数口径”下，空树高度为 **−1**，单节点树高度为 0。很多教材和题目采用“节点数口径”（空树高度 0、单节点树高度 1），两种口径只差 1，本身没有对错，**错的是在同一段代码里混用**。本文所有算法统一使用边数口径；遇到 LeetCode 等平台按题目定义为准。

> **关键认知：** 高度和深度是相对定义，不是绝对量；使用前必须声明“从哪个方向数、空树取什么值”，否则 `height(left) - height(right)` 这类比较会整体偏移，平衡判断和 `+1` 的位置都会出错。

### 满、完美与完全

这三个词在不同教材里的口径不一致，最典型的是“满二叉树”：

| 名称（英文） | 定义 | 数量关系 | 典型用途 |
|---|---|---|---|
| 满二叉树（full） | 每个节点要么是叶，要么有两个孩子 | 叶数 = 内部节点数 + 1 | 表达式树、Huffman 树的形态 |
| 完美二叉树（perfect） | 每一层都填满 | 高度 h 时节点数 = $2^{h+1}-1$ | 理论分析、分治递归树 |
| 完全二叉树（complete） | 除最后一层外全满，最后一层从左到右连续排列 | n 个节点时高度 = $\lfloor \log_2 n \rfloor$ | 堆的数组表示（见[堆与优先队列](./07-堆与优先队列.md)）|

注意：中文教学材料里的“满二叉树”通常指每层都填满，对应英文的 **perfect**；英文教材（如 CLRS）的 **full** 指每个节点 0 或 2 个孩子。看到题目里的“满二叉树”先确认按哪种口径。

完全二叉树不用指针也能存：按层从上到下、从左到右编号成数组下标，父子关系是纯算术：

```dart
/// 完全二叉树用 0 起始下标存储时的父子下标公式。
int parentIndex(int index) => (index - 1) ~/ 2;
int leftChildIndex(int index) => 2 * index + 1;
int rightChildIndex(int index) => 2 * index + 2;
```

不需要存任何链接，数组下标本身就编码了结构；代价是“完全”这个形状约束必须由插入删除逻辑维持，堆就建立在这条性质上。

> **面试高频：** 完全二叉树为什么适合用数组存？
> **答题脉络：** 形状没有空洞 → 按层编号连续 → 父子下标用算术式互推 → 省掉两个指针，访问连续内存。
> **追问方向：** 普通二叉树数组存储要浪费多少空间；堆的插入删除如何维持“完全”形状（链接 `07`）。

## Dart 节点表示

树在内存里就是一组通过引用相连的对象。Dart 没有“通用多叉树”标准容器（[dart:collection 容器清单](https://api.dart.dev/dart-collection/dart-collection-library.html)，核查日期：2026-09）；算法题中的二叉树自行建模即可。一个最小节点只需要值和左右链接：

```dart
/// 二叉树节点：只保留算法题常用的 value/left/right 三个字段。
class TreeNode<T> {
  TreeNode(this.value);

  T value;
  TreeNode<T>? left;
  TreeNode<T>? right;
}

/// 构造本文反复使用的样例树：
///      1
///     / \
///    2   3
///   / \   \
///  4   5   6
TreeNode<int> buildSampleTree() {
  final root = TreeNode<int>(1);
  root.left = TreeNode<int>(2);
  root.right = TreeNode<int>(3);
  root.left!.left = TreeNode<int>(4);
  root.left!.right = TreeNode<int>(5);
  root.right!.right = TreeNode<int>(6);
  return root;
}
```

<!-- verify: .work/verify/A06/tree_basics.dart -->

空树就直接用 `null` 表示：不制造“空对象”，也让所有递归函数的第一个分支统一成“`node == null` 怎么办”。`left`/`right` 的类型写成 `TreeNode<T>?`，编译器会强制你在解引用前处理空值。节点默认的 `==` 是**引用身份**比较：两个值都是 42 的节点不相等，除非它们是同一个对象；LCA、交点这类题都依赖身份。多一个 `parent` 指针能让“向上走”变简单，但会带来存储开销与双向一致性维护成本，算法题里通常省掉它，需要回溯路径时用显式栈记录祖先链。

> **关键认知：** 空树用 `null` 根表示，节点比较默认是引用身份；凡是声称“两棵树相等/相交”的代码，先确认比较的到底是值还是对象。

## 深度优先遍历

树的递归定义天然对应递归遍历：处理当前节点，再递归处理两棵子树。三种顺序的区别只有一个——**在什么时机访问根**：

```dart
/// 前序：进入节点时访问，再处理左右子树。
List<T> preorder<T>(TreeNode<T>? root) {
  final result = <T>[];
  void visit(TreeNode<T>? node) {
    if (node == null) return;
    result.add(node.value);
    visit(node.left);
    visit(node.right);
  }

  visit(root);
  return result;
}

/// 中序：左子树处理完再访问，然后处理右子树。
List<T> inorder<T>(TreeNode<T>? root) {
  final result = <T>[];
  void visit(TreeNode<T>? node) {
    if (node == null) return;
    visit(node.left);
    result.add(node.value);
    visit(node.right);
  }

  visit(root);
  return result;
}

/// 后序：左右子树都处理完才访问。
List<T> postorder<T>(TreeNode<T>? root) {
  final result = <T>[];
  void visit(TreeNode<T>? node) {
    if (node == null) return;
    visit(node.left);
    visit(node.right);
    result.add(node.value);
  }

  visit(root);
  return result;
}
```

<!-- verify: .work/verify/A06/traversal_dfs.dart -->

对样例树，三种顺序分别是前序 `[1, 2, 4, 5, 3, 6]`、中序 `[4, 2, 5, 1, 3, 6]`、后序 `[4, 5, 2, 6, 3, 1]`。三种顺序都遍历 n 个节点，时间复杂度 O(n)；递归栈的额外空间是 O(h)，h 为树高。访问时机的差别决定了用途：

- **前序**：访问节点时还没有任何子树信息，适合“传递下去”的任务——复制树、序列化、打印目录结构。
- **中序**：访问节点时左子树已经处理完，适合 BST 的有序遍历，以及把表达式树还原成中缀形式。
- **后序**：访问节点时两棵子树都已处理完，适合“汇总上来”的任务——求高度、求子树和、释放节点、自底向上判断性质。

> **关键认知：** 遍历顺序不会改变节点集合，只改变访问时机；节点被访问时“子树信息是否就绪”才是选择顺序的依据。另外，中序序列有序是 BST 不变量带来的结果，普通二叉树的中序没有任何排序保证。

### 递归转显式栈

递归深度受运行平台栈资源限制，Dart 也未承诺跨平台固定的递归深度上限（本文在 Dart 3.12.2 原生 VM 上验证，[核查日期：2026-09]）。输入可能是深链时，可以用显式栈替代递归。中序的写法是：一路向左把沿途节点压栈，弹栈时访问，再转向右子树：

```dart
/// 显式栈中序：先把左链整体压栈，弹栈时访问，再转向右子树。
List<T> inorderIterative<T>(TreeNode<T>? root) {
  final result = <T>[];
  final stack = <TreeNode<T>>[];
  var current = root;
  while (current != null || stack.isNotEmpty) {
    // 1. 一路向左，把沿途节点记在栈里。
    while (current != null) {
      stack.add(current);
      current = current.left;
    }
    // 2. 栈顶是当前最左、最早该访问的节点。
    final node = stack.removeLast();
    result.add(node.value);
    // 3. 处理它的右子树，下一轮循环继续向左。
    current = node.right;
  }
  return result;
}
```

<!-- verify: .work/verify/A06/traversal_dfs.dart -->

栈里保存的始终是“还没访问根、但左子树已经走到底”的祖先链，这就是这段代码的不变量。前序只要把“压栈顺序”改成先右后左；后序可以先按“根→右→左”前序遍历，最后反转结果。还存在 O(1) 额外空间的 Morris 遍历，但它要临时改写指针，正确性推理更重，生产代码很少直接用。

> **面试高频：** 三种 DFS 顺序分别在什么场景用？
> **答题脉络：** 先问“访问节点时子树信息是否已就绪”→ 前序向下传递、中序用于有序序列、后序向父节点汇总。
> **追问方向：** 中序转迭代的栈不变量；前序+中序如何重建树；后序为什么可以用“反转的前序”实现。

## 广度优先与层序遍历

深度优先顺着一条路径走到底；广度优先（Breadth-First Search，BFS）则一层一层向外扩。它用队列（先进先出）实现：出队一个节点，把它的孩子依次入队。要按层分组，就在每轮循环开始时记下队列长度——这一批恰好是同一层：

```dart
/// 层序遍历：每一轮只处理当前队列里已有的节点，它们恰好是同一层。
List<List<T>> levelOrder<T>(TreeNode<T>? root) {
  final levels = <List<T>>[];
  if (root == null) return levels;
  final queue = Queue<TreeNode<T>>()..add(root);
  while (queue.isNotEmpty) {
    final level = <T>[];
    // 1. 先记下这一层的节点数；循环里新加进来的是下一层。
    for (var remaining = queue.length; remaining > 0; remaining--) {
      final node = queue.removeFirst();
      level.add(node.value);
      if (node.left != null) queue.add(node.left!);
      if (node.right != null) queue.add(node.right!);
    }
    levels.add(level);
  }
  return levels;
}
```

<!-- verify: .work/verify/A06/traversal_bfs.dart -->

样例树的层序结果是 `[[1], [2, 3], [4, 5, 6]]`。BFS 的额外空间是 O(w)，w 为最大层宽；DFS 是 O(h)。链状树适合 DFS（队列只需 O(1)），星形树适合 BFS（栈只需 O(1)）——“哪种遍历更省空间”取决于树的形状，不能一概而论。层序适合“每层单独处理”的问题（每层平均值、右视图）和找“最近的”目标（最小深度），注意 Dart 的 `List.removeAt(0)` 是 O(n)，队列必须用 `dart:collection` 的 `Queue.removeFirst()`，否则总复杂度会退化到 O(n²)。

> **关键认知：** BFS 按“到根的距离”分层，第一次遇到目标节点时的层数就是最少边数；DFS 只保证遍历完，不保证路径最短。无权图最短路之所以用 BFS，正是这条性质。

## 二叉搜索树

线性结构的两难在 BST 上得到统一：BST 在二叉树上加一条不变量——**对每个节点，左子树中所有键都小于它，右子树中所有键都大于它**。这是一条**子树级**的界，不只是和直接孩子比较：只保证“左孩子 < 根 < 右孩子”的实现，可能让隔了几层的节点落在错误区间里。BST 的第二个常用性质可以直接由定义推出：**中序遍历序列严格递增**；反过来，需要“按序输出”时中序就是现成的。

**重复键必须先声明策略**：可以让右子树接受等值键、可以在节点里加计数字段、也可以拒绝重复插入。策略不同，中序序列（允许重复 vs 严格递增）、`rank` 和 `floor` 的含义都会变化。本文选择“拒绝重复插入”，保证中序严格递增，让后续每个操作都有唯一答案。下面三段代码取自 `bst.dart` 的类实现：为便于阅读去掉了类内缩进，并省略了 `size`/`isEmpty` 等辅助成员；完整文件与断言见块后的隐藏映射。

```dart
class BstNode<T> {
  BstNode(this.key);

  final T key;
  BstNode<T>? left;
  BstNode<T>? right;

  /// 以该节点为根的子树节点数；rank() 依赖它把代价压到 O(h)。
  int count = 1;
}

class BinarySearchTree<T extends Comparable<Object?>> {
  BstNode<T>? _root;

  /// 插入键；键已存在时保持原树不动并返回 false。
  bool insert(T key) {
    final result = _insert(_root, key);
    _root = result.node;
    return result.inserted;
  }

  ({BstNode<T>? node, bool inserted}) _insert(BstNode<T>? node, T key) {
    if (node == null) {
      // 1. 走到空位：新节点只会挂在这里，这里也是查找未命中的落点。
      return (node: BstNode<T>(key), inserted: true);
    }
    final comparison = key.compareTo(node.key);
    if (comparison < 0) {
      // 2. 递归插入左子树，再用返回值更新链接。
      final result = _insert(node.left, key);
      node.left = result.node;
      if (result.inserted) node.count++;
      return (node: node, inserted: result.inserted);
    }
    if (comparison > 0) {
      final result = _insert(node.right, key);
      node.right = result.node;
      if (result.inserted) node.count++;
      return (node: node, inserted: result.inserted);
    }
    // 3. 重复键策略：不覆盖、不新建，保证中序序列严格递增。
    return (node: node, inserted: false);
  }
}
```

“插入 = 未命中查找 + 在落点挂新节点”是最容易记的模型：查找走到空链接的位置，就是插入位置。递归函数把“更新后的子树根”作为返回值交给上一层，调用方重新挂链接，这也是树结构修改类操作的通用写法。查到节点后不要覆盖它，`BstNode.key` 声明为 `final` 就是在类型层面阻止“改键破坏不变量”。搜索、求最小/最大键都是沿一条路径走到底的循环：最小键就是最左节点，最大键就是最右节点，时间复杂度都是 O(h)。

`floor` 和 `rank` 展示“BST 的结构信息”能换到什么：

```dart
/// 小于等于 key 的最大键；不存在这样的键时返回 null。
T? floor(T key) {
  BstNode<T>? candidate;
  var node = _root;
  while (node != null) {
    final comparison = key.compareTo(node.key);
    if (comparison == 0) return node.key;
    if (comparison < 0) {
      // 1. 当前键太大，floor 只可能在左子树。
      node = node.left;
    } else {
      // 2. 当前键是候选；右子树里也许还有更接近 key 的键。
      candidate = node;
      node = node.right;
    }
  }
  return candidate?.key;
}
```

```dart
/// rank(key)：严格小于 key 的键个数，也是 key 在有序序列中的插入位置。
int rank(T key) {
  var node = _root;
  var less = 0;
  while (node != null) {
    final comparison = key.compareTo(node.key);
    if (comparison <= 0) {
      // 当前键不小于 key，不计入。
      node = node.left;
    } else {
      // 左子树与当前节点都小于 key，整批记入。
      less += 1 + _count(node.left);
      node = node.right;
    }
  }
  return less;
}
```

`rank` 之所以能保持 O(h)，靠的是每个节点缓存的子树节点数 `count`；如果每次都现场统计左子树大小，最坏会退化到 O(n)。`ceiling`（大于等于 key 的最小键）与 `floor` 完全对称；需要“第 k 小”时，比较 `count(left)` 与 k 就能一次下行找到目标，这也是[知识点应用](#知识点应用)里 230 题的另一种解法。

删除分成三种形态，前两种很直接，第三种需要一次“位置替换”（下面是 `_delete` 命中后的分支，保留原缩进）：

```dart

    if (node.left == null) return (node: node.right, deleted: true);
    if (node.right == null) return (node: node.left, deleted: true);
    // 3. 两个孩子：用右子树最小键（中序后继）顶替位置。
    final successor = _minNode(node.right)!;

    successor.left = node.left;
    _refreshCount(successor);
    return (node: successor, deleted: true);
```

为什么是“右子树的最小键”？它是中序序列中紧接着被删键的那个键（中序后继），让它站到被删节点的位置，所有左子树键仍小于它、剩余右子树键仍大于它，不变量保持成立；对称地也可以用左子树的最大键（中序前驱）顶替。`search`、`insert`、`min`、`floor`、`rank`、`delete` 的时间都是 O(h)：平衡时 O(log n)，最坏退化成链时 O(n)，下一节解释“平衡”如何给这个最坏值封顶。

> **关键认知：** BST 的正确性来自“整棵子树都在同一区间内”这一不变量，而增删改查的运行时间全部由树高决定；删除操作只恢复不变量，**不负责**恢复平衡。固定的“总用后继顶替”策略不对称，Culberson 证明足够多轮随机插入与 Hibbard 删除后，平均查找路径长度会退化为 $\Theta(\sqrt{n})$（见 [R6]）。

> **面试高频：** BST 删除有两个孩子的节点，为什么要找中序后继？
> **答题脉络：** 删除后要同时满足两条不变量 → 后继是右子树最小值，能切在左小右大的分界上 → 用 `deleteMin` 从右子树拿走它并接上剩余部分。
> **追问方向：** 用前驱顶替是否可行；为什么删除会让 BST 失去平衡；`count` 字段如何在删除路径上更新。

## 树高与平衡

按从小到大顺序往 BST 里插键，每次新键都挂在最右边，树退化成一条链：6 个键的树高就是 5，所有操作从 O(log n) 变成 O(n)。形状不由操作者控制，而由**插入顺序**控制——这是普通 BST 最大的不稳定来源。

先看两个不需要平衡就能得出的界。含 n 个节点的二叉树，高度 h 满足：

- 高度 h 的二叉树的上界来自链：$h \le n-1$；下界来自每层容量：第 0 层最多 1 个节点、第 1 层最多 2 个……最多有 $2^{h+1}-1$ 个节点，因此 $n \le 2^{h+1}-1$，即 $h \ge \lceil \log_2(n+1) \rceil - 1$。

下界说明：**任何**二叉树都至少有对数高度，但上界完全不受控。平衡树的思路，是人为限制高度，让 h 落在 $\Theta(\log n)$：

- **AVL 树**：每个节点左右子树高度差不超过 1。严格的高度平衡换来计算上的保证：高度不超过约 $1.44\log_2(n+2)$（Weiss 教材给出该界）。
- **红黑树**：用颜色约束“最长路径不超过最短路径的两倍”。含 n 个内部节点的红黑树高度至多 $2\log_2(n+1)$（CLRS 引理 13.1），界比 AVL 松，但插入删除时触发重构的次数更少。
- **2-3 查找树**：允许节点存 2 个键、带 3 个孩子，插入时通过“分裂上移”维持所有叶在同一深度。Sedgewick 教材用 2-3 树到左倾红黑树的一一对应来解释红黑树的平衡机制。

这些结构的恢复动作都是**旋转**和**颜色/分裂调整**：某个局部高度差超标时，用常数次指针改写把超标“转”到别处，代价沿插入/删除路径展开，总成本与树高同阶。本文不展开完整实现：工程中要的是“动态有序集合”这个能力，直接用现成实现。

> **关键认知：** “平衡”不是让树变成最优形状，而是给最坏高度封顶，使操作的复杂度不再被插入顺序支配；代价是每次修改后要花 O(log n) 时间做局部重整。

> **面试高频：** 为什么平衡树能把查找锁在 O(log n)？
> **答题脉络：** 高度每加 1，节点数至少按几何级数增长（AVL 用 Fibonacci 式递推，红黑树靠黑色高度） → n 的下界反过来给 h 上界 → 操作成本 O(h) 变成 O(log n)。
> **追问方向：** AVL 与红黑树谁的常数更小；为什么红黑树的界是 $2\log_2(n+1)$；平衡在删除后如何恢复。

## 自底向上的树形计算

树的问题里有一大类是“汇总”型的：求高度、判断平衡、求子树和、求直径、找 LCA。它们有一条共同套路：**后序返回子树的摘要，父节点只做常数次合并**。

以“判断高度平衡”为例。错误做法有两种：只看根节点高度差（内层可能已不平衡），以及对每个节点重新求一次子树高度（同一批节点被反复访问）。正确做法是一次后序，让每个节点只被访问一次：

```dart
/// 自底向上版本：一次后序遍历，O(n)。
({int height, bool balanced}) subtreeInfo(TreeNode<int>? node) {
  bottomUpCalls++;
  if (node == null) return (height: -1, balanced: true);
  final left = subtreeInfo(node.left);
  if (!left.balanced) return (height: -1, balanced: false);
  final right = subtreeInfo(node.right);
  if (!right.balanced) return (height: -1, balanced: false);
  final height = 1 + (left.height > right.height ? left.height : right.height);
  return (height: height, balanced: (left.height - right.height).abs() <= 1);
}
```

<!-- verify: .work/verify/A06/balanced_tree.dart -->

返回值是 Dart 3 的记录类型，包含两个字段：子树高度和“子树是否平衡”。一旦某棵子树传回不平衡，上层直接短路，不再关心具体高度。验证文件里的计数对比很直观：退化链上“自上而下”版本做了 12 次高度计算，后序版本只需 10 次节点访问；换成 15 个节点的完美二叉树，差距变成 98 次对 31 次——重复求高度的写法会随树规模迅速放大。

“返回复合状态”和“共享一个全局变量”是两种可选风格。全局变量（或类字段）省掉了元组打包，但把隐含状态带进了函数，递归中途出错、并发复用或单元测试时都更难隔离；返回记录是纯函数，多写一个字段换来可测试性。算法题里还有一种折中：用不可能出现的哨兵值表示“已经失败”，例如高度用 −1 表示不平衡，让返回值退化成单个整数；前提是这个值永远不会和合法结果冲突。

> **关键认知：** 后序返回值的含义是“这棵子树的摘要”；父节点只做常数次合并，因此整棵树 O(n)。自上而下反复向子树“问同样的问题”，本质是把同一个摘要算了很多遍。

## 什么时候用，什么时候别用

适合用树：数据本身有层级或包含关系（目录、分类、DOM、表达式）；需要动态维护有序键集合，并且要前驱/后继、排名区间、最小/最大；问题可以按“同类子问题”递归分解，且需要自底向上合并信息。不适合用树：只需要等值查找时哈希表更直接（链接[哈希表](./05-哈希表.md)）；数据静态且已排序时数组加二分即可（链接[查找与二分查找](./10-查找与二分查找.md)）；一次性的层级转换（比如把嵌套 JSON 拍平成列表）用显式栈或现成序列化工具通常更短；为了面试题手写完整平衡树之前，先写清楚“要支持哪些操作”。

Dart 工程里需要“有序映射”时，`dart:collection` 已经提供了基于自调整二叉搜索树的 `SplayTreeMap` 与 `SplayTreeSet`，支持按键有序迭代、首尾键和前后驱查询（[SplayTreeMap API 文档](https://api.dart.dev/dart-collection/SplayTreeMap-class.html)，核查日期：2026-09）；下面从 `ordered_map.dart` 中摘取演示这些能力的函数，自定义比较器的演示在文件其余部分：

```dart
/// 演示 SplayTreeMap/SplayTreeSet 的按键有序特性。
void demoOrderedMap() {
  // 1. 迭代顺序按键排序，而不是插入顺序。
  final ranking = SplayTreeMap<String, int>();
  ranking['banana'] = 2;
  ranking['apple'] = 1;
  ranking['cherry'] = 3;
  _check(ranking.keys.join(',') == 'apple,banana,cherry', '迭代顺序按键排序');

  // 2. 有序结构支持前驱/后继式查询。
  _check(ranking.firstKey() == 'apple' && ranking.lastKey() == 'cherry', '首尾键');
  _check(ranking.firstKeyAfter('apple') == 'banana', '后继键');
  _check(ranking.lastKeyBefore('cherry') == 'banana', '前驱键');

  // 3. SplayTreeSet 同理：集合元素按键有序迭代。
  final orderedSet = SplayTreeSet<int>()
    ..add(3)
    ..add(1)
    ..add(2);
  _check(orderedSet.join(',') == '1,2,3', '有序集合');
}
```

## 常见坑与边界

- **高度口径混用**：边数与节点数两套口径相差 1，空树取 −1 还是 0 也会整体偏移；写代码前先声明，并在测试里覆盖空树和单节点。
- **忘记空树**：所有递归/迭代入口先处理 `null`；`nodeCount(null)`、`height(null)`、`inorder(null)` 都应是合法输入。
- **BST 重复键没有策略**：不声明就等于把中序、`floor`、`rank` 的语义交给实现细节；要么拒绝重复，要么显式计数。
- **平衡判断只查根节点**：`|height(left) − height(right)| ≤ 1` 只验证了根，内层子树可能早已失衡；必须对每个节点成立。
- **重复求子树高度**：自上而下写法让同一子树被反复遍历；用后序一次返回摘要（见[自底向上的树形计算](#自底向上的树形计算)）。
- **递归爆栈**：链状输入递归深度等于 n；Dart 未承诺跨平台递归深度上限，输入形状不可控时改用显式栈。
- **遍历重建的前提**：前序 + 中序、后序 + 中序在键互不相同时能唯一重建；前序 + 后序一般不能，值有重复时中序也无法区分同值节点。
- **节点身份与值混淆**：LCA、交点等题要用 `identical`；默认 `==` 是身份比较，重写 `==` 时要同步维护 `hashCode`。
- **BFS 的性能陷阱**：用 `List` 当队列并反复 `removeAt(0)` 会退化成 O(n²)，应使用 `Queue.removeFirst()`；忘记“层边界快照”则拿不到分层结果。
- **修改 BST 的键**：`BstNode.key` 设为 `final` 就是防止“改键破坏不变量”；需要换键时先删后插。

### LeetCode 94：二叉树的中序遍历

递归版直接复用[深度优先遍历](#深度优先遍历)的框架；显式栈版本见同节。边界是空树与偏斜树：

```dart
/// LeetCode 94：二叉树的中序遍历（递归版）。
List<int> inorderTraversal(TreeNode<int>? root) {
  final result = <int>[];
  void visit(TreeNode<int>? node) {
    if (node == null) return;
    visit(node.left);
    result.add(node.value);
    visit(node.right);
  }

  visit(root);
  return result;
}
```

/// LeetCode 110：判断二叉树是否高度平衡（自底向上，O(n)）。

### LeetCode 230：BST 中第 k 小的元素

利用 BST 的中序有序性：中序遍历的第 k 个节点就是答案。用显式栈边遍历边计数，找到后立即返回，时间 O(h + k)、空间 O(h)。函数契约要写清 `k` 从 1 开始，越界抛 `RangeError`：

```dart
/// LeetCode 230：BST 中第 k 小的键（k 从 1 开始；越界抛 RangeError）。
int kthSmallest(TreeNode<int>? root, int k) {
  if (k < 1) throw RangeError('k 必须从 1 开始，实际为 $k');
  var remaining = k;
  final stack = <TreeNode<int>>[];
  var current = root;
  while (current != null || stack.isNotEmpty) {
    while (current != null) {
      stack.add(current);
      current = current.left;
    }
    final node = stack.removeLast();
    remaining--;
    if (remaining == 0) return node.value;
    current = node.right;
  }
  throw RangeError('k=$k 超出节点个数');
}
```

### LeetCode 236：二叉树的最近公共祖先

后序返回“在这棵子树里找到了什么”：两边各找到一个 p 或 q，当前节点就是分叉点；只找到一边就把结果上交。节点比较必须用身份（`identical`）。题目保证 p、q 都存在于树中；若这个前提不成立，返回值的含义会变，需要额外约定：

```dart
/// LeetCode 236：二叉树最近公共祖先；题设保证 p、q 都存在于树中。
TreeNode<int>? lowestCommonAncestor(
  TreeNode<int>? root,
  TreeNode<int> p,
  TreeNode<int> q,
) {
  if (root == null || identical(root, p) || identical(root, q)) return root;
  final left = lowestCommonAncestor(root.left, p, q);
  final right = lowestCommonAncestor(root.right, p, q);
  if (left != null && right != null) return root;
  return left ?? right;
}
```

## 面试考点与追问

> **面试高频：** 递归遍历怎么改成显式栈？
> **答题脉络：** 明确栈里存什么不变量（中序：尚未访问根的祖先链）→ 循环“向左走到底 → 弹栈访问 → 转向右子树” → 前序调换压栈顺序、后序反转“根右左”结果。
> **追问方向：** 为什么不直接把后序压栈反转；Morris 遍历为什么能 O(1) 空间；栈的最大深度是多少。

> **面试高频：** AVL 树与红黑树怎么取舍？
> **答题脉络：** 先比平衡松紧（AVL 更严，查询路径更短）→ 再比重构次数（红黑树插入删除旋转更少）→ 按读写比例选择，工程库实现中红黑树及其变体更常见。
> **追问方向：** 为什么红黑树高度上界是 2·log₂(n+1)；2-3 树与左倾红黑树的对应；删除在两种结构里的代价差。

> **面试高频：** 普通二叉树的 LCA 与 BST 的 LCA 有什么不同？
> **答题脉络：** 普通二叉树没有顺序信息，只能自底向上收集“找到了谁”；BST 可以直接用区间比较：两个键都小于当前键去左、都大于去右、否则当前节点就是分叉点。
> **追问方向：** 普通树版本为什么必须保证 p、q 存在；BST 版本能否迭代写；带 parent 指针时如何改成“两条链求交点”。

## 小结

树用引用表达层级，术语口径（高度/深度、空树取值）必须先声明；遍历顺序决定访问节点时哪些子树信息已经就绪；BST 用“整棵子树落在同一区间”的不变量换取有序操作，但复杂度由树高决定；平衡树的职责只是给最坏高度封顶；自底向上的后序计算则让每个子树的摘要只被合并一次。
