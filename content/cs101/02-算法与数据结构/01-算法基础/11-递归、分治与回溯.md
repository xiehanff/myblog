# 算法与数据结构｜递归、分治与回溯

打开一份嵌套 JSON 统计叶子节点数量，遍历一棵二叉树，算出一个目录占用的总空间——这些任务的代码往往都写成"函数调用自己"。原因不是递归更高级，而是这些结构本身就是自相似的：整棵树由更小的同种子树拼成，整个表达式由更小的子表达式拼成。

能读懂递归和能写对递归却是两件事。漏掉基线会无限递归；`result.add(path)` 与 `result.add(List.of(path))` 的差别会让几乎所有结果退化成空列表；把 DFS、分治、回溯和动态规划都叫"递归题"，就会在该缓存的时候继续写指数级搜索，在该输出全部方案的时候反而去套一个求最优值的模型。

本文按"递归为什么能描述自相似结构 → 写对递归的三个条件 → 递归的成本与迭代替代 → 分治 → 回溯 → 去重与剪枝 → 与记忆化、动态规划的边界"推进，最后用四道题演示从题目到范式的映射，并把每个复杂度的成立前提写清楚。

## 为什么递归适合描述自相似结构

先看"自相似"具体指什么。以下任务里，整体和部分是同一种东西：

- 二叉树：每个节点要么是叶子，要么挂着两棵二叉树；目录树里每个目录又是目录或文件。
- 算术表达式：`2*3-4*5` 的左右两侧又是算术表达式。
- 链表：每个节点的 `next` 又是一条链表（可能是空的），节点模型见 [链表](./03-链表.md)。

对这类结构，"整棵树有多少节点"与"子树有多少节点"是同一种问题，只是规模不同。递归正是把这种关系直接写进代码：**函数的参数描述一个完整任务，函数体内只处理当前这一层，剩下的交给规模更小的同一次调用。**

汉诺塔把这件事展示得最清楚。任务契约是"把 n 个圆盘从 `from` 柱经 `buffer` 柱搬到 `to` 柱"：先把上面 n-1 个盘子按同一契约搬到中转柱，再搬走最大的盘子，最后把这 n-1 个盘子按同一契约搬到目标柱。两次搬运都不需要重新想"怎么搬"，因为契约已经描述了全部要求。写递归时常用一句话概括这种信任：**假设更小规模的问题已经被解决，我只需要正确地拼装它的结果。**这与数学归纳法中的归纳假设是同一个东西。

递归的执行方式也由此确定：每次调用压入一个栈帧（参数、局部变量、返回位置），一次调用返回后才继续执行同一层的后续代码；整批调用构成一棵调用树，执行顺序是树上的深度优先遍历，而"当前在哪一层、这一层的现场是什么"由调用栈隐式保存。

> **关键认知：** 递归不是循环的花哨写法：循环描述"状态如何逐步演变"，递归描述"问题如何分解为更小的同类问题"；调用栈只是这种分解的执行方式。

## 写对递归的三个条件

### 基线：最小规模能直接给出答案

递归必须在某个规模上停下，并直接返回结果。汉诺塔的基线是"只剩一个盘子"，斐波那契的基线是 `n < 2`。

基线还有一个更隐蔽的要求：**判据必须与问题的结构一致。**在"按任意顺序给表达式加括号"（LeetCode 241）里，很自然会写成"表达式长度为 1 时返回它本身"，但输入可能是多位数 `10`：长度为 2，却没有任何运算符可切分。正确的基线不是"长度为 1"，而是"没有运算符"，此时整段就是一个数。

### 规模严格缩小：每次递归都朝基线推进

递归调用必须作用在严格更小的规模上。汉诺塔里是 `n - 1`，二分里是区间长度减半；需要留意的正是"看起来在缩小、实际没有"的写法：参数没变、区间端点没动、只缩小了输出而不缩小输入。只要存在一个良基的度量（圆盘个数、区间长度、剩余字符数）在每次调用中严格减少，终止性就有保证；反之，即使程序在某组输入上跑得通，也说明不了它会终止。

### 由子问题构造当前答案：返回值契约明确

递归函数必须回答"我给调用者什么"。汉诺塔打印移动步骤，它的契约是副作用；斐波那契返回数值，它的契约是计算结果；后面的回溯不返回值，而是把方案写进结果集。参数含义与返回值约定一旦写清，"怎么拼装"就是局部的工程问题，而不是全盘猜测。

下面是汉诺塔：契约写在签名上，基线写在最前面，两次同规模调用加一次搬运拼出当前答案。

```dart
// 前置条件：Dart 3.x；纯 Dart；无第三方运行时依赖；断言需用 `dart run --enable-asserts` 启用。
// 汉诺塔：把 n 个圆盘从 from 柱经 buffer 柱搬到 to 柱，小盘必须始终压在大盘之上。

final List<String> moves = <String>[];

void hanoi(int n, String from, String buffer, String to) {
  // 1. 基线：只有一个盘子时不需要再分解，直接搬走。
  if (n == 1) {
    moves.add('$from->$to');
    return;
  }
  // 2. 先把上面 n-1 个盘子挪到中转柱，露出最大的盘子。
  hanoi(n - 1, from, to, buffer);
  // 3. 搬走最大的盘子。
  hanoi(1, from, buffer, to);
  // 4. 再把 n-1 个盘子搬到目标柱，落在最大盘子上面。
  hanoi(n - 1, buffer, from, to);
}
```

计算 2^n − 1 的辅助函数、`main` 与断言见 companion file 的第 20–40 行。在 Dart 3.12.2（Windows x64）上实测：n = 3 的移动序列是 `A->C, A->B, C->B, A->C, B->A, B->C, A->C`，共 7 次，第一次与最后一次都在搬最小的盘子。

移动次数可以严格推出。设最少需要 M(n) 次：要把最大的盘子从 `from` 搬到 `to`，它上面的 n-1 个盘子必须先全部离开这两根柱子，即至少 M(n-1) 次；最大盘至少搬一次；落地后另外 n-1 个盘子还要全部搬到它上面，又至少 M(n-1) 次。于是 M(n) ≥ 2·M(n-1) + 1 且 M(1) = 1，解得 M(n) ≥ 2^n - 1；上面的三步算法正好达到这个下界，所以**移动次数是 2^n - 1，任何算法都不可能更少**。时间与调用次数同阶（Θ(2^n)），空间是 O(n) 的调用栈。

这里还有一个容易忽略的表示边界：n = 64 时移动次数是 2^64 - 1，超过 Dart Native 上 64 位有符号 `int` 的范围（−2^63 … 2^63 − 1），`(1 << n) - 1` 会回绕成错误的值（`assert((1 << 63) < 0)` 验证了这一点）；Web 平台上 `int` 的精确范围只到 ±(2^53 − 1)。

> **关键认知：** 递归的正确性来自归纳法：基线直接正确，每一步在当前层只做拼接；缺了基线或规模没有严格缩小，再多测试也只能证明"某些输入没崩"。

> **面试高频：** 递归的三要素是什么？怎么证明一个递归不会无限调用？
> **答题脉络：** 先讲契约（参数描述什么任务、返回什么）→ 再给基线及它的判据来源 → 再说明每次调用都在某个良基度量上严格变小，从而终止 → 最后指出归纳法与调用树是同一件事的两种说法。
> **追问方向：** 基线的判据为什么不总是"规模为 1"、互递归的终止性、分支数大于 1 时"每支都缩小"是否足够。

## 递归的成本与迭代替代

递归的代价由三个互不相同的量组成：**调用次数**（调用树节点总数，决定时间与函数调用开销）、**每层工作量**（扫描区间、拷贝列表、组合结果等）、**最大深度**（调用栈最深时的层数，决定额外空间）。混成一个就会算错。

用朴素递归计算斐波那契（`fib(n) = fib(n-1) + fib(n-2)`）在实测中很直观：`fib(20)` 一共调用了 **21891** 次（= 2·fib(21) − 1），但栈最深只有 **20** 层调用；也就是说，"调用次数爆炸"和"栈爆炸"是两件事。把同样的式子加上缓存后，`fib(20)` 只需要 39 次调用，`fib(90)` 也只要 179 次——调用次数从指数级降到了与 n 同阶。

```dart
// 前置条件：Dart 3.x；纯 Dart；无第三方运行时依赖；断言需用 `dart run --enable-asserts` 启用。
// 比较朴素递归与记忆化递归的调用次数和最大深度。

int naiveCalls = 0;
int maxDepth = 0;

/// 朴素斐波那契：每个调用都展开两棵子树，depth 用于记录当前栈深度。
int fibNaive(int n, int depth) {
  naiveCalls++;
  if (depth > maxDepth) maxDepth = depth;
  if (n < 2) return n;
  return fibNaive(n - 1, depth + 1) + fibNaive(n - 2, depth + 1);
}

final Map<int, int> memo = <int, int>{};
int memoCalls = 0;

/// 记忆化斐波那契：每个 n 只真正计算一次。
int fibMemo(int n) {
  memoCalls++;
  final cached = memo[n];
  if (cached != null) return cached;
  final value = n < 2 ? n : fibMemo(n - 1) + fibMemo(n - 2);
  memo[n] = value;
  return value;
}
```

计数与断言见 companion file 的第 28–54 行。这里第一次出现"同一个子问题被反复求解"，它是记忆化与动态规划的入口：缓存键就是参数 `n`，因为 `fib(n)` 的答案只由 `n` 决定，与"它是被谁调用的"无关。

**其一，递归的额外空间按最大深度计，而不是按调用次数计。**等价的说法是：递归的空间复杂度等于调用树的高度（乘以每层局部变量的规模），输出与缓存不计在内。汉诺塔是 O(n)，二分是 O(log n)，而 `fib(20)` 的 21891 次调用只需要 20 层栈。

**其二，递归式是估算时间的标准工具。**像 `T(n) = 2·T(n/2) + O(n)` 这样的递归式描述了"分成几个、每个多大、合并要多少"，求解方法与主定理见 [复杂度分析与算法思想](./01-复杂度分析与算法思想.md)；漏掉合并成本或子问题个数带来的倍增，都会给出偏低的结论。

至于"尾递归会自动变成 O(1) 栈"这类说法，**在 Dart 上不能依赖**：语言规范只定义函数调用语义，没有承诺尾调用消除，官方语言仓库也明确表示不把它作为语言级保证（原因之一是编译到 JavaScript 时无法可靠实现）。

需要改成迭代时，就把隐式栈显式化：用一个 `List` 当栈（`add` 压栈、`removeLast` 出栈），栈里保存"当前任务"所需的全部状态（参数与进度），循环处理；深度由输入决定且无法保证有界时（可能退化成链的树遍历、文件系统层级）尤其值得换。容器用法见 [栈与队列](./04-栈与队列.md)。

> **关键认知：** 递归的空间复杂度取决于调用树的最大深度，而不是调用总次数；尾递归写法不会在 Dart 中自动带来 O(1) 栈。

> **面试高频：** 一个递归函数的时间与空间分别怎么算？递归和迭代怎么取舍？
> **答题脉络：** 先写出递归式说明子问题个数与每层工作 → 时间按调用树节点数（或递归式求解）给结论 → 空间按最大深度给结论，并说明是否计入输出与缓存 → 再说明什么时候必须改迭代（深度不可控）以及改写方式（显式栈保存状态）。
> **追问方向：** 调用树节点的精确计数（如斐波那契的 2·F(n+1) − 1）、递归式与主定理、尾递归在各语言中的保证差异、递归深度与线程栈的关系。

## 分治：拆开、求解、合并

分治（divide and conquer）是递归的一种组织方式，它把任务拆成**若干个规模更小的同类子任务**，分别求解后合并：

1. **divide**：把输入划分为若干部分，通常是两半或按位置切分。
2. **conquer**：递归求解每一部分，规模小到可以直答时停下。
3. **combine**：把子结果合并成当前结果。

它与"减治"（decrease and conquer）的区别在于子问题个数：二分查找每轮只保留一个子问题，是减治，所以深度是 O(log n)；归并排序把数组分成两半、两边都要处理，是分治，所以调用树是二叉树。边界细节见 [查找与二分查找](./10-查找与二分查找.md)。

分治成立需要三个条件：**子问题相互独立**（求解其中一个不需要另一个的中间结果）、**可合并**（存在把子结果拼成整体答案的方法，且拼装成本可接受）、**规模严格缩小**（与所有递归一样，这是终止性的前提）。

归并排序与快速排序是两种典型对照（实现见 [排序](./09-排序.md)）：归并的分是平凡的（对半切），代价花在合并（Θ(n)），递归式 `T(n) = 2T(n/2) + Θ(n)`；快排的分要花力气（划分），但分完之后不需要合并，平均情形下划分近似均匀、递归式同阶，两者都得到 O(n log n)。快排的最坏情形是 `T(n) = T(n-1) + Θ(n)`，退化为 O(n²)，因此"快排平均 O(n log n)"必须带上"平均/随机化"的前提。

> **关键认知：** 分治的前提是子问题独立且结果可合并；一旦多个分支反复求解同一子问题，就应该转而缓存中间状态（记忆化或动态规划），而不是继续分治。

> **面试高频：** 分治和动态规划的区别是什么？
> **答题脉络：** 先给出两者的共同点（都把问题拆小、都需要规模缩小与边界）→ 再给判据：子问题是否重叠、是否要保留每个子问题的结果供多个父问题复用 → 用归并排序（独立子问题，分治）与斐波那契/背包（重叠子问题，DP）对比 → 最后说明分治的复杂度由递归式决定，DP 的复杂度由状态数 × 每状态转移数决定。
> **追问方向：** 减治与分治的区别、主定理的三种情形、快排最坏退化、分治能否用记忆化（例如按区间切分的 241）。

## 回溯是决策树上的 DFS

有一类问题不是"算出一个值"，而是"列出所有满足条件的方案"：全排列、子集、N 皇后、数独、括号生成。它们的共同结构是**每一步做一次选择，最终方案由一串选择组成**；把所有可能的选择串起来就得到决策树，求解过程就是在这棵树上做深度优先搜索，边走边维护当前选中的那条路径。

标准的回溯框架有四个组成部分：

- **路径（path）**：已经做过的选择，也就是当前从根走到这个节点所经过的边。
- **选择列表**：在当前状态下还有哪些候选可以被选中。
- **约束条件**：排除掉注定不合法的选择，这是剪枝的来源。
- **结束条件**：什么时候当前路径已经是一个完整方案，需要把它记录下来。

一个容易混淆的地方是"答案出现在哪里"，不同问题不一样：**求排列时答案是叶子**（长度必须等于输入长度）；**求子集时答案是所有节点**（包括空集）；**求组合和时答案是满足约束的中间节点**。搞清楚这一点，才知道收集结果应该写在函数开头还是写在基线里；下面用长度为 n 的 0/1 序列演示这个框架。

```dart
// 前置条件：Dart 3.x；纯 Dart；无第三方运行时依赖；断言需用 `dart run --enable-asserts` 启用。
// 回溯模板：枚举长度 n 的全部 0/1 序列，演示 choose -> explore -> unchoose。

List<List<int>> binaryStrings(int n) {
  final result = <List<int>>[];
  final path = <int>[];

  void backtrack() {
    // 1. 结束条件：路径已经包含 n 个决策，就是一个完整方案。
    if (path.length == n) {
      result.add(List<int>.of(path));
      return;
    }
    // 2. 选择列表：当前位置可以取 0，也可以取 1。
    for (final choice in const <int>[0, 1]) {
      path.add(choice);
      backtrack();
      path.removeLast();
    }
  }

  backtrack();
  return result;
}
```

"选择—探索—撤销"三步必须成对出现：`path.add(choice)` 是选择，递归调用是探索，`path.removeLast()` 是撤销。撤销不是可选的收尾动作，而是**回溯的正确性条件**：同一层的所有分支必须看到同一份状态，否则后续分支会被前一个分支的选择污染。可以把这理解为一条不变量——"进入某一层的函数体时，`path` 恰好等于从根到当前的路径"，选择前的状态、探索后的状态、撤销后的状态都满足它。

这个模块里还有一个极易踩到的坑：**把可变列表的引用放进结果集**。如果写成 `result.add(path)`，结果集里的 8 个"方案"其实指向同一个列表对象，而回溯结束时这个列表已经清空，输出就变成 8 个空列表。companion file 第 26–45 行的反例函数把这一点断言成了"每个元素都是空列表"，第 47–57 行的 `main` 则验证正确版本有 8 个长度 3 的序列。`List.of` 的语义是"用给定元素创建一个新列表"，见 [Dart API](https://api.dart.dev/stable/dart-core/List/List.of.html)。

> **关键认知：** 回溯 = 在决策树上做 DFS，并在回到父节点时恢复状态；"选择"与"撤销"是一对操作，只写其中一个都会得到错误结果。

> **面试高频：** 回溯的模板有哪些固定部分？为什么必须有"撤销"这一步？
> **答题脉络：** 先给四个要素（路径、选择列表、约束、结束条件）→ 说明答案在叶子还是所有节点由问题决定 → 用"同层所有分支必须看到同一份状态"解释撤销的必要性 → 再用"结果集存引用"的例子说明收集答案时必须复制路径。
> **追问方向：** 排列与子集的模板差异、去重的层级、剪枝写在哪里、递归版本如何改成显式栈或迭代法。

## 去重与剪枝

输入里出现重复值时，不同分支可能产生同一个方案：`[1, 2, 2]` 的两个 `2` 在决策树上是对称的，会给出两份 `[2, 2]` 和两份 `[1, 2]`。**去重的依据是"同一层的同一个取值只尝试一次"，不是"跳过所有重复值"**；标准做法是先排序，再在同一层跳过与前一个分支取值相同的分支：

```dart
// 前置条件：Dart 3.x；纯 Dart；无第三方运行时依赖；断言需用 `dart run --enable-asserts` 启用。
// 去重：排序后只在"同一层"跳过与前一个分支相同的取值。

List<List<int>> subsetsWithDup(List<int> numbers) {
  final sorted = List<int>.of(numbers)..sort();
  final result = <List<int>>[];
  final path = <int>[];

  void backtrack(int start) {
    result.add(List<int>.of(path));
    for (var index = start; index < sorted.length; index++) {
      // 1. index > start 表示这是"同一层"的后续分支，跳过重复取值。
      if (index > start && sorted[index] == sorted[index - 1]) continue;
      path.add(sorted[index]);
      backtrack(index + 1);
      path.removeLast();
    }
  }

  backtrack(0);
  return result;
}
```
<!-- verify: .work/verify/A11/dedup_subsets.dart -->

判据 `index > start` 是关键：它表示"当前不是本层的第一个候选"。写成 `index > 0` 会把"在同一条分支里继续选相同的值"也误判为重复，从而漏掉合法的 `[2, 2]`。companion file 第 24–42 行的反例函数与第 44–56 行的 `main` 把这组差异断言成了可执行事实：正确的写法得到 6 个子集（`[], [1], [1,2], [1,2,2], [2], [2,2]`），过度去重只剩 4 个。另一个常见等价写法是 `used` 数组配合 `index > 0 && a[index] == a[index-1] && !used[index-1]`，判断依据仍然是"前一个相同值是否已被本层用掉"。

剪枝是另一件事：在确定性不合法或不可能更优的分支上提前返回。常见三类是可行性剪枝（当前选择已经违反约束）、界剪枝（当前值已超过目标，因为数组有序而可以直接结束本层）、以及对称性剪枝（多个候选到达同一状态）。下面用一个"统计和为 target 的子集个数"的例子对比剪枝前后的节点访问量。

```dart
// 前置条件：Dart 3.x；纯 Dart；无第三方运行时依赖；断言需用 `dart run --enable-asserts` 启用。
// 剪枝只减少被访问的节点数，不改变答案集合。

int visits = 0;

/// 统计元素和恰好为 target 的子集个数；numbers 会先升序排序，
/// 因此某个候选已经超过剩余预算时，它后面的候选只会更大。
int countSubsetSums(List<int> numbers, int target, {bool prune = true}) {
  final sorted = List<int>.of(numbers)..sort();
  var count = 0;

  void backtrack(int start, int remaining) {
    visits++;
    if (remaining == 0) {
      count++;
      return;
    }
    for (var index = start; index < sorted.length; index++) {
      // 剪枝：候选值已经超过剩余预算，本层后面的候选只会更大。
      if (prune && sorted[index] > remaining) break;
      backtrack(index + 1, remaining - sorted[index]);
    }
  }

  backtrack(0, target);
  return count;
}
```
<!-- verify: .work/verify/A11/prune_sum.dart -->

`main`（第 29–48 行）在 `[1..8]`、target = 10 上实测：两种写法都得到 8 个答案，但剪枝版本只访问 40 个节点，不剪枝版本访问了 219 个。注意剪枝成立有前提：**数组必须已有序**，否则 `sorted[index] > remaining` 之后的元素未必更大，"直接结束本层"就没有依据。此外 `break` 与 `continue` 的语义不同：`break` 结束整个本层循环（依赖排序保证后面的候选都不可行），`continue` 只跳过当前候选。

> **关键认知：** 去重回答"同一层要不要尝试同一个值"，剪枝回答"这个分支还有没有必要继续"；两者都只改变搜索树的形状与被访问的节点数，不改变最坏情况下的指数级结论。

> **面试高频：** 含重复元素的排列/子集/组合怎么去重？剪枝能改善多少复杂度？
> **答题脉络：** 先说明重复来自"同层同一取值被多次展开" → 给出排序 + 同层跳过的判据与它的前提 → 说明为什么不能写成全局跳过重复值（会漏解）→ 再说明剪枝只减少被访问的节点数，最坏时间仍由搜索树规模决定，且必须写明"排序"这类前提。
> **追问方向：** 排列去重为什么还要看 `used`、剪枝与排序的依赖关系、可行性剪枝与界剪枝的区别、如何在输出全部方案时估算下界。

## 回溯、记忆化与动态规划的边界

这三者不是三个互斥的题型，而是一条连续的选择链。面对一个问题，按顺序问三个问题即可：

1. **需要输出所有方案，还是只要一个值（最优值/方案数）？**如果需要输出所有方案，输出规模本身就是下界：排列是 n!、子集是 2^n、按运算符切分表达式是卡塔兰数。任何算法都不可能比"打印答案"更快，此时回溯最直接，优化空间只在于剪枝与避免重复枚举。
2. **是否存在被反复求解的同一个子问题？**如果不同的决策路径会到达同一个状态，就该缓存这个状态的结果，即记忆化。这里的判据是状态是否"只由决定未来的信息构成"。
3. **状态依赖是否可以排成一个有向无环图？**可以的话，就能按拓扑顺序自底向上填表，也就是动态规划；状态与转移的完整方法见 [动态规划](./12-动态规划.md)。

第 2 步最容易出错的地方是**缓存键里混入了路径信息**：前面斐波那契的缓存键是 `n`，因为答案只由 `n` 决定；而如果把"当前路径"也塞进键里，同一状态会被拆成无数条目，缓存既不命中也不正确。正确的做法是问：为了算出剩余部分的答案，我需要知道哪些信息？"已经走过哪些分支"通常不属于这类信息，"当前位置、剩余容量、已选个数"才是。

以例题中的表达式加括号为例：一个子表达式的结果只由这个子表达式自己决定，与"它是从哪次切分中产生的"无关，因此状态键可以是子表达式的字符串（或它在原串中的区间 `[i, j)`）。用区间做键做记忆化后，不同子问题只有 O(k²) 个，重复的子树不会再被重算——但输出结果本身仍是卡塔兰数规模，这条下界不会因为缓存而改变。

> **关键认知：** 缓存键必须只包含"决定未来答案"的状态；路径是到达当前状态的历史，把它写进键会让缓存失效甚至给出错误结果。

> **面试高频：** 同一个问题，什么时候用回溯，什么时候用记忆化搜索，什么时候用动态规划？
> **答题脉络：** 先问"要输出什么"（所有方案 → 回溯，输出规模即下界）→ 再问"子问题是否重叠"（重叠 → 加缓存）→ 再问"依赖是否有环"（无环 → 可自底向上）→ 最后说明三者代码骨架高度相似，区别在是否记录路径、是否缓存、遍历顺序由谁决定。
> **追问方向：** 状态定义怎么写、记忆化与制表的取舍、缓存键遗漏信息的表现（答案偏大或偏小）、输出全部方案时能不能提前确定复杂度下界。

## 什么时候用，什么时候别用

适合使用递归的场景（正例）：

- 数据结构本身自相似：树的遍历、链表递归反转、目录遍历，递归层次与结构层次一致，代码几乎是把定义抄一遍。
- 问题契约天然是"对更小规模做同一件事"：汉诺塔、二分、表达式求值。
- 需要枚举所有合法方案，或按决策树搜索并回溯：全排列、子集、组合和、N 皇后、数独。此时输出规模就是下界，搜索是最直接的结构。
- 子问题相互独立且可以合并：归并排序、快速排序、分治法求最大子数组。

不适合的场景（反例）：

- 简单的线性扫描：求数组和、找最大值、逐字符处理。循环更短也更快，递归只增加了调用开销与深度风险。
- 子问题高度重叠且只要一个值：斐波那契、背包、编辑距离。应先加缓存（记忆化或 DP），否则会重复计算到指数级；朴素递归在 `fib(90)` 这种规模下根本无法在合理时间内返回。
- 深度由输入决定且不可控，或只需一个最优答案且存在可证明的贪心做法：可能退化成链的树、深度不受限的解析应改成显式栈的迭代写法；后一类应优先考虑更直接的方法（见 [贪心](./13-贪心.md)）。

## 常见坑与边界

- **没有推进或基线判据错。**递归调用没有让规模变小（参数未变、区间端点未移动），或者用"长度为 1"代替"没有运算符"这类结构性判据（见 LeetCode 241），输入稍变就出错。
- **共享可变状态没有回滚。**`path`、`used`、集合类的占用标记必须与选择严格对称地撤销；漏掉一个，后续分支就带着脏状态继续搜索。
- **把引用当结果。**`result.add(path)` 存的是引用，调用者看到的是回溯结束后的空列表；收集答案时用 `List.of(path)` 复制。
- **去重的层级错。**`index > start` 与 `index > 0` 相差的不是"严格性"，而是同层与同枝的区别，前者保留合法重复，后者会漏解。
- **复杂度算错。**回溯的时间是"搜索树节点数 × 每节点工作"，输出全部方案时结果规模是下界；递归空间按最大深度计，不按调用次数计。
- **边界输入。**空数组、单元素、全部元素相同、目标值为 0 或负数，都要有明确行为；本文的 companion file 都覆盖了其中至少两个。

### 常见误区

- ❌ 递归太危险，能写循环就写循环。
  ✅ 两者描述的是不同东西：深度为 O(log n) 的递归（二分）比手写循环更清晰；只有深度由输入决定且不可控时，递归才有实质风险。
- ❌ 尾递归会被自动优化，不用担心栈。
  ✅ Dart 语言规范不承诺尾调用消除，官方语言仓库也明确表示不把它作为语言级保证；是否复用栈帧取决于实现，不能依赖。
- ❌ `result.add(path)` 和 `result.add(List.of(path))` 效果相同。
  ✅ 前者存引用，所有方案会随回溯一起被清空；后者才是一份独立快照。

## 知识点应用

### 分治：按运算符切分表达式

下面四道题覆盖分治、排列、子集与约束搜索，每题按"为什么匹配本知识点 → 状态与不变量 → 实现 → 复杂度 → 边界"展开；归档题解保留 Java 实现，主线代码为 Dart。

题目：[LeetCode 241. Different Ways to Add Parentheses](https://leetcode.com/problems/different-ways-to-add-parentheses/)，归档见 [05-分治.md](../02-LeetCode题解/05-分治.md)。

**为什么匹配：**给表达式加括号等价于"选择某个运算符作为最后一次运算"，左右两侧又各自是同一种问题，属于典型的按位置切分型分治，不需要合并函数之外的额外结构。

**状态与不变量：**子问题由"子表达式"确定，且子表达式的结果集合与它来自哪次切分无关；基线是"不含任何运算符"，此时整段字符串就是一个（可能是多位数的）数字。

```dart
// 前置条件：Dart 3.x；纯 Dart；无第三方运行时依赖；断言需用 `dart run --enable-asserts` 启用。
// LeetCode 241：按任意顺序给表达式加括号，返回所有可能的计算结果。

int calls = 0;

List<int> diffWaysToCompute(String expression) {
  calls++;
  final result = <int>[];

  for (var index = 0; index < expression.length; index++) {
    final symbol = expression[index];
    if (symbol != '+' && symbol != '-' && symbol != '*') continue;

    // 1. 以当前运算符作为最后一次运算，分别求解左右两个子表达式。
    final left = diffWaysToCompute(expression.substring(0, index));
    final right = diffWaysToCompute(expression.substring(index + 1));

    // 2. 左右结果做笛卡尔组合，结果个数是两边的乘积。
    for (final l in left) {
      for (final r in right) {
        result.add(switch (symbol) {
          '+' => l + r,
          '-' => l - r,
          _ => l * r,
        });
      }
    }
  }

  // 3. 基线不是"长度为 1"，而是"没有运算符"：整段就是一个多位数。
  if (result.isEmpty) result.add(int.parse(expression));
  return result;
}
```
<!-- verify: .work/verify/A11/diff_ways_241.dart -->

**复杂度：**设运算符个数为 k。朴素实现中每个运算符位置都会触发一次切分，总调用次数满足 N(k) = 1 + 2·ΣN(j)，解得 N(k) = 3^k（实测 k = 3 时为 27 次）；输出结果个数是第 k 个卡塔兰数 C(2k, k)/(k+1)（k = 3 时为 5，实测输出 `[-34, -14, -10, -10, 10]`）。每次调用还要扫描并切分当前子串，因此时间是 O(3^k · n) 量级，空间是 O(k) 的递归深度加上子串本身的开销（不含输出）。用子表达式或区间 `[i, j)` 作为键做记忆化可以把状态数降到 O(k²)，但输出规模的下界不变。

**边界用例：**`2-1-1` 有两个结果 `0, 2`（对应两种结合方式）；`2*3-4*5` 的五个结果包含重复值 `-10`；多位数 `10` 说明基线不能用"长度为 1"（companion file 第 46–47 行）。

### 排列：每一步从剩下的元素里选一个

题目：[LeetCode 46. Permutations](https://leetcode.com/problems/permutations/)，归档见 [06-搜索.md](../02-LeetCode题解/06-搜索.md)。

**为什么匹配：**方案由"每一步选哪个元素"组成，答案是决策树的叶子（路径长度等于输入长度），属于最标准的回溯模型。

**状态与不变量：**`path` 保存已经选中的元素且不重复，`used[i]` 与 `path` 保持一致——"元素 i 在 path 中"当且仅当 `used[i]` 为真。递归调用前后必须同时维护这两者：选择时同步置位，撤销时同步清空。

```dart
// 前置条件：Dart 3.x；纯 Dart；无第三方运行时依赖；断言需用 `dart run --enable-asserts` 启用。
// LeetCode 46：返回全部排列，输入保证元素互不相同。

List<List<int>> permute(List<int> numbers) {
  final result = <List<int>>[];
  final path = <int>[];
  final used = List<bool>.filled(numbers.length, false);

  void backtrack() {
    // 1. 结束条件：路径长度等于输入长度，得到一个完整排列。
    if (path.length == numbers.length) {
      result.add(List<int>.of(path));
      return;
    }
    for (var index = 0; index < numbers.length; index++) {
      // 2. 约束：已经在路径中的元素不能再选。
      if (used[index]) continue;
      used[index] = true;
      path.add(numbers[index]);
      backtrack();
      path.removeLast();
      used[index] = false;
    }
  }

  backtrack();
  return result;
}
```
<!-- verify: .work/verify/A11/permutations_46.dart -->

**复杂度：**输出规模是 n!，每个答案需要复制长度为 n 的路径，因此时间是 Θ(n · n!)，空间是 O(n) 的递归栈与辅助数组，输出本身占 Θ(n · n!)（不含在算法额外空间中）。实测 n = 8 时返回 40320 个排列。

**边界用例：**空输入返回一个空排列（`[[]]`），单元素返回一个排列；输入含重复值（`[1, 1, 2]`）时本模板会返回重复排列，说明"去重"是模板之外的一步（对照做法见 [06-搜索.md](../02-LeetCode题解/06-搜索.md)）。

### 子集：每个节点都是一个答案

题目：[LeetCode 78. Subsets](https://leetcode.com/problems/subsets/)，归档见 [06-搜索.md](../02-LeetCode题解/06-搜索.md)。

**为什么匹配：**每个元素只有"选"与"不选"两种状态，方案是决策树上任意节点对应的路径，因此收集答案要写在函数入口而不是基线里。

**状态与不变量：**参数 `start` 表示"下一个可以选择的元素下标"，它保证每个元素只在本层之后的候选里出现一次，从而不会产生 `[1, 2]` 与 `[2, 1]` 这样的顺序重复；`path` 始终是从根到当前节点的路径。

```dart
// 前置条件：Dart 3.x；纯 Dart；无第三方运行时依赖；断言需用 `dart run --enable-asserts` 启用。
// LeetCode 78：返回集合的全部子集，输出规模是 Θ(2^n)。

List<List<int>> subsets(List<int> numbers) {
  final result = <List<int>>[];
  final path = <int>[];

  void backtrack(int start) {
    // 1. 每个节点都是一个合法答案，进入时先收集。
    result.add(List<int>.of(path));

    // 2. start 保证每个元素只在"选或不选"两类分支中出现，避免顺序不同的重复。
    for (var index = start; index < numbers.length; index++) {
      path.add(numbers[index]);
      backtrack(index + 1);
      path.removeLast();
    }
  }

  backtrack(0);
  return result;
}
```
<!-- verify: .work/verify/A11/subsets_78.dart -->

**复杂度：**输出规模是 Θ(2^n)，每个子集最多复制 n 个元素，时间是 Θ(n · 2^n)；空间是 O(n) 的递归深度（不含输出）。实测 n = 10 时返回 1024 个子集。

**边界用例：**空数组的唯一答案是空集 `[[]]`（`backtrack(0)` 入口先收集一次，不需要额外判空）；`[1,2,3]` 的 8 个结果中第一个是空集、最后一个只含 `3`。若输入含重复值，需要叠加第 6 节的同层去重（对照 90 题）。

### 约束搜索：N 皇后

题目：[LeetCode 51. N-Queens](https://leetcode.com/problems/n-queens/)，归档见 [06-搜索.md](../02-LeetCode题解/06-搜索.md)。

**为什么匹配：**每一行必须放一个皇后，行内只选一个列，冲突只发生在列与两条对角线上——这是"逐层做决策 + 约束剪枝"的标准模型。

**状态与不变量：**按行从上到下放置，只需记录三类占用：列 `column`、"↘"对角线（`row - column` 恒定）、"↙"对角线（`row + column` 恒定）。不变量是"三个集合里的值恰好等于已放置皇后所占据的列与对角线"，放置与撤销必须同时更新三者。

```dart
// 前置条件：Dart 3.x；纯 Dart；无第三方运行时依赖；断言需用 `dart run --enable-asserts` 启用。
// LeetCode 51：N 皇后，用三个集合记录列和两条对角线上的占用情况。

List<List<String>> solveNQueens(int n) {
  final result = <List<String>>[];
  final columns = <int>{};
  final diagonals = <int>{}; // row - column，同一条"↘"对角线
  final antiDiagonals = <int>{}; // row + column，同一条"↙"对角线
  final placement = <int>[]; // 每行皇后所在的列

  void backtrack(int row) {
    // 1. 结束条件：n 行都放好了皇后，把当前布局渲染成棋盘。
    if (row == n) {
      result.add(
        List<String>.generate(n, (current) {
          final line = List<String>.filled(n, '.');
          line[placement[current]] = 'Q';
          return line.join();
        }),
      );
      return;
    }

    for (var column = 0; column < n; column++) {
      // 2. 约束剪枝：列、↘ 对角线、↙ 对角线都必须空闲。
      if (columns.contains(column) ||
          diagonals.contains(row - column) ||
          antiDiagonals.contains(row + column)) {
        continue;
      }
      columns.add(column);
      diagonals.add(row - column);
      antiDiagonals.add(row + column);
      placement.add(column);

      backtrack(row + 1);

      placement.removeLast();
      antiDiagonals.remove(row + column);
      diagonals.remove(row - column);
      columns.remove(column);
    }
  }

  backtrack(0);
  return result;
}
```
<!-- verify: .work/verify/A11/n_queens_51.dart -->

**复杂度：**节点数上界是每行 n 个候选构成的搜索树规模（O(n!) 量级），剪枝后实际访问远小于此；每个解需要 O(n) 时间渲染成棋盘。空间是 O(n)（三个集合、`placement` 与递归深度），不含输出。实测 n = 1..8 的解数序列是 `1, 0, 0, 2, 10, 4, 40, 92`，与 [OEIS A000170](https://oeis.org/A000170) 一致。

**边界用例：**n = 1 有唯一解 `["Q"]`；n = 2 与 n = 3 无解（序列中的两个 0 会被"搜索完所有分支"自然得出，而不是特判）；n = 4 有 2 个解。用三个 `Set<int>` 记录占用是本节的写法，等价的位掩码写法（用整数的位表示列与对角线占用）把集合操作换成位运算，常数更小但可读性下降，位运算语义见 [位运算技巧](./14-位运算技巧.md)。

## 面试考点与追问

递归与搜索类问题在面试中很少只问"写出来"，而是沿着"定义是否准确 → 复杂度能否推导 → 边界是否覆盖 → 能否优化"这条链条追问。可以按下面的顺序复述：

1. **契约与终止。**先说明参数描述什么任务、返回什么，再指出每次调用在哪个度量上严格变小，并给出基线及它的判据来源。
2. **复杂度与边界。**时间按调用树节点数或递归式给，空间按最大深度给，输出与缓存是否计入要说明；空输入、单元素、全相同元素、深度可能退化的输入逐项检查。
3. **范式选择。**要输出全部方案还是只要一个值；子问题是否重叠；状态依赖是否有环。这三问决定用回溯、记忆化还是动态规划，优化方向按剪枝（前提是排序或约束单调）、记忆化（前提是状态键正确）、显式栈（前提是深度不可控）依次尝试。

> **面试高频：**排列、组合、子集这三个模板到底差在哪？
> **答题脉络：**先看答案在决策树的哪个位置（排列在叶子、子集在所有节点、组合和在满足约束的节点）→ 再看下一层候选如何生成（排列用 `used` 全局排除，子集/组合用 `start` 限制只向后选）→ 最后看是否需要额外区间约束（组合和用剩余目标值做剪枝）。
> **追问方向：**含重复元素的版本怎么改去重判据、`start` 与 `used` 能否互相替代、带重访限制的搜索（如单词搜索）如何标记与恢复访问状态。

高频追问还包括：递归改成显式栈时栈里要保存哪些字段；为什么"看起来像 DP"的问题用回溯会超时（子问题重叠而没有缓存）；以及树形结构上的 DFS 与本文回溯的关系——前中后序遍历是"结构驱动的递归"，回溯是"决策驱动的 DFS"，两者共用调用栈机制，但答案的收集位置由问题定义决定（见 [树与二叉树](./06-树与二叉树.md)、[字符串算法](./15-字符串算法.md)）。

## 小结

递归把"整体由同类的小整体拼成"直接写进代码，分治规定这些小整体必须相互独立且能合并，回溯则在决策树上做深度优先搜索并在回边恢复状态；三者共用同一套调用栈机制，区别只在问题如何分解、答案在树的哪个位置、以及是否需要缓存中间状态。

## 一句话总结

递归用同一份契约描述更小的同类问题，分治要求这些子问题独立且可合并，回溯则在决策树上做深度优先搜索并在回边恢复状态，而选择哪一种取决于要输出什么、子问题是否重叠以及状态依赖是否有环。
