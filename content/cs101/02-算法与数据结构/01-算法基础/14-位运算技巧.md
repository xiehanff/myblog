# 位运算技巧

面试里反复出现这样几类题：数组里除一个数外其他数都出现两次，找出只出现一次的那个；判断一个数是不是 2 的幂；不用 `+ - * /` 实现整数加法。它们考的不是会不会写 `&`、`^`、`<<`，而是能不能把“成对抵消”“进位”“最低有效位”这类约束翻译成比特上的恒等式。

只背下 `x & (x - 1)` 能清掉最低位的 1 是不够的。换一种输入约束、换一个位宽、换一门语言，结论就可能不成立——把 Java 的 32 位技巧原样搬进 Dart，`1 << 31` 的含义就变了。所以本文要求每个技巧都带着前提出现：依赖多少位宽、对 0 和负数如何处理、循环次数的上界是多少。

路线是：先划清与[二进制表示与位运算](../../01-数据表示/01-二进制表示与位运算.md)的分工，再确认 Dart 的位运算语义；然后依次建立掩码、异或抵消、最低有效位三组恒等式，并把它们组合成小集合表示与位加法；最后用选择边界、常见坑和四道例题收束。

## 本篇边界：表示知识到算法工具

同一组 `& | ^ ~ << >> >>>` 符号，在两个场景里回答两个不同的问题：

- 数据表示篇回答“这串位在机器里怎么解释”：进制、补码、整数提升、不同语言的移位契约。
- 本文回答“约束怎么映射到比特、映射之后能推出什么恒等式”：集合、奇偶、唯一性、进位。

因此本文不重复补码教材和语言对比，只给一句结论并链接过去。所有结论都在 **Dart Native（有符号 64 位补码）** 上讨论；Web 目标的 32 位截断语义只作为提醒出现，不写成通用结论。下文出现的 `w` 统一指目标位宽，本文取 `w = 64`。

全文由三个恒等式家族构成：

1. 掩码家族：`x | (1 << k)`、`x & ~(1 << k)`——对单一位做局部修改。
2. 异或家族：`x ^ x = 0`——成对出现的约束可以直接抵消。
3. 低位家族：`x & -x`、`x & (x - 1)`——定位与清除最低有效位。

> **关键认知：** 位运算技巧的本质是用一个机器字同时表示多个布尔状态，把“集合、奇偶、唯一性”的约束压缩成常数空间的表示；代价是元素个数必须落在机器字宽度内，超过宽度后性质会改变。

> **面试高频：** 位运算题到底在考什么？
> **答题脉络：** 先读输入约束（是否成对出现、是否小集合、是否固定位宽）→ 再从三个恒等式家族选一个 → 最后把位宽与 0/负数边界写进函数契约。
> **追问方向：** 哪些结论只在补码下成立；哪些结论只在固定宽度下成立；换成 Dart 的 64 位后哪一步会变。

## Dart 位运算语义

算法代码里与位宽相关的错误几乎都来自三类假设：移位量的合法范围、取反作用的宽度、右移补什么。先把这三件事定下来。

Dart Native 的 `int` 是有符号 64 位补码，第 63 位就是符号位；`~`、一元负号 `-x` 和 `>>` 都按这个宽度解释。`>>` 是算术右移（高位补符号位），`>>>` 是零填充右移（结果非负）。移位量必须非负，否则抛 `ArgumentError`。下面这段代码把影响算法写法的边界固定下来，也是正文唯一一份完整引用的可运行文件：

```dart
// 前置条件：Dart 3.12.2；纯 Dart，无第三方依赖；Dart VM（原生 64 位 int）。
// 运行：dart run .work/verify/A14/dart_semantics.dart
void main() {
  // 1. 原生 int 是有符号 64 位补码：第 63 位就是符号位。
  _check(1 << 62 > 0 && 1 << 63 < 0, '1 << 63 把 1 送进了符号位');

  // 2. >> 补符号位，>>> 补 0：同一个负数得到两个不同的结果。
  _check(-9 >> 2 == -3, '>> 是算术右移');
  _check(-9 >>> 2 == 4611686018427387901, '>>> 把 64 位模式当无符号数看');
  _check(-1 >>> 1 == 0x7FFFFFFFFFFFFFFF, '>>> 的结果不会是负数');

  // 3. ~ 与一元负号都按 64 位解释，而不是按某个字段的宽度。
  _check(~0x0F == -16 && 12 & -12 == 4, '取反与取负都作用于整个位模式');

  // 4. 算术运算先于移位求值，掩码表达式必须写括号。
  _check(1 << 2 + 1 == 8, '1 << 2 + 1 等于 1 << 3，而不是 (1 << 2) + 1');

  // 5. 移位量必须非负；超出位宽的结果属于实现行为，不应依赖。
  var threw = false;
  try {
    final bad = 1 << -1;
    print('不应走到这里：$bad');
  } on ArgumentError {
    threw = true;
  }
  _check(threw, '负移位量抛出 ArgumentError');
  _check(1 << 64 == 0 && -1 >>> 64 == 0, '超出位宽在 3.12.2 原生 VM 上得到 0');

  // 6. 需要固定宽度时显式声明：32 位子字在原生与 Web 上口径一致。
  _check((-1).toUnsigned(32) == 0xFFFFFFFF, '取低 32 位并按无符号解释');
  _check(0xFFFFFFFF.toSigned(32) == -1, '再按有符号 32 位解释');
  _check((-1).toUnsigned(32) & 1 == 1, '截断后的最低位仍然是 1');
  print('Dart 位运算语义检查通过');
}

void _check(bool condition, String message) {
  if (!condition) {
    throw StateError(message);
  }
}
```

对算法写法的直接影响是：

- 用 `1 << k` 构造掩码时 `k` 必须小于 63，否则第 63 位把结果变成负数（`1 << 63` 是最小负数，不是 2 的 63 次方）。
- 超过 63 的移位量不会报错，但结果不再有数学含义；本文把它当作实现行为，代码必须先做范围检查，而不是依赖回绕。
- `x & -x` 里的 `-x` 是 64 位取负；对非负 `x` 它就是补码意义上的“最低位 1”，对负数则要按 64 位模式重新理解。

> **时效信息（核查日期：2026-09）：** “超出位宽得到 0”这类行为来自 Dart 3.12.2 原生 VM 的实测；Dart 官方只规定移位量必须非负，超出位宽的结果不属于语言保证。Web 目标会把位运算截断到 32 位并按无符号解释，差异与跨平台建议见[数据表示篇的 Dart 一节](../../01-数据表示/01-二进制表示与位运算.md#dart原生-64-位web-上按-32-位截断)。

> **关键认知：** “Dart 的 `int` 是 64 位”只在原生平台成立；本文所有恒等式都附带“64 位原生 `int`”这一前提，需要 32 位语义时必须显式 `toUnsigned(32)` / `toSigned(32)` 并测试边界。

> **面试高频：** 把 Java 位运算代码搬到 Dart 要注意什么？
> **答题脉络：** 位宽从 32 变 64 → 溢出与回绕发生在不同的位置 → `>>>` 与 `~` 的解释随之改变 → 需要固定 32 位语义时显式截断并补边界测试。
> **追问方向：** `1 << 31` 在两门语言里分别是多少；`>>` 与 `>>>` 的差别；跨平台时为什么推荐按 32 位子字操作。

## 掩码的基本操作

把机器字看成一排编号从 0 开始的开关，掩码就是“只对第 k 个开关动手”的表达方式。四种基本操作覆盖了所有单比特需求：

| 目标 | 表达式（k 从 0 开始） | 重复执行的后果 |
| --- | --- | --- |
| 测试第 k 位 | `(flags & (1 << k)) != 0` | 无副作用 |
| 设置第 k 位 | `flags \| (1 << k)` | 幂等：再设一次不变 |
| 清除第 k 位 | `flags & ~(1 << k)` | 幂等：再清一次不变 |
| 翻转第 k 位 | `flags ^ (1 << k)` | 两次翻转回到原值 |

把它们写成命名函数，比在业务代码里散落 `0x80` 之类的魔法数可靠得多：

```dart
/// 第 [bit] 位是否为 1。
bool hasBit(int flags, int bit) => (flags & (1 << bit)) != 0;

/// 把第 [bit] 位置为 1；重复设置不改变结果。
int setBit(int flags, int bit) => flags | (1 << bit);

/// 把第 [bit] 位清为 0；重复清除不改变结果。
int clearBit(int flags, int bit) => flags & ~(1 << bit);

/// 翻转第 [bit] 位；连续翻转两次回到原值。
int toggleBit(int flags, int bit) => flags ^ (1 << bit);
```

抽取范围：companion 文件开头的四个函数，`main()` 与断言（幂等性、统一初始化、`clearBit(-1, 63)`、`1 << 63` 落在符号位）见同一文件。

清除和翻转都用到了 `~(1 << k)`，它本身是负数；真正保证结果落在原值位域内的是随后的 `&`——只有原值中为 1 的位会留下来。多比特字段的读写是同一套思路的推广：读取写 `(value >> shift) & ((1 << width) - 1)`，写入写 `value & ~mask | ((fieldValue << shift) & mask)`，其中 `mask = ((1 << width) - 1) << shift`；字段布局与整数提升带来的边界见[掩码一节](../../01-数据表示/01-二进制表示与位运算.md#掩码只让自己关心的位留下来)。单次掩码操作只访问一个机器字：时间 O(1)、额外空间 O(1)，前提是位位置 `0 <= k < 64`。

> **关键认知：** 掩码只改变被指定的位，是因为“设置用 `|`、清除用 `& ~`、翻转用 `^`”分别对应布尔代数的“置真、置假、取反”；表达式里少一个括号或写错位位置，改动的就是别的位。

## XOR 的抵消性质

异或（exclusive or，XOR）可以看作逐位的模 2 加法：每一位独立地做“相同得 0、不同得 1”的运算。因此它满足交换律与结合律，`0` 是单位元，每个值都是自己的逆元：`x ^ y = y ^ x`、`(x ^ y) ^ z = x ^ (y ^ z)`、`x ^ 0 = x`、`x ^ x = 0`。

前两条性质意味着**折叠顺序不影响结果**：把数组从头异或到尾，等价于按任意顺序重排后再异或；每个元素只以“出现次数的奇偶性”进入结果——偶数次两两抵消成 0，奇数次会留下。

单个唯一数是直接应用：`result` 初值为 0，遍历一次数组把所有数异或进来，留下的就是唯一数。两个唯一数时结果不够用，需要先分组：

1. `diff = x ^ y` 是两个唯一数异或的结果；因为 `x != y`，所以 `diff != 0`。
2. `diff &= -diff` 取出 `diff` 最低位的 1，这一位必然是两者第一个不同的位。
3. 用这一位把全部元素分成两组：两个唯一数落在不同组，其余元素在同一组内仍然成对，两组各自折叠异或即得答案。

```dart
/// 恰好两个元素各出现一次、其余元素都恰好出现两次时，返回升序的两元素。
List<int> twoUniqueNumbers(List<int> numbers) {
  var diff = 0;
  for (final value in numbers) {
    diff ^= value;
  }
  // 1. diff 是两个唯一数异或的结果；它的最低位 1 就是两者第一个不同的位。
  diff &= -diff;
  var first = 0;
  var second = 0;
  // 2. 用这一个位把元素分成两组，两组内部各自折叠异或。
  for (final value in numbers) {
    if ((value & diff) == 0) {
      first ^= value;
    } else {
      second ^= value;
    }
  }
  return first < second ? [first, second] : [second, first];
}
```

抽取范围：companion 文件的 `twoUniqueNumbers`；同文件还定义了折叠异或的 `singleNumber`（例题 2 会再给出）与三次异或交换 `swapXor`，并包含全部断言。

三次异或交换必须记住一个边界：`i == j` 时三步都在同一个位置自异或，元素会被清零。它也没有工程收益：需要多写三行、依赖 `i != j` 的前提，可读性还更差，工程代码里应当避免。折叠 XOR 的时间复杂度是 O(n)、额外空间 O(1)；两个唯一数的分组也只需两趟线性扫描，空间同样 O(1)。这些结论的前提是“其余元素恰好出现两次”：出现四次的元素同样抵消，而出现次数为奇数且多于一次时，折叠结果不再是“唯一数”。

> **关键认知：** 异或折叠保留的是“出现奇数次的那些位模式”，它既不知道每个元素出现了几次，也不知道它们的位置；所以它只能回答“谁出现了奇数次”，不能回答“谁出现了一次”。

> **面试高频：** 出现两个唯一数时怎么把它们分开？
> **答题脉络：** 全部异或得到 `x ^ y` → 找一个两者不同的位（任意一个 1 都可以，常用最低位 1）→ 按该位分成两组 → 组内抵消。
> **追问方向：** 分组位选最高位行不行；数组里其余元素出现三次怎么办。

## lowbit 与清除最低位

上一节用 `diff & -diff` 解决分组，这一节把它抽象成两个对偶操作：

- `x & -x`：提取最低有效位（least significant bit，lowbit）——只保留最低的那个 1，其他位全为 0。
- `x & (x - 1)`：清除最低位的 1——其他位保持不变。

两个式子都在补码下成立：`-x` 等于 `~x + 1`，减 1 只影响最低位的 1 及其右侧的位，按位与恰好把“不受影响的部分”提取出来；完整的位级推导见[数据表示篇](../../01-数据表示/01-二进制表示与位运算.md#常用位运算技巧与它们的适用边界)。由它们可以导出三个常用结论：

1. **判断 2 的幂**：2 的幂只有一个 1，清掉它就变成 0，所以 `x > 0 && (x & (x - 1)) == 0`。`x > 0` 不能省：0 会被误判，最小负数 `1 << 63` 的位模式也只有一个 1。
2. **统计 1 的个数（Brian Kernighan 算法）**：每轮清掉一个 1，循环次数等于 1 的个数。
3. **循环次数的上界**：位模式里最多有 `w` 个 1，因此两条路径在最坏情况下分别是 O(popcount) 与 O(w)。

```dart
/// 取出最低位的 1 所代表的值；x 必须大于 0。
int lowestBit(int x) => x & -x;

/// 清除最低位的 1；x 为 0 时仍返回 0。
int clearLowestBit(int x) => x & (x - 1);

/// 判断 2 的幂：0 和负数都不是。
bool isPowerOfTwo(int x) => x > 0 && (x & (x - 1)) == 0;

/// Brian Kernighan 统计 1 的个数：循环次数等于 1 的个数。
int popCount(int x) {
  var count = 0;
  var rest = x;
  while (rest != 0) {
    rest &= rest - 1;
    count++;
  }
  return count;
}
```

抽取范围：companion 文件的四个函数；同文件还有逐位扫描版本 `popCountByScan`（固定 64 轮）与断言，覆盖 `clearLowestBit(0) == 0`、`!isPowerOfTwo(0)`、`!isPowerOfTwo(-4)`、`popCount(-1) == 64` 等边界。

统计 1 的两种实现复杂度必须分开表述：Kernighan 算法是 **O(popcount)**，逐位扫描是 **O(w)**，本文 `w = 64`。两者最坏情况都是 64 轮，Kernighan 的优势出现在 1 比较稀疏时（`1 << 62` 只需一轮）。如果题目的位宽口径不同——例如要求统计 32 位模式——要先用 `toUnsigned(32)` 限定范围，否则负数（`-1`）会被算成 64 个 1 而不是 32 个。lowbit 还是树状数组（Fenwick tree）的核心：索引 `i` 的父节点是 `i + (i & -i)`，更新步长就是 `i & -i`。本文只把它作为“lowbit 被真实数据结构依赖”的提示，不展开实现。

> **关键认知：** `x & (x - 1)` 每执行一次，位模式里 1 的个数恰好减一，因此它的循环次数由 1 的个数决定，而不由位宽决定；这条不变量同时给出了 2 的幂判断与 popcount 两个算法。

## 位掩码表示小集合

如果集合元素可以编号为 `0..n-1`，那么“第 i 个元素在不在集合里”就是一个布尔值，正好放进第 i 位。集合运算于是变成位运算：

| 集合语义 | 位运算表达式 | 前提 |
| --- | --- | --- |
| 加入第 i 个元素 | `set \| (1 << i)` | `0 <= i < 64` |
| 移除第 i 个元素 | `set & ~(1 << i)` | 同上 |
| 判断成员 | `(set & (1 << i)) != 0` | 同上 |
| 交集 / 并集 | `a & b` / `a \| b` | 两个集合编号口径一致 |
| 差集 | `a & ~b` | 同上 |
| 集合大小（元素个数） | `popCount(set)` | 同上 |

子集枚举是位掩码最有价值的用法，写法是每轮执行 `sub = (sub - 1) & set`。它的不变量是：`sub` 始终是 `set` 的子掩码，且数值严格递减，序列最终到达 0。`sub` 的每个取值对应一个唯一子集，因此总轮数为 `2^k`（`k` 是 `set` 中 1 的个数），每轮 O(1)。

```dart
/// 把第 [element] 个元素加入集合。
int addToSet(int set, int element) => set | (1 << element);

/// 从集合中移除第 [element] 个元素；元素不存在时保持不变。
int removeFromSet(int set, int element) => set & ~(1 << element);

/// 第 [element] 个元素是否在集合中。
bool contains(int set, int element) => (set & (1 << element)) != 0;

/// 枚举 [set] 的所有子集，从全集开始、以空集结束。
List<int> allSubsets(int set) {
  final subsets = <int>[];
  // 1. 每轮用 (sub - 1) & set 跳到下一个更小的子掩码。
  for (var sub = set; ; sub = (sub - 1) & set) {
    subsets.add(sub);
    if (sub == 0) {
      break;
    }
  }
  return subsets;
}
```

抽取范围：companion 文件开头的集合操作与 `allSubsets`；断言覆盖 `addToSet(a, 0) == a`、枚举 3 个元素得到 8 个子集、每个结果都是原集合的子掩码。

集合操作本身是常数时间，但“常数”受机器字宽度约束：一个 `int` 最多承载 63 个安全编号（第 63 位是符号位，避开它最稳妥），超过之后必须改用 `List<int>` 分段或专门的位集合结构，空间量级也随之从 O(1) 变回 O(n / w)。把集合当作动态规划状态时，状态数仍是 `2^n`，位压缩只改变表示、不改变指数规模：枚举全部子集的 O(2^k)，加上每个状态内部的 O(n) 转移，就是状态压缩 DP 的 O(2^n · n)（详见[递归、分治与回溯](./11-递归、分治与回溯.md)与[动态规划](./12-动态规划.md)）。

> **关键认知：** 位掩码集合不是“更快的 `Set`”，而是“元素个数受机器字宽度限制的集合”；它的空间收益来自把 n 个布尔值折叠成一个字，一旦 n 超过字宽，就必须退回到多字表示。

> **面试高频：** 什么时候可以用状态压缩？
> **答题脉络：** 先确认状态是“一个子集的指示器”而不是计数 → 再看 n 是否落在机器字宽度内 → 最后核对状态数 `2^n` 与转移代价能否接受。
> **追问方向：** n = 20 时状态数与内存估算；枚举子集为什么是 O(2^k)；n 超过 64 怎么办。

## 不用算术运算做加法

“不使用 `+ - * /` 求两个整数之和”能成立，是因为加法可以拆成两个布尔问题：当前位上的和、以及要传给更高位的进位。设某一位的两个加数分别是 `a` 和 `b`，则“无进位和”是 `a ^ b`，“进位”是 `(a & b) << 1`，而 `a + b` 等于把这两者当作新的加数继续分解。

终止性来自进位本身：`(a & b) << 1` 的最低位一定是 0，每轮迭代都会让进位尾部多一个 0，因此最多 `w` 轮之后进位归零。**位宽是这段代码语义的一部分**：Java 的 `int` 固定 32 位、左移溢出的位自动丢弃，所以 `while` 循环可以不加掩码；Dart 的 `int` 是 64 位，直接照抄会得到 64 位语义——`0x7FFFFFFF + 1` 变成 2³¹，而题目语义应为 -2³¹。实测中 32 位掩码版本处理 `-5 + 12` 需要 29 轮、`-1 + 1` 需要 32 轮（上界就是 32），同一组输入在 64 位原生写法下分别要 61 轮和 64 轮（对照实现见 `.work/verify/A14/bit_add.dart`）。完整实现与断言放在例题 4，时间复杂度是 O(w)、`w = 32`，额外空间 O(1)。

> **关键认知：** 位运算做加法的正确性依赖“固定宽度、溢出位被丢弃”这一前提；同样的表达式在 64 位语义下不再是同一个算法，必须显式掩码才能把语义固定下来。

> **面试高频：** 为什么 Java 版可以 `while (b != 0)` 而 Dart 版要加掩码？
> **答题脉络：** Java 的 `int` 固定 32 位、左移溢出位直接丢弃 → Dart 原生 `int` 是 64 位，溢出发生在第 64 位 → 要复现题目语义就得先用 `toUnsigned(32)` 截断、每轮用 `& 0xFFFFFFFF` 限制进位。
> **追问方向：** 循环次数怎么证明有界；`toSigned(32)` 在结果解释里的作用。

## 什么时候用，什么时候别用

**适用**：

- 数据本身就是位字段：权限、协议标志、硬件寄存器，位就是最自然的表示。
- 输入约束直接提供“成对抵消”：处理这类唯一数问题时，折叠异或比哈希表更省空间；集合规模很小且元素编号连续（例如 `n <= 20` 的状态压缩）时，一次 `&` 就能完成集合运算。
- 题目要求 O(1) 额外空间或禁止算术运算符，而位运算提供了等价表达。

**不适用**：

- 普通业务集合。需要按名字查询、序列化、遍历成员时，`Set` / `enum` 的表达力和可维护性都更好；位掩码的低成本只体现在“元素少、访问密”的场景。
- 元素个数会增长到超过机器字宽度时，要么用多字位集合，要么直接用 `Set<int>`，不要为了保留位技巧而与位宽搏斗。
- 数值可能超出固定位宽（例如需要任意精度）。用 `BigInt`，不要假设位运算会按 32 位或 64 位回绕。
- 把算术改写成位运算以求“更快”。`% 2 != 0` 与 `& 1` 编译后通常一样快，而前者对负数、对读者意图都更清楚；把整数除法改写成右移更危险：`-5 ~/ 2` 是 -2（向零取整），`-5 >> 1` 是 -3（向负无穷取整），二者语义不同。
- 把三次异或当成“无临时变量交换”的通用技巧。它只对整数成立，依赖 `i != j` 的前提，可读性也更差。

## 常见坑与边界

- ❌ 忘记移位与算术的优先级：`1 << k + 1` 是 `1 << (k + 1)`，不是 `(1 << k) + 1`。✅ 掩码表达式显式加括号，例如 `(1 << width) - 1`、`((1 << width) - 1) << shift`。
- ❌ 把 `^` 当成幂运算。✅ Dart 里 `^` 是异或，而且没有 `**` 运算符，需要幂时用 `dart:math` 的 `pow`。
- ❌ 把 `~(1 << k)` 直接当作字段掩码使用。✅ 它是负数（64 位取反），只有与 `&` 配对时才安全。
- ❌ 让 `k` 越界：`1 << 63` 是负数（最小负数），`1 << 64` 在 Dart 3.12.2 原生 VM 上得到 0。✅ 构造掩码前检查 `0 <= k < 63`；要用满 64 位时单独处理符号位。
- ❌ 用 `>>` 处理负数位模式后再按 32 位口径统计。✅ 需要位模式本身时用 `>>>` 或 `toUnsigned(32)`，因为 `>>` 会补符号位。
- ❌ 判断 2 的幂时只写 `x & (x - 1) == 0`。✅ 必须补 `x > 0`：0 会被误判，`1 << 63` 的位模式也只有一个 1，但它是负数。
- ❌ 把 `x & -x` 用在 `x = 0` 上并期待“最低位的 1”。✅ `0 & -0` 仍然是 0，没有最低有效位可取，调用方要先排除 0。
- ❌ 认为位掩码集合是 O(1) 空间的万能容器。✅ 只有 `n <= 63` 时它才是一个机器字；超过后空间与操作都要按多字位集合重新分析。
- ❌ 看到状态压缩就以为“空间被优化掉了”。✅ 位掩码只压缩表示，状态数仍是 `2^n`，转移代价仍是 O(n)。
- ❌ 用三次异或交换 `i == j` 的两个位置。✅ 把 `i != j` 写成函数契约，或干脆使用临时变量。
- ❌ 把 Web 上的位运算结果当成 Dart 的通用行为。✅ 原生是 64 位补码，Web 会截断到 32 位并按无符号解释，跨平台代码要显式按 32 位子字操作。

## 知识点应用

### 例题 1：LeetCode 461. 汉明距离

[题目链接（力扣）](https://leetcode.cn/problems/hamming-distance/) / [归档参考](../02-LeetCode题解/16-位运算.md#1-统计两个数的二进制表示有多少位不同)

前置条件：Dart 3.12.2；纯 Dart；Dart VM（原生 64 位 `int`）。

- **问题匹配点**：汉明距离就是两个位模式不同的位数，属于“先把差异变成位模式，再统计 1 的个数”的组合；题目保证 `x, y` 为非负整数，位宽无歧义。
- **不变量**：`diff = x ^ y` 中每个 1 恰好对应一位不同；每轮 `diff &= diff - 1` 让 1 的个数减一。
- **实现**：

```dart
int hammingDistance(int x, int y) {
  // 1. 异或把“不同的位”变成 1。
  var diff = x ^ y;
  var count = 0;
  // 2. 每轮消掉最低位的 1，循环次数正好等于 1 的个数。
  while (diff != 0) {
    diff &= diff - 1;
    count++;
  }
  return count;
}
```

<!-- verify: .work/verify/A14/lc461_hamming_distance.dart -->

- **复杂度**：时间 O(popcount(x ^ y))，最坏 O(w)，`w = 64`；空间 O(1)。边界情况：`x == y` 时结果为 0；`x = 0, y = 0x7FFFFFFF` 时结果为 31；断言文件里还对比了固定 64 轮的逐位扫描版本，两者结果相同。

### 例题 2：LeetCode 136. 只出现一次的数字

[题目链接（力扣）](https://leetcode.cn/problems/single-number/) / [归档参考](../02-LeetCode题解/16-位运算.md#2-数组中唯一一个不重复的元素)

前置条件：Dart 3.12.2；纯 Dart；Dart VM（原生 64 位 `int`）。

- **问题匹配点**：题目给出的约束正是“其余元素恰好出现两次”，这是折叠异或能够成立的充分条件。
- **状态**：`result` 始终是“已扫描元素中出现奇数次的位模式的异或和”，扫描结束时唯一出现的元素恰好留下。
- **实现**：

```dart
int singleNumber(List<int> numbers) {
  var result = 0;
  for (final value in numbers) {
    result ^= value;
  }
  return result;
}
```

<!-- verify: .work/verify/A14/lc136_single_number.dart -->

- **复杂度**：时间 O(n)，空间 O(1)；不需要哈希表，也不需要额外数组。
- **边界用例**：数组只有一个元素时直接返回它；元素为负数时性质不变（`[-1, -1, -2]` 返回 -2）；空数组不在题面约束内，当前实现返回 0，调用方不应把 0 当作有效结果依据。

### 例题 3：LeetCode 338. 比特位计数

[题目链接（力扣）](https://leetcode.cn/problems/counting-bits/) / [归档参考](../02-LeetCode题解/16-位运算.md#13-统计从-0--n-每个数的二进制表示中-1-的个数)

前置条件：Dart 3.12.2；纯 Dart；Dart VM（原生 64 位 `int`）。

- **问题匹配点**：题目要求对每个 `i` 输出 1 的个数，并提示可以做到 O(n)；递推需要“丢掉一位之后答案如何变化”，正是 lowbit 家族的应用。
- **状态与递推**：`i >> 1` 等价于丢掉最低位，`i & 1` 是被丢掉的那一位，于是 `counts[i] = counts[i >> 1] + (i & 1)`；等价地，`i & (i - 1)` 去掉一个 1，于是 `counts[i] = counts[i & (i - 1)] + 1`。
- **实现**（这里给出主递推；等价的 lowbit 递推、O(n · w) 的校验实现与断言见 companion 文件）：

```dart
List<int> countBits(int n) {
  final counts = List<int>.filled(n + 1, 0);
  for (var i = 1; i <= n; i++) {
    counts[i] = counts[i >> 1] + (i & 1);
  }
  return counts;
}
```

<!-- verify: .work/verify/A14/lc338_counting_bits.dart -->

- **复杂度**：时间 O(n)（每个 `i` 只做常数次位运算），空间 O(n)，其中 n 是输出数组长度；O(n) 成立是因为递推只依赖已经算出的更小下标。
- **边界用例**：`n = 0` 返回 `[0]`；`n = 5` 返回 `[0,1,1,2,1,2]`；两种递推与逐个数统计的版本交叉验证到 `n = 1000`。

### 例题 4：剑指 Offer 65. 不用加减乘除做加法

[题目链接（力扣，当前题名 LCR 190「加密运算」）](https://leetcode.cn/problems/bu-yong-jia-jian-cheng-chu-zuo-jia-fa-lcof/) / [归档参考](../03-剑指Offer题解/065-不用加减乘除做加法.md#解题思路)

前置条件：Dart 3.12.2；纯 Dart；Dart VM（原生 64 位 `int`）。

- **问题匹配点**：加法的每一轮都可分解为“无进位和”与“进位”，两者都能用位运算表达；题目明确“结果不会溢出 32 位整数”，给出了位宽前提。
- **不变量**：`x` 是已确定的无进位和部分，`y` 是尚未并入的进位；每轮结束后两者之和保持不变，直到 `y == 0`。
- **实现**（抽取范围：companion 文件的 `add` 与轮次计数器，`main()` 断言见同文件）：

```dart
/// 加法轮次计数，用于验证循环次数的上界。
int addCallCount = 0;

int add(int a, int b) {
  // 1. 题目固定 32 位整数语义，先把操作数收敛到 32 位无符号模式。
  var x = a.toUnsigned(32);
  var y = b.toUnsigned(32);
  // 2. x ^ y 是无进位和，(x & y) << 1 是进位；掩码保证进位不会逃出 32 位。
  while (y != 0) {
    final carry = (x & y) << 1 & 0xFFFFFFFF;
    x = x ^ y;
    y = carry;
    addCallCount++;
  }
  // 3. 把 32 位模式解读回有符号整数。
  return x.toSigned(32);
}
```

<!-- verify: .work/verify/A14/offer065_add_without_ops.dart -->

- **复杂度**：时间 O(w)，`w = 32`（进位链最长等于位宽）；空间 O(1)。
- **边界用例**：`add(0, 0) == 0`；`add(5, -1) == 4`；`add(-1, -1) == -2`；不掩码的 64 位版本会在 `0x7FFFFFFF + 1` 上给出 2³¹，而题目语义应为 -2³¹，这让“先声明位宽再写恒等式”成为可验证的结论。

## 面试考点与追问

1. **异或为什么能找出单个唯一数？** 交换律与结合律 → 顺序无关 → 每个元素只保留出现次数的奇偶性 → “其余恰好两次”是必要前提。追问：出现三次怎么办；能不能只用一个变量。
2. **两个唯一数如何分组？** `x ^ y != 0` → 任取一个为 1 的位（常用最低位 1）→ 该位把两个数分到不同组 → 组内折叠抵消。追问：分组位的选择是否影响结果；额外空间是否仍为 O(1)。
3. **统计 1 的个数有哪几种复杂度？** Kernighan O(popcount) 与逐位扫描 O(w) → 最坏情况相同、稀疏位模式差异明显 → 负数要先确定位宽口径。追问：32 位与 64 位口径如何用 `toUnsigned` 固定。
4. **判断 2 的幂为什么要 `x > 0`？** 0 会被误判，`1 << 63` 的位模式也只有一个 1 但它是负数。追问：判断 4 的幂要加什么条件；`x & -x` 与 `x & (x - 1)` 的对偶关系。
5. **状态压缩的边界在哪里？** 元素编号必须落在机器字内 → 状态数仍是 `2^n` → 超过字宽改用分段位集合或普通集合。追问：n = 20 时的状态与内存估算。
6. **Dart 与 Java 的位运算差异会怎样改变算法？** 32 位与 64 位 → 溢出位置改变 → `>>>` 与 `~` 的解释变化 → 需要固定语义时显式 `toUnsigned` / `toSigned`。追问：`1 << 31` 在两门语言里的值。

## 小结

写位运算代码前先回答三个问题：位宽是多少、0 与负数是否在输入范围内、状态数会不会超过机器字。掩码修改、异或抵消、低位提取与清除这三组恒等式都建立在这些前提之上；离开前提，它们就只是“碰巧能通过样例”的代码。
