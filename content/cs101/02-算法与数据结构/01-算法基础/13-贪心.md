# 贪心

排课时先安排结束最早的会议，找零时先抓面额最大的硬币，压缩文本时给最高频的字符最短的编码——这些决定都只看眼前的一小步。把这种直觉写成循环通常只有几行，但结果有时严格最优，有时错得很远。

硬币面额是 {1, 3, 4}、要凑 6 元时，“先抓最大的”给出 4 + 1 + 1 共三枚，而 3 + 3 只要两枚；同一套直觉换成面额 {1, 5, 10} 后又能一直给出正确答案。所以“每一步取最好”本身不是算法，它只是一条候选策略：要成为正确答案，必须补上一句“这样选为什么不会丢掉最优解”。

本文先把贪心拆成可检查的四要素，再给出三类可套用的正确性证明，然后用区间调度、资源分配和哈夫曼编码把证明写完整，最后用背包问题说明它在什么位置必须让位给动态规划。

## 为什么局部最优有时足够

把求解过程看成决策序列：第一步选什么，第二步在剩余部分里选什么……枚举所有序列是指数级的，动态规划要求把子问题的解都存下来，而贪心只保留一个决策：**选完就不回头**。

正因为不可撤销，贪心要成立就必须回答一个存在性问题：**是否存在一个最优解，它包含我这一步的选择？** 如果答案是肯定的，就可以把这一步固定下来，然后对“剩下的部分”重复同样的问题；如果答案是否定的，无论这一步当时看起来多划算，全局最优都已经丢了。

用这个标准检查上面两个找零例子。面额 {1, 5, 10} 时，任何最优解都不会用两个 5 去换一个 10 吗——不会，因为 10 更大；于是“先抓最大面额”总能被交换进某个最优解。面额 {1, 3, 4} 时，凑 6 的最优解 {3, 3} 里根本没有 4，第一步就错了，后面再正确也救不回来。

> **关键认知：** 贪心算法是不可撤销的选择规则加上正确性证明；“每一步取最大或最小”只是候选策略。局部最优能推出全局最优是特定问题的结构性质，不是普遍规律，必须逐题验证。

> **面试高频：** 拿到一道题，怎样判断能不能用贪心？
> **答题脉络：** 先找出一个看起来安全的局部选择 → 尝试交换论证（假设某个最优解不含它，把它换进去，验证可行性不变、目标值不变差）→ 换成后归纳到剩余子问题 → 证明写不出来就退回动态规划，并用小规模穷举对拍找反例。
> **追问方向：** 区间调度为什么按结束时间；0-1 背包为什么不能用价值密度；分数背包与 0-1 背包的差别在哪里。

## 贪心算法的构成

一个贪心算法由四部分组成，缺一不可，否则很容易写出“对样例成立、换了数据就错”的代码：

1. **候选集合**：每一步可以从哪些元素里选，例如所有区间、所有饼干、所有符号。
2. **选择规则**：按什么键取极值，例如“结束时间最早”“能满足需求的最小资源”“频率最低”。
3. **可行性检查**：选择之后，剩余部分是否还能满足约束，例如区间是否仍不与已选区间重叠。
4. **目标函数**：如何比较两个完整解，例如保留的区间个数最多、总收益最大、加权路径长度最小。

排序就是把选择规则预处理成扫描顺序：按结束时间排好序之后，“取结束时间最早的可行区间”变成“从左到右，能接上就接”。它不改变问题的解空间，只把安全的选择排到扫描顺序的前面；代价是一次 O(n log n) 的排序，收益是把每步 O(n) 的比较全部省掉。如果只是需要反复取极值而不需要全局顺序，用最小堆可以做到同样的选择开销，详见[堆与优先队列](./07-堆与优先队列.md)；排序本身的机制见[排序](./09-排序.md)。

> **关键认知：** 排序不改变问题，它只是把“每步比较所有候选”换成“按安全顺序扫描一次”，复杂度从 O(n²) 的比较降到 O(n log n) 排序加 O(n) 扫描。

三种求解思路的对照：枚举保留所有完整解，动态规划保留每一类子问题的最优值，贪心只保留一个决策。

| 方法 | 每步保留什么 | 典型时间 | 是否回溯 |
| --- | --- | --- | --- |
| 枚举搜索 | 所有完整解 | 指数级 | 是 |
| 动态规划 | 每类子问题的最优值 | 状态数 × 转移数 | 不回溯，但保留多个分支 |
| 贪心 | 一个决策 | 排序 O(n log n) + 扫描 O(n) | 不回溯，也不保留备选 |

## 三类正确性证明

### 交换论证

设 OPT 是任一最优解。如果 OPT 已经包含贪心的选择 g，就对剩余子问题归纳；否则在 OPT 中找一个元素 y，把 y 换成 g，证明替换后的解仍可行且目标值不变差。这样就构造出了“包含 g 的最优解”，存在性得证。检查重点是两件事：**可行性**（约束不被破坏）和**目标值**（不劣于原解）；只检查其中一件是常见错误，例如把两个区间互换后忘了检查端点是否仍然不重叠。区间调度的第一步就是把最优解的第一个区间换成结束时间最早的那个。

### 始终领先

把贪心解 G 与任意最优解 OPT 的元素按顺序对齐，证明贪心在第 k 步的“已完成进度”不落后于 OPT 的第 k 步。例如分配饼干时，处理完前 i 块饼干后，贪心满足的孩子数不少于任何策略；进度始终领先，结束时就不可能落后。这种方式适合两个解可以自然逐项配对的问题，例如线性扫描、区间和序列类问题。

### 问题切分

证明贪心的选择把原问题切成“已确定的部分 + 结构相同的子问题”。哈夫曼编码是标准例子：合并两个频率最低的节点后，把新节点看作一个频率为二者之和的符号，问题从 σ 个符号变成 σ − 1 个符号，结构完全不变，于是可以归纳（递归建模见[递归、分治与回溯](./11-递归、分治与回溯.md)）。股票问题的“把价格序列切成若干段、每段独立兑现”也是同一思路。

切出来的子问题必须与原问题同型；如果切完以后约束变了（例如“至少选 k 个”这类全局约束），归纳就不再成立。

> **关键认知：** 三类证明的内核是同一个存在性命题——“存在一个最优解包含贪心的这一步选择”；区别只在于用替换、对齐还是拆解把它写出来。

> **面试高频：** 交换论证具体要检查什么？
> **答题脉络：** 明确贪心的第一个选择 → 构造包含它的候选解 → 证明可行性不被破坏 → 证明目标值不变差 → 对剩余子问题归纳。
> **追问方向：** 区间调度第一步怎么交换；哈夫曼为什么能把最低频符号换到最深处；交换后相等的情况怎么处理。

## 区间调度模型

模型：给出 n 个区间 `[start, end]`，求最多能选出多少个两两不重叠的区间。会议室分配、课程表、气球问题都是这个模型。

选择规则：**按结束时间升序，取结束时间最早的区间；之后只接受开始时间不早于上次结束时间的区间。**

结束时间才是关键，这一点用两个小反例就能看清：

- 按开始时间最早选：区间 `[1,10]`、`[2,3]`、`[4,5]`。贪心先拿 `[1,10]`，只能得到 1 个，最优是后两个共 2 个。
- 按长度最短选：区间 `[0,5]`、`[4,7]`、`[6,9]`。贪心先拿 `[4,7]`，同样只能得到 1 个，最优是首尾两个共 2 个。

交换论证：设 OPT 的第一个区间是 o，贪心选的是 g（结束时间最早）。若 o ≠ g，则 g 的结束时间 ≤ o 的结束时间；OPT 中其余区间的开始时间都 ≥ o 的结束时间，因此也 ≥ g 的结束时间。把 o 换成 g 后所有区间仍两两不重叠，区间个数不变。于是存在含 g 的最优解，对“开始时间不早于 g.end”的子问题递归使用同一论证即可。

> **关键认知：** 区间调度的安全选择是结束时间最早的区间，理由是它给后续区间留下的可用时间最长；这是“始终领先”的直观版本，也可以严格写成交换论证。

> **面试高频：** 区间调度为什么按结束时间，而不是开始时间或区间长度？
> **答题脉络：** 先用两个反例说明另外两种排序会失败 → 指出“剩余可用时间最长”是不变量 → 用交换论证把最优解的第一个区间替换成它 → 归纳到剩余子问题。
> **追问方向：** 端点相接算不算重叠会怎样改变条件；如果要保留的是区间数量最多的子集，和“删掉最少多少个区间”如何互换。

## 匹配与资源分配

模型：有若干需求和若干资源，一个资源最多满足一个需求，满足条件是“资源 ≥ 需求”，求最多能满足的需求数。饼干分配是标准例子。

选择规则：**需求升序、资源升序，用“能满足当前最小需求的最小资源”去匹配；不能满足就换下一个资源重新尝试，匹配成功则两边都前进。**

为什么保留大资源是安全的：满足关系是单调的——大资源能覆盖的需求集合包含小资源能覆盖的集合。把一块小资源用在最容易被满足的需求上，不会损失任何可能性；大资源则留给更挑剔的需求。

交换论证：设 OPT 把最小需求 b 配给了资源 t，贪心选出的是满足 b 的最小资源 c。若 t ≠ c，则 c ≤ t，把 t 换成 c：b 仍然被满足，其它配对不受影响，因为用更小的资源去满足固定需求不会让任何原本可行的配对变得不可行。所以贪心不劣于任何最优解。

> **关键认知：** 资源分配能贪心的前提是“资源能力随规模单调”；一旦资源是专属的、不可替代的，单调性消失，双指针失效，就要转向图匹配模型，见[图](./08-图.md)。

> **面试高频：** 为什么“能满足当前需求的最小资源”不会浪费资源？
> **答题脉络：** 说明满足关系的单调性 → 用交换论证把更大的资源换出来 → 大资源留给更挑剔的需求 → 结论：贪心满足的孩子数不少于任何策略。
> **追问方向：** 如果资源可以拆分（连续）结果如何；如果需求必须精确相等是否还成立；资源与需求数量相差很大时双指针的行为。

## 哈夫曼编码

前缀码的动机来自定长编码的浪费：假设四个符号 a、b、c、d 的频率分别是 10、20、40、80，固定用 2 位编码，总长度是 `2 × (10+20+40+80) = 300` 位。既然 d 出现的次数是 a 的八倍，它理应占用更短的码字。

前缀码要求：**任何一个码字都不是另一个码字的前缀。** 这样解码时从左向右逐位读，读到的第一个完整码字就是答案，不会产生歧义。前缀码可以用二叉树表示：叶子是符号，根到叶子的路径（向左记 0、向右记 1）是码字；总代价是加权路径长度 `WPL = Σ fᵢ · lenᵢ`，也就是编码后的总位数。0/1 位串与字节序的表示细节属于数据表示，见[二进制表示与位运算](../../01-数据表示/01-二进制表示与位运算.md)。

选择规则：**每次取出频率最低的两个节点，合并成一个频率为二者之和的新节点，重复 σ − 1 次**（σ 是不同符号的个数）。合并顺序用最小堆维护，堆的实现见[堆与优先队列](./07-堆与优先队列.md)。

为什么安全，用两步交换论证说明：

1. 设 a、b 是树中深度最大的一对兄弟叶子，x 是最低频的符号。把 x 与 a 交换，代价变化为 `(f_a − f_x) × (depth(x) − depth(a))`，其中 `f_a ≥ f_x` 且 `depth(x) ≤ depth(a)`，所以代价不增。同理把另一个最低频符号换到 b 的位置。
2. 于是存在一棵最优树，频率最低的两个符号是最深的一对兄弟叶子，把它们合并（父节点频率为二者之和）不会损失最优性；此时问题变成 σ − 1 个符号的同型问题，归纳即可。

复杂度：σ 个不同符号、用二叉堆实现优先队列时，做 σ − 1 次合并、每次 O(log σ)，建树时间 O(σ log σ)；此外输出码表本身的长度最坏为 O(σ²) 位（频率呈递推分布时深度可达 σ − 1）。前提是符号按单个字符独立编码、频率已知且固定。

下面是纯 Dart 实现（验证环境 Dart 3.12.2，无第三方依赖）。第一段是节点定义与最小堆：

```dart
class HuffmanNode {
  HuffmanNode(this.frequency, this.symbol, this.order, [this.left, this.right]);

  final int frequency;
  final String? symbol; // 内部节点为 null
  final int order; // 频率相同时的稳定 tie-break
  final HuffmanNode? left;
  final HuffmanNode? right;
}

/// 只实现建树需要的 add / removeMin 的最小堆。
class MinHeap {
  final _items = <HuffmanNode>[];

  int get length => _items.length;

  void add(HuffmanNode node) {
    var child = _items.length;
    _items.add(node);
    while (child > 0) {
      final parent = (child - 1) ~/ 2;
      if (_compare(_items[parent], _items[child]) <= 0) break;
      final temporary = _items[parent];
      _items[parent] = _items[child];
      _items[child] = temporary;
      child = parent;
    }
  }

```

入堆是上浮：新元素与父节点比较，比父节点小就交换，直到堆序恢复。取最小值是下沉：先取出堆顶，把最后一个元素挪到堆顶，再和更小的孩子交换：

```dart
  HuffmanNode removeMin() {
    final minimum = _items.first;
    final last = _items.removeLast();
    if (_items.isEmpty) return minimum;
    _items[0] = last;
    var parent = 0;
    while (true) {
      final left = 2 * parent + 1;
      final right = left + 1;
      var smallest = parent;
      if (left < _items.length &&
          _compare(_items[left], _items[smallest]) < 0) {
        smallest = left;
      }
      if (right < _items.length &&
          _compare(_items[right], _items[smallest]) < 0) {
        smallest = right;
      }
      if (smallest == parent) break;
      final temporary = _items[parent];
      _items[parent] = _items[smallest];
      _items[smallest] = temporary;
      parent = smallest;
    }
    return minimum;
  }

  /// 先比频率，再比插入序，保证同一输入得到同一棵码表。
  static int _compare(HuffmanNode a, HuffmanNode b) {
    final byFrequency = a.frequency.compareTo(b.frequency);
    return byFrequency != 0 ? byFrequency : a.order.compareTo(b.order);
  }
}
```

第三段是建树与码表生成，以及沿树解码：

```dart
/// 哈夫曼编解码器：建一次树，之后可反复编码与解码。
class HuffmanCodec {
  HuffmanCodec(Map<String, int> frequencies) {
    if (frequencies.isEmpty) return;

    // 1. 所有符号各自成为叶子节点，先按 (频率, 插入序) 入堆。
    final heap = MinHeap();
    var order = 0;
    for (final entry in frequencies.entries) {
      heap.add(HuffmanNode(entry.value, entry.key, order++));
    }

    // 2. 每次取出频率最低的两个节点合并，新节点的频率是二者之和。
    while (heap.length > 1) {
      final left = heap.removeMin();
      final right = heap.removeMin();
      heap.add(
        HuffmanNode(
          left.frequency + right.frequency,
          null,
          order++,
          left,
          right,
        ),
      );
    }
    _root = heap.removeMin();

    // 3. 左分支记 0、右分支记 1，走到叶子就得到该符号的编码。
    _collect(_root!, '');
  }

  final codes = <String, String>{};
  HuffmanNode? _root;

  void _collect(HuffmanNode node, String prefix) {
    final symbol = node.symbol;
    if (symbol != null) {
      // 单符号字母表没有分支可走，按约定给 1 位码。
      codes[symbol] = prefix.isEmpty ? '0' : prefix;
      return;
    }
    _collect(node.left!, '${prefix}0');
    _collect(node.right!, '${prefix}1');
  }

  /// 沿建好的树逐位解码；位串以半个码字结尾时抛错。
  String decode(String bits) {
    final root = _root;
    if (root == null) return '';
    if (root.symbol != null) return root.symbol! * bits.length;

    final buffer = StringBuffer();
    var node = root;
    for (final bit in bits.split('')) {
      if (bit != '0' && bit != '1') {
        throw const FormatException('位串只能包含 0 和 1');
      }
      node = bit == '0' ? node.left! : node.right!;
      final symbol = node.symbol;
      if (symbol != null) {
        buffer.write(symbol);
        node = root;
      }
    }
    if (!identical(node, root)) throw const FormatException('位串以半个码字结尾');
    return buffer.toString();
  }
}
```

对上面 a、b、c、d 的频率分布，码表是 `a → 000`、`b → 001`、`c → 01`、`d → 1`，加权路径长度 250，比定长编码的 300 少 50 位。验证文件里还断言了前缀码性质、往返编解码一致、频率相同时结果确定、空输入、单符号字母表（约定 1 位码）和“位串以半个码字结尾时抛错”这类边界（加权路径长度的计算函数也在其中）。

> **关键认知：** 哈夫曼的贪心选择是“合并频率最低的两个节点”，它安全的原因是低频符号可以被交换到最优树最深的一对兄弟叶子上，合并这两个位置不会损失最优性。

> **面试高频：** 哈夫曼为什么每次合并频率最低的两个节点？
> **答题脉络：** 先定义加权路径长度 → 说明最深位置放低频符号不亏（交换论证）→ 最低频的两个符号可以做成最深的一对兄弟叶子 → 合并后问题规模减一，归纳成立 → 补充：码字不唯一，唯一的是最优代价。
> **追问方向：** 前缀码为什么能唯一解码；频率相同时怎么办；哈夫曼是否总是压缩率最高的方案（按符号独立编码时最优，算术编码等上下文方法不受此限制）。

## 贪心与动态规划

两者共享同一个前提：**最优子结构**——整问题的最优解由子问题的最优解组成。区别在于如何处理“选哪个”：动态规划保留每一类子问题的最优值，因为最优选择取决于尚未处理的输入；贪心额外断言“某个局部选择一定出现在某个最优解中”，于是不必保留分支。

分数背包与 0-1 背包正好演示了有没有这个断言的差别：

- **分数背包**：物品可以切开，按价值密度（价值 ÷ 重量）从高到低装，最后一件切开来补满。它可以贪心，交换论证是：任何最优解若在装完所有更高密度物品之前就装了低密度物品，把少量重量从低密度物品移到高密度物品上，总价值不变差；反复交换直到与贪心一致。
- **0-1 背包**：物品不能切开，同样的密度贪心会失败。反例：价值 `[60, 100, 120]`、重量 `[10, 20, 30]`、容量 50。密度是 6、5、4，贪心装前两件得到 160；最优是后两件共 220。失败原因是局部选择不可逆地消耗了容量，剩下的 20 容量装不下第 3 件，而放弃第一件就能腾出空间。

下面是 0-1 背包的密度贪心与暴力最优值（纯 Dart，验证环境 Dart 3.12.2，无第三方依赖），用来确认这个反例：

```dart
/// 0-1 背包的密度贪心：装不整件就跳过，继续尝试后面的物品。
int greedyZeroOneKnapsack(List<int> values, List<int> weights, int capacity) {
  var remaining = capacity;
  var total = 0;
  for (final index in _byValueDensity(values, weights)) {
    // 1. 不能切开：只接受整件能装下的物品。
    if (weights[index] <= remaining) {
      remaining -= weights[index];
      total += values[index];
    }
  }
  return total;
}

/// 暴力：枚举所有子集得到 0-1 背包的最优值，只适合物品数很少的情况。
int bestZeroOneKnapsack(List<int> values, List<int> weights, int capacity) {
  var best = 0;
  for (var mask = 0; mask < 1 << values.length; mask++) {
    var weight = 0;
    var value = 0;
    for (var index = 0; index < values.length; index++) {
      if (mask >> index & 1 == 1) {
        weight += weights[index];
        value += values[index];
      }
    }
    if (weight <= capacity && value > best) best = value;
  }
  return best;
}

/// 按价值密度降序返回物品下标；用交叉相乘比较，避免浮点误差。
List<int> _byValueDensity(List<int> values, List<int> weights) {
  return List<int>.generate(values.length, (index) => index)..sort((a, b) {
    final left = values[a] * weights[b];
    final right = values[b] * weights[a];
    return right.compareTo(left);
  });
}
```

复杂度方面，暴力枚举是 O(2ⁿ · n)，只适合验证小规模；真正的 0-1 背包需要 O(n · V) 状态的动态规划（V 是容量），见[动态规划](./12-动态规划.md)；分数背包的贪心是 O(n log n) 排序加 O(n) 扫描。

> **关键认知：** 能写出动态规划转移不代表必须用动态规划；只要“某个选择一定属于某个最优解”可以证明，贪心就能把状态表压缩成一次排序加一次扫描——但 0-1 背包说明，没有这个证明时不能省。

> **面试高频：** 贪心与动态规划的分界线在哪里？
> **答题脉络：** 两者都要求最优子结构 → 动态规划保留所有子问题的最优值，贪心断言局部选择必然出现在某个最优解里 → 用分数背包与 0-1 背包说明“局部选择是否可交换”就是分界 → 证明不出来时优先动态规划。
> **追问方向：** 为什么 0-1 背包规模稍大就难解而分数背包可贪心；能否给 0-1 背包加额外假设让密度贪心成立。

## 什么时候用，什么时候别用

可以优先考虑贪心的三个信号：

- **能写出交换论证**：把任一最优解替换成包含当前选择的形式后，可行性不变、目标值不变差。本文的区间调度、资源分配、哈夫曼都属于这一类。
- **资源或候选具有单调结构**：更大的资源能完成的任务集合包含小资源能完成的集合，因此交换不会损失可能性。
- **决策的依据只依赖已处理部分和当前候选**：做出选择后，剩余问题与原问题同型，不需要回头修正。

遇到下列情况就不要用贪心：

- **0-1 背包按价值密度**：局部选择消耗了不可再生的容量。
- **任意面额的找零**：面额 {1, 3, 4} 凑 6 就是反例。
- **局部决策改变后续可行集合且无法交换**：需要“恰好用完”的约束、选择之间有互斥或耦合关系的分配问题、带全局约束的最优化问题等。
- **必须记住“上一步具体选了谁”才能继续**：例如带连续限制的状态机，这类问题把状态显式写出来就是动态规划。

实用流程是：先用小规模穷举对拍（例如本文对 122 题穷举了 19530 组价格序列），找不到反例再尝试写交换论证；证明写不出来，就老实回到动态规划。

## 常见坑与边界

- **用样例代理证明**：找零 {1, 3, 4} 在 4 元时贪心恰好最优，6 元才暴露问题。至少要用穷举对拍覆盖小规模的全部输入。
- **排序键选错**：区间调度按开始时间或按区间长度都是常见错误选择，安全键是结束时间。
- **端点开闭不一致**：LeetCode 435 里相接不算重叠（`[1,2]` 与 `[2,3]` 可以同时保留），而飞镖问题里相接算重叠（一支箭可以同时刺破 `[1,2]` 和 `[2,3]`）。比较符必须跟着题面的定义走，不能从另一个变体照搬。
- **排序的副作用与比较器**：`List.sort` 原地排序，本文示例都先复制再排序；比较相等键时不要依赖 `List.sort` 的稳定性（Dart 文档明确不保证稳定），要把次关键字写进比较器；比较器应使用 `compareTo`，而不是把两个大数相减。
- **相等值的处理**：频率或权重相等时具体解不唯一，要输出某种字典序最小解就得补规则。
- **小规模的正确性没有来源**：剪绳子问题里 n = 2、3 必须特判，因为题面要求至少切成两段，n = 3 自身不是合法切法。
- **大指数直接求幂**：剪绳子的取模版本 n 最大 1000，`3^332` 远超 64 位整数范围，必须用快速幂逐步取模，并且假设原生 64 位 `int`。
- **把一个变体的证明套到另一个变体**：证明绑定的是具体的选择规则和端点约定，改动定义后交换检查必须重做。

## 知识点应用

下面四道题按“问题匹配点 → 不变量 → Dart 实现 → 复杂度 → 边界用例”组织，代码是从验证文件里抽取的核心函数（前置条件统一为 Dart 3.x、纯 Dart、无第三方依赖，验证环境 Dart 3.12.2），归档题解保留原 Java 实现，只作为对照入口。

### 1. 分配饼干（LeetCode 455）

[题目](https://leetcode.com/problems/assign-cookies/)｜归档：[../02-LeetCode题解/03-贪心思想.md](../02-LeetCode题解/03-贪心思想.md)

- **问题匹配点**：需求与资源都存在单调的“满足”关系，且资源不可拆分，是排序加双指针的匹配模型。
- **不变量**：处理到 `(child, cookie)` 时，前 `child` 个孩子都已满足并消耗了排序后靠前的若干块饼干，`sortedSizes[cookie]` 是尚未使用的最小饼干。
- **边界用例**：没有饼干（`sizes` 为空，题面允许）返回 0；饼干全部偏小返回 0；孩子比饼干多时返回饼干数形成的上限。

```dart
/// 排序 + 双指针：最小的可用资源优先分配给最容易满足的需求。
int findContentChildren(List<int> greed, List<int> sizes) {
  // 1. 排序前先复制：List.sort 原地修改列表，不该改掉调用方的输入。
  final sortedGreed = [...greed]..sort();
  final sortedSizes = [...sizes]..sort();

  var child = 0;
  var cookie = 0;
  while (child < sortedGreed.length && cookie < sortedSizes.length) {
    if (sortedSizes[cookie] >= sortedGreed[child]) {
      // 2. 能满足就发出去：饼干的剩余部分不能给别人，直接消耗掉。
      child++;
    }
    // 3. 无论是否满足，这块饼干都已出局（太小或已用掉），换下一块。
    cookie++;
  }
  return child;
}
```

复杂度：设孩子数为 m、饼干数为 n，时间是 O(m log m + n log n)，额外空间 O(m + n)（复制输入）。前提是使用比较排序，`O(m + n)` 的空间来自两处复制的列表。

### 2. 无重叠区间（LeetCode 435）

[题目](https://leetcode.com/problems/non-overlapping-intervals/)｜归档：[../02-LeetCode题解/03-贪心思想.md](../02-LeetCode题解/03-贪心思想.md)

- **问题匹配点**：求“最少移除多少个”等于总数减去“最多保留多少个不重叠区间”，后者就是本节的区间调度模型。
- **不变量**：扫描到第 i 个区间时，`lastEnd` 是已选区间的最大结束时间，`count` 是保留数；只接受开始时间不早于 `lastEnd` 的区间。
- **边界用例**：题目保证 1 ≤ n；三个完全相同的区间要移除 2 个；端点相接（`[1,2]`、`[2,3]`）不重叠，条件用 `>=`。

```dart
/// 按结束时间贪心，返回最多可保留的不重叠区间个数。
int maxNonOverlapping(List<List<int>> intervals) {
  if (intervals.isEmpty) return 0;

  // 1. 复制一份再排序：List.sort 会原地修改调用方传入的列表。
  final sorted = [
    for (final interval in intervals) [interval[0], interval[1]],
  ];

  // 2. 主键取结束时间；相同则再按开始时间，避免依赖 List.sort 的稳定性。
  sorted.sort((a, b) {
    final byEnd = a[1].compareTo(b[1]);
    return byEnd != 0 ? byEnd : a[0].compareTo(b[0]);
  });

  // 3. 第一个区间结束最早，它一定可以出现在某个最优解里。
  var count = 1;
  var lastEnd = sorted.first[1];

  // 4. 只有开始时间不早于上次结束时，才接受下一个区间。
  for (var index = 1; index < sorted.length; index++) {
    if (sorted[index][0] >= lastEnd) {
      count++;
      lastEnd = sorted[index][1];
    }
  }
  return count;
}

/// LeetCode 435：最少移除多少个区间，等价于总数减去最多保留数。
int eraseOverlapIntervals(List<List<int>> intervals) =>
    intervals.length - maxNonOverlapping(intervals);
```

复杂度：时间 O(n log n)（排序主导）加 O(n) 扫描，额外空间 O(n)；前提是区间端点比较为 O(1)，使用比较排序，n 为区间个数。当前题面约束 n ≤ 10⁵、端点绝对值 ≤ 5 × 10⁴，Dart 的 `int` 足以容纳，比较用 `compareTo` 不涉及减法溢出。

### 3. 买卖股票的最佳时机 II（LeetCode 122）

[题目](https://leetcode.com/problems/best-time-to-buy-and-sell-stock-ii/)｜归档：[../02-LeetCode题解/03-贪心思想.md](../02-LeetCode题解/03-贪心思想.md)

- **问题匹配点**：允许无限次交易且同一天可以先卖后买，于是相邻两天的价格差可以逐段独立兑现，正是“问题切分”的形态。
- **不变量**：遍历到第 i 天时，`profit` 等于所有正的价格增量之和，也就是“在第 i 天前每段上涨都恰好兑现”的上界。
- **边界用例**：只有一天返回 0；单调下降返回 0；单调上升等于首尾价差。

```dart
/// 贪心：把价格序列拆成若干段，每段上涨都单独兑现，下跌增量直接丢弃。
int maxProfit(List<int> prices) {
  var profit = 0;
  for (var day = 1; day < prices.length; day++) {
    final gain = prices[day] - prices[day - 1];
    if (gain > 0) profit += gain;
  }
  return profit;
}
```

复杂度：时间 O(n)，额外空间 O(1)；前提是交易成本为零（当前题面如此）。收益上界来自“任何一次交易的利润都等于区间内相邻价差之和，因此总利润不超过所有正增量的和”，而逐日兑现恰好达到这个上界。验证文件用状态机动态规划和暴力搜索在长度 1 到 6、取值 0 到 4 的 19530 组序列上三方对拍一致。

### 4. 剪绳子（剑指 Offer 14）

[归档：014-剪绳子.md](../03-剑指Offer题解/014-剪绳子.md)｜当前页面：力扣 [LCR 131](https://leetcode.cn/problems/jian-sheng-zi-lcof/)（不取模，2 ≤ n ≤ 58）、[LCR 132](https://leetcode.cn/problems/jian-sheng-zi-ii-lcof/)（取模 10⁹ + 7，2 ≤ n ≤ 1000）

- **问题匹配点**：把 n 拆成至少两段正整数使乘积最大，长度 3 的“性价比”最高且不受后续排列影响，属于问题切分的贪心。
- **不变量**：对 n ≥ 4，最优解中不出现长度 1 的段（`1 × (n−1) < n`），也不出现长度 ≥ 5 的段（`3 × (n−3) > n`），所以最优解只由 2 和 3 组成，且 3 尽可能多。
- **边界用例**：n = 2、3 必须特判，因为题面要求至少两段；n % 3 == 1 时要退掉一个 3，把它和余数 1 组成 2 + 2。

```dart
/// 贪心（不取模）：尽可能拆出 3；余数为 1 时把一个 3 换成 2 + 2。
int cuttingRope(int n) {
  if (n == 2) return 1;
  if (n == 3) return 2;
  var timesOf3 = n ~/ 3;
  // 1. 余 1 时，3 + 1 的乘积 3 不如 2 + 2 的乘积 4，退掉一个 3。
  if (n - timesOf3 * 3 == 1) timesOf3--;
  final timesOf2 = (n - timesOf3 * 3) ~/ 2;
  // 2. 余 0 全是 3，余 2 只有一个 2，余 1 已经变成两个 2。
  return _pow(3, timesOf3) * _pow(2, timesOf2);
}
```
<!-- verify: .work/verify/A13/a13_cut_rope.dart -->

复杂度：不取模版本做 O(n / 3) 次普通乘法（n ≤ 58 时结果不超过 64 位有符号整数上限）。取模版本 n 最大 1000，`3^332` 远超 64 位整数范围，必须用快速幂逐步取模，完整实现（含 `cuttingRopeMod`、`_powMod` 与 `BigInt` 精确 DP 对拍）见同一个验证文件。这里的基础假设是原生平台 64 位 `int`：两个小于 10⁹ + 7 的数相乘不超过 10¹⁸，仍在 2⁶³ − 1 之内（[Dart 内置类型文档](https://dart.dev/language/built-in-types)）；若在 Dart Web 上运行，`int` 按 JavaScript 数值表示，范围只有 ±2⁵³ − 1，此时必须改用 `BigInt`。验证文件用 `BigInt` 精确动态规划在 n = 2…1000 上对拍了贪心与取模结果。

## 面试考点与追问

- **识别与证明**：先说清“贪心是不可撤销的选择加存在性证明”，再给交换论证的完整链条；只背“每一步取最优”会被追问反例。
- **区间调度的排序键**：结束时间最早是安全选择，理由是剩余可用时间最长；被追问时补两个反例（按开始时间、按长度）。
- **端点定义**：435 的相接不算重叠、飞镖问题的相接算重叠，条件分别是 `>=` 和 `>`；端点定义改变后必须重做交换检查，不能照搬。
- **贪心与动态规划**：分界是“局部选择是否可以被交换进某个最优解”；分数背包可以，0-1 背包不可以。
- **哈夫曼**：最低频符号可以被交换到最深的一对兄弟叶子上，所以每次合并最低频的两个节点；码字不唯一，唯一的只是最优加权路径长度。
- **工程细节**：Dart 的 `List.sort` 不保证稳定，相等键需要显式次关键字；取模加快速幂要说明位宽假设。

## 小结

贪心的代码通常只有几行，真正的工作量在证明：先确认“存在一个最优解包含这一步选择”，再确认剩余问题是同型子问题；写不出这两步，就应该回到动态规划或者用小规模穷举找反例。
