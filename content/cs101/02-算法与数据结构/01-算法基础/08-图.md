# 算法与数据结构｜08-图：表示、遍历与最短路径

课程有先修依赖，好友关系互相指向，路网里两点之间往往不止一条路线——这些关系都不是“一对多”。把这类数据塞进树的结构里，第一件会发生的事通常是死循环：树的遍历默认没有环，而依赖和社交网络里到处是环。

树依赖两个前提：每个节点只有一个父节点，任意两点之间只有一条简单路径。图把这两个前提都去掉了，问题也因此变多：能不能到达、最少走几步、总代价多少、一组依赖能不能排出执行顺序、加一条边会不会形成环。

本文沿这条主线推进：先分清图的类型与术语，因为类型直接决定可选算法；再比较邻接表、邻接矩阵和边集；然后从广度优先搜索（Breadth-First Search，BFS）与深度优先搜索（Depth-First Search，DFS）的共同框架出发，依次解决无权最短路、非负权最短路、依赖排序和动态连通；最后收束到选择边界、常见坑与四道例题。

## 为什么树不够表达一般关系

树的遍历之所以简单，是因为“从根往下走”这个方向本身包含了顺序信息：不会回到祖先，也不需要比较哪条路更短。图没有这种便利，三点差别直接对应三类新问题：

- **多路径**：同样的起点和终点之间可能有很多路线。树只问“能不能到达”，图必须问“哪条路代价最小”。
- **环**：无向图里一条边天然构成往返，有向图里 `A 依赖 B`、`B 依赖 A` 会互相等待。遍历必须显式记录“进过哪些顶点”，否则同一个环会被无限走下去。
- **方向与权重**：`A 是 B 的先修课` 与反向的边是两条不同的边；`A 到 B 有 5 公里` 和“A 到 B 有一条边”也不是同一件事。

判断方法很直接：如果数据里存在“两个对象互相引用”“同一对对象间有多个连接”或“连接有代价”，那就不是树；如果只需要保持层级并快速查找，树仍然更省事（见[树与二叉树](./06-树与二叉树.md)）。

决定算法选型的是三件事：有向还是无向、边有没有权重、要回答的是可达性、最短路、先后顺序还是动态连通——同一组顶点和边，换一个目标就要换一套算法；它是不是“一张图”并不是关键。

## 图的术语与分类

图由顶点集合 V 和边集合 E 组成，记作 `G = (V, E)`。下面几个维度决定后续能选哪些算法，读题时应当先把它们标出来。

### 有向与无向

无向边 `{u, v}` 表示 u 与 v 相邻；有向边（弧）`u -> v` 表示只能从 u 走到 v。无向图通常展开成两条弧，所以无向图的弧数是边数的两倍。顶点的度在两种图里含义不同：无向图中度是相邻顶点数，有向图中拆成入度（指向它的弧数）与出度（它指出的弧数）。指向自身的边叫自环，同一对顶点之间的多条边叫平行边；它们不改变算法框架，但会影响度数统计。

### 权重、路径与环

边带数值代价就是加权图；不带权重时把每条边的代价视为 1，也就是“无权图”。路径是顶点序列，长度有两种口径：无权图里是边的条数，加权图里是边权之和——本文提到“距离”时都会说明是哪一种。环是起点与终点相同的路径；加权图中环的总权重为负就叫负环，穿过它可以让路径代价无限变小，此时“最短路”根本没有定义。

### 连通、强连通与 DAG

无向图中任意两个顶点都能互相到达，就叫连通图，极大连通子图叫连通分量。有向图的门槛更高：任意两点双向可达才叫强连通，对应的极大子图是强连通分量（Strongly Connected Component，SCC）。只要求沿边方向能排出先后顺序、不含任何有向环的图叫有向无环图（Directed Acyclic Graph，DAG）。

| 图的类型 | 判定要点 | 典型问题 |
| --- | --- | --- |
| 无向无权 | 边双向、代价相同 | 连通分量、最少边数路径、无向环检测 |
| 有向无权 | 边的方向有意义 | 可达性、拓扑排序、有向环检测 |
| 有向带权（非负） | 每条弧带非负代价 | 单源最短路 |
| 有向带权（可含负权） | 允许负代价，需排除负环 | 带负权的最短路、负环检测 |
| DAG | 有向且无环 | 依赖排序、路径计数、关键路径 |

> 同一份边列表按有向和无向两种口径解释，会得到不同的度数与连通性结论；题面写的是 `[a, b]` 时先确认“谁指向谁”——把无向边只登记一次是遍历丢边的头号来源。

## 图的表示

### 三种表示与取舍

三种表示回答的是同一个问题“与某个顶点相邻的还有谁”，量级差异就是取舍依据：邻接表的空间与遍历都是 O(V + E)，判边要扫过 deg(u) 条边；邻接矩阵空间与遍历都是 O(V²)，但判边是 O(1)；边集的空间只有 O(E)，但判边与枚举邻居都要扫全部边。

稀疏图（E 远小于 V²）用邻接表；稠密图或顶点数很少、又需要频繁判边时用邻接矩阵；只按边迭代、不需要枚举邻居的算法（如 Bellman-Ford）可以直接用边集。

### Dart 数据模型与隐式图

最直接的邻接表是 `List<List<int>>`：外层下标是顶点，内层列表是出边终点；加权时把终点换成 `(终点, 权重)` 的 record 即可。下面这段代码把“登记边”收在一起，并说明两种登记口径的区别。

```dart
// 前置条件：Dart 3.12.2；纯 Dart，无第三方依赖；Dart VM。
/// 无权有向图的邻接表；无向图靠双向登记同一张表来表达。
class AdjacencyList {
  AdjacencyList(this.vertexCount)
    : outgoing = List<List<int>>.generate(vertexCount, (_) => <int>[]);

  final int vertexCount;
  final List<List<int>> outgoing;

  // 1. 有向边只登记一次：from -> to。
  void addDirected(int from, int to) {
    outgoing[from].add(to);
  }

  // 2. 无向边等价于两条方向相反的弧，漏掉任何一条都会丢掉连通性。
  void addUndirected(int a, int b) {
    outgoing[a].add(b);
    outgoing[b].add(a);
  }
}
```

companion 文件里还有 `arcCount()`（弧数等于所有出度之和）与 `transpose()`（每条弧掉头，用于“从终点反向搜索”）。同一份边列表 `[[0,1],[1,2],[2,0],[2,3]]` 分别按有向和无向建表后：有向口径下顶点 3 的出度是 0（它只有入度），无向口径下弧数是边数的两倍、顶点 3 的度是 1；转置后 `2 -> 0` 变成 `0 -> 2`，出度与入度互换。

“遍历是 O(V + E)”只对邻接表成立；换成邻接矩阵后，枚举单个顶点的邻居要扫一整行，整张图遍历退化为 O(V²)，稀疏图上凭空多出一个 V 倍。

> **面试高频：** 邻接表和邻接矩阵怎么选？
> **答题脉络：** 估算顶点数与边数量级 → 稀疏图选邻接表拿 O(V + E) 的遍历 → 需要 O(1) 判边或图很稠密时选矩阵 → 只按边计算的算法直接用边集。
> **追问方向：** 无向图要登记几条弧；反向图怎么建；顶点编号从 1 开始时数组怎么留空位。

大量题目把图藏在二维数组里：`1` 是陆地、`0` 是水，或者 `0` 可走、`1` 是墙。这时不需要构造顶点对象和邻接表——行列下标就是顶点编号，邻居由固定偏移量算出，网格的表示与原地修改见[数组与字符串](./02-数组与字符串.md)。代价是算法与网格结构绑定：一旦要换成一维编号或动态加边，就得补上真正的建图步骤。

## BFS 与 DFS

### 共同框架与标记时机

两种遍历做的是同一件事，只有一处不同：BFS 用队列（先进先出，见[栈与队列](./04-栈与队列.md)），DFS 用栈或递归（先入后出，见[递归、分治与回溯](./11-递归、分治与回溯.md)）。其余三件事完全一致：维护“待访问”集合、给每个顶点一个标记、每次取出一个顶点后把它的未标记邻居放进集合。

BFS 的性质来自队列顺序：第 k 层顶点全部在第 k+1 层之前出队，所以第一次访问某个顶点时走的边数最少。DFS 的性质来自栈顺序：它会把一条路走到底再回头，因此天然适合整条路径相关的处理，例如后序位置记录与回溯枚举；它的显式栈写法只多一个细节——邻居要逆序压栈，才能在弹栈时保持与递归一致的访问顺序。

```dart
/// BFS 分层遍历：返回访问顺序。
List<int> bfsOrder(List<List<int>> graph, int start) {
  final order = <int>[];
  final visited = List<bool>.filled(graph.length, false);
  final queue = Queue<int>()..addLast(start);
  visited[start] = true; // 1. 入队时立即标记。
  while (queue.isNotEmpty) {
    final u = queue.removeFirst();
    order.add(u);
    for (final v in graph[u]) {
      // 2. 只有未标记的邻居才入队：保证每个顶点最多进队一次。
      if (visited[v]) continue;
      visited[v] = true;
      queue.addLast(v);
    }
  }
  return order;
}
```

把标记推迟到出队时再做，结果看起来“也能跑”：无权 BFS 的距离仍然正确，因为距离只在第一次写入时生效，但顶点会被重复放进队列。companion 文件构造了一张两层各 3 个顶点、第二层每个顶点有 3 条入边的图，两种写法差异如下（Dart 3.12.2，Windows x64，代码内计数）：入队时标记共入队 7 次、无重复出队；出队时标记入队 13 次、重复出队 6 次，距离结果两者相同。差值来源很清楚：第二层 3 个顶点各有 3 条入边，出队才标记时它们会被各自的 3 个前驱各推一次，多出的 6 次出队是纯开销。用邻接表时这种重复是 O(E) 级别的；用邻接矩阵时每次重复都要扫一整行，总代价上升为 O(V · E)，稠密图上就是 O(V³)。

### 非连通图与连通分量

单次遍历只能覆盖与起点连通的顶点。要处理非连通图，必须在外面再套一层循环，对每个还没被访问过的顶点重新发起一次遍历，遍历次数就是连通分量数。孤立顶点不会被任何一次搜索“发现”，只能靠这层外层循环命中——漏掉它是最常见的计数错误。

`visited` 的语义是“已经进入待访问集合”，不是“已经处理完”。把它放在入队（入栈）的位置，是保证每个顶点只被处理一次、从而让遍历保持 O(V + E) 的前提。

> **面试高频：** BFS 和 DFS 怎么选？
> **答题脉络：** 先看问题要“最少步数”还是“整条路径/后序处理” → 前者用 BFS 的分层性质，后者用 DFS 的栈性质 → 再看图是否可能很深，深图避免递归 DFS → 两者复杂度同为 O(V + E)，差别在性质而不在效率。
> **追问方向：** 为什么 DFS 不能直接求出无权最短路；显式栈与递归的访问顺序是否必须一致；出队才标记 `visited` 会付出什么代价。

## 无权图最短路

无权图里边的代价都是 1，“最短路”就是最少边数路径。BFS 的分层性质正好给出答案：队列中顶点按距离非降排列，所以距离第一次被写入时就是最短距离，不需要任何比较；顺带记录一个前驱数组，就能在 O(V) 时间内还原任意可达顶点的一条最短路径。

```dart
/// BFS 距离与前驱：distance[start] == 0，predecessor[start] == -1。
(List<int> distance, List<int> predecessor) bfsDistance(
  List<List<int>> graph,
  int start,
) {
  final distance = List<int>.filled(graph.length, unreachable);
  final predecessor = List<int>.filled(graph.length, -1);
  final queue = Queue<int>()..addLast(start);
  distance[start] = 0;
  while (queue.isNotEmpty) {
    final u = queue.removeFirst();
    for (final v in graph[u]) {
      if (distance[v] != unreachable) continue;
      // 3. 距离首次被写入就是最短距离：同层顶点的距离全部相等。
      distance[v] = distance[u] + 1;
      predecessor[v] = u;
      queue.addLast(v);
    }
  }
  return (distance, predecessor);
}
```

同一文件里的 `pathTo(predecessor, target)` 沿前驱一路回溯到起点再反转，得到 `0->1->2->3->4` 这样的显式路径。时间是 O(V + E)（前提是使用邻接表），额外空间是 O(V) 的队列、距离与前驱数组。

用 DFS 代替 BFS 会得到一个不同的量：它记录的是“第一次走到目标时走了多深”，而这不是最短距离。在一张“0 到 1 到 2 到 3 到 4 的长链，再加一条 0-4 捷径”的图上，BFS 给出的距离是 1，而 DFS 先走长链时首次到达顶点 4 的深度是 4。DFS 缺少“先看近处”的保证，这与实现优劣无关。

> BFS 给出最短路的条件是“所有边的代价相同”。一旦边带权重，层数最小不等于代价最小——BFS 会找出边数最少的路径，而不是总权重最小的路径。

## 非负权最短路

边带权重之后，路径的好必须重新定义。所有带权最短路算法都在重复一个局部修正动作——松弛（relax）：如果 `d[u] + w < d[v]`，就更新 `d[v] = d[u] + w` 并把 v 的前驱改成 u。它们区别只在“按什么顺序松弛、松弛多少次”。

Dijkstra 的核心是从尚未确定的顶点里取出当前候选距离最小的那个，宣布它的距离已经确定，然后用它去松弛邻居。这个“宣布确定”之所以成立，依赖两个条件：所有边权非负，以及每次取的都是最小候选。

```dart
/// 非负权单源最短路：返回 (距离数组, 前驱数组)。
(List<int> distance, List<int> predecessor) dijkstra(
  List<List<WeightedEdge>> graph,
  int source,
) {
  final n = graph.length;
  final distance = List<int>.filled(n, infinity);
  final predecessor = List<int>.filled(n, -1);
  final heap = MinHeap();
  distance[source] = 0;
  heap.push((0, source));
  while (!heap.isEmpty) {
    // 1. 取出当前距离最小的顶点：它的距离已经不会再变小。
    final (d, u) = heap.pop();
    // 2. 陈旧条目：同一顶点可能被多次入堆，旧距离直接丢弃。
    if (d > distance[u]) continue;
    // 3. 松弛：只对“能变短”的出边写入新距离。
    for (final (v, weight) in graph[u]) {
      if (weight < 0) {
        throw ArgumentError('Dijkstra 要求非负权，收到了权重 $weight');
      }
      final candidate = d + weight;
      if (candidate < distance[v]) {
        distance[v] = candidate;
        predecessor[v] = u;
        heap.push((candidate, v));
      }
    }
  }
  return (distance, predecessor);
}
```

在 companion 文件的例图里，`0 -> 1` 直连代价 4，而 `0 -> 2 -> 1` 只要 3：Dijkstra 会先取出代价更小的顶点 2，最终给出距离 3，并让前驱数组还原出 `0->2->1->3`。第 3 步的 `if (weight < 0) throw` 不是装饰，而是显式声明算法的前提——遇到负权边时它宁可直接报错，也不返回一个看似正常的结果。

Dart SDK 没有内置优先队列，companion 文件手写了一个最小二叉堆，入堆与出堆都是 O(log n)；堆结构的完整推导见[堆与优先队列](./07-堆与优先队列.md)。工程代码也可以直接用 `package:collection` 的 `HeapPriorityQueue`，其官方文档同样把入队与取出描述为摊还 O(log n)。

Dijkstra 的复杂度必须连实现口径一起说：线性扫描未确定顶点是 O(V²)，不需要堆、稠密图表现稳定；二叉堆配合“减小键”是 O((V + E) log V)，每个顶点出堆一次、每条边触发一次键更新；本文写法允许陈旧条目，距离变小时就再入堆一次，出堆时用 `d > distance[u]` 丢掉旧条目，因此堆中最多有 E 条记录，时间按入堆条目数计是 O(E log V)。前驱数组会随更短路径的出现而更新，这正是 companion 文件里“先入堆的 10 被后来的 2 覆盖”所检查的行为。

### 负权边为什么破坏不变量

只要允许负权，就存在这样的输入：某个顶点的距离先被“宣布确定”，之后又从另一个顶点绕过来发现更短的路线。下面这个小图就是最小反例。

```text
顶点与边：0 -> 1 (2)、0 -> 2 (3)、2 -> 1 (-2)
真实最短距离：d(1) = 0 -> 2 -> 1 = 1

教科书版 Dijkstra（出堆即定案）的执行过程：
  取出 0：d(1) = 2 入堆，d(2) = 3 入堆
  取出 1（d = 2，此时最小）：定案 d(1) = 2，顶点 1 没有出边
  取出 2（d = 3）：想把 2 -> 1 的 -2 边松弛成 1，但 1 已定案，只能放弃
结果：d(1) = 2，与真实的 1 不符
```

companion 文件 `bellman_ford.dart` 验证了两件事：出堆即定案的教科书版 Dijkstra（该文件里的 `dijkstraFinalizingEarly`）在这张图上给出 2，而 Bellman-Ford 给出正确的 1；本文正式版 Dijkstra 则直接拒绝负权输入。

Bellman-Ford 的思路是把松弛顺序这件事彻底放弃：任意最短路径最多包含 V - 1 条边，所以反复扫描全部边并松弛 V - 1 轮即可，时间 O(V · E)。它允许负权边；如果第 V 轮仍有边能被松弛，说明存在从源点可达的负环，此时最短路没有下界。本文只把它当作 Dijkstra 的边界入口——负环检测针对的是从源点可达的负环，全源最短路与最小生成树是另外的问题。

Dijkstra 的“已确定”不变量同时依赖非负权与“每次取最小”两个条件：非负权保证后续发现的新路径不会比当前候选更短，取最小保证候选顺序与最终顺序一致。去掉任何一个，被提前定案的顶点就可能被更短的路径推翻。

> **面试高频：** Dijkstra 为什么不能处理负权边？
> **答题脉络：** 先复述不变量：出堆的顶点被宣布为最终距离 → 负权边意味着“绕远路可能更便宜”，后续仍可能产生更小距离 → 不变量被破坏 → 需要能重复松弛的算法。
> **追问方向：** 负环与负权边的区别；Bellman-Ford 的轮数与复杂度；O((V + E) log V) 与 O(E log V) 分别对应哪种实现。

## 拓扑排序

有一类问题不关心“怎么走代价最小”，只关心“谁必须排在谁前面”：选课依赖、构建任务依赖、包安装顺序。能回答这个问题的是拓扑排序——把 DAG 的顶点排成线性序列，使每条边 `u -> v` 中的 u 都排在 v 前面；如果图里有环，这个顺序根本不存在。

Kahn 入度法的思路是“谁没有未完成的前置，谁就可以先做”：把所有入度为 0 的顶点放进队列，取出一个就把它从图里删掉（后继入度减一），谁减到 0 谁就解锁。最终输出的顶点数少于 V，就说明剩下的顶点互相依赖。

```dart
/// Kahn 入度法：返回一个拓扑序；图中有环时返回 null。
List<int>? kahnOrder(List<List<int>> graph) {
  final n = graph.length;
  final inDegree = List<int>.filled(n, 0);
  for (var u = 0; u < n; u++) {
    for (final v in graph[u]) {
      inDegree[v]++;
    }
  }
  // 1. 入度为 0 的顶点没有前驱，可以最先安排。
  final queue = Queue<int>();
  for (var v = 0; v < n; v++) {
    if (inDegree[v] == 0) queue.addLast(v);
  }
  final order = <int>[];
  while (queue.isNotEmpty) {
    final u = queue.removeFirst();
    order.add(u);
    for (final v in graph[u]) {
      // 2. 去掉 u 之后，后继 v 的入度减一；减到 0 就解锁。
      if (--inDegree[v] == 0) queue.addLast(v);
    }
  }
  // 3. 输出顶点数少于 V：剩下的顶点互相依赖，构成环。
  return order.length == n ? order : null;
}
```

另一种做法是 DFS 后序反转：在递归返回时才把顶点加入列表，最后整体反转。它的环检测靠三色标记——白色是未访问，灰色是“正在递归栈上”，黑色是已完成；走到灰色顶点说明存在回到当前路径的边，也就是环。companion 文件的 `dfsPostOrder` 用 `_unvisited / _onStack / _done` 实现了这一点。

两种实现的输出都不唯一：同一张图可能有多个合法顺序。若题目要求“字典序最小的顺序”，把 Kahn 的普通队列换成最小堆即可。测试里两种实现在同一张图上输出了不同的序列，且都用 `isValidTopologicalOrder` 校验通过。

拓扑序存在当且仅当图是 DAG。Kahn 输出长度不足 V，正好说明剩下的顶点构成了环，并非算法没算完；也正因为顺序通常不唯一，只有每一步可选的顶点都唯一时才谈得上唯一拓扑序。

> **面试高频：** 拓扑排序如何判环？结果唯一吗？
> **答题脉络：** 先确认是有向图 → 入度法用“输出顶点数少于 V”判环，DFS 用“回到递归栈上的顶点”判环 → 顺序不唯一，需要最小字典序时把队列换成最小堆。
> **追问方向：** 无向图能不能做拓扑排序；Kahn 与 DFS 各自的额外收益；如何求出所有依赖路径而不是一条顺序。

## 并查集

还有一类问题既不关心路径，也不关心顺序，只反复问“这两个元素现在是不是同一个集合”，并且会不断把两个集合合并起来。典型场景是动态连通：网络里两台主机是否连通、加多少条边才会出现环、账户去重时哪些账号属于同一个人。

朴素做法很直接：给每个顶点存一个分量编号，合并时把其中一个分量的所有顶点改写成另一个编号。这就是 Quick Find——查询 O(1)，但每次合并要扫描整个数组，O(n)。反过来只改一个指针（Quick Union）能让合并变快，代价是查询要沿父指针向上找根，最坏退化成深度 n 的链。两个改进可以叠加：合并时总把较小的树挂到较大的树下面（按大小或按秩合并），树高被压到 O(log n)；查询时顺手把路径上的顶点直接挂到根上（路径压缩），后续几乎不再需要上行。实现上只有两个数组：`parent[v]` 初始指向自己、表示每个顶点各成一个分量，`sizeOf[root]` 记录这棵树的大小，`union` 时被更新的就是这两个数组。

```dart
class CompressedWeightedUf {
  final List<int> parent;
  final List<int> sizeOf;

  int find(int v) {
    // 1. 先沿父指针找到根，同时记录这一段路有多长。
    var root = v;
    while (parent[root] != root) {
      root = parent[root];
    }
    // 2. 再把路径上的每个顶点直接改指根节点。
    var current = v;
    while (parent[current] != root) {
      final next = parent[current];
      parent[current] = root;
      current = next;
    }
    return root;
  }

  bool union(int a, int b) {
    final rootA = find(a);
    final rootB = find(b);
    if (rootA == rootB) return false;
    // 3. 这里的比较用“树的大小”，合并规则与不压缩版本一致。
    if (sizeOf[rootA] < sizeOf[rootB]) {
      parent[rootA] = rootB;
      sizeOf[rootB] += sizeOf[rootA];
    } else {
      parent[rootB] = rootA;
      sizeOf[rootA] += sizeOf[rootB];
    }
    return true;
  }
}
```

两种改进的效果可以分离观察。companion 文件在 1024 个顶点上做了两组对比（Dart 3.12.2，Windows x64，计数由代码内的 `steps` 统计）：链式合并 `union(v, v + 1)` 时，Quick Find 的数组写入次数是 1047552，正好等于 `(n - 1) · n`；Quick Union 的森林最大深度是 1023；按大小合并的森林最大深度是 1。换成“每次把两棵同样大的树并起来”的均衡合并后，按大小合并的树高是 10，也就是 log₂ 1024；在这样一棵树上查询全部 1024 个顶点，不压缩版本累计上行 5120 次，路径压缩版本累计 3049 次、最终树高降到 1。压缩版本并没有降到 0，因为 `union` 内部也要调用 `find`，压缩在合并阶段就已经生效，所以“3049 比 5120 少”才是这组对比的准确读法。

复杂度要按合并规则分别写：Quick Find 的 `union` 是 O(n)；Quick Union 的 `find` 与树高同阶，最坏 O(n)；按大小（或按秩）合并的树高是 O(log n)；再叠加路径压缩后，单次操作的均摊成本是 O(α(n))，其中 α 是阿克曼函数的反函数（inverse Ackermann function），增长极慢，长序列的总成本是 O((n + m) · α(n))。归档素材里“非常接近 1”只是一种直观说法，严谨表述就是这组均摊界；也不要把它写成 O(1)。

并查集维护的是一种等价关系：只回答“是否同一集合”，不记录两点的具体路径，不支持把集合拆开，也完全不看边的方向。需要路径时用 BFS 或 Dijkstra，需要方向与顺序时用拓扑排序。

> **面试高频：** 并查集的复杂度与适用边界是什么？
> **答题脉络：** 先说朴素实现的代价（Quick Find 合并 O(n)、Quick Union 最坏树高 n）→ 再说两个改进分别解决什么（按大小/秩压树高、路径压缩把均摊降到 O(α(n))）→ 最后说清它不做什么：不给路径、不支持拆分、不区分方向。
> **追问方向：** 路径压缩为什么不会破坏正确性；按大小与按秩的区别；合并后集合数量如何维护。

## 什么时候用，什么时候别用

把前文结论收成一张选择表。先读题面确认图类型（有向/无向、有无权重），再按问题目标挑算法：

| 问题目标 | 首选算法 | 前提与边界 |
| --- | --- | --- |
| 可达性、连通分量、无向环检测 | BFS 或 DFS | 邻接表下 O(V + E)，两种遍历等价 |
| 无权图最少边数路径 | BFS | 所有边代价相同，需距离与前驱数组 |
| 非负权单源最短路 | Dijkstra | 不能有负权边，复杂度取决于取最小候选的实现 |
| 可含负权的单源最短路、负环检测 | Bellman-Ford | O(V · E)，检测从源点可达的负环 |
| 依赖顺序、有向环检测 | 拓扑排序 | 只对 DAG 有解，结果通常不唯一 |
| 动态连通、加边过程中判无向环 | 并查集 | 只回答是否同集合，不支持拆分与路径查询 |

- **网格题不要为“规范”去建通用对象图。** 下标就是顶点编号，邻居由偏移量给出，隐式表示更省内存也更少出错。
- **有向图的环检测不能用并查集。** 它表达的是无向的等价关系，`A -> B` 与 `B -> A` 在它眼里都是“A 与 B 合并”，会把有向环判成无环。
- **只问“是否同一集合”时不要写最短路。** 哈希表与并查集的分工见[哈希表](./05-哈希表.md)：前者面向“是否出现过”，后者面向“是否同集合”的增量合并。
- **边权可能为负、需要全源最短路、或路径带额外约束时，不要直接套本文模板。** 负权与负环属于 Bellman-Ford 的地盘；带“只能经过 k 条边”“必须避开某些点”这类约束时，往往需要扩展状态再搜。

并查集与 BFS 都能回答“是否连通”，差别在于并查集面向“多次合并 + 多次查询”的增量场景且看不到路径，BFS/DFS 面向“给定当前图求一次结果”的场景且顺带给出路径与距离。

## 常见坑与边界

### 常见误区

- ❌ 把 `[a, b]` 当成“a 指向 b”而不看题面。✅ 先确认依赖方向（如 `[课程, 先修]` 表示先修指向课程）再建边；方向搞反时拓扑排序会给出相反的顺序，却仍然“看起来合理”。
- ❌ 出队时才标记 `visited`。✅ 入队（入栈）时就标记：距离结果可能不变，但队列会被重复条目撑大。
- ❌ 只从一个起点搜一次就统计连通分量。✅ 外层循环要覆盖全部顶点，孤立顶点只有在那一层才会被计数。
- ❌ 认为网格的斜角也是邻居。✅ 4 邻域与 8 邻域是不同的图，题面写了“8-directionally connected”才能斜着走（见[例题 2](#例题-2leetcode-1091-二进制矩阵中的最短路径)）。
- ❌ 假设拓扑序唯一。✅ 只有每一步可选的顶点都唯一时才唯一；需要最小字典序就把队列换成最小堆。
- ❌ 在 1-based 编号的题里直接拿顶点号当数组下标，或忘记维护分量数。✅ `parent` 数组要开 n + 1 个槽位；分量数只在成功合并时减 1（见[例题 4](#例题-4leetcode-684-冗余连接)）。
- ❌ 在带负权的图上跑 Dijkstra 并相信结果。✅ 要么换 Bellman-Ford，要么在实现里显式拒绝负权输入。
- ❌ 把并查集的“非常接近 O(1)”当成 O(1)，或以为它能给出路径、能拆集合。✅ 严谨说法是均摊 O(α(n))；路径查询与动态拆分别属于 BFS/Dijkstra 与其他数据结构。

递归 DFS 的深度等于当前路径上的顶点数，而不是顶点总数，链式输入下可能是 O(V)。例题 1 在 300×300 全陆地的最大输入上（90000 个格子）会抛出 `StackOverflowError`，同一输入的显式队列版本正常返回（Dart 3.12.2 / Windows x64；调用栈上限随平台与线程配置而变）；规模未知时优先考虑迭代写法，或把递归深度写进输入约束。另外，多重边与自环不改变算法框架，但会改变入度、出度与环检测的结论，判定前要确认它们是否在输入范围内。

## 知识点应用

### 例题 1：LeetCode 200. 岛屿数量

[题目链接（力扣）](https://leetcode.cn/problems/number-of-islands/)

前置条件：Dart 3.12.2；纯 Dart；网格由 `'0'`/`'1'` 组成，`1 <= m, n <= 300`。

- **不变量**：`sink` 被调用时格子一定是未访问的陆地，返回时与它连通的所有陆地都被改写成 `'0'`；因此外层循环每命中一次 `'1'`，恰好对应一个尚未统计的岛屿。
- **实现**（原地修改网格，用 `'0'` 代替 visited 矩阵）：

```dart
/// 岛屿数量；grid 会被就地修改，调用后网格内不再有 '1'。
int numIslands(List<List<String>> grid) {
  if (grid.isEmpty || grid.first.isEmpty) return 0;
  final rows = grid.length;
  final columns = grid.first.length;
  var islands = 0;

  void sink(int r, int c) {
    // 1. 越界或不是陆地就返回：这是递归的基线。
    if (r < 0 || r >= rows || c < 0 || c >= columns || grid[r][c] != '1') {
      return;
    }
    // 2. 上岸即改写成水，代替额外的 visited 矩阵。
    grid[r][c] = '0';
    // 3. 只向上下左右四个方向扩散：斜角不算连通。
    sink(r - 1, c);
    sink(r + 1, c);
    sink(r, c - 1);
    sink(r, c + 1);
  }

  for (var r = 0; r < rows; r++) {
    for (var c = 0; c < columns; c++) {
      if (grid[r][c] != '1') continue;
      // 4. 每发现一块没被淹掉的陆地，就说明多了一个连通分量。
      islands++;
      sink(r, c);
    }
  }
  return islands;
}
```

- **复杂度**：时间 O(m · n)（每个格子最多被访问一次），空间 O(m · n)（最坏情况下的递归栈或队列）。
- **边界用例**：题面两个示例分别返回 1 与 3；四角相连的网格返回 4（斜角不算连通）；全水返回 0；单格陆地返回 1。原地修改是有代价的：断言检查了调用后网格中不再有 `'1'`。

### 例题 2：LeetCode 1091. 二进制矩阵中的最短路径

[题目链接（力扣）](https://leetcode.cn/problems/shortest-path-in-binary-matrix/)

前置条件：Dart 3.12.2；纯 Dart；`0` 可通行、`1` 是墙，`1 <= n <= 100`，相邻格按 8 方向连通。

- **不变量**：队列中格子的距离非降；格子第一次被写入距离时就等于最短步数，因此可以提前返回，不必遍历完整张图。
- **实现**（不修改输入；方向表由常量给出，便于对照 4 邻域）：

```dart
int _shortestPath(List<List<int>> grid, List<(int, int)> directions) {
  final n = grid.length;
  // 1. 起点或终点被挡住时不可能有清晰路径。
  if (grid[0][0] != 0 || grid[n - 1][n - 1] != 0) return -1;

  final distance = List<List<int>>.generate(n, (_) => List<int>.filled(n, -1));
  final queue = Queue<(int row, int column)>();
  distance[0][0] = 1; // 2. 距离就是经过的格子数，起点算 1。
  queue.addLast((0, 0));
  while (queue.isNotEmpty) {
    final (row, column) = queue.removeFirst();
    if (row == n - 1 && column == n - 1) return distance[row][column];
    for (final (dr, dc) in directions) {
      final nextRow = row + dr;
      final nextColumn = column + dc;
      // 3. 越界、是墙、或已经访问过都不入队。
      if (nextRow < 0 || nextRow >= n) continue;
      if (nextColumn < 0 || nextColumn >= n) continue;
      if (grid[nextRow][nextColumn] != 0) continue;
      if (distance[nextRow][nextColumn] != -1) continue;
      // 4. BFS 首次到达就是最短：同层顶点的距离相同。
      distance[nextRow][nextColumn] = distance[row][column] + 1;
      queue.addLast((nextRow, nextColumn));
    }
  }
  return -1;
}
```

### 例题 4：LeetCode 684. 冗余连接

[题目链接（力扣）](https://leetcode.cn/problems/redundant-connection/)

前置条件：Dart 3.12.2；纯 Dart；输入是 n 个顶点（编号 1..n）的 n 条无向边，保证图由一棵树加一条边构成。

- **不变量**：处理完前 k 条边后，并查集的分量划分等同于这 k 条边构成的连通关系；因此“两端已连通”当且仅当加入这条边会形成环。
- **实现**（按大小合并 + 路径压缩，替换归档题解里的 Quick Find 版本；`find` 与上一节相同）：

```dart
  // 1. 题面顶点编号是 1..n，数组要留出 n + 1 个槽位。
  final parent = List<int>.generate(edges.length + 1, (v) => v);
  final sizeOf = List<int>.filled(edges.length + 1, 1);

  // 2. 逐条加边：一旦两端已经连通，这条边就是环上的多余边。
  for (final edge in edges) {
    final a = edge[0];
    final b = edge[1];
    final rootA = find(a);
    final rootB = find(b);
    if (rootA == rootB) return [a, b];
    // 3. 按大小合并，保证树高是对数级。
    if (sizeOf[rootA] < sizeOf[rootB]) {
      parent[rootA] = rootB;
      sizeOf[rootB] += sizeOf[rootA];
    } else {
      parent[rootB] = rootA;
      sizeOf[rootA] += sizeOf[rootB];
    }
  }
  return const [];
```

- **复杂度**：时间 O(n · α(n))（每条边两次 `find`，均摊接近常数），空间 O(n)。
- **边界用例**：题面示例返回 `[2, 3]`；`[[1,4],[1,2],[2,3],[3,4]]` 这类“回边出现在前面”的输入要返回输入中最后一条可选边 `[3,4]`，companion 文件用暴力算法（逐条尝试删除并检查剩下的 n - 1 条边是否连通无环）交叉验证了这一点；1000 个顶点的链加一条闭合边也能正确处理。`edges.length + 1` 的数组长度是 1-based 编号的关键，少一个槽位就会越界。

## 面试考点与追问

1. **BFS 与 DFS 的差别是什么？** 只有“待访问集合是队列还是栈”这一处，其余框架相同 → 差别体现在性质上：BFS 给出分层与最短边数，DFS 给出路径结构与后序位置 → 复杂度同为 O(V + E)。追问：为什么 DFS 不能求无权最短路；树遍历代码能不能直接搬到图上；哪些处理必须放在后序位置。
2. **`visited` 什么时候标记？** 入队/入栈时标记保证每个顶点最多被处理一次 → 出队才标记会重复入队，距离可能仍正确但成本上升 → 加权算法中“需要重复松弛”是另一种情形。追问：出队才标记在什么情况下会给出错误答案；邻接矩阵下的重复扫描代价。
3. **邻接表与邻接矩阵怎么选？** 稀疏图选邻接表拿 O(V + E) 的遍历 → 稠密图或需要 O(1) 判边时选矩阵 → 只按边计算的算法用边集。追问：无向图要登记几次；反向图如何构造；1-based 编号怎么处理。
4. **Dijkstra 为什么不能处理负权边？** 不变量是“出堆即最终” → 负权边让绕远的路线可能更便宜 → 已定案的顶点可能被推翻 → 需要 Bellman-Ford 这类允许重复松弛的算法。追问：负权边与负环的区别；Bellman-Ford 为什么是 V - 1 轮；两种复杂度口径来自哪种实现。
5. **拓扑排序如何判环？结果唯一吗？** 入度法用输出顶点数是否达到 V 判环，DFS 用三色标记判环 → 顺序通常不唯一 → 最小字典序把队列换成最小堆。追问：无向图的拓扑排序为什么没有定义；如何同时输出所有合法顺序。
6. **并查集的复杂度与边界？** Quick Find 合并 O(n)、Quick Union 最坏树高 n → 按大小/秩合并把树高压到 O(log n)，路径压缩把单次操作均摊降到 O(α(n)) → 它不给路径、不支持拆分、不看方向。追问：为什么路径压缩不破坏正确性；为什么有向环检测不能用它。

## 小结

读图题的顺序是固定的：先判断有向还是无向、边有没有权重，再选表示，然后按问题目标挑算法——可达性与连通分量用 BFS/DFS，无权最短路用 BFS，非负权最短路用 Dijkstra，依赖顺序用拓扑排序，动态连通用并查集。每一种选择都带着前提，把前提写进代码（例如拒绝负权的 `throw`）比事后猜结果可靠得多。
