## 为什么线性数据仍值得系统学习

长度 n 的序列有 n(n+1)/2 个连续区间。如果每问一次“某个区间的和、最值或是否满足条件”都重新扫一遍区间，光枚举区间就是 Θ(n²)，再叠加内层操作就会到 Θ(n³)。线性技巧的价值，就在于把这些重复计算换成一次性的状态维护。

数组和字符串能支持这些技巧，是因为它们提供了三类可推导的结构信息：**顺序**（前后关系稳定，排序后还带来单调性，有序才能放心丢掉一侧）、**连续**（区间增删一个端点时，和、计数、最值可以增量更新）、**下标**（`i` 与 `n - 1 - i` 的对称、`i + k` 的偏移、环形下标）。

双指针、滑动窗口、前缀和不是三套孤立模板，它们都在用位置关系消掉重复计算；能否套用，取决于问题是否具备对应的单调性或可累加性。

本文只讨论一维序列的通用技巧。链表用节点引用代替下标（见[链表](./03-链表.md)），矩阵是“数组的数组”，栈、队列与哈希表各有一篇主文。

## 数组的存储模型与操作成本

数组模型的核心是“位置由下标决定”：元素按位置排成一列，`a[i]` 的地址可以由首地址加 `i × 元素大小` 直接算出，因此按下标读写在模型上是 O(1)。代价来自同一个约束——位置必须连续：一旦在中间插入或删除，插入点之后的元素都要整体后移或前移。

| 操作 | 模型成本 | 原因 |
|---|---|---|
| 按下标读/写 `a[i]` | O(1) | 地址由下标直接算出 |
| 按值查找 | O(n) | 位置未知，只能逐个比较 |
| 尾部追加 | 均摊 O(1) | 容量不足时整体搬移，摊到每次追加是常数次写入 |
| 中间插入/删除 | O(n) | 插入点之后的元素整体后移或前移 |

O(1) 随机访问和 O(n) 中间插删来自同一条约束：元素按位置排列。想保留快速按下标定位，就必须接受改动位置时的整体搬移；这是抽象成本，不排除具体实现用缓存或批量搬移改变常数因子。

落到 Dart：`List<E>` 是“可按下标索引、有长度”的接口，默认实现是可增长数组。官方文档在 [List class](https://api.dart.dev/stable/dart-core/List-class.html) 页面说明默认可增长列表时保证“一串 `add` 操作各自均摊常数时间”，同时提醒“其他 `List` 实现可能有不同的性能行为”。`List.filled` 的 `growable` 默认为 `false`，得到固定长度列表；`[]` 字面量得到可增长列表。下面的程序同时观察这三件事：

```dart
// 前置条件：Dart 3.12.2；纯 Dart（只依赖 dart:core）；Dart VM 原生 64 位 int。
// 运行：dart run --enable-asserts .work/verify/A02/list_model.dart
void main() {
  // 1. List.filled 的 growable 默认为 false，得到固定长度列表。
  final fixed = List<int>.filled(3, 0);
  var rejectedAdd = false;
  try {
    fixed.add(1);
  } on UnsupportedError {
    rejectedAdd = true;
  }
  print('固定长度列表拒绝 add：$rejectedAdd');

  // 2. [] 字面量创建可增长列表，长度可以由 add 改变。
  final growable = <int>[1, 2, 3];
  growable.add(4);
  print('可增长列表：$growable');

  // 3. 中间插入要把后半段整体后移：移动次数 = 已用长度 - 插入位置。
  //    这里用"缓冲区预留一格"的模型模拟一次 insert，并数出真实的元素写入次数。
  final buffer = List<int>.filled(9, 0);
  for (var i = 0; i < 8; i++) {
    buffer[i] = i;
  }
  var moved = 0;
  for (var i = 8; i > 2; i--) {
    buffer[i] = buffer[i - 1];
    moved++;
  }
  buffer[2] = 99;
  print('在索引 2 插入：移动 $moved 个元素，结果 $buffer');
}
```

<!-- verify: .work/verify/A02/list_model.dart -->

实际输出印证了三点：固定长度列表拒绝 `add`；在 8 个元素、索引 2 处插入要移动 6 个元素；可增长列表可以直接追加。中间插入的成本在于“多搬了多少元素”，而不是“多了几个元素”——移动次数正好等于已用长度减去插入位置。尾部追加虽然单次最坏也要搬一次全部元素，但把连续 n 次追加的总搬移量摊开，平均到每次是常数次写入；完整的均摊推导见[复杂度分析与算法思想](./01-复杂度分析与算法思想.md#最好平均最坏期望与均摊)。

## Dart 中的 List 与 String

### List：接口、可变性与视图

`List<E>` 是接口，不是某一种具体存储；`<int>[]` 是默认的可增长实现，`List<int>.filled(n, 0)` 默认是固定长度实现。[Dart 的泛型是具化的](https://dart.dev/language/generics)（reified）：类型实参在运行期保留并参与检查，`List<int>` 经 `dynamic` 混入其他类型会在运行期抛 `TypeError`，`list is List<int>` 也能在运行期判定，不靠约定。固定长度列表改长度会抛 `UnsupportedError`；可增长列表支持 `add`、`insert`、`removeAt`，其中 `insert` 和 `removeAt` 的代价就是上表里的 O(n) 搬移。

还有两个容易忽略的行为：`List.filled(n, fill)` 的 n 个位置[共享同一个 `fill` 对象](https://api.dart.dev/stable/dart-core/List/List.filled.html)，填充引用类型时要用 `List.generate(n, (_) => [])`，否则会“改一个、全都变”；复制与视图也不同，[`sublist`](https://api.dart.dev/stable/dart-core/List/sublist.html) 返回新列表，[`asMap()`](https://api.dart.dev/stable/dart-core/List/asMap.html) 是底层列表的不可写视图，`List.unmodifiable` 适合对外暴露只读快照。

```dart
// 前置条件：Dart 3.12.2；纯 Dart（只依赖 dart:core）。
// 运行：dart run --enable-asserts .work/verify/A02/list_views.dart
void main() {
  final source = <int>[1, 2, 3];

  // 1. sublist 返回新列表：改动副本不影响源列表。
  final copy = source.sublist(0, 2);
  copy[0] = -1;
  print('复制：$copy，源列表：$source');

  // 2. asMap 返回不可写视图：源列表变化后，视图读到的值一起变化。
  final view = source.asMap();
  source[0] = 100;
  print('视图：view[0] = ${view[0]}');
}
```

<!-- verify: .work/verify/A02/list_views.dart -->

区分复制与视图看的是“底层是不是同一份数据”，能不能写并不是标准。只读检查用视图，不必付出拷贝成本；需要隔离时用复制，代价是 O(k) 的拷贝。

### String 没有 char：三层口径

Dart 的 [`String`](https://api.dart.dev/stable/dart-core/String-class.html) 不可变，内容是一串 UTF-16 码元，这一点与 Java、JavaScript 一致；不同之处在于 Dart 没有独立的 `char` 类型，`s[i]` 返回的是一个只含单个码元的字符串。同一个“字符”在三种口径下的数量可以不同：

| 口径 | 含义 | Dart 入口 |
|---|---|---|
| 码元 | UTF-16 编码单元，16 位 | `length`、`s[i]`、`codeUnitAt`、`codeUnits` |
| 码点 | Unicode 标量值；增补平面字符用代理对表示 | `runes` |
| 字素簇 | 用户感知的一个字符，可含多个码点 | `characters`（`package:characters`） |

[Dart 团队维护的 `characters` 包](https://pub.dev/packages/characters)当前稳定版是 1.4.1，基于 Unicode 16.0.0，提供字素簇级别的切分。编码原理、代理对与乱码排查属于数据表示篇，见[字符编码与乱码](../../01-数据表示/02-字符编码与乱码.md)；这里只看 Dart 的行为：

```dart
// 前置条件：Dart 3.12.2；纯 Dart；characters 1.4.1（Dart 团队维护，dart:core 没有字素簇 API）。
// 运行：dart run --enable-asserts .work/verify/A02/string_layers.dart
import 'package:characters/characters.dart';

void main() {
  const ascii = 'Dart'; // 基本多文种平面：三种口径的数量相同
  const clef = '\u{1D11E}'; // 高音谱号：两个码元、一个码点
  const family = '\u{1F468}\u{200D}\u{1F469}\u{200D}\u{1F467}\u{200D}\u{1F466}';
  const precomposed = '\u00E9'; // é：单个码点
  const decomposed = 'e\u0301'; // e + 组合尖音符

  // 1. 码元口径：下标、length 和 codeUnits 都在 UTF-16 码元上工作。
  print('ascii.length=${ascii.length}，clef[0] 的码元=${clef[0].codeUnits}');
  print("clef.split('') 得到 ${clef.split('').length} 段，代理对被拆开");

  // 2. 码点口径：runes 把代理对合成一个码点。
  print('clef：length=${clef.length}，runes.length=${clef.runes.length}');

  // 3. 字素簇口径：characters 按用户感知的字符切分。
  print(
    'family：码元 ${family.length}、码点 ${family.runes.length}、'
    '字素簇 ${family.characters.length}',
  );
  print(
    'é：码元序列相等=${precomposed == decomposed}，'
    '字素簇个数 ${precomposed.characters.length} 和 ${decomposed.characters.length}',
  );
}
```

<!-- verify: .work/verify/A02/string_layers.dart -->

运行输出：`clef` 的 `length=2`、`runes.length=1`，`split('')` 得到 2 段；`family` 的码元、码点、字素簇数量是 11、7、1；两种写法的 é 码元序列不相等，字素簇都是 1 个。

在 Dart 里问“字符串有多长”之前，先说明问的是码元、码点还是字素簇。`s[i]` 只保证返回一个码元；`split('')` 按码元切分，可能产出不成对的代理值。

## 双指针

双指针指用两个下标在同一序列上协同移动。常见三种形态：相向（从两端向内）、同向（读写分离或快慢）、两个序列各持一个指针（归并）。形态本身不重要，重要的是循环不变量、移动规则和终止条件能否写清楚。

### 相向双指针：移动为什么不会漏解

以 [167. Two Sum II - Input Array Is Sorted](https://leetcode.com/problems/two-sum-ii-input-array-is-sorted/)（归档：[LeetCode 题解 - 双指针](../02-LeetCode题解/01-双指针.md)）为例：数组按非递减顺序排列，要求找出和等于 `target` 的两个数。

- **不变量**：若存在解 `(p, q)`（`p < q`），则始终有 `left <= p` 且 `q <= right`，解还留在 `[left, right]` 内。
- **移动规则**：若 `nums[left] + nums[right] < target`，那么对任意 `k <= right` 都有 `nums[left] + nums[k] <= nums[left] + nums[right] < target`，`nums[left]` 不可能出现在任何解里，可以安全 `left++`；和偏大时同理抛弃 `nums[right]`。
- **终止条件**：`left >= right` 时区间内没有剩余的一对数。

```dart
// 前置条件：Dart 3.12.2；纯 Dart，无第三方依赖；numbers 按非递减顺序排列。
// 运行：dart run --enable-asserts .work/verify/A02/two_sum_ii.dart
/// 返回 1 起始的一对下标；题目保证恰好一组解，未找到时返回空列表。
List<int> twoSumSorted(List<int> numbers, int target) {
  var left = 0;
  var right = numbers.length - 1;
  while (left < right) {
    final sum = numbers[left] + numbers[right];
    if (sum == target) {
      return [left + 1, right + 1];
    }
    // 1. 和偏小：numbers[left] 配上任何更靠左的右端只会更小，可以安全放弃它。
    if (sum < target) {
      left++;
    } else {
      // 2. 和偏大：numbers[right] 配上任何更靠右的左端只会更大，同样可以放弃。
      right--;
    }
  }
  return const [];
}
```

<!-- verify: .work/verify/A02/two_sum_ii.dart -->

每个下标最多被访问一次，时间 O(n)；只用两个下标变量，额外空间 O(1)。注意“不会漏解”的论证只用到数组有序：双指针的合法性来自单调性，不来自“指针动了两下”。

相向双指针的移动规则必须由“被放弃的那一侧不可能再有解”推出来；如果只能靠试一试验证，说明还缺一个单调性前提。

### 同向指针：读写职责分离

同向双指针把下标分成“读”和“写”两种职责，不变量是：

`[0, write)` 是已经就位的输出，`[read, length)` 是还没读过的输入，且 `write <= read` 恒成立。

写指针不会越过读指针，所以写操作永远不会破坏未读数据，可以在原数组上完成保序压缩或去重：[283. Move Zeroes](https://leetcode.com/problems/move-zeroes/) 压缩非零元素，[26. Remove Duplicates from Sorted Array](https://leetcode.com/problems/remove-duplicates-from-sorted-array/) 去重，都是同一结构。快慢指针（链表判环、找中点）是同向指针在链表上的对应形态，见[链表](./03-链表.md#快慢指针)。

快慢指针的“快慢”指职责划分而非速度设定：一个负责发现，一个负责写下；所有原地的同向双指针算法都靠 `write <= read` 这个不变量保证安全。

## 滑动窗口

滑动窗口可以看成“两个指针 + 一个区间统计量”。它有两种形态：窗口宽度固定，或宽度随约束变化。

### 固定窗口：进出各一次

固定窗口求“长度为 k 的窗口最大和”：先算出第一个窗口，之后每移动一步，右边进一个元素、左边出一个元素，窗口宽度恒为 k。

```dart
// 前置条件：Dart 3.12.2；纯 Dart，无第三方依赖；1 <= k <= nums.length。
// 运行：dart run --enable-asserts .work/verify/A02/fixed_window.dart
/// 返回所有长度为 k 的窗口中的最大和；每个元素进出窗口时各被处理一次。
int maxFixedWindowSum(List<int> nums, int k) {
  var sum = 0;
  for (var i = 0; i < k; i++) {
    sum += nums[i]; // 1. 先算出第一个窗口的和。
  }
  var best = sum;
  for (var right = k; right < nums.length; right++) {
    sum += nums[right]; // 2. 右边进一个。
    sum -= nums[right - k]; // 3. 左边出一个，窗口宽度保持为 k。
    if (sum > best) {
      best = sum;
    }
  }
  return best;
}
```

<!-- verify: .work/verify/A02/fixed_window.dart -->

每个元素最多进窗口一次、出窗口一次，时间 O(n)；只需要窗口和与当前最优两个变量，额外空间 O(1)。这段代码也示范了滑窗的常见写法：不要在循环里重算窗口统计量，而是用“进入”和“退出”两个增量操作维护它。

### 可变窗口：收缩条件必须单调

可变窗口的通用模板只有四步：`right` 右移并加入 `nums[right]`；只要窗口不满足约束，`left` 就右移并移出 `nums[left]`；窗口合法时用当前窗口更新答案；直到 `right` 走完整个序列。

模板成立需要两个单调性前提：扩张只会让约束变差（或不变），收缩只会让它变好（或不变）；并且“窗口是否合法”能由当前统计量判断。缺一个，模板不只是会变慢，还会直接给出错误答案。

复杂度上，`left` 和 `right` 都只向右移动：`right` 最多走 n 步，内层 `while` 里 `left` 的总步数也不超过 n，所以“进窗口 + 出窗口”合计 O(n)。注意这是摊还意义上的 O(n)：某一步可能连续收缩多次，但总步数有上界。剑指 Offer 48 进一步利用“最近位置”把 while 收缩优化成一次跳转：记录每个字符最近出现的下标，如果它落在当前窗口内，`left` 直接跳到它的下一位，效果等价于执行了若干次 `left++`。

两个失效的例子值得记住。含负数的数组求“和 ≥ target 的最短子数组”时，扩张不再让和单调增大，`left` 右移还可能让和变大，模板失效，要改用前缀和加哈希计数（见[哈希表](./05-哈希表.md#常见组合)）。求每个窗口的最大值时，窗口最大值在收缩时无法 O(1) 还原，需要单调队列，见[栈与队列](./04-栈与队列.md#单调队列)。

滑动窗口比双指针多一个前提：窗口的合法性必须随端点移动单调变化。不满足单调性时，套模板会漏解，而不是仅仅变慢。

## 前缀和与差分

### 半开区间与前缀和

前缀和把“重复累加”换成“一次预处理 + 两次相减”。约定 `prefix[i]` 表示前 i 个元素之和，`prefix[0] = 0`，于是半开区间 `[l, r)` 的和就是

`prefix[r] - prefix[l]`

闭区间 `[left, right]` 等价于半开区间 `[left, right + 1)`，代进去就是 `prefix[right + 1] - prefix[left]`。多开一位（长度 n+1）的目的正是让 `left = 0` 时公式不变；如果定义成“含当前元素的和”，每个从 0 开始的区间都要特判。

预处理 O(n)，每次查询 O(1)，额外空间 O(n)。二维是同样的思路：`P[i][j]` 表示前 i 行、前 j 列的元素和，矩形 `[r1, r2) × [c1, c2)` 的和用容斥得到 `P[r2][c2] - P[r1][c2] - P[r2][c1] + P[r1][c1]`。

前缀和把区间查询降到 O(1) 的代价是“数据必须静态”：数组一旦修改，已建好的前缀和就失效，需要重建或改用动态结构。

### 差分：前缀和的逆运算

差分数组记录相邻元素之差：`diff[i] = a[i] - a[i-1]`，约定 `a[-1] = 0`。给区间 `[l, r]` 整体加 `value` 时只需要两处记账：`diff[l] += value`、`diff[r+1] -= value`；最后对 `diff` 求一遍前缀和，就还原出每个位置的实际值。

```dart
// 前置条件：Dart 3.12.2；纯 Dart，无第三方依赖；区间按闭区间 [l, r] 传入。
// 运行：dart run --enable-asserts .work/verify/A02/difference_array.dart
/// 差分数组：用 O(1) 记录一次区间加，最后用一次前缀和还原每个位置的值。
class DifferenceArray {
  DifferenceArray(int length) : _diff = List<int>.filled(length + 1, 0);

  final List<int> _diff;

  // 1. 区间 [l, r] 加 value：起点记账，r 的下一位反向记账。
  void add(int l, int r, int value) {
    _diff[l] += value;
    _diff[r + 1] -= value;
  }

  // 2. 前缀和把差分还原成每个位置的累计增量。
  List<int> toValues() {
    final values = List<int>.filled(_diff.length - 1, 0);
    var running = 0;
    for (var i = 0; i < values.length; i++) {
      running += _diff[i];
      values[i] = running;
    }
    return values;
  }
}
```

<!-- verify: .work/verify/A02/difference_array.dart -->

每次区间加是 O(1)，最后还原一次 O(n)，额外空间 O(n)。它适合“先批量修改、最后统一读取”的离线场景；如果修改和查询交替出现，“点更新 + 区间查询”要换树状数组或线段树，本文只点到为止。

前缀和与差分互为逆运算：前者用 O(n) 预处理换 O(1) 区间查询，后者用两个端点记账换 O(1) 区间修改；两者都要求另一半是静态的或离线的。

## 原地修改与覆盖方向

原地算法要求 O(1) 额外空间，代价是必须想清楚“往哪个方向写才不会覆盖还没读的数据”。常见方向有三种：读写指针（写指针只在已处理区间内前进，保序压缩，283）；从尾部写（两个有序序列归并到同一个数组时从后往前填，88）；循环覆盖（把下标看作映射 `i -> (i + k) mod n`，它会分成若干个环，必须让每个环写完回到起点，否则会丢元素；数组轮转也可以用三次反转绕开）。

```dart
// 前置条件：Dart 3.12.2；纯 Dart，无第三方依赖；nums1 的有效长度为 m + n。
// 运行：dart run --enable-asserts .work/verify/A02/merge_sorted_array.dart
/// 把有序的 nums2 归并进 nums1，原地完成，不返回新数组。
void mergeSorted(List<int> nums1, int m, List<int> nums2, int n) {
  var write = m + n - 1; // 1. 从最后一个位置开始写：未被覆盖的空位总在待读数据右侧。
  var i = m - 1;
  var j = n - 1;
  while (j >= 0) {
    // 2. 每轮把两个序列中较大的那个放到 write 位置。
    if (i >= 0 && nums1[i] > nums2[j]) {
      nums1[write] = nums1[i];
      i--;
    } else {
      nums1[write] = nums2[j];
      j--;
    }
    write--;
  }
  // 3. nums2 用完后不必再搬 nums1 的前缀：剩余元素已经在正确位置。
}
```

<!-- verify: .work/verify/A02/merge_sorted_array.dart -->

从尾部写的安全性来自一个不变量：循环每一轮开始时 `write = i + j + 1`，而 `i`、`j` 是尚未读取的下标，所以写入位置永远严格大于两个待读位置，不会覆盖还没比较的元素。反过来，如果从头写，第一次写入就可能覆盖 `nums1` 中还没读取的元素。

最后是接口契约：Dart 的 `List` 可变，函数如果就地修改参数，必须在名字或文档里说明；调用方若还要用原数据，先自行复制。原地是性能手段，不是默认行为。

原地修改的正确性取决于“未读数据永远不会被写指针覆盖”；覆盖方向和循环顺序都是为这个不变量服务的，写错方向算法必然失败。

## 什么时候用，什么时候别用

选择工具前先回答四个问题：数据有序吗？答案是连续区间吗？查询与修改哪个是批量的？输入允许被修改吗？

适合用的信号：

- 数组有序，或比较后能排除一侧 → 相向双指针。正例：167 在 O(n) 内找到两数之和；需要找边界位置时则用二分，见[查找与二分查找](./10-查找与二分查找.md#lower-bound-与-upper-bound)。
- 答案是连续区间，且窗口合法性随端点移动单调 → 滑动窗口。正例：Offer 48 最长不重复子串。
- 数据静态、查询很多 → 前缀和。正例：303 的多次区间和查询。
- 修改是一批区间加、之后才统一读取 → 差分。正例：多次给区间加值后一次性输出结果。
- 要求 O(1) 额外空间且输入可改 → 读写指针、从尾归并。正例：283 保序压缩、88 归并。

不适合用的信号（反例）：

- 需要频繁在中间插入删除 → 用可增长 `List` 反复 `insert` 会让整体退化到 O(n²)，考虑链表或其他结构。
- 窗口约束不单调 → 含负数的“子数组和恰好为 target”不能用滑窗，改用前缀和加哈希计数（[哈希表](./05-哈希表.md#常见组合)）。
- 既要区间查询、又要随时修改 → 前缀和与差分都不够，需要树状数组或线段树。
- 语义上要“用户感知的字符” → 不能用码元下标，改用 `characters`。
- 输入不能改（调用方共享、需要保留原序）→ 先复制或用不可变视图，不要偷偷就地修改。

## 常见坑与边界

- **空序列与单元素**：`nums.length - 1` 在空数组上得到 -1；滑窗前先检查 `k <= nums.length`，双指针先检查 `left < right`。Offer 48 对空串应返回 0。
- **端点约定混用**：一半用闭区间、一半用半开区间，off-by-one 就会冒出来。把公式钉死在一种约定上（本文统一用半开 `[l, r)` 推导，闭区间只在出入参转换时出现），并在函数名或注释里写清区间类型。
- **窗口收缩写错**：收缩条件要用 `while` 而不是 `if`；用“最近位置”直接跳左边界时，必须判断该位置是否落在当前窗口内（例如 `seen >= left`），否则 `left` 会被拉回更早的位置，窗口里重新出现重复字符。
- **前缀和溢出**：Dart 原生 [`int`](https://api.dart.dev/stable/dart-core/int-class.html) 是有符号 64 位补码，“溢出时回绕到该范围”（官方文档原文），不会抛异常；编译到 JavaScript 时整数只有 53 位精确度。先看题目给的范围，必要时用 `BigInt`，不要靠“结果看起来对”判断。
- **按码元切断字符**：`s[i]` 和 `split('')` 都作用于码元，可能产出不成对的代理值；要码点用 `runes`，要用户感知字符用 `characters`。
- **切片的额外成本**：`sublist` 每次返回新列表，在循环里对每个下标取一段较长的切片会把 O(n) 扫描变成 O(n²)；只需要读取时改用下标偏移或视图。
- **`List.filled` 的共享引用**：`List.filled(3, [])` 的三个位置是同一个列表对象；要独立对象就用 `List.generate`。

### 把 0 移到末尾：读写指针

[283. Move Zeroes](https://leetcode.com/problems/move-zeroes/)（归档：[14-数组与矩阵](../02-LeetCode题解/14-数组与矩阵.md)）。题目要求把所有 0 移到末尾、非零元素保持相对顺序，并且不能复制数组，这正是读写指针的适用信号。不变量：`[0, write)` 里的元素是已处理过的非零元素，保持原相对顺序；`read` 扫过的元素都已被判定。

```dart
// 前置条件：Dart 3.12.2；纯 Dart，无第三方依赖；原地修改 nums，不返回新数组。
// 运行：dart run --enable-asserts .work/verify/A02/move_zeroes.dart
/// 把所有 0 移到末尾，非零元素的相对顺序不变。
void moveZeroes(List<int> nums) {
  var write = 0; // 1. write 左侧是已经就位的非零元素。
  for (var read = 0; read < nums.length; read++) {
    if (nums[read] != 0) {
      nums[write] = nums[read]; // 2. 把非零元素按原顺序搬到前面。
      write++;
    }
  }
  // 3. 剩余位置全部置 0。
  for (var i = write; i < nums.length; i++) {
    nums[i] = 0;
  }
}
```

<!-- verify: .work/verify/A02/move_zeroes.dart -->

时间 O(n)（每个元素被读一次、非零元素被写至多一次）；额外空间 O(1)。边界：全 0（`write` 始终为 0，末段全部置 0）、没有 0（`write` 追平 `read`）、单元素（退化为不写不改），断言文件里各有一例。

### 最长不含重复字符的子串：可变窗口

剑指 Offer 48「最长不含重复字符的子字符串」（归档：[048-最长不含重复字符的子字符串](../03-剑指Offer题解/048-最长不含重复字符的子字符串.md)）。求最长的不含重复字符的连续子串长度，是可变窗口的标准题：右端点负责扩张，左端点负责在出现重复时恢复合法性。

> **时效信息（核查日期：2026-09-22）：** 力扣已把原“剑指 Offer”系列重编为 LCR 题号，本题现在的页面标题是 [LCR 167. 招式拆解 I](https://leetcode.cn/problems/zui-chang-bu-han-zhong-fu-zi-fu-de-zi-zi-fu-chuan-lcof/)，题干约束也扩大为字母、数字、符号与空格；英文站对应 [3. Longest Substring Without Repeating Characters](https://leetcode.com/problems/longest-substring-without-repeating-characters/)。

不变量：`[left, right]` 内始终不含重复字符；`lastSeen[ch]` 记录 `ch` 最近一次出现的下标。

```dart
// 前置条件：Dart 3.12.2；纯 Dart，无第三方依赖；按 UTF-16 码元切分（示例限定 ASCII 输入）。
// 运行：dart run --enable-asserts .work/verify/A02/longest_without_repeat.dart
/// 返回最长不含重复字符的子串长度；按码元切分，非 BMP 字符会被拆开。
int longestUniqueSubstring(String s) {
  var best = 0;
  var left = 0; // 窗口 [left, right] 始终不含重复字符。
  final lastSeen = <String, int>{}; // 字符 -> 最近一次出现的下标。
  for (var right = 0; right < s.length; right++) {
    final ch = s[right];
    final seen = lastSeen[ch];
    // 1. 重复字符若落在窗口内，左边界直接跳到它的下一位。
    if (seen != null && seen >= left) {
      left = seen + 1;
    }
    // 2. 记录当前位置，并用当前窗口长度更新答案。
    lastSeen[ch] = right;
    final length = right - left + 1;
    if (length > best) {
      best = length;
    }
  }
  return best;
}
```

时间 O(n)：`right` 走 n 步，`left` 每次跳转也只向右，累计不超过 n 步；额外空间 O(min(n, σ))，σ 为字符集大小。边界：空串返回 0、全同字符返回 1、`dbascDdad` 返回 6。注意本实现按码元切分字符串，示例只覆盖 ASCII；如果输入可能含增补平面字符，必须先明确题目要求的字符口径。

### 区间和查询：前缀和

[303. Range Sum Query - Immutable](https://leetcode.com/problems/range-sum-query-immutable/)（归档：[07-动态规划](../02-LeetCode题解/07-动态规划.md)）。题目给出一个静态数组，要求多次返回区间和；查询多、数据不变，正是前缀和的信号。不变量：`_prefix[i]` 表示前 i 个元素之和，`_prefix[0] = 0`。

```dart
// 前置条件：Dart 3.12.2；纯 Dart，无第三方依赖；查询满足 0 <= left <= right < n。
// 运行：dart run --enable-asserts .work/verify/A02/range_sum_immutable.dart
/// 用长度为 n + 1 的前缀和数组，支持 O(1) 的区间和查询。
class NumArray {
  NumArray(List<int> nums) : _prefix = List<int>.filled(nums.length + 1, 0) {
    // 1. prefix[i] 表示前 i 个元素之和，下标 0 是空区间。
    for (var i = 0; i < nums.length; i++) {
      _prefix[i + 1] = _prefix[i] + nums[i];
    }
  }

  final List<int> _prefix;

  /// 闭区间 [left, right] 的和，等价于半开区间 [left, right + 1)。
  int sumRange(int left, int right) => _prefix[right + 1] - _prefix[left];
}
```

<!-- verify: .work/verify/A02/range_sum_immutable.dart -->

构造 O(n)，每次查询 O(1)，额外空间 O(n)。边界：`left == right` 退化成单元素区间；`[0, n-1]` 是全区间；`nums` 为空时题目约束本身不成立（本题要求 `nums.length >= 1`），任何查询都会越界，验证文件里用 `RangeError` 显式观察到这一点。

### 除自身以外数组的乘积：前后缀累积

[238. Product of Array Except Self](https://leetcode.com/problems/product-of-array-except-self/)（归档：[08-数学](../02-LeetCode题解/08-数学.md)）。题目禁用除法并要求 O(n)，而除法在有 0 时本来也不成立，于是用“前缀积 × 后缀积”替代。不变量：第一遍结束后 `answer[i]` 等于 i 之前所有元素的乘积；第二遍从右往左乘上后缀积，`answer[i]` 就是最终答案。

```dart
// 前置条件：Dart 3.12.2；纯 Dart，无第三方依赖；不使用除法；输出数组不计入额外空间。
// 运行：dart run --enable-asserts .work/verify/A02/product_except_self.dart
/// 返回 answer，其中 answer[i] 是除 nums[i] 之外所有元素的乘积。
List<int> productExceptSelf(List<int> nums) {
  final n = nums.length;
  final answer = List<int>.filled(n, 1);
  // 1. 第一遍从左往右：answer[i] 先存下 i 之前所有元素的乘积。
  var prefix = 1;
  for (var i = 0; i < n; i++) {
    answer[i] = prefix;
    prefix *= nums[i];
  }
  // 2. 第二遍从右往左：再乘上 i 之后所有元素的乘积。
  var suffix = 1;
  for (var i = n - 1; i >= 0; i--) {
    answer[i] *= suffix;
    suffix *= nums[i];
  }
  return answer;
}
```

<!-- verify: .work/verify/A02/product_except_self.dart -->

时间 O(n)（两遍扫描），额外工作空间 O(1)，输出数组按题目追问的口径不计入额外空间。边界：数组含一个 0（除 0 所在位置外全为 0）、含两个 0（全为 0）、元素为负（乘积符号交替）。题目保证任意前后缀的乘积落在 32 位有符号范围内，而 Dart 原生 `int` 是 64 位；跨平台编译时仍要留意 53 位精度问题。

## 面试考点与追问

> **面试高频：** 数组和链表在访问与插删上的成本差异怎么答？
> **答题脉络：** 按下标访问 O(1) vs O(n) → 已知前驱后插删 O(1) vs O(n) → 强调“已知节点/前驱”这个前提 → 再补缓存局部性与内存开销。
> **追问方向：** 单链表删除当前节点为什么仍要 O(n)；哨兵节点；LRU 的哈希表与双链表怎么分工。

> **面试高频：** 滑动窗口为什么是 O(n) 而不是 O(n²)？
> **答题脉络：** 每个端点只单向移动 → `right` 最多 n 步 → 内层收缩的 `left` 总步数也有上界 → 结论是摊还 O(n)。
> **追问方向：** 什么条件下滑窗失效；固定窗口与可变窗口的差异；单调队列解决的最大值问题。

> **面试高频：** 前缀和数组为什么要多开一位？
> **答题脉络：** 定义成“前 i 个元素之和” → `[l, r)` 的和是 `prefix[r] - prefix[l]` → 闭区间 `[l, r]` 用 `prefix[r+1] - prefix[l]` → 多开一位让 0 起点不需要特判。
> **追问方向：** 二维前缀和的容斥；前缀异或和前缀积是否适用；数组可修改时前缀和为什么失效。

> **面试高频：** 归并两个有序数组到 `nums1`，为什么必须从尾部开始写？
> **答题脉络：** 从头写会覆盖 `nums1` 还没比较的元素 → 尾部是当前最大的空位 → 每轮 `write = i + j + 1` 保证写入位置在待读数据右侧。
> **追问方向：** 为什么 `nums2` 用完后就可以停止；链表归并不需要这个技巧的原因。

> **面试高频：** Dart 里 `s[i]` 拿到的到底是什么？
> **答题脉络：** 码元 → `length`、`split('')` 同口径 → `runes` 是码点 → `characters` 是字素簇 → 增补平面字符会被索引切坏。
> **追问方向：** emoji 的“长度”为什么可能是 2；如何截断字符串而不产生乱码；正则为什么也不能按字素簇匹配。

> **面试高频：** 如果区间查询要边改边查，前缀和还够用吗？
> **答题脉络：** 前缀和与差分都假设另一半静态或离线 → 点更新加区间查询需要树状数组或线段树 → 说明复杂度取舍。
> **追问方向：** 树状数组的 lowbit 含义；线段树的惰性标记；分块能否兼顾区间修改。

## 小结

选工具的顺序是：先看数据是否有序（决定能否用相向双指针），再看答案是否是连续区间且约束单调（决定能否用滑窗），然后看查询与修改的批量性（决定用前缀和还是差分），最后确认输入能不能改（决定是否原地修改）。字符串在套用任何技巧之前，还要先声明按码元、码点还是字素簇计数。
