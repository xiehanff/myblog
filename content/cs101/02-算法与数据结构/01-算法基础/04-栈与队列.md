# 算法与数据结构｜04-栈与队列

编辑器的撤销、浏览器的后退、编译器的括号检查、地图的最短路径搜索——这些功能看起来毫不相干，却在重复同一个动作：只关心“最近一个”或“最早一个”元素。用普通数组或哈希表硬解当然也能写出正确代码，但代价是必须自己维护“下一个该取谁”的记账，还要防止调用方绕过这份记账去修改数据。

栈（stack）与队列（queue）做的是减法：把访问限制在固定的一端或两端，让顺序成为结构自身的不变量。限制之后，撤销只需弹栈，括号匹配只需比较栈顶，层序遍历只需依次出队；反过来，当问题需要随机访问、按优先级取元素或任意位置插入删除时，它们就不再合适。

路线是：先看受限访问换来了什么，再依次建立栈、队列、双端队列的模型与实现成本，落到 Dart 的容器选择；然后用单调栈、单调队列解决两类“候选会被永久淘汰”的问题；最后用四道例题、常见坑与面试追问收束。本文假定你已了解均摊分析的基本口径，相关机制可先看[复杂度分析与算法思想](./01-复杂度分析与算法思想.md#最好平均最坏期望与均摊)。

## 为什么限制访问反而有用

先看两类最小场景。撤销功能要求“最近一次操作先被撤销”，括号匹配要求“最后打开的开括号先被闭合”，递归与深度优先搜索要求“先恢复最近的状态”——它们共享后进先出（Last-In-First-Out，LIFO）顺序。任务排队、消息缓冲、树的层序遍历则要求“最早到达的先被处理”，是先进先出（First-In-First-Out，FIFO）顺序。

如果不用这两种结构，通常有两种做法：要么每次遍历整个集合去找“最近/最早”的元素，把成本摊到每次操作上；要么自己维护一个游标并小心地增删元素，把顺序知识散落进业务代码。两种做法都让正确性依赖调用方的自觉。`List.removeAt(0)` 当队列的例子最能说明问题：写出队列语义不难，难的是让两端操作都保持廉价。

限制访问带来三个可验证的收益。

1. **不变量简单**：只有“最近未弹出”或“最早未出队”两个候选可操作，正确性只需一条顺序断言。
2. **两端操作便宜**：约束之后，数组或链表都能把关键操作做成常数时间，不必为了任意位置访问付出代价。
3. **接口窄**：调用方无法绕过结构去做中间插入，顺序不会在“看不见的地方”被破坏。

栈和队列是顺序契约，而不是存储方式。同一个底层数组可以实现成栈、环形队列或双端队列，区别在于允许哪些操作、以及两端的操作成本。

## 栈：后进先出

### 栈的不变量与基本操作

栈只开放一端：`push` 压入元素、`pop` 弹出并返回栈顶、`peek` 查看栈顶，外加 `isEmpty` 与元素个数。它的不变量可以精确写成一句话：**`pop` 返回最近一次尚未弹出的 `push` 元素**。栈不关心元素的值，也不提供按位置访问；正因为约束足够强，数组和链表都能轻松满足它。

逆序输出、括号与标签匹配、表达式求值、递归改迭代、深度优先搜索的显式栈，都是同一条不变量的不同外观。需要按到达顺序处理时不能用栈：把任务压入栈再弹出，会得到反过来的处理顺序。

### 数组栈与均摊扩容

数组栈把列表尾部当作栈顶：`add` 入栈，`removeLast` 出栈，`last` 查看栈顶。Dart 里这是最省事的栈表示。

```dart
// 前置条件：Dart 3.x；纯 Dart；无第三方运行时依赖。
// 用 List 的尾部当栈顶：add 入栈，removeLast 出栈。
void main() {
  final stack = <int>[];

  // 1. 入栈：新元素追加到列表尾部，尾部就是栈顶。
  stack.add(1);
  stack.add(2);
  stack.add(3);
  assert(stack.last == 3);

  // 2. 出栈：removeLast 先移除再返回，顺序与入栈严格相反。
  assert(stack.removeLast() == 3);
  assert(stack.removeLast() == 2);
  assert(stack.removeLast() == 1);
  assert(stack.isEmpty);

  // 3. 空栈上出栈会抛异常，而不是返回 null 或静默忽略。
  var threw = false;
  try {
    stack.removeLast();
  } on RangeError {
    threw = true; // Dart 3.12.2 原生 VM 实测为 RangeError。
  }
  assert(threw);

  print('List 栈：LIFO 成立；空栈 removeLast 抛出异常');
}
```

`pop` 与 `peek` 是常数时间。`push` 需要区分两种情形：容量未满时追加是常数时间；容量耗尽时需要申请更大数组并把已有元素复制过去，这一次是 O(n)。以常见的倍增扩容为模型（容量依次 1、2、4、8……），从空栈开始的 n 次 `push` 累计复制少于 2n 次，因此 **`push` 均摊（amortized）时间是 O(1)**。注意这是长序列的平均上界，某一次恰好触发扩容的 `push` 仍然可能是 O(n)。均摊 O(1) 说的是“n 次操作的总代价被 n 平摊后是常数”，并不保证每次操作都很快；把均摊写成最坏会低估长尾，把最坏写成均摊会在实时性要求下出错。

> **时效信息（核查日期：2026-09）：** Dart 3.12.2 的 `List.add`、`List.removeLast` 文档（[List API](https://api.dart.dev/dart-core/List-class.html)）只约定“可增长列表”等前提，没有承诺复杂度。本文的均摊结论由“倍增扩容模型”推导，不代表 Dart 运行时的公开契约。

若实现还需要在大量弹出后回收内存，可以在元素数降到容量的四分之一时把容量减半：这样再压入一个元素也不会立刻触发扩容，避免了在容量边界反复扩缩的抖动。弹栈时把腾出的槽位置空（release the reference）可以避免容器继续引用已经弹出的对象；在 Dart 中内存回收由 GC 负责，标准库容器是否清槽不是语言契约，不需要也不可能手动模仿。

### 链式栈

链式栈用单链表承载 LIFO：栈顶就是表头，`push` 用头插法新建节点，`pop` 摘掉表头。它与链表共享同一套节点操作，详见[链表](./03-链表.md)。

```dart
// 前置条件：Dart 3.x；纯 Dart；无第三方运行时依赖。
/// 单链表栈：头插法把最新元素放在表头，表头就是栈顶。
class LinkedStack<T> {
  _Node<T>? _top;
  int _size = 0;

  int get size => _size;
  bool get isEmpty => _top == null;

  // 1. 入栈：新节点先指向旧栈顶，再成为新的栈顶。
  void push(T value) {
    _top = _Node<T>(value, _top);
    _size++;
  }

  // 2. 出栈：取出旧栈顶的值后，让它的后继成为新栈顶。
  T pop() {
    final node = _top;
    if (node == null) throw StateError('stack is empty');
    _top = node.next;
    _size--;
    return node.value;
  }
}

class _Node<T> {
  _Node(this.value, this.next);

  final T value;
  _Node<T>? next;
}
```

完整文件含 `main()` 与断言（空栈 `pop` 抛 `StateError`），见 companion 的 `void main()` 部分。链式栈的每次 `push`、`pop` 都是最坏 O(1)，不需要扩容复制；代价是每个元素多一个引用字段、每次入栈多一次节点分配。数组栈则在“分配成本低的普通场景”下常数更小。两者没有绝对优劣，选谁取决于是否需要最坏情况保证。

链式栈用“每元素一个额外引用 + 每次入栈一次分配”换取每次操作的最坏 O(1)；数组栈用“偶尔一次 O(n) 复制”换取更小常数与更快访问。均摊最优与最坏最优是两种不同的保证。

> **面试高频：** 数组栈和链式栈怎么选？
> **答题脉络：** 先问是否需要最坏保证（实时上界不能有长尾扩容）→ 再看每元素开销（链表多一个引用、多一次分配）→ 数组栈均摊更省，链式栈最坏更稳。
> **追问方向：** 均摊与最坏的区别；扩容因子与缩容阈值；在有 GC 的语言里“节点分配”还算不算成本。

## 队列与双端队列

### FIFO 不变量与链式队列

队列开放两端：`addLast` 入队、`removeFirst` 出队、`first` 查看队首。不变量是：**`removeFirst` 返回尚未出队的最早 `addLast` 元素**。

用单链表实现队列时，需要同时维护队首与队尾两个引用：入队改 `last`，出队改 `first`。队首引用必须指向链表头，因为出队后要让队首的后继成为新队首，而这只有从表头出发才拿得到。难点不在“存”，而在两个端点必须始终满足同一条链式不变量：所有元素恰好落在 `first` 到 `last` 的这条单链上，队列为空时两个引用同时为空——出队把最后一个元素取走后如果不清空 `last`，它会继续指向已不在队列里的节点。

双端队列（double-ended queue，deque）在两端都允许进出：`addFirst`、`addLast`、`removeFirst`、`removeLast` 都是合法操作。它不新增顺序类型，只是把栈与队列合并成一种更通用的结构；单调队列就是只使用其中一部分操作的受限用法。

### 为什么 `List.removeAt(0)` 不是队列

用 `List` 模拟队列时，入队是 `add`，出队却只能写 `removeAt(0)`。[`List.removeAt` 的文档](https://api.dart.dev/dart-core/List/removeAt.html)明确写着它会“把后面所有元素向前移动一位”：数组头部腾出的空间不能被复用，代价被转嫁到搬移上。设队列中有 n 个元素，一次出队搬移 n−1 个元素，连续出队 n 次就是 Θ(n²)。正确选择是环形缓冲，或直接使用 `Queue`。

队列的约束是“两端操作都便宜”，不只是“按到达顺序取元素”这一句话。用数组头部出队能通过功能测试，却让每次出队的成本与队列长度成正比；只要队列会长期增长，这就不是可用的队列实现。

### 环形缓冲

环形缓冲（circular buffer）是数组队列的标准做法：固定容量的一段槽位，用 `head` 指向下一个出队位置、`tail` 指向下一个入队位置，两个下标都对容量取模、循环前进；出队不搬移元素，只把 `head` 向前挪一格。为了区分“空”和“满”（两种状态下 `head` 与 `tail` 都可能相等），额外维护元素个数 `size`，或者牺牲一个槽位作为判满标记。

```dart
// 前置条件：Dart 3.x；纯 Dart；无第三方运行时依赖。
/// 定长环形队列：用 head / tail 下标和 size 区分“空”与“满”。
/// 容量必须为正数；教学实现不做扩容，满了就报错。
class CircularQueue<T> {
  CircularQueue(this._capacity) : _slots = List<T?>.filled(_capacity, null);

  final List<T?> _slots;
  final int _capacity;
  int _head = 0; // 下一个出队的槽位
  int _tail = 0; // 下一个入队的槽位
  int _size = 0;

  int get size => _size;
  bool get isEmpty => _size == 0;
  bool get isFull => _size == _capacity;

  // 1. 入队：写 tail 槽后让 tail 前进一格并环绕。
  void addLast(T value) {
    if (isFull) throw StateError('queue is full');
    _slots[_tail] = value;
    _tail = (_tail + 1) % _capacity;
    _size++;
  }

  // 2. 出队：返回 head 槽的值、清空该槽，再让 head 环绕前进。
  T removeFirst() {
    if (isEmpty) throw StateError('queue is empty');
    final value = _slots[_head] as T; // _size > 0 保证该槽非空。
    _slots[_head] = null;
    _head = (_head + 1) % _capacity;
    _size--;
    return value;
  }

  // 3. 查看队首：只读 head 槽，不移动下标。
  T get first {
    if (isEmpty) throw StateError('queue is empty');
    return _slots[_head] as T;
  }
}
```

环形缓冲用下标环绕复用已出队元素腾出的空间，全程不搬移元素；它必须靠 `size`（或一个空槽标记）才能区分满与空，单看 `head == tail` 没有足够信息。

## 在 Dart 中选择容器

Dart 的集合库没有为栈单独定义类型：惯用表示就是 `List<T>` 的尾部操作。队列与双端队列统一由 `Queue<T>` 接口表达，`Queue()` 工厂默认返回 `ListQueue`（环形缓冲实现）；[`ListQueue` 文档](https://api.dart.dev/dart-collection/ListQueue-class.html)承诺 remove/peek 为常数时间、add 为均摊常数时间。需要明确的两端最坏常数时间时可以用 `DoubleLinkedQueue`，[其文档](https://api.dart.dev/dart-collection/DoubleLinkedQueue-class.html)承诺两端增删与查看均为常数时间，代价是每个元素多一个链引用。

| 需求 | 惯用容器 | 关键操作 | 实现与文档承诺 |
|---|---|---|---|
| 栈（LIFO） | `List<T>` | `add` / `removeLast` / `last` | 没有专用 `Stack` 类型；尾部即栈顶；复杂度未做文档承诺 |
| 队列与双端队列 | `Queue<T>`（默认 `ListQueue`） | `addLast` / `removeFirst` / `addFirst` / `removeLast` / `first` / `last` | 环形缓冲；remove/peek 常数时间、add 均摊常数时间 |
| 需要明确的两端最坏常数时间 | `DoubleLinkedQueue<T>` | 同上 | 双链表；两端增删与 peek 常数时间 |

```dart
// 前置条件：Dart 3.x；纯 Dart；无第三方运行时依赖。
// 用 dart:collection 的 Queue 覆盖队列与双端队列操作。
import 'dart:collection';

void main() {
  final queue = Queue<int>();
  // 1. Queue() 默认由 ListQueue 实现（文档承诺 remove/peek 常数时间）。
  assert(queue is ListQueue<int>);

  // 2. FIFO：addLast 入队，removeFirst 出队。
  queue.addLast(1);
  queue.addLast(2);
  queue.addLast(3);
  assert(queue.first == 1);
  assert(queue.removeFirst() == 1);
  assert(queue.removeLast() == 3);

  // 3. addFirst 让它同时充当双端队列（栈顶换到队首）。
  queue.addFirst(0);
  assert(queue.first == 0 && queue.last == 2);

  // 4. 空队列上取元素抛 StateError，而不是返回 null。
  queue.clear();
  var threw = false;
  try {
    queue.removeFirst();
  } on StateError {
    threw = true;
  }
  assert(threw);

  // 5. 双链表实现同样满足 Queue 接口，两端操作有常数时间文档承诺。
  final Queue<int> deque = DoubleLinkedQueue<int>();
  deque.addLast(1);
  deque.addFirst(0);
  assert(deque.first == 0 && deque.removeLast() == 1);

  print('Queue：FIFO、双端操作与空队列 StateError 断言通过');
}
```

> **时效信息（核查日期：2026-09）：** 截至 Dart 3.12.2，`dart:core` 与 `dart:collection` 中没有名为 `Stack` 的集合类型；栈由 `List<T>` 或自定义类型承担。`List<T>` 也没有专门的双端队列操作，需要 `addFirst` 时请用 `Queue<T>`。

在 Dart 中，“栈”是 `List` 的一种用法，“队列与双端队列”统一由 `Queue` 表达；`ListQueue` 这个默认实现就是前面手写的环形缓冲，官方文档给出的复杂度承诺正好对应它的三个操作。

> **面试高频：** Dart 里没有 `Stack` 类型，栈和队列分别用什么？
> **答题脉络：** 栈 → `List` 的 `add` / `removeLast` / `last` → 队列与双端队列 → `Queue` 接口，默认 `ListQueue` → 需要文档承诺的两端最坏常数时间时换 `DoubleLinkedQueue`，同时说明每元素多一个链引用。
> **追问方向：** `removeAt(0)` 为什么不能当队列；`Queue()` 的默认实现是什么；空容器上操作的异常行为。

## 单调栈

### 从暴力到线性

“对每个元素，求它右侧第一个更大的元素”是单调栈的入门问题。暴力做法对每个位置向右扫描，最坏 O(n²)——当数组严格递减时，每个元素都要扫到末尾才能确认没有答案。

换一个角度：从左到右扫描时，有些元素的答案还“悬而未决”。扫描到新元素 x 时，栈顶那些比 x 小的候选立刻被 x 解决；而它们被弹出后，就再也不会影响后续判断了。栈里保存的正是这些“尚未解决”的元素。为了同时得到位置（计算距离、写入答案），栈里存下标而不是值。

以 `[2, 1, 2, 4, 3]` 为例：2 入栈；1 比栈顶 2 小，也入栈；下一个 2 弹出 1 并结算（它的下一个更大值就是 2），但弹不出 2，于是 2 入栈；4 依次弹出 2、2 并结算；最后 3 入栈，栈里留下 4 和 3，它们没有更大的后继。

```dart
// 前置条件：Dart 3.x；纯 Dart；无第三方运行时依赖。
/// 返回每个元素右侧第一个严格更大的元素，不存在则为 -1。
List<int> nextGreaterValue(List<int> numbers) {
  final result = List<int>.filled(numbers.length, -1);
  final stack = <int>[]; // 存下标；对应值从栈底到栈顶严格递减。

  for (var i = 0; i < numbers.length; i++) {
    // 1. 弹出所有比当前元素小的候选，并就地结算答案。
    while (stack.isNotEmpty && numbers[stack.last] < numbers[i]) {
      result[stack.removeLast()] = numbers[i];
    }
    // 2. 当前下标成为新的“尚未解决”候选。
    stack.add(i);
  }
  return result;
}
```

### 为什么弹出就是正确答案

设被弹出的下标为 p，当前下标为 i（栈顶满足 `a[p] < a[i]` 时才会弹出）。要证明 i 是 p 右侧第一个更大位置，只需排除中间存在更大元素：如果存在 j 满足 p < j < i 且 `a[j] > a[p]`，那么扫描到 j 时 p 已经在栈里（否则 p 的答案会更早确定，与它在 i 时刻仍未被弹出矛盾），而栈顶条件会让 j 把 p 弹出，p 不可能留到现在。矛盾说明 p 与 i 之间没有更大的元素，i 就是答案。

代价方面，每个下标恰好入栈一次，出栈至多一次，栈操作的累计次数不超过 2n，所以整个扫描是 O(n) 时间、O(n) 额外空间（栈最多同时保存 n 个下标）。单调栈的“单调”指栈内元素对应值从栈底到栈顶保持有序，方向取决于问题：求“下一个严格更大”时栈内严格递减、弹出更小者；求“下一个严格更小”时全部反过来。

单调栈在被弹出时才结算答案：栈里是尚未找到答案的候选，弹出意味着“第一个更大的元素出现了”；每个下标至多进出一次，这是它把暴力 O(n²) 降成 O(n) 的根据。

> **面试高频：** 单调栈弹出时结算，为什么不会漏掉答案？
> **答题脉络：** 先定义栈里存什么（尚未解决的下标）→ 再反证“中间若有更大元素会更早弹出” → 得出弹出时刻的 i 就是右侧第一个更大位置 → 最后由每个下标进出各一次得到 O(n)。
> **追问方向：** 相等值弹不弹；为什么存下标不存值；把“下一个更大”换成“下一个更小”要改哪几处。

## 单调队列

### 队首过期与队尾淘汰

滑动窗口最大值要求每移动一格返回窗口内的最大值。暴力做法每次重扫窗口，共 O(n·k)；用大顶堆可以做到 O(n log k)（仓库归档的剑指 Offer 59 用的就是这种解法），而单调队列可以做到 O(n)。

关键观察是：窗口右移时，新元素会让一批“更早进队、值又更小”的旧元素永远失去机会——它们比新元素更早离开窗口，而且永远比新元素小，不可能是任何未来窗口的最大值。这些元素可以从队尾永久淘汰。同时，已经滑出窗口左侧的元素要从队首移除。

于是维护一个双端队列，保存候选元素的下标，并保持两条不变量：

1. **位置不变量**：队列里只有当前窗口内的下标；队首下标一旦小于窗口左边界就出队。
2. **值不变量**：下标对应的值从队首到队尾非严格递减；新元素进队前，从队尾弹出所有比它小的值。

两条不变量合起来保证队首就是窗口最大值。每一步的顺序是：先处理队首过期，再从队尾淘汰，加入当前下标；窗口成形后输出队首。以 `[1, 3, -1, -3, 5, 3, 6, 7]`、k = 3 为例：处理完前三个元素后，队列里只剩值 3、-1 对应的下标，队首对应值 3，前两个窗口都输出 3；遇到 5 时，过期的队首先出队，队尾比 5 小的候选全部被淘汰，队首变成 5；同样的过程让 6、7 依次成为后续窗口的最大值。

单调队列同时维护位置顺序与值顺序：队首过期处理“离开窗口”，队尾淘汰处理“被新元素永久压制”。两件事缺一不可——只做其中一件都得不到正确答案。

### 为什么必须存下标

如果队列只存值，就无法判断队首值是否还在当前窗口内。有人会用“队首值等于滑出的元素就出队”来补救，但这会误伤：窗口内若有两个相等的最大值，滑出的只是其中一个，按值相等把队首删掉，另一个同值元素还在窗口内却已经被丢弃，后续窗口的最大值就会算错。存下标后，过期判断用下标比较，值比较只用于队尾淘汰，两件事互不干扰。

相等值本身保留与否由“严格性”决定：求最大值的题目允许重复最大值，因此队尾淘汰条件写 `<`（保留相等），队列非严格递减；若改用 `<=` 弹出相等值，就必须再用计数或其他信息跟踪重复元素，否则会重蹈上面的错误。

> **面试高频：** 滑动窗口最大值为什么要存下标，相等值保留哪一个？
> **答题脉络：** 位置 → 判断队首是否过期；值 → 判断队尾是否被淘汰；相等值 → 由题意决定严格/非严格，允许重复最大值时保留相等值，让非严格递减的队首依次过期。
> **追问方向：** 弹出相等值会怎样；k = 1 时结构退化成什么；堆解法在什么场景下更合适。

## 什么时候用，什么时候别用

**适用**：

- 只访问最近元素：撤销/重做、括号与标签匹配、表达式求值、DFS 的显式栈、回溯中的状态恢复（见[递归、分治与回溯](./11-递归、分治与回溯.md)）。
- 只访问最早元素：任务与消息排队、缓冲区、BFS 与层序遍历（见[树与二叉树](./06-树与二叉树.md)、[图](./08-图.md)）。
- 需要在两端进出且保持到达顺序：双端队列；窗口内的极值维护则用单调队列。
- 候选项会被新元素永久淘汰：下一个更大/更小元素用单调栈；滑动窗口极值用单调队列；滑动窗口本身的基础模型见[数组与字符串](./02-数组与字符串.md#滑动窗口)。

**不适用**：

- 需要按优先级而不是到达顺序取元素：用堆（见[堆与优先队列](./07-堆与优先队列.md)）。反例是想取“当前最大的任务”却用栈或队列，只能得到最近或最早的任务。
- 需要按位置或键随机访问、按值查找：用数组或哈希表；栈队列的接口故意不提供这些能力。
- 窗口统计不能由淘汰关系维护：窗口内元素和、频率、第 k 大，分别需要前缀和、哈希表或堆。反例是用单调队列求窗口平均值——被淘汰的小元素对总和仍有贡献，单调队列把它们丢掉了，答案无法恢复。

## 常见坑与边界

- ❌ 在空容器上 `pop` / `removeFirst` / `removeLast`。✅ 先判 `isEmpty`；Dart 不会返回 `null`，而是抛运行时异常。在当前 SDK 上，`List.removeLast` 抛 `RangeError`、`Queue.removeFirst` 抛 `StateError`，但异常类型不属于 API 契约，不要依赖某个具体类型。
- ❌ 环形队列只用 `head == tail` 判空或判满。✅ 额外维护 `size`，或牺牲一个槽位；本文实现用 `size`。
- ❌ 单调栈的单调方向写反。✅ 先写下“什么样的候选会被新元素淘汰”作为弹出条件，再由它决定栈内顺序；严格性由题目定义（“更大”还是“不小于”）决定。
- ❌ 单调队列存值而不是下标。✅ 过期必须用位置判断；存下标后，值比较与位置比较互不干扰，重复最大值也不会被误删。
- ❌ 把均摊 O(1) 当成“每次都快”。✅ 一次触发扩容的 `push`、一次触发搬运的队列 `pop` 都可能处理 O(n) 个元素；均摊描述的是长序列的平均上界。
- ❌ 用 `List.removeAt(0)` 维护队列。✅ 单次出队 Θ(n)、n 次出队 Θ(n²)；改用 `Queue` 或环形缓冲。

### 例题 1：LeetCode 20. 有效的括号

[题目链接（力扣）](https://leetcode.cn/problems/valid-parentheses/) / [归档参考](../02-LeetCode题解/11-栈和队列.md#4-用栈实现括号匹配)

前置条件：Dart 3.12.2；纯 Dart；Dart VM。

- **问题匹配点**：括号嵌套要求“最后打开的开括号最先闭合”，这正是 LIFO；任意时刻需要比较的对象只有“最近一个未闭合的开括号”，即栈顶。
- **不变量**：扫描完任意前缀后，栈内保存尚未闭合的开括号；栈空且无遗留才算合法。
- **实现**：

```dart
// 前置条件：Dart 3.x；纯 Dart；无第三方运行时依赖。
// LeetCode 20：只含 “()[]{}” 的字符串是否合法。
bool isValidParentheses(String text) {
  // 1. 用闭括号到开括号的映射判断类型是否匹配。
  const openingOf = {')': '(', ']': '[', '}': '{'};
  final stack = <String>[];

  for (var i = 0; i < text.length; i++) {
    // 题面只含 6 种 ASCII 括号字符，按 UTF-16 code unit 取字符是安全的。
    final ch = text[i];
    final opening = openingOf[ch];
    if (opening == null) {
      // 2. 开括号压栈，等待它对应的闭括号。
      stack.add(ch);
    } else {
      // 3. 闭括号必须与栈顶同类型；栈空说明闭括号没有对应开括号。
      if (stack.isEmpty || stack.removeLast() != opening) return false;
    }
  }
  // 4. 全部处理完后栈必须为空，否则有未闭合的开括号。
  return stack.isEmpty;
}
```

### 例题 2：LeetCode 739. 每日温度

[题目链接（力扣）](https://leetcode.cn/problems/daily-temperatures/) / [归档参考](../02-LeetCode题解/11-栈和队列.md#5-数组中元素与下一个比它大的元素之间的距离)

前置条件：Dart 3.12.2；纯 Dart；Dart VM。

- **问题匹配点**：答案是对每个位置求“右侧第一个更高温度”的距离，属于 Next Greater 家族；下标在弹出时才结算等待天数。
- **不变量**：栈内保存“还没等到更暖天气”的天数下标，对应温度从栈底到栈顶严格递减。
- **实现**：

```dart
// 前置条件：Dart 3.x；纯 Dart；无第三方运行时依赖。
// LeetCode 739：对每天的温度，返回还要等几天才会更暖。
List<int> dailyTemperatures(List<int> temperatures) {
  final answer = List<int>.filled(temperatures.length, 0);
  final stack = <int>[]; // 存“还没等到更暖天气”的下标，温度从栈底到栈顶递减。

  for (var today = 0; today < temperatures.length; today++) {
    // 1. 当前温度解决掉所有比它低、且还挂在栈顶的候选。
    while (stack.isNotEmpty && temperatures[stack.last] < temperatures[today]) {
      final colderDay = stack.removeLast();
      // 2. 弹出那一刻才能确定等待天数：today 是最近的一个更暖日。
      answer[colderDay] = today - colderDay;
    }
    // 3. 今天自己还没有更暖的未来，入栈等待。
    stack.add(today);
  }
  return answer;
}
```

- **边界用例**：全程降温时答案全为 0（0 表示“之后不会再升高”，不是等待 0 天）；全程升温时每个元素都被下一天解决；相等温度不算更暖，弹出条件必须是 `<`。

### 例题 3：LeetCode 239. 滑动窗口最大值（剑指 Offer 59 - I）

[题目链接（力扣，LeetCode 239）](https://leetcode.cn/problems/sliding-window-maximum/) / [归档参考](../03-剑指Offer题解/059-滑动窗口的最大值.md#解题思路)

> **时效信息（核查日期：2026-09）：** 仓库归档的“剑指 Offer 59 - I 滑动窗口的最大值”与 LeetCode 239 同题。力扣中文站已把剑指 Offer 系列改挂 LCR 编号：原 slug `hua-dong-chuang-kou-de-zui-da-zhi-lcof` 的页面现呈现为 “LCR 183. 望远镜中最高的海拔”，方法签名为 `maxAltitude(heights, limit)`；本文用同题的 LeetCode 239 作为官方链接。

前置条件：Dart 3.12.2；纯 Dart；Dart VM。

- **问题匹配点**：窗口每次只移动一格，新元素会永久淘汰一批“更早且更小”的旧元素，满足单调队列的适用条件；相比归档中的大顶堆解法（O(n log k)），单调队列把查询最大值降为 O(1)。
- **不变量**：队列只保存当前窗口内的下标；对应值从队首到队尾非严格递减，队首即窗口最大值。
- **实现**：

```dart
// 前置条件：Dart 3.x；纯 Dart；无第三方运行时依赖。
// LeetCode 239 滑动窗口最大值（仓库归档为剑指 Offer 59 - I）。
import 'dart:collection';

List<int> maxInWindows(List<int> numbers, int k) {
  // 1. 非法窗口按归档约定返回空列表。
  if (k <= 0 || k > numbers.length) return const [];
  final window = Queue<int>(); // 存下标；对应值从队首到队尾非严格递减。
  final result = <int>[];

  for (var right = 0; right < numbers.length; right++) {
    final left = right - k + 1;
    // 2. 队首过期：滑出窗口的下标从队首移除。
    if (window.isNotEmpty && window.first < left) window.removeFirst();
    // 3. 队尾淘汰：新元素让所有更小的候选永久失去机会。
    while (window.isNotEmpty && numbers[window.last] < numbers[right]) {
      window.removeLast();
    }
    window.addLast(right);
    // 4. 窗口成形后，队首就是当前窗口最大值。
    if (left >= 0) result.add(numbers[window.first]);
  }
  return result;
}
```

- **复杂度**：时间 Θ(n)（每个下标至多入队一次、出队一次）；额外空间 O(k)（队列最多保存 k 个下标）。
- **边界用例**：重复最大值保留相等元素，队列非严格递减，输出不会漏掉任何一个窗口；k = 1 时退化为直接输出原数组；k = n 时只有一个输出；非法窗口（k ≤ 0 或 k > n）返回空列表，与归档解法一致。

### 例题 4：LeetCode 232. 用栈实现队列

[题目链接（力扣）](https://leetcode.cn/problems/implement-queue-using-stacks/) / [归档参考](../02-LeetCode题解/11-栈和队列.md#1-用栈实现队列)

前置条件：Dart 3.12.2；纯 Dart；Dart VM。

- **问题匹配点**：题目只允许标准栈操作。元素依次经过两个栈会被反转两次，顺序恰好还原成 FIFO；真正的设计点是如何把搬运成本摊薄。
- **不变量**：输入栈只接收 `push`；输出栈一旦非空，其栈顶就是队首，期间 `pop`/`peek` 不需要搬运。
- **实现**：

```dart
// 前置条件：Dart 3.x；纯 Dart；无第三方运行时依赖。
// LeetCode 232：只用两个栈实现队列。
class MyQueue {
  final _inStack = <int>[]; // 只负责入队
  final _outStack = <int>[]; // 只负责出队

  bool get isEmpty => _inStack.isEmpty && _outStack.isEmpty;

  // 1. 入队：直接压入输入栈。
  void push(int value) => _inStack.add(value);

  // 2. 出队：先把可能需要的元素搬完，再从输出栈顶弹出队首。
  int pop() {
    _moveIfNeeded();
    if (_outStack.isEmpty) throw StateError('queue is empty');
    return _outStack.removeLast();
  }

  // 3. 查看队首：与 pop 共享搬运逻辑，但不弹出。
  int peek() {
    _moveIfNeeded();
    if (_outStack.isEmpty) throw StateError('queue is empty');
    return _outStack.last;
  }

  // 4. 搬运：只有输出栈为空时才把输入栈整体倒入，翻转一次顺序。
  void _moveIfNeeded() {
    if (_outStack.isNotEmpty) return;
    while (_inStack.isNotEmpty) {
      _outStack.add(_inStack.removeLast());
    }
  }
}
```

<!-- verify: .work/verify/A04/lc232_queue_with_stacks.dart -->

完整文件含 `main()` 与断言（交叉 push/pop、空队列 StateError），见 companion。

- **复杂度**：单次 `pop`/`peek` 最坏 O(n)（恰好触发一次整体搬运），但每个元素至多被搬运一次，m 次操作的总搬运代价不超过入队元素个数，因此**均摊 O(1)**；两个栈合计额外空间 O(n)。
- **边界用例**：交叉 `push`/`pop` 仍保持 FIFO；题面保证空队列不会被 `pop`/`peek`，但实现主动抛 `StateError`，避免静默返回脏数据。

## 面试考点与追问

下面每个问题都能在前文找到机制，这里只给出复述链，便于自检：

1. **数组栈与链式栈如何权衡？** 均摊 O(1) 与最坏 O(1) 是两种保证 → 朴素数组栈偶尔触发 O(n) 复制，链式栈用额外引用与分配换最坏稳定 → 依据是否需要实时上界选择。
2. **两个栈实现队列为什么是均摊 O(1)？** 搬运只在输出栈为空时发生 → 每个元素至多被搬运一次 → 总代价与操作次数同阶 → 单次最坏 O(n) 与均摊 O(1) 同时成立。
3. **BFS 为什么必须用队列？** BFS 按层扩展，必须按发现顺序处理 → 先发现的节点先展开 → 这正是 FIFO；用栈会得到 DFS 的访问顺序。
4. **单调栈为什么不会漏答案？** 栈内是尚未解决的候选 → 反证中间不存在更大元素 → 弹出时刻就是答案结算时刻 → 每个下标进出各一次，总代价 O(n)。
5. **滑动窗口最大值为什么存下标、相等值保留哪一个？** 位置用于判断过期，值用于队尾淘汰 → 允许重复最大值时保留相等值，队列非严格递减 → 若弹出相等值，必须额外跟踪计数，否则会误删仍在窗口内的同值元素。
6. **这些容器线程安全吗？** 本文的 `List`、`Queue` 与自定义结构都不承诺并发语义；只读或单线程内使用，跨 isolate 需要复制或消息传递，并发细节不在本文展开。

## 小结

栈与队列的核心是顺序不变量：栈保证“最近未弹出”，队列保证“最早未出队”；数组、链表与环形缓冲只是承载这些不变量、决定两端成本的实现。单调栈与单调队列在此之上多走一步——把会被新元素永久淘汰的候选提前剔除——从而把一类嵌套匹配与滑窗极值问题从 O(n²)、O(n log k) 压到线性时间。
