# 算法与数据结构｜查找与二分查找

在一个百万行的有序日志里定位第一条报错记录，在一张按阈值排列的配置表里找"第一个不小于给定值的档位"，或者判断"装载能力至少多大才能按时运完所有包裹"——这三类问题的共同点是：候选答案有顺序，而暴力做法要把每个候选都看一遍。

只记住"有序数组用二分"并不够。二分真正的门槛不在记忆力，而在边界：区间是闭的还是半开的？hi 取 n 还是 n−1？循环用 `lo <= hi` 还是 `lo < hi`？为什么有的实现返回 −1，有的返回插入位置？只要区间含义没写清，改一个等号就会死循环或漏掉端点。

本文的路线是：先把查找抽象成"排除候选"，说清二分成立需要什么条件；再固定一种区间不变量，用同一套模板写出精确查找、lower bound 与 upper bound；然后把模板迁移到旋转数组和在"答案空间"上二分；最后回到有序符号表与工程选型，并用四道题检验能否独立写对。

## 查找的本质是排除候选

在没有任何结构的数据里找一个值，只能逐个比较：n 个元素最坏看 n 次，这叫线性查找（linear search）。它也不需要数据携带额外信息，是"无信息可用"时的基线。

一旦数据带上结构，查找就变成"排除不需要看的部分"：

- 有序数组：比较一次，就能判定目标不可能落在哪一侧；
- 哈希表：用散列函数直接算出候选桶，平均一轮定位，但不支持顺序相关的操作（见 [哈希表](./05-哈希表.md)）；
- 二叉搜索树：沿比较路径向下，每层丢掉一半左右的子树（见 [树与二叉树](./06-树与二叉树.md)）。

> **关键认知：** 查找速度的上限由数据结构携带的信息决定；二分不是"更聪明的遍历"，而是利用有序性做排除，排除得越准，剩余候选越少。

预处理不是免费的。把无序数据排一次序是 O(n log n)，换来之后每次查询 O(log n)；只有在"查询多、更新少"时这笔账才划算。ThreeSumBinarySearch 把三重循环的 O(n³) 降成"排序 + 每对元素二分"的 O(n² log n)，排序成本必须记进总账，一旦漏算或忽略重复元素处理，结论就会出错（复杂度记账方式见 [复杂度分析与算法思想](./01-复杂度分析与算法思想.md)）。

## 二分查找成立的条件

二分查找（binary search）同时依赖两个条件：

1. 随机访问：能在 O(1) 时间内定位第 mid 个候选（数组的下标访问为什么是常数级，见 [数组与字符串](./02-数组与字符串.md)）；
2. 单调判定：存在一个布尔谓词，随着候选位置向某个方向移动，它的结果只翻转一次，例如先 false 后 true。

用第二条重新表述：二分真正要找的是**转换点**。设 ok(i) 为布尔谓词，且 ok(0), ok(1), ... 呈 false...false, true...true 的形态，二分就能找到第一个满足 ok 的位置。"找出等于 target 的元素"只是它的特例：

```text
精确查找 = 找第一个 nums[i] >= target 的位置，再检查该位置的值是否等于 target。
```

反例同样重要：谓词不单调时二分失效。例如"找第一个下标 i 使 nums[i] 为奇数"（数组本身无序时），或者"容量越大开销越小"的后半段又反弹，这类问题不能套二分的壳。

随机访问也不能省。链表按下标访问的代价与距离成正比，每轮定位中点都要走过当前区间的一半，累计代价 Θ(n)，并没有把线性扫描的 n 降下来（每轮都从头定位时更差）。跳表用多级索引换回近似随机访问能力，属于另一个话题。

> **关键认知：** 二分成立的条件不是"数组有序"，而是"存在一个在候选空间上单调的谓词，且探测一个候选的代价是常数级"；有序数组只是满足这个条件最常见的一种载体。

## 区间不变量

初学者写错二分，几乎都出在区间含义没有固定：lo、hi 表示什么？循环条件该用 `lo <= hi` 还是 `lo < hi`？hi 初值取 n 还是 n−1？返回什么？

本文主模板固定一种解释：**用两个下标夹住答案，答案（转换点）始终在闭区间 [lo, hi] 内；hi 的初值取 n，是一个允许等于数组长度的上界哨兵。**

```text
lo = 0; hi = n                     // 不变量：答案 t 满足 lo <= t <= hi
while (lo < hi)                    // 只要区间还多于一个点
    mid = lo + (hi - lo) ~/ 2      // mid 一定落在 lo..hi-1
    if 判定(mid) 为真
        hi = mid                   // 转换点不会在 mid 右侧
    else
        lo = mid + 1               // mid 及其左侧都可以排除
return lo                          // lo == hi，就是转换点
```

为什么这个模板会终止、且每一步都保持不变量：

- 进入循环时 lo < hi，所以 mid ∈ [lo, hi−1] 一定是合法下标；
- 判定为真说明转换点 t 满足 t ≤ mid（单调性保证第一个 true 不会出现在 mid 之后），所以把区间收缩为 [lo, mid]；判定为假说明 t > mid，收缩为 [mid+1, hi]；
- 两个分支分别让 hi 严格变小、lo 严格变大，区间长度 hi−lo 严格递减，循环必然终止；
- 结束时 lo == hi，区间收缩成一点，它就是答案。

hi = n 是哨兵，不是"最后一个候选的下标"。当数组里所有元素都小于 target 时，"插入位置"就是 n；如果把 hi 取成 n−1，这个位置就没有下标可以表示，这正是漏掉端点返回值的根源。

教材里更常见的另一种写法是闭区间精确查找：l = 0、r = n−1，循环 `while (l <= r)`，命中直接返回 mid，区间变空表示未找到。它没有哨兵位置，区间含义是"候选集合 [l, r]，空集即失败"：

| 维度 | 主模板（找转换点） | 对照模板（精确查找） |
|---|---|---|
| 区间解释 | 答案在 [lo, hi]，hi 可为 n | 候选在 [l, r]，r 最大 n−1 |
| 循环条件 | `lo < hi` | `l <= r` |
| 命中处理 | 不返回，继续向边界收缩 | 立即 `return mid` |
| 未命中 | 返回插入位置 0..n | 返回 −1 |
| 重复元素 | 稳定返回第一个满足的位置 | 命中即返回，位置不确定 |

一个贯穿全文的写法约定：mid 用 `lo + (hi - lo) ~/ 2`。Dart 原生 int 是 64 位二补码，常规数组规模不会让 `lo + hi` 溢出；但编译到 Web 时 int 由 JavaScript number 承担，只有 53 位精确整数范围，超大下标下 `lo + hi` 会先丢精度（见参考资料 [R4]、[R5]）。先减后加与直接相加一样快，作为默认习惯没有代价。

> **关键认知：** 二分正确性首先是一个区间语义问题：先写清"答案一定落在哪个范围、边界是否可取"，移动规则、循环条件和返回值都是这个语义的推论。

## 精确查找

最常见的问题：在有序数组里找一个等于 target 的元素，找不到返回 −1。

把"找等于"改写为"找第一个 ≥ target 的位置"后，主模板直接给出定位；找到位置后检查该位置的值是否真是 target 即可：

```dart
/// 第一个 >= target 的下标；若所有元素都小于 target，返回 nums.length。
int lowerBound(List<int> nums, int target) {
  var lo = 0;
  var hi = nums.length; // 答案上界哨兵：允许等于 n（插入到末尾）
  while (lo < hi) {
    // 1. 取中点：先减后加，不依赖 lo + hi 不溢出这个前提。
    final mid = lo + (hi - lo) ~/ 2;

    // 2. 比较后排除不可能的一半，保证答案仍在 [lo, hi] 中。
    if (nums[mid] < target) {
      lo = mid + 1; // mid 及其左侧都小于 target
    } else {
      hi = mid; // mid 可能是答案，不能排除
    }
  }
  return lo; // 结束时 lo == hi，它就是插入位置
}

/// 精确查找：返回任意一个等于 target 的下标，找不到返回 -1。
int indexOf(List<int> nums, int target) {
  final first = lowerBound(nums, target);
  return (first < nums.length && nums[first] == target) ? first : -1;
}
```

<!-- verify: .work/verify/A10/lower_upper_bound.dart -->

- 时间：n 个候选下最多 ⌊log₂n⌋ + 1 轮迭代，每轮只做一次比较，总 O(log n)；前提是随机访问 O(1)、比较 O(1)。n = 0 时一轮都不进入；
- 空间：只用 lo、hi、mid 三个下标，O(1) 额外空间；
- 端点：target 小于所有元素时返回 0，大于所有元素时返回 n，两种情况都不需要特判。

未找到时返回什么有两套常见约定：

- 返回 −1：调用方只关心"在不在"（上面采用的就是这种）；
- 返回插入位置：调用方可以直接拿到"插入到哪还能保持有序"，也就是 lowerBound 的原样返回值。

同一份逻辑用闭区间对照模板写出来是另一种形状：

```text
l = 0; r = n - 1
while (l <= r)
    mid = l + (r - l) ~/ 2
    if nums[mid] == target:  return mid
    if nums[mid] < target:   l = mid + 1
    else:                    r = mid - 1
return -1
```

它更短，但在有重复元素时返回哪个命中位置不确定，也无法表达"插入到末尾"。两种写法都可以用，前提是一次只选一种解释，不要把两套区间语义混着写。

> **关键认知：** 精确查找回答的是"存在性与一个命中位置"；需要稳定地拿到第一个或最后一个位置时，必须升级为下一节的边界二分，而不是在精确查找上补丁。

## lower bound 与 upper bound

精确查找只回答"等不等于"；更通用的两个边界回答的是"target 影响的范围从哪里开始、到哪里结束"：

- lower bound：第一个 ≥ target 的位置；
- upper bound：第一个 > target 的位置。

两个函数只差一次比较：

```dart
/// 第一个 > target 的下标；若所有元素都 <= target，返回 nums.length。
int upperBound(List<int> nums, int target) {
  var lo = 0;
  var hi = nums.length; // 上界哨兵
  while (lo < hi) {
    final mid = lo + (hi - lo) ~/ 2;
    if (nums[mid] <= target) {
      lo = mid + 1; // mid 及其左侧都 <= target
    } else {
      hi = mid;
    }
  }
  return lo;
}
```

<!-- verify: .work/verify/A10/lower_upper_bound.dart -->

- lower bound 的排除条件是 `nums[mid] < target`，等于的情况被保留，于是停在第一个相等的元素；
- upper bound 的排除条件是 `nums[mid] <= target`，等于被一并排除，于是越过所有相等的元素，停在第一个更大的元素。

把两个边界组合起来，就得到 target 的完整出现区间：

```text
出现区间 = [lowerBound(target), upperBound(target))    // 左闭右开
出现次数 = upperBound(target) - lowerBound(target)
第一个位置 = lowerBound(target)
最后一个位置 = upperBound(target) - 1
```

target 不存在时两个边界重合，次数自然为 0；target 比所有元素大时两个边界都是 n；数组为空时两个边界都是 0。这些情况都不需要 if 特判，**但取"最后一个位置"前必须确认两个边界不重合**，否则会读到不属于 target 的元素。

> **关键认知：** `lowerBound` 与 `upperBound` 是同一个模板的两个实例，区别只在比较符是否带等号；"出现区间 = [lowerBound, upperBound)"比"命中后向两侧线性扩展"可靠得多，后者在整个数组都是 target 时退化为 O(n)。

## 旋转数组等局部有序结构

旋转数组把升序数组从某个位置切开、交换两段，例如 [4, 5, 6, 7, 0, 1, 2]。它全局无序，但结构没有被完全破坏：前半段整体大于后半段，且两段内部各自递增。取一个固定参考值 `pivot = nums[n-1]`，谓词 `nums[i] <= pivot` 在整段上仍是"前假后真"：

```text
nums = [4, 5, 6, 7, 0, 1, 2]，pivot = nums[n-1] = 2
下标：         0  1  2  3  4  5  6
nums[i] <= 2： F  F  F  F  T  T  T
第一个 T 的位置 4，就是最小值 0 的下标
```

单调性的来源：旋转后的数组由两段拼成——前缀是原数组的尾部，全部大于 pivot；后缀是原数组的头部，全部 ≤ pivot。所以谓词恰好只翻转一次，第一个 true 就是最小值的下标。模板与前面完全一致，只是比较对象换成了固定的 pivot。

> **关键认知：** 旋转数组还能二分，不是因为"它近似有序"，而是旋转只破坏全局有序、保留了"一个转换点"的弱结构；一旦重复值让 `nums[i] <= pivot` 不再单调（形如 [3, 3, 1, 3] 的排列），这套固定参考值的写法就不能照搬。

有重复元素的变体（Find Minimum in Rotated Sorted Array II）必须额外处理 `nums[mid]` 与参考值相等的情况，最坏会退化到 O(n) 线性扫描，这里不展开。

## 在答案空间上二分

二分不限于"在数组里找位置"。只要一个问题能回答"某个值 x 是否可行"，并且可行性随 x 单调，就可以直接在答案的取值范围上二分，这叫**答案域二分**（binary search on answer），也叫"二分答案"。

四步套路：

1. 明确要最小化或最大化什么量，这个量的取值范围就是二分区间 [lo, hi]；
2. 写出判定 ok(x) = "x 可行"，并证明单调性：若 x 可行，则所有更大的 x 也可行（或反向）；
3. 确定上下界并留出哨兵位置，表示"没有可行解"这种可能；
4. 套主模板找转换点，复杂度 = O(log(hi − lo) × 单次判定成本)。

判定封装成参数后，模板和数组二分完全一样：

```dart
/// 在答案范围 [lo, hi] 中找最小的使 ok(x) 为 true 的 x。
/// 要求 ok 单调：一旦为 true，其后的值都为 true。
/// 若 [lo, hi) 内没有满足的值，返回哨兵 hi。
int firstTrue(int lo, int hi, bool Function(int) ok) {
  while (lo < hi) {
    final mid = lo + (hi - lo) ~/ 2;
    if (ok(mid)) {
      hi = mid; // mid 可能是答案，只排除它右侧
    } else {
      lo = mid + 1; // mid 及其左侧都不满足
    }
  }
  return lo;
}
```

<!-- verify: .work/verify/A10/first_true.dart -->

两个使用要点：

- 单调性必须证明，不能靠"看起来像"。常见形式是"已经满足约束的解，加更多资源仍然满足"：`容量 x 装得下所有物品` ⇒ `容量 x+1 也装得下`；
- 二分区间是值域而不是下标，上界可能到 2³¹ 量级，因此判定式里不要做可能溢出的乘法。下面 69 题用 `mid > x ~/ mid` 代替 `mid * mid > x` 就是这个原因：乘法在定宽 32 位整数里会溢出，在 Dart Web 的 53 位精确整数范围内也可能丢精度。

实数域的二分是同一个思想，但终止条件不同：不要用 `lo == hi` 去等两个浮点数收敛，而是固定迭代次数（每轮区间减半，100 轮后长度缩小 2¹⁰⁰ 倍，远超常用精度），或者当 `hi - lo < ε` 时停止，并声明精度假设。

> **关键认知：** 答案域二分的复杂度是 O(log(值域宽度) × 单次判定成本)，值域宽度和数组长度是两回事；判定本身是 O(n) 时整体是 O(n log V)，是否划算要按数据范围算账，而不是默认"带二分就一定更快"。

一个容易漏掉的成本账：如果数据本来无序，"先排序再二分"的总成本包含 O(n log n) 的排序；只查一次时它比 O(n) 线性扫描更贵。动态规划中的 LIS 使用辅助数组加二分做到 O(n log n)，是因为它把 O(n) 的状态转移压缩成"维护最小结尾 + 二分更新"，见 [动态规划](./12-动态规划.md)。

## 有序符号表

把键值对存进按键有序的数组，就是有序符号表（ordered symbol table）的最朴素实现。它的地基是 `rank(key)`：第一个 ≥ key 的位置。key 存在时 rank 是它的下标，不存在时 rank 是它应该插入的位置——这正是 lower bound 的语义。

```dart
/// 用一对平行数组实现的有序符号表：查找 O(log n)，插入 O(n)。
class OrderedArraySymbolTable<K extends Comparable<Object?>, V> {
  final List<K> _keys = [];
  final List<V> _values = [];

  int get length => _keys.length;

  /// rank(key)：第一个 >= key 的下标，也就是 key 的插入位置。
  int rank(K key) {
    var lo = 0;
    var hi = _keys.length;
    while (lo < hi) {
      final mid = lo + (hi - lo) ~/ 2;
      if (_keys[mid].compareTo(key) >= 0) {
        hi = mid; // mid 可能是目标位置
      } else {
        lo = mid + 1;
      }
    }
    return lo;
  }

  V? get(K key) {
    final index = rank(key);
    if (index < _keys.length && _keys[index].compareTo(key) == 0) {
      return _values[index];
    }
    return null;
  }

  void put(K key, V value) {
    final index = rank(key);
    if (index < _keys.length && _keys[index].compareTo(key) == 0) {
      _values[index] = value; // 命中：只更新值
    } else {
      _keys.insert(index, key); // 未命中：在 rank 位置插入，代价是移动元素
      _values.insert(index, value);
    }
  }

  K? minKey() => _keys.isEmpty ? null : _keys.first;
  K? maxKey() => _keys.isEmpty ? null : _keys.last;
}
```

<!-- verify: .work/verify/A10/ordered_symbol_table.dart -->

- get：先 rank 定位，再确认该位置真的等于 key，是则取值，否则返回 null；
- put：命中则更新，未命中则在 rank 处插入；Dart 的 `List.insert` 要把插入点之后的元素整体后移，代价 O(n)；
- minKey / maxKey：有序数组的两端天然是最小/最大键，O(1)。

因此它的复杂度分工是"查找对数、插入线性"，选型取决于读写的比例：

| 结构 | 查找 | 插入 | 有序操作（rank/范围/最值） | 额外结构 |
|---|---|---|---|---|
| 有序数组 + rank | O(log n) | O(n)，移动元素 | 支持 | 两个平行数组，O(n) |
| 平衡二叉搜索树 | O(log n) 最坏 | O(log n) 最坏 | 支持 | 节点与指针，O(n) |
| 哈希表 | O(1) 期望、O(n) 最坏 | O(1) 期望、O(n) 最坏 | 不支持 | 桶数组，O(n) |

读多写少、还要按顺序做范围查询，用有序数组；读写都频繁，用平衡 BST（见 [树与二叉树](./06-树与二叉树.md)）；只需要按 key 取值、不需要顺序，用哈希表（见 [哈希表](./05-哈希表.md)）。

> **关键认知：** rank 同时承担"查找命中位置"和"插入位置"两种语义，是有序符号表把查找与插入串起来的枢纽；它的实现就是 lower bound，不是另起炉灶的二分。

## 什么时候用，什么时候别用

### 适合用二分

- 数据静态或低频更新、查询次数多：一次排序 O(n log n) 换每次查询 O(log n)，查询量达到 log n 以上的量级就回本；
- 在有序数组中求第一个/最后一个满足条件的位置：用 lower/upper bound 一次拿到出现次数、插入位置和出现区间；
- 判定单调且代价小的最值决策：最小容量、最小时间、"最大值的最小化"等，把求最值转成找转换点；
- 一个正面例子：长度为 10⁶ 的有序数组上做 10⁶ 次查询，线性查找约 10¹² 次比较；二分只需约 2×10⁷ 次（若数据还要现排序，再加同量级的 2×10⁷ 次）。

### 不适合用二分

- 数据无序且只查一次：先排序再二分的 O(n log n) 比一次 O(n) 线性扫描更贵；只想一次性找第 k 小，排序或快速选择是另一条路（见 [排序](./09-排序.md)）；
- 不支持 O(1) 随机访问：链表、流式数据、只能顺序前进的迭代器，定位中点的代价会吃掉收益；
- 频繁插入删除：有序数组每次插入 O(n)，应改用平衡树、跳表或哈希；
- 判定不单调：只是"取值有范围"不代表能二分，谓词必须只翻转一次；
- 判定本身太贵：每轮判定都是 O(n)、问题规模又不大时，直接扫描往往更简单；
- 字符串子串匹配：这不是有序数组上的二分问题，模式串定位有 KMP 等专用算法，见 [字符串算法](./15-字符串算法.md)。

## 常见坑与边界

- ❌ hi 初值取 n−1，还指望返回"插入到末尾"的位置。
  ✅ 主模板的 hi 是上界哨兵，初值必须是 n；返回 n 表示"所有元素都小于 target"。
- ❌ 循环用 `lo <= hi`，分支里却写 `hi = mid` 或 `lo = mid`。
  ✅ 这样区间可能不收缩：例如 nums = [0, 1, 2]、target = 1，会反复命中同一个 mid。先定区间语义，再配套写循环条件和移动规则。
- ❌ 不检查就用返回值下标访问数组。
  ✅ 主模板保证 mid ∈ [lo, hi−1] 合法，但**返回值本身可能是 n**；拿第一个/最后一个位置或读 `nums[位置]` 之前必须先判断范围。
- ❌ 命中就返回，然后对重复元素的题目声称"返回的是第一个位置"。
  ✅ 精确查找模板在重复值下返回任意一个命中位置；要第一个或最后一个，必须用 lower/upper bound。
- ❌ 忽略空数组与"所有值都小于 target"的情况。
  ✅ lowerBound 在空数组上返回 0；`upperBound - lowerBound` 对空数组自然为 0；需要特别检查的是返回值等于 n 时的调用方逻辑。
- ❌ 习惯性写 `(lo + hi) ~/ 2` 而不解释前提。
  ✅ 定宽 32 位整数语言里 lo + hi 可能溢出；Dart 原生 int 是 64 位，但 Web 上只有 53 位精确整数范围。`lo + (hi - lo) ~/ 2` 与语言无关，成本相同。
- ❌ 把"看起来有范围"当成"可以二分"。
  ✅ 先证明 false...true 只翻转一次，再动手；证明不了就换方法。
- ❌ 只算二分的 O(log n)，漏掉排序成本。
  ✅ 总成本 = 预处理 + 查询次数 × 单次查询；一次性场景下排序可能直接超过线性扫描。
- ❌ 浮点二分用 `lo < hi` 死等收敛。
  ✅ 实数域用固定迭代次数或精度阈值终止，并写明所需精度。

### 例题 1：278. First Bad Version

问题匹配点：`isBadVersion` 单调，一旦某个版本坏，之后的版本都坏，要找"第一个 true"，是主模板的直接应用。

不变量：第一个坏版本号始终在 [lo, hi] 内，hi 初值 n+1 是哨兵；每轮询问 mid，坏则收右界，好则排除 mid 及左侧。

```dart
/// 返回第一个坏版本号；题面保证 [1, n] 内至少有一个坏版本。
int firstBadVersion(int n, bool Function(int) isBadVersion) {
  // 1. 用上界哨兵 n + 1 夹住答案；答案最大是 n。
  var lo = 1;
  var hi = n + 1;
  while (lo < hi) {
    final mid = lo + (hi - lo) ~/ 2;

    // 2. 询问中点：坏则向左收，好则向右收。
    if (isBadVersion(mid)) {
      hi = mid; // mid 是坏版本，第一个坏版本在它或它左侧
    } else {
      lo = mid + 1; // mid 是好版本，答案在它右侧
    }
  }
  return lo; // 3. lo 是第一个为 true 的版本号
}
```

<!-- verify: .work/verify/A10/first_bad_version.dart -->

- 复杂度：时间 O(log n)，空间 O(1)，前提是每次 API 调用 O(1)；
- 边界用例（验证文件通过注入谓词模拟 API 并记录调用次数）：坏版本在首、中、末三种位置都能找回答案；n = 1 时只询问一次；n = 10⁶ 时最坏 20 次询问，不超过 ⌊log₂n⌋+1。

### 例题 2：153. Find Minimum in Rotated Sorted Array

问题匹配点：旋转数组上 `nums[i] <= nums[n-1]` 仍是单次翻转的谓词，第一个 true 就是最小值。

不变量：最小值始终在 [lo, hi] 内；判定为真说明 mid 属于后半段，最小值在 mid 或它左侧；判定为假说明 mid 还在前半段，最小值在它右侧。

```dart
/// 返回旋转有序数组的最小值。
int findMinInRotated(List<int> nums) {
  final pivot = nums[nums.length - 1]; // 固定的参考值 nums[n-1]
  var lo = 0;
  var hi = nums.length - 1; // 答案在闭区间 [lo, hi] 内
  while (lo < hi) {
    final mid = lo + (hi - lo) ~/ 2;

    // 谓词 nums[i] <= pivot 单调：前半段全为 false，后半段全为 true。
    if (nums[mid] <= pivot) {
      hi = mid; // mid 已在后半段，最小值不在它右侧
    } else {
      lo = mid + 1; // mid 还在前半段，最小值在它右侧
    }
  }
  return nums[lo];
}
```

<!-- verify: .work/verify/A10/rotation_min.dart -->

- 复杂度：时间 O(log n)，空间 O(1)；前提是元素互异，因此谓词严格单调；
- 边界用例：完全没有旋转（返回第一个元素）、只有一个元素、两个元素且已交换（[2, 1]）、旋转点在各处；
- 不适用：本题题面保证元素唯一；有重复值的变体需要额外处理相等情况，最坏退化为 O(n)，不能照搬。

### 例题 4：69. Sqrt(x)

问题匹配点：判定 `mid * mid > x` 随 mid 单调（前半 false、后半 true），要找的是它前面一个值，属于答案域二分。

不变量：在 [1, x+1] 上用哨兵 x+1 找第一个使 `mid > x ~/ mid` 的位置，减 1 就是向下取整的平方根；谓词等价于 `mid * mid > x`，但不做乘法。

```dart
/// 69. Sqrt(x)：返回 floor(sqrt(x))，x 为非负整数。
int mySqrt(int x) {
  if (x <= 0) return 0; // 题面 x >= 0，这里提前返回，也避免除零

  // 1. 谓词 mid > x ~/ mid 等价于 mid * mid > x（mid 为正），但不做乘法。
  // 2. 在 [1, x + 1] 上找第一个 true，x + 1 是哨兵；答案就是它前面一个值。
  return firstTrue(1, x + 1, (mid) => mid > x ~/ mid) - 1;
}
```

<!-- verify: .work/verify/A10/sqrt_integer.dart -->

- 复杂度：时间 O(log x)，空间 O(1)；x = 0 提前返回；
- 边界用例：0、1、2、3 等小值；完全平方数（49、64）与它的相邻值；大边界 2³¹−1 的答案是 46340，中间量不做乘法，不会因 46341² ≈ 2.15×10⁹ 在 32 位环境中溢出，也避开 Web 53 位精度问题；
- 验证文件复用「在答案空间上二分」一节的 `firstTrue`，断言覆盖上述全部用例。

## 面试考点与追问

> **面试高频：** 二分的循环不变量怎么描述？`l <= r` 和 `l < r` 有什么区别？
> **答题脉络：** 先说区间语义（答案在 [lo, hi] 且 hi 可为哨兵，或候选集 [l, r] 且空集表示失败）→ 再给配套的移动规则 → 最后用区间严格收缩论证终止。
> **追问方向：** `hi = mid` 与 `hi = mid - 1` 各自何时用；写一个不收缩而死循环的例子；mid 的下取整/上取整与终止性的关系。

> **面试高频：** 怎么求 target 的出现次数和出现区间？
> **答题脉络：** 出现区间是 [lowerBound(t), upperBound(t)) → 两个函数只差比较符是否带等号 → 不存在时两边界重合 → 命中后向两侧线性扩展的退化陷阱。
> **追问方向：** target 比所有元素大/小时边界值是什么；重复元素下精确查找为什么不能保证第一个位置。

> **面试高频：** 旋转有序数组为什么还能二分？
> **答题脉络：** 旋转只破坏全局有序，`nums[i] <= nums[n-1]` 仍是单次翻转的谓词 → 第一个 true 就是最小值 → 重复值会让谓词不再单调。
> **追问方向：** 比较 `nums[mid]` 与当前 `nums[hi]` 的等价写法；有重复值变体的退化；旋转数组上查找 target（相关题号 33、81）。

> **面试高频：** 二分答案怎么做？怎么证明能二分？
> **答题脉络：** 定义要最小化或最大化的量 → 写出 ok(x) → 证明单调（可行解加资源仍可行）→ 定上下界与哨兵 → 复杂度 O(log V × 判定成本)。
> **追问方向：** 值域很大时上界怎么选；判定本身 O(n) 时是否划算；浮点二分的终止策略。

> **面试高频：** 链表能不能二分？哈希表能替代二分吗？
> **答题脉络：** 二分的前提是 O(1) 随机访问加单调谓词 → 链表定位中点要遍历半个当前区间，累计仍是 Θ(n)，量级上与线性扫描相同 → 哈希没有顺序，做不了 rank、范围与最值查询。
> **追问方向：** 跳表为什么能恢复对数级定位；有序数组、平衡树、哈希的选型边界。

> **面试高频：** `mid = (l + r) / 2` 有什么问题？
> **答题脉络：** 定宽整数下 l + r 可能溢出 → 先减后加与语言无关 → Dart 原生 64 位与 Web 53 位精确范围的差异。
> **追问方向：** 非负操作数下 `~/` 的行为；mid 取整方向如何影响收缩与终止。

## 小结

写二分时先别急着决定"哪边移动"：用一句话写清候选区间与答案位置（例如"答案 t 满足 lo ≤ t ≤ hi，hi 是上界哨兵"），再让每条移动规则排除掉确定不是答案的区间，最后检查 lo == hi 时的返回值是否覆盖"不存在、插入末尾"这些情况。模板只有一套，变的只是谓词。

## 一句话总结

> 二分的正确性来自区间不变量：先确定答案被哪两个下标夹住、边界能否取到，再用"每轮排除一半"的移动规则收缩到一点，谓词不同只是换了比较条件。
