# 复杂度分析与算法思想

同一道题，两份都能通过测试的实现，在数据量涨十倍后可能一个仍在几十毫秒内返回、另一个直接超时。把两份代码各跑一遍、比一下耗时，是最自然的直觉做法，却几乎总是给出会被下一次运行推翻的结论：换台机器、改一次输入分布、甚至只是多跑几次让 JIT 预热，数字就会变。

这篇笔记要解决的不是“记几个阶数”，而是建立一套可比较的分析习惯：先定义输入规模和成本模型，再用渐近记号描述增长趋势，然后逐类数清顺序、分支、嵌套、对数循环与隐藏的复制成本。接着区分最好、最坏、平均、期望与均摊这五个容易被混用的口径，用递归式处理分治结构，最后把实测放回它应有的位置——只能佐证，不能证明。
路线是：先定规模与成本模型，再统一上界、下界、紧确界的记号与前提，练习时间与空间的分析方法；然后处理多口径与递归式；最后讨论实测与模型的分工，并给出算法思想地图、选型边界、常见误区与三道同题多解的演练。

## 为什么不能只看一次运行时间

最直觉的评估方式是“跑一遍、看耗时”。问题是这个数字同时混进了至少四类与分析目标无关的因素：机器与负载（主频、内存带宽、其他进程）、编译模式与预热（`dart run` 用 Dart VM 的 JIT 编译器 [R10]，前几轮偏慢；AOT 编译出的可执行文件表现不同）、输入分布（有序、随机、全相同或倒序会改变分支与缓存行为）、常数与实现细节（运行时、分配器、内存访问模式）。
下面把同一件 Θ(n²) 的工作在四个规模上各跑一次：

```dart
// 前置条件：Dart 3.x；纯 Dart；无第三方运行时依赖；用 `dart run` 执行。
// 实测版倍率实验：用 dart:core 的 Stopwatch 取代旧文的 Java StopWatch 工具类。
// 本文件只打印耗时，不对时间做断言：机器负载与 JIT 预热会让单次结果抖动。

/// 待测量的工作：n 轮、每轮 n 次加法，基本操作量 Θ(n²)。
int quadraticWork(int n) {
  var touches = 0;
  for (var round = 0; round < n; round++) {
    for (var index = 0; index < n; index++) {
      touches++; // 1. 结果要返回，循环体不会被优化掉。
    }
  }
  return touches;
}

void main() {
  int? previousMicros;
  print('n\t耗时(ms)\t倍率');
  for (final n in [500, 1000, 2000, 4000]) {
    final stopwatch = Stopwatch()..start(); // 1. 只测量目标代码本身。
    quadraticWork(n);
    stopwatch.stop();

    final micros = stopwatch.elapsedMicroseconds;
    final ratio = previousMicros == null
        ? '-'
        : (micros / previousMicros).toStringAsFixed(2);
    print('$n\t${(micros / 1000).toStringAsFixed(1)}\t\t$ratio');
    previousMicros = micros;
  }
}
```

在验证环境（Dart SDK 3.12.2，Windows x64，`dart run`，JIT）连续运行三次，得到的表格几乎一样：

```text
n       耗时(ms)        倍率
500     0.3             -
1000    0.7             2.00
2000    1.6             2.30
4000    6.2             3.90
```

规律是：只有到 n = 4000 时，倍率才接近 Θ(n²) 应有的 4；前面两行的 2.0 与 2.3 明显偏低，因为固定开销（循环启动、计时器精度、JIT 预热）还没有被摊薄。也就是说，**小规模实测会把一个平方级算法显示得比它的阶数更乐观**。

> **关键认知：** 一次运行时间测的是“这次输入、这台机器、这个编译模式”的代价；复杂度描述的是运行时间随规模增长的趋势，两者不是同一件事，也不能互相替代。

## 输入规模与成本模型

要得到可比较的结论，必须先把两件事写清楚：`n` 到底是什么，以及我们打算数什么操作。

### 先定规模再定基本操作

`n` 是输入规模的度量，常见选择有：序列长度、字符串长度、图的顶点数 $V$ 与边数 $E$、容量或查询次数 $k$、整数的位宽。同一份代码换一种规模定义，结论就会变：把“整数个数”当规模时遍历是线性的；把“整数的位宽”当规模时，一次加法本身就不再是常数操作。
成本模型（cost model）是在规模之外指定“哪种操作计 1 次”：数组访问次数、元素比较次数、哈希操作次数、写回次数都是常用选择；Sedgewick 在 ThreeSum 的分析里就固定只数数组访问次数 [R2]。指定成本模型的目的不是精确预测毫秒数，而是把算法与它的具体实现、语言和机器隔离开。

下面三个函数用同一个成本模型（比较/计数操作各记 1 次）度量三种看似相似的循环结构（节选自 `growth_orders.dart`，完整文件还含 `main` 断言与打印）：

```dart
/// 三角嵌套：内层从外层之后开始，比较次数为 n(n-1)/2，仍然是 Θ(n²)。
int pairComparisons(int n) {
  var count = 0;
  for (var i = 0; i < n; i++) {
    for (var j = i + 1; j < n; j++) {
      count++; // 1. 每次比较记一次基本操作。
    }
  }
  return count;
}

/// 对数循环：k 每轮翻倍，轮数为 ⌊log₂ n⌋。
int doublingSteps(int n) {
  var count = 0;
  for (var k = 1; k < n; k *= 2) {
    count++;
  }
  return count;
}

/// 内层固定 3 次：写成两层循环，总成本依然是 Θ(n)。
int fixedInnerLoop(int n) {
  var count = 0;
  for (var i = 0; i < n; i++) {
    for (var j = 0; j < 3; j++) {
      count++;
    }
  }
  return count;
}
```

```text

8       28              3             24
64      2016            6             192
512     130816          9             1536
4096    8386560         12            12288
```

三条读表结论：内层次数随外层变化时，总数是 $n(n-1)/2$，仍然是 $\Theta(n^2)$；内层次数固定为 3 时，两层循环也只是 $\Theta(n)$；`doublingSteps` 每轮把规模翻倍，轮数是 $\lfloor \log_2 n \rfloor$，所以是 $\Theta(\log n)$。**循环层数只是提示，不是结论**。
规模也可能不止一个参数：两段规模分别为 $n$ 和 $m$ 的顺序循环总成本是 $n+m$，不能合并成一个 $n$；图算法通常记账为 $O(V+E)$，字符串算法常出现 $O(L \cdot \sigma)$（长度为 $L$、字符集大小为 $\sigma$）。

> **关键认知：** 复杂度是“规模定义 + 成本模型”的函数；不写清 `n` 指什么、每次记什么操作，“这个算法是 O(n²)”没有可验证的含义。

> **面试高频：** 让你分析一段代码的复杂度时，第一步做什么？
> **答题脉络：** 定义规模 → 选成本模型 → 数清每部分执行次数 → 求和保留主导项 → 说明前提与边界口径。
> **追问方向：** 多参数规模（V、E）、输入分布、最好与最坏的差别、隐藏的排序与复制成本。

## 渐近记号回答的是上界还是紧确界

渐近记号把“增长趋势”形式化。用 $f(n)$ 表示成本函数，$g(n)$ 表示参照函数：

- $f(n) = O(g(n))$：存在正常数 $c$ 与 $n_0$，使得对所有 $n \ge n_0$ 有 $0 \le f(n) \le c \cdot g(n)$——$g$ 是 $f$ 的一个**上界**。
- $f(n) = \Omega(g(n))$：存在正常数 $c$ 与 $n_0$，使得对所有 $n \ge n_0$ 有 $0 \le c \cdot g(n) \le f(n)$——$f$ 的一个**下界**。
- $f(n) = \Theta(g(n))$：同时存在 $O$ 与 $\Omega$ 两组常数——$g$ 与 $f$ 同阶，是**紧确界**。

记号定义与 $n_0$ 的作用见 CLRS 第 3 章 [R1]。

**“$O$”不是等号，而是“不超过”**：说“二分查找是 $O(\log n)$”只是给出上界；说“二分查找是 $O(n)$”也成立，只是浪费信息。日常交流中人们说“是 $O(n^2)$”时往往想表达 $\Theta(n^2)$，但严格写下来应该区分上界、下界与紧确界。
忽略低阶项与常数需要两个前提：$n$ 足够大（$n \ge n_0$），且常数差异不主导实际规模下的计算量。反例之一是小数据：$n = 3$ 时 $n^3$ 与 $1000n$ 谁更大，与 $n \to \infty$ 的结论正好相反。反例之二是大常数：$\Theta(n^2)$ 的算法每步只做一次访问、而 $\Theta(n \log n)$ 的对手每步做几十次运算时，中等规模下前者仍可能更快。

还要注意：**“最好/最坏”和渐近记号是两个维度**。记号描述的是函数；最好/最坏描述的是“在哪些输入上取这个函数的值”。所以“插入排序最坏是 $\Theta(n^2)$、最好是 $\Theta(n)$”与“插入排序是 $O(n^2)$”可以同时成立。

> **关键认知：** $O$ 只给出增长的上界，不声称这是最紧的界；只有当上下界同阶时，才可以写 $\Theta$。

> **面试高频：** $O$、$\Omega$、$\Theta$ 的区别是什么，这句话哪里不对——“插入排序最坏是 $O(n^2)$，所以最好也是 $O(n^2)$”？
> **答题脉络：** 先给三个定义 → 再区分“记号”与“输入口径” → 用插入排序的最好 $\Omega(n)$、最坏 $\Theta(n^2)$ 说明结论 → 指出 $O(n^2)$ 对所有输入都成立但不紧。
> **追问方向：** $n_0$ 的作用、大常数为什么会让理论结论与实际相反、为什么工程上仍要测常数。

## 时间复杂度的分析方法

分析时间复杂度只有四个基本动作，加上一个容易漏掉的记账习惯。

1. **顺序**：两段依次执行，成本相加。
2. **分支**：`if/else` 只走一支，成本取两支的较大值；循环里的分支要按最坏情况或期望口径单独说明。
3. **嵌套**：若内层次数与外层无关，成本相乘；若内层次数随外层变化，必须求和。
4. **对数**：每轮把规模减半（`n ~/ 2`）或翻倍（`k *= 2`），层数是 $\Theta(\log n)$。
5. **记账习惯**：切片、拼接、排序、合并、哈希冲突这些“看起来只有一行”的操作，成本要按元素个数计。

第五条最容易被漏。下面这个单层循环每轮复制剩余后缀，执行次数是 $n$ 次，但总复制量是 $n + (n-1) + \cdots + 1$（节选自 `hidden_cost.dart`）：

```dart
/// 每轮复制剩余后缀，复制总量是 n + (n-1) + ... + 1 = n(n+1)/2。
int sublistCopyCost(int n) {
  final source = List<int>.generate(n, (index) => index);
  var copied = 0;
  for (var i = 0; i < n; i++) {
    final window = source.sublist(i); // 1. sublist 会新建列表并复制元素。
    copied += window.length;
  }
  return copied;
}
```
<!-- verify: .work/verify/A01/hidden_cost.dart -->

把它与同样扫描整个列表、每轮只做 $O(1)$ 工作的对照实现（`singleScanCost`）相比，复制总量与访问总量的比值随 n 增长：n = 100 时是 101.0，n = 400 时是 401.0，n = 1600 时是 1601.0。这个比值本身就是证据：一层循环，却是 $\Theta(n^2)$。

> **关键认知：** 数循环层数只能提示候选阶数；结论必须来自“每部分执行多少次”的求和。单层循环里放一次 O(n) 的复制，复杂度就是 Θ(n²)。

## 空间复杂度

讨论空间复杂度时先要明确三种口径：输入数据占的空间、算法运行中额外申请的空间、返回结果占的空间。工程与面试里默认说的是**额外空间**，但输出是否计入必须写清楚：有些题目（例如要求常量额外空间的两数之和）会显式规定输出不计入。

原地算法（in-place）指额外空间为 $O(1)$ 的实现。注意 Dart 里很多“看起来不乱用空间”的写法其实会复制：`List.of`、`sublist`、`toList` 都会新建列表，因此排序前“顺手复制一份”就把额外空间从 $O(1)$ 变成了 $O(n)$。递归的调用栈则要按深度计数：每层一次函数调用就是一份栈帧。$T(n) = T(n-1) + O(1)$ 的递归额外空间是 $\Theta(n)$，而 $T(n) = T(n/2) + O(1)$ 的递归额外空间是 $\Theta(\log n)$。同一个算法改写成循环通常能把栈空间降到 $O(1)$，但方向反过来不成立：不能把递归的栈空间当作零，也不能依赖实现去消除它——是否内联或消除尾递归属于编译器的实现细节，不是语言层面的承诺。

> **关键认知：** 空间复杂度默认指额外空间，递归的调用栈算额外空间；因此“递归版和迭代版时间一样，所以空间也一样”通常是错的。

> **面试高频：** 递归到底算不算空间？
> **答题脉络：** 先问“计不计输入与输出” → 递归栈按深度计 → 用 $T(n)=T(n-1)+1$ 得 $\Theta(n)$、用 $T(n)=T(n/2)+1$ 得 $\Theta(\log n)$ → 再说明实现层面的尾部消除不能当承诺。
> **追问方向：** 原地算法的定义、记忆化引入的额外空间、切片与复制如何破坏 $O(1)$ 额外空间。

## 最好、平均、最坏、期望与均摊

同一份代码在不同输入上成本不同，于是出现了五个口径，它们回答的是不同的问题：

| 口径 | 回答的问题 | 是否依赖概率假设 |
|---|---|---|
| 最好 | 最有利输入下的成本下界 | 否 |
| 最坏 | 所有输入都不超过的界，是实时与安全场景的依据 | 否 |
| 平均 | 按输入分布求出的期望成本 | 是，需要输入分布 |
| 期望 | 算法自身随机性（如随机主元、随机打乱）带来的平均成本 | 是，随机来自算法 |
| 均摊 | 一串操作的总成本除以操作次数 | 否 |

**均摊不是平均**：均摊只做“把总成本除以次数”的代数运算，不需要任何分布假设；平均与期望才需要概率模型。这个区分直接影响结论能不能在对抗性输入下成立。

动态数组的追加是均摊分析的标准案例。下面这个模型在容量不足时把容量翻倍，统计 n 次追加造成的元素写入总次数（含扩容复制，节选自 `amortized_growth.dart`）：

```dart
/// 模型一：容量不足时翻倍，返回 n 次 add 造成的元素写入总次数。
int doublingGrowWrites(int addCount) {
  var capacity = 1;
  var size = 0;
  var writes = 0;
  for (var i = 0; i < addCount; i++) {
    if (size == capacity) {
      for (var k = 0; k < size; k++) {
        writes++; // 1. 扩容时逐个复制已有元素。
      }
      capacity *= 2;
    }
    size++;
    writes++; // 2. 写入新元素本身。
  }
  return writes;
}

/// 断言翻倍模型的关键结论：总写入小于 3n，均摊到每次追加是常数。
void checkDoublingModel() {
  assert(doublingGrowWrites(4) == 7);
  assert(doublingGrowWrites(16) == 16 + 15);
  assert(doublingGrowWrites(1000) <= 3 * 1000);
}
```

```text
n       翻倍模型总写入  每次 add 均摊  每次加 1 模型总写入
8       15              1.88            36
64      127             1.98            2080
512     1023            2.00            131328
4096    8191            2.00            8390656
```

复制量的求和是 $1 + 2 + 4 + \cdots + 2^{k-1} < n$，所以 n 次追加的总写入小于 $2n$，**均摊到每次追加是 $O(1)$**；但它同时保留了“触发扩容的那一次是 $\Theta(n)$”这个最坏情况。单次最坏与序列均摊并不矛盾，因为最坏情况很少发生且代价被后续操作摊薄了。作为对照，如果每次只把容量加 1，总写入是 $n(n+1)/2$，均摊也退化成 $\Theta(n)$。两个常见的期望复杂度结论也要带上前提：哈希表链式实现的查找是 $\Theta(1 + \alpha)$，$\alpha = n/m$ 是装载因子，只有 $\alpha$ 有界且哈希把键近似均匀分布时，才可以近似说“期望 $O(1)$”，最坏情况仍是 $\Theta(n)$；快速排序在随机化主元下期望 $\Theta(n \log n)$，而未随机化、且每次取首元素为主元时，已排序输入会退化成 $\Theta(n^2)$。

> **关键认知：** 均摊是对一串操作整体成本的平均，不含概率假设；平均与期望依赖输入分布或算法随机性，三者不能互换。

> **面试高频：** 动态数组的追加为什么既能说“单次最坏 O(n)”，又能说“均摊 O(1)”？
> **答题脉络：** 先说清单次最坏与序列均摊是两个口径 → 把 n 次追加的复制量求和得到小于 2n → 均摊常数 → 指出触发扩容那一次仍线性，并说明扩容倍数取 1 会怎样。
> **追问方向：** 装载因子与哈希期望、摊还分析的记账/势能方法、平均与均摊的差别。

## 递归式与增长阶

### 分治与递归式

递归式（recurrence）用三段信息描述一个算法：子问题分成几个、每个子问题多大规模、除了递归之外还要做多少工作。这两个式子覆盖了最常见的两类结构：

- $T(n) = T(n/2) + O(1)$：每层只保留一半，只递归一次（折半查找）。层数 $\log_2 n$，每层常数工作，得 $\Theta(\log n)$。
- $T(n) = 2T(n/2) + O(n)$：分成两个子问题，合并成本与规模成正比（归并排序）。每层合计 $n$，共 $\log_2 n$ 层，得 $\Theta(n \log n)$。

递归树是最直观的推导工具：把“每层的工作量”写成一列，再乘层数。第一类每层是常数、层数是 $\log n$；第二类每层是 $n$、层数是 $\log n$。用计数器实测这两个式子，结果与推导一致（节选自 `recursion_cost.dart`，完整文件还含 `linearDepth` 与 `main` 断言）：

```dart
int binarySearchCalls = 0;
int naiveFibCalls = 0;

/// T(n) = T(n/2) + O(1)：每步只保留一半区间，返回下探层数。
int halvingDepth(int size) {
  binarySearchCalls++;
  if (size <= 1) return 0; // 1. 基本情况：区间里至多剩一个元素。
  return 1 + halvingDepth(size ~/ 2); // 2. 规模减半，只递归一次。
}

/// 计数模型：T(n) = 2T(n/2) + n，返回归并排序的合并写入总次数。
int mergeTreeWrites(int size) {
  if (size <= 1) return 0;
  final middle = size ~/ 2;
  return size + mergeTreeWrites(middle) + mergeTreeWrites(size - middle);
}

/// 朴素递归 fib：call(n) = call(n-1) + call(n-2) + 1，调用次数指数增长。
int naiveFib(int n) {
  naiveFibCalls++;
  if (n < 2) return n;
  return naiveFib(n - 1) + naiveFib(n - 2);
}
```
<!-- verify: .work/verify/A01/recursion_cost.dart -->

- `halvingDepth(1024)` 返回 10，函数共被调用 11 次；同一份文件里 `linearDepth(1000)` 返回 1000，说明 $T(n)=T(n-1)+O(1)$ 的递归深度就是 $n$，这是额外空间而不是时间。
- `mergeTreeWrites(1024) == 1024 × 10`，与 $n \log_2 n$ 吻合。
- 朴素递归 fib 在 $n = 20$ 时需要 21891 次调用，$n$ 每增加 1，调用次数大约乘以黄金比 $\varphi \approx 1.618$：**指数级，不是线性**。重复子问题的止损方式是把结果记下来（记忆化）或自底向上递推，见[动态规划](./12-动态规划.md)。

主定理（master theorem）给出了求解 $T(n) = aT(n/b) + f(n)$（$a \ge 1$，$b > 1$）的一族现成结论，但要记住它的适用边界：它只处理这种形式，且需要比较 $f(n)$ 与 $n^{\log_b a}$ 的增长关系；形式不匹配（例如 $T(n) = T(n-1) + T(n-2) + O(1)$）或合并成本不是幂次形式时，回到递归树或代入法更可靠。本文只给出判断依据，不展开成公式表，需要时查 CLRS 第 4 章 [R1]。

> **关键认知：** 递归深度决定调用栈空间，调用次数决定时间；把两者混在一起，就会得出“递归都是 O(n)”这类错误结论。

> **面试高频：** 为什么二分查找是 O(log n)？
> **答题脉络：** 每次只保留一半候选 → 层数为 $\log_2 n$ → 每层常数工作 → 时间 $\Theta(\log n)$；递归实现的空间同样按层计，是 $\Theta(\log n)$；再给迭代版对照。
> **追问方向：** 主定理什么时候不适用、归并排序的 $\log$ 从哪来、朴素递归为什么必须记忆化。

## 从实测到模型

### 倍率实验能做什么

既然单次计时不可靠，一个自然的补救是“倍率实验”：把规模依次翻倍，观察成本比值。如果 $T(n) \approx a n^b$，那么 $T(2n)/T(n) \to 2^b$，于是比值 8 提示立方、4 提示平方、2 提示线性。为了排除计时噪声，先用同一模型统计操作次数（节选自 `doubling_ratio.dart`）：

```dart
/// Θ(n³)：三重循环的判断次数为 n(n-1)(n-2)/6（ThreeSum 暴力版的内循环）。
int tripleChecks(int n) {
  var count = 0;
  for (var i = 0; i < n; i++) {
    for (var j = i + 1; j < n; j++) {
      for (var k = j + 1; k < n; k++) {
        count++; // 1. 只统计基本操作，不关心具体的加法和比较。
      }
    }
  }
  return count;
}

/// Θ(n² log n)：每一对 (i, j) 之后做一次二分查找，每次约 log₂ n 步
/// （对应 ThreeSum 的“排序 + 二分查找”版本）。
int pairChecksWithBinarySearch(int n) {
  final steps = n.bitLength; // n 的二进制位数 = ⌊log₂ n⌋ + 1
  var count = 0;
  for (var i = 0; i < n; i++) {
    for (var j = i + 1; j < n; j++) {
      for (var k = 0; k < steps; k++) {
        count++; // 1. 二分查找的每一步记一次比较。
      }
    }
  }
  return count;
}
```

三次方的比值从 8.857 单调下降到 8.047，趋近 $2^3 = 8$；带对数因子的那一列从 4.960 只降到 4.453，趋近 4 的速度慢得多。原因可以直接算出来：$T(n) = n^2 \log n$ 时，$\frac{T(2n)}{T(n)} = 4 \cdot \frac{\log 2n}{\log n} = 4 \cdot (1 + \frac{1}{\log_2 n}) \to 4$，也就是说**对数因子在有限规模下会被吸收进比值**，只能靠“极限上趋近”来区分：旧文把三重循环的结论写成 $a N^3 \log N$，正是被这类有限规模下的偏差误导，正确的量级是 $\Theta(n^3)$。

实测版倍率实验的前提是足够大的规模与稳定的环境：把上面那段 `quadraticWork` 的耗时按倍率排列，只有最后一行才接近 4：2.00 → 2.30 → 3.90。实测能做的是佐证阶数、发现实现层面的意外（分配、缓存、GC）；不能做的是证明渐近阶，更不能把一次测量推广到其他平台。

> **关键认知：** 倍率实验只能佐证增长阶：它检验的是有限规模处的趋势，对数因子与常数都可能在这段区间里伪装成别的阶。

## 常见算法思想地图

面对新问题，先判断“它像哪一类”，比先回忆模板更有效。下表只负责给方向，每个机制的推导与不变量在对应的主文里展开。

| 思想 | 识别信号 | 常见代价 | 展开阅读 |
|---|---|---|---|
| 枚举与剪枝 | 规模很小，状态空间可穷举 | 指数级，剪枝后大幅下降 | [递归、分治与回溯](./11-递归、分治与回溯.md) |
| 双指针与滑动窗口 | 序列有序，或答案对应连续区间 | 两端单向移动，$\Theta(n)$ | [数组与字符串](./02-数组与字符串.md) |
| 排序与二分 | 无序但可付一次排序成本；候选可分半排除 | $\Theta(n \log n)$ 或 $\Theta(\log n)$ | [排序](./09-排序.md) / [查找与二分查找](./10-查找与二分查找.md) |
| 分治 | 问题可拆成同型子问题再合并 | 由递归式决定，常用 $n \log n$ | [递归、分治与回溯](./11-递归、分治与回溯.md) |
| 贪心 | 局部最优可证明能扩展为全局最优 | 通常含一次排序，$\Theta(n \log n)$ | [贪心](./13-贪心.md) |
| 动态规划 | 有重叠子问题与最优子结构 | 状态数 × 状态转移成本 | [动态规划](./12-动态规划.md) |
| 随机化 | 输入分布未知或可能被对抗 | 期望界，最坏界通常不变 | 本文“从实测到模型” |

使用顺序建议是：先看规模的量级，再看结构（有序、连续区间、树/图、最优子结构），最后回到复杂度确认方向可行。三个问题都可以先问同一件事：**“我能不能少看一些候选？”**

> **关键认知：** 思想地图回答的是“从哪个方向开始试”，不提供模板；方向选定后仍然要用复杂度模型确认它在给定规模下可行。

## 什么时候用，什么时候别用

**该用的时候：**

- 判断可行性。n = 10⁵ 时 $\Theta(n^2)$ 需要约 $10^{10}$ 次基本操作，超出秒级预算的数量级，直接说明这条方向不可行，应改找 $\Theta(n \log n)$ 或 $\Theta(n)$ 的做法。
- 比较方案并解释取舍。同一道题的三种模型可以排序：期望线性的哈希、$\Theta(n \log n)$ 的排序、$\Theta(n^2)$ 的两两比较。
- 评估容量与内存预算。$\Theta(n)$ 的额外空间在 $10^8$ 规模下是否可接受，是设计阶段就该回答的问题。

**不该用的时候（反例）：**

- 不能用它替代基准测试。同样的阶数，常数差异可以让实际耗时差出数倍；同样，实测的“谁快”也不能反过来证明阶数。
- 不能用它当实时保证。控制回路、音视频这类场景需要的是最坏界与常数上界，而不是期望或均摊结论。
- 不能在小数据上唯阶数论。$n = 32$ 时 $\Theta(n^2)$ 只有约 500 次比较，一个常数很小、缓存友好的简单实现，往往胜过大材小用的复杂结构。
- 不能忽略内存访问模式。同样是 $\Theta(n)$，顺序访问与跳跃访问的常数不同；具体差多少依赖平台与实现，不做无来源的硬件结论。
- 不能忽略业务约束。内存上限、网络往返次数、精度要求（例如改用 `BigInt` 会更慢）都可能比阶数更早成为瓶颈。

> **关键认知：** 复杂度适合回答“规模扩大后谁更可行”，不适合回答“这一次谁更快”；把两者混用，就会在小数据上做出错误的工程取舍。

## 常见坑与边界

### 常见误区

- ❌ 哈希查找“就是 $O(1)$”。✅ 它依赖装载因子与哈希分布，期望是 $\Theta(1+\alpha)$，最坏仍是 $\Theta(n)$。
- ❌ 数循环层数得出复杂度。✅ 内层次数随外层变化时必须求和；三角嵌套是 $\Theta(n^2)$，内层固定次数的两层循环是 $\Theta(n)$。
- ❌ 只统计“看起来像工作”的那一行。✅ 切片、拼接、排序、合并、哈希冲突都要记账；一层循环里放一次 `sublist` 就是 $\Theta(n^2)$。
- ❌ 把均摊当平均。✅ 均摊是序列整体成本除以次数，不需要分布假设；平均与期望需要。
- ❌ 递归一律写成 $O(n)$，或忘记把栈空间计入额外空间。✅ 先写递归式，再分别算调用次数与最大深度。
- ❌ 忽略整数溢出。✅ Dart Native 的 `int` 是 64 位、溢出按补码回绕；超出范围要换 `BigInt`，编译到 Web 时还要另算数值语义。
- ❌ 用 `assert` 做业务校验。✅ 断言只在开启时执行，未开启时连参数表达式都不会求值（`dart run` 默认关闭，`dart test` 会开启）；本文的代码要用 `dart run --enable-asserts` 运行才会检查。

### 边界与反例

- 规模定义会改变结论：整数输入按“个数”计是 $\Theta(n)$，按“位数”计则加法和除法都不再是常数操作。
- 并行与 I/O 超出模型范围：渐近记号描述的是顺序执行的基本操作次数，不描述并发下的墙钟时间。
- 语言与平台差异：Dart Native 的 `int` 是 64 位补码回绕，编译到 JavaScript 时整数范围与位运算语义另有约束 [R5]。
- 记忆化是用空间换时间：递归的栈与缓存都要算进额外空间，别只看到时间下降。

> **关键认知：** 复杂度的每个结论都挂在前提上——规模定义、成本模型、分布假设、整数位宽；前提丢掉以后，剩下的只是一句口号。

## 知识点应用

### 同一道题的三种模型：包含重复元素

**问题与匹配。** [LeetCode 217: Contains Duplicate](https://leetcode.com/problems/contains-duplicate/) 判断数组是否存在重复元素（$1 \le n \le 10^5$，$-10^9 \le \text{nums}[i] \le 10^9$）[R7]，适合作为“用空间换时间”的最小样本：三种做法分别对应本文的成本模型、隐藏的排序成本与期望复杂度三节。**不变量。** 暴力版是“已检查过的前缀中没有答案”，排序版靠“重复元素在有序数组中必然相邻”，哈希版靠“集合中存在过的元素恰好是已扫描的前缀”（节选自 `contains_duplicate.dart`，完整文件还有 `main` 的交叉验证与“输入未被修改”断言）。

```dart
/// 模型一：两两比较。时间 Θ(n²)，额外空间 Θ(1)。
bool containsDuplicateBruteForce(List<int> nums) {
  for (var i = 0; i < nums.length; i++) {
    for (var j = i + 1; j < nums.length; j++) {
      if (nums[i] == nums[j]) return true;
    }
  }
  return false;
}

/// 模型二：先排序再比较相邻元素；会改动列表，所以先复制一份。
bool containsDuplicateSorting(List<int> nums) {
  final sorted = List<int>.of(nums); // 1. 复制，保持调用方数据不变。
  sorted.sort(); // 2. Dart 文档不承诺 sort 稳定，也不公开其复杂度。
  for (var i = 1; i < sorted.length; i++) {
    if (sorted[i] == sorted[i - 1]) return true;
  }
  return false;
}

/// 模型三：用集合记录出现过的值。时间期望 Θ(n)，额外空间 Θ(n)。
bool containsDuplicateHashing(List<int> nums) {
  final seen = <int>{};
  for (final value in nums) {
    if (!seen.add(value)) return true; // 1. add 返回 false 表示已经存在。
  }
  return false;
}
```

**复杂度。** 暴力是 $\Theta(n^2)$ 时间、$O(1)$ 额外空间；排序是比较排序，下界是 $\Omega(n \log n)$，加上复制一份的 $O(n)$ 空间；哈希版期望 $\Theta(n)$ 时间、$\Theta(n)$ 空间。**边界。** 空数组与单元素直接为假；排序版必须复制输入，否则会静默修改调用方的数据；Dart 的 `List.sort` 文档不承诺稳定性，也不公开复杂度，所以这里只写“比较排序的量级”。归档题解见 [哈希表题解](../02-LeetCode题解/12-哈希表.md)。

### 递归树里重复了什么：爬楼梯

**问题与匹配。** [LeetCode 70: Climbing Stairs](https://leetcode.com/problems/climbing-stairs/) 求爬 n 级台阶的方法数（$1 \le n \le 45$）[R8]，每次可走 1 或 2 级，匹配“递归式与增长阶”：直接按定义递归会把同一批子问题重复计算，递归树暴露的正是重复子问题。**状态与不变量。** $ways(n) = ways(n-1) + ways(n-2)$，边界 $ways(1) = 1$、$ways(2) = 2$；朴素递归调用的次数满足 $C(n) = C(n-1) + C(n-2) + 1$（节选自 `climbing_stairs.dart`，完整文件还有 `main` 对基准情况、调用次数与 64 位边界的断言）。

```dart
int naiveCalls = 0;

/// 直接按定义递归：调用次数满足 call(n) = call(n-1) + call(n-2) + 1，
/// 等价于 2F(n) - 1（F 为标准斐波那契数），因此随 n 指数增长。
int climbStairsNaive(int n) {
  naiveCalls++;
  if (n <= 2) return n;
  return climbStairsNaive(n - 1) + climbStairsNaive(n - 2);
}

/// 自底向上：时间 Θ(n)，额外空间 Θ(1)。
int climbStairsIterative(int n) {
  var waysTwoBefore = 1; // ways(0) = 1：站在起点算一种方法。
  var waysOneBefore = 1; // ways(1)
  for (var step = 2; step <= n; step++) {
    final ways = waysOneBefore + waysTwoBefore;
    waysTwoBefore = waysOneBefore;
    waysOneBefore = ways;
  }
  return n == 0 ? 1 : waysOneBefore;
}

/// BigInt 版本：不受 Dart Native 的 64 位回绕影响。
BigInt climbStairsBigInt(int n) {
  var waysTwoBefore = BigInt.one;
  var waysOneBefore = BigInt.one;
  for (var step = 2; step <= n; step++) {
    final ways = waysOneBefore + waysTwoBefore;
    waysTwoBefore = waysOneBefore;
    waysOneBefore = ways;
  }
  return n == 0 ? BigInt.one : waysOneBefore;
}
```

**复杂度。** 朴素递归时间随 $\varphi^n$ 增长（$n = 20$ 时实测 13529 次调用），栈深度是 $\Theta(n)$；迭代版时间 $\Theta(n)$、额外空间 $O(1)$。**边界。** $n = 1$ 与 $n = 2$ 是基准情况；题目约束到 45，迭代版范围内结果不超过 64 位，但 $ways(93)$ 已经超过 $2^{63}-1$，Dart Native 的 `int` 会回绕（实测得到 1293530146158671551，而真实值是 19740274219868223167），超出范围时应改用 `BigInt`。归档题解见 [动态规划题解](../02-LeetCode题解/07-动态规划.md)。

### 有序数组把双循环变成双指针：两数之和

**问题与匹配。** [LeetCode 167: Two Sum II - Input Array Is Sorted](https://leetcode.com/problems/two-sum-ii-input-array-is-sorted/) 在按非递减排序的 1-indexed 数组中找到和为目标值的两个数，题目保证恰好一个解，并要求常量额外空间 [R9]，匹配“输入结构决定分析”：有序性把 $n^2$ 个候选对压缩成一条单向移动的路径。**不变量。** 每轮只移动一个指针，移动后若答案存在，必然仍在 $[left, right]$ 区间内：和偏小时 `left` 左侧的位置与任何右侧元素的和只会更小，可以直接排除；和偏大时 `right` 右侧同理。因此每轮至少排除一个位置，总轮数不超过 $n-1$（节选自 `two_sum_sorted.dart`，完整文件还有 `main` 对两组实现的交叉验证与只读输入断言）。

```dart
/// 双指针。时间 Θ(n)，额外空间 Θ(1)，不修改输入；无解返回空列表。
List<int> twoSumTwoPointers(List<int> numbers, int target) {
  var left = 0;
  var right = numbers.length - 1;
  while (left < right) {
    final sum = numbers[left] + numbers[right];
    if (sum == target) return [left + 1, right + 1];
    if (sum < target) {
      left++; // 1. 和太小：较小的一侧只能右移，否则不可能变大。
    } else {
      right--; // 2. 和太大：较大的一侧只能左移，否则不可能变小。
    }
  }
  return const [];
}

/// 记录双指针版本的移动次数，用于验证“每轮至少移动一个指针”。
int twoPointerMoves(List<int> numbers, int target) {
  var left = 0;
  var right = numbers.length - 1;
  var moves = 0;
  while (left < right) {
    final sum = numbers[left] + numbers[right];
    if (sum == target) return moves;
    if (sum < target) {
      left++;
    } else {
      right--;
    }
    moves++;
  }
  return moves;
}
```

**复杂度。** 暴力枚举所有下标对是 $\Theta(n^2)$、额外空间 $O(1)$；双指针是 $\Theta(n)$、额外空间 $O(1)$，并且输入保持只读（`twoPointerMoves` 验证了移动次数不超过 $n-1$）。**边界。** $n = 2$ 时循环体只执行一次；重复值如 `[1, 1, 2]`、目标 2 要返回前两个下标；无解时函数契约返回空列表（题目本身保证有解，但函数不应依赖这一点）；传入不可修改的常量列表也不能抛异常。归档题解见 [双指针题解](../02-LeetCode题解/01-双指针.md)。

## 面试考点与追问

这一节只给复述顺序与追问方向，具体推导都在上文对应章节。

- **分析流程**：规模 → 成本模型 → 执行次数求和 → 保留主导项 → 前提（[输入规模与成本模型](#输入规模与成本模型)）。追问：多参数规模、输入分布、隐藏的复制成本。
- **记号辨析**：$O$、$\Omega$、$\Theta$ 的定义与误用（[渐近记号回答的是上界还是紧确界](#渐近记号回答的是上界还是紧确界)）。追问：$n_0$、大常数、紧确与不紧的区别。
- **二分查找**：为什么是 $\Theta(\log n)$，递归栈算不算空间（[递归式与增长阶](#递归式与增长阶)）。追问：迭代与递归的空间差别、区间开闭带来的边界。
- **快速排序**：最坏 $\Theta(n^2)$、期望 $\Theta(n \log n)$，随机化的作用（[最好、平均、最坏、期望与均摊](#最好平均最坏期望与均摊)）。追问：随机化改变的是期望还是最坏。
- **哈希查找与动态数组**：哈希期望 $\Theta(1+\alpha)$ 的前提与最坏情况；动态数组单次最坏 $\Theta(n)$ 与均摊 $O(1)$ 如何并存（[最好、平均、最坏、期望与均摊](#最好平均最坏期望与均摊)）。追问：装载因子、冲突处理、扩容倍数、均摊与平均的差别。
- **常数与缓存**：只解释影响方向，不给无依据的倍数（[什么时候用，什么时候别用](#什么时候用什么时候别用)）。

> **面试高频：** 面试官让你估计一段代码的复杂度，最容易在哪里失分？
> **答题脉络：** 先声明规模与成本模型 → 逐段求和 → 保留主导项并说明口径（最坏还是期望）→ 主动指出隐藏成本与前提，而不是背一个阶数。
> **追问方向：** 规模定义不同导致结论不同、期望与均摊被混用、只算循环层数而不算复制成本。

## 小结

分析任何一段代码都按“规模 → 基本操作 → 边界口径 → 权衡”过一遍：先说清 `n` 指什么、每次记什么操作；再数清各部分的执行次数并保留主导项；然后说明结论属于最坏、期望还是均摊；最后交代常数、内存与业务约束是否会让结论反转。
