# 操作系统与程序运行

一个 `undefined reference to 'add'`、一次 RSS 不下降、一个互相等待的线程、一条 `write` 成功却丢失的日志，通常被分别归入“链接问题”“内存泄漏”“死锁”“磁盘故障”。它们其实共享同一条主线：源码如何变成进程、进程如何获得虚拟地址空间、多个执行流如何共享 CPU 与内存、I/O 又如何穿过内核到达设备。

本板块把这条主线拆成六篇正文：操作系统提供哪些抽象与边界，程序如何从源码变成运行的进程，虚拟内存与函数调用如何支撑一个指针，多个执行流如何被调度与同步，以及一次读写如何到达存储设备。索引按通用原理组织，可观察实现以 x86-64 Linux 为主，但不把 Linux 实现当作唯一标准；网络层的 Socket 抽象与内核 I/O 的关系见[网络板块的 Socket 与 I/O 模型](../04-计算机网络/10-Socket与I-O模型.md)。

## 这一板块解决什么问题

操作系统是硬件的资源管理者、抽象提供者和隔离边界：它把 CPU、内存与设备包装成进程、地址空间和文件，再把这些对象分给多个使用者，并立好互不越界的规则。本板块的回放顺序不是 API 清单，而是“程序如何真正运行”的四类问题：

1. 应用为什么不能直接操作硬件，内核通过什么受控边界提供服务？
2. 一段源码在运行前要经过哪些产物，一条失败信息属于哪个阶段？
3. 变量、指针、函数调用和堆分配在地址空间里如何落地？
4. 多个线程、多个进程与存储设备之间如何共享、等待与同步？

## 教程学习路线

推荐顺序为 01 → 06 → 04 → 02 → 03 → 05，它与文件编号不同，原因如下：

1. [01-操作系统概述](./01-操作系统概述.md)：建立抽象、保护与系统调用的总图，是后面五篇的坐标系。
2. [06-程序从源码到运行](./06-程序从源码到运行.md)：先知道什么被装载，再谈它运行在哪里；虽然编号靠后，第一次阅读时提前读最省力。
3. [04-虚拟内存、地址空间与函数调用](./04-虚拟内存、地址空间与函数调用.md)：把刚装载好的程序放进地址空间，解释指针、栈、堆与页表。
4. [02-进程、线程与调度](./02-进程、线程与调度.md)：地址空间就位后，再看多个执行流如何共享 CPU。
5. [03-同步、进程通信与死锁](./03-同步、进程通信与死锁.md)：处理执行流之间的共享与等待，以及出问题时怎么排查。
6. [05-I/O、存储与文件系统](./05-I-O、存储与文件系统.md)：最后沿一次 `read` 与 `write` 走到设备，把缓冲、页缓存与持久化串起来。

只做面试复习时，可以直接跳到“面试高频入口”按问题定位；每一步读完后应能达到的完成标准见下一节。

## 完成标准

- 能用一个 `read` 调用串起用户态、系统调用、内核与设备的分工，并说明中断、异常与系统调用的区别。
- 能画出两条链路：源码文本 → 目标文件 → ELF → 进程映像；虚拟地址 → 页表与 TLB → 物理页帧。
- 能对“进程与线程与协程”“互斥锁与条件变量与信号量”“阻塞与非阻塞与异步”给出带边界的对比。
- 遇到链接失败、内存异常、线程卡死或磁盘 I/O 现象时，能说出从哪篇进入、先收集哪类证据。

## 按故障现象进入

- `undefined reference to ...`：先确认错误发生在预处理、编译、汇编还是链接阶段，入口：[错误发生在哪一个阶段](./06-程序从源码到运行.md#错误发生在哪一个阶段)。
- `cannot open shared object file`：检查动态链接器的查找顺序，入口：[动态链接器如何找到并绑定共享库](./06-程序从源码到运行.md#动态链接器如何找到并绑定共享库)；不要对不可信文件使用 `ldd`，替代读法见 [ldd 很方便，但不要对不可信文件使用](./06-程序从源码到运行.md#ldd-很方便但不要对不可信文件使用)。
- RSS 不下降或触发 OOM：从地址空间与分配器开始，入口：[从 VIRT、RSS 到一次内存排查](./04-虚拟内存、地址空间与函数调用.md#从-virtrss-到一次内存排查)。
- 程序以 Segmentation Fault 退出：先区分栈溢出、保护页与野指针，入口：[栈溢出、保护页与栈保护不是一回事](./04-虚拟内存、地址空间与函数调用.md#栈溢出保护页与栈保护不是一回事)。
- 线程互相等待、进程卡死：入口：[实战排查卡住的线程](./03-同步、进程通信与死锁.md#实战排查卡住的线程)；通用命令见 [Linux 命令行与进程排查](../07-工程工具与代码质量/01-Linux命令行与进程排查.md)。
- 磁盘延迟高、写入行为不符合预期：入口：[现代 Linux 块 I/O 层](./05-I-O、存储与文件系统.md#现代-linux-块-io-层)、[用一次文件读取串起全链路](./05-I-O、存储与文件系统.md#用一次文件读取串起全链路)。

## 平台与示例约定

- 原理以通用操作系统模型为准；可观察实现以 x86-64 Linux 配合 GCC、Binutils 与 glibc 为主，命令输出只引用稳定字段，并随发行版与工具链版本变化。
- 涉及平台专属行为时会显式标注，同一流程在 macOS 与 Windows 的差异见[程序从源码到运行](./06-程序从源码到运行.md#同一流程在-macos-与-windows-如何落地)。
- 索引不写死具体内核与编译器版本号；时效性断言的核查日期以各篇正文内的标注为准。
- 与网络板块的分工：Socket 抽象与网络 I/O 编程归网络板块，内核 I/O 路径与多路复用实现归本板块 [05-I/O、存储与文件系统](./05-I-O、存储与文件系统.md)。
