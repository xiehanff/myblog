# 工程工具与代码质量

这个板块和前面的学科不同：它是五类需要时回来查的工程能力，而不是按课程顺序建立的知识体系。命令行与进程排查让你在机器上定位“为什么慢、为什么占着端口、为什么杀不掉”；Git 管住代码的演进历史；正则表达式处理文本的批量匹配与替换；代码可读性与风格决定团队每次修改要付多少理解成本；重构方法论把“容易修改”落实成可验证的小步变换。它们的共同点是：工具服务于“把问题定位清楚、让代码容易改”，而不是为了用工具本身。

读法上不要把它当成主线课程：先知道每个入口解决什么问题，遇到具体任务再翻到对应篇目。原理不在这里重复——进程状态机、文件系统、I/O 模型在[操作系统与程序运行](../03-操作系统与程序运行/README.md)，本板块只讲操作侧视角与排错路线；正则只讲写法、边界与引擎差异，不展开某一门语言的实现源码。

## 按任务进入：学习顺序与前置知识

五篇之间没有强制先后；真正决定从哪一篇开始的是你手上的问题。

- **定位线上进程、端口、磁盘或日志问题** → [01-Linux命令行与进程排查](./01-Linux命令行与进程排查.md)。前置是 OS 的[进程、线程与调度](../03-操作系统与程序运行/02-进程、线程与调度.md)与 [I/O、存储与文件系统](../03-操作系统与程序运行/05-I-O、存储与文件系统.md)，前篇只讲命令侧的观察与操作。完成标准：能对“CPU 高 / 端口被占用 / 进程杀不掉 / 磁盘满”给出从现象到具体命令的排查路线，并知道危险命令的边界。
- **管理代码历史、分支与协作** → [02-Git](./02-Git.md)。独立阅读。完成标准：能解释工作区、暂存区、历史与 HEAD 的关系，说清 merge 与 fast forward 的差别，并独立处理冲突、储藏与历史查找。
- **批量匹配、提取或替换文本** → [03-正则表达式](./03-正则表达式.md)。独立阅读。完成标准：能写出带字符集、分组、回溯引用与前后查找的表达式，并说明贪婪匹配、回溯与不同引擎方言带来的边界。
- **评审命名、注释、函数与控制流** → [04-代码可读性与风格](./04-代码可读性与风格.md)。独立阅读，但与[程序设计板块](../05-程序设计与软件设计/README.md)互为参照。完成标准：能用“读者要重建什么意图”评价代码，知道什么时候不该抽取函数，并把格式类问题交给格式化与 lints 而不是评审。
- **让已有代码更容易修改** → [05-重构方法论与实践](./05-重构方法论与实践.md)。前置是基本的测试、版本控制和代码阅读能力；完成标准：能区分功能开发与重构，建立行为基线，按坏味道选择手法，并用小步变换保持代码始终可工作。
