# 工程工具与代码质量｜03-正则表达式

正则表达式是一种描述文本模式的语言，常用于查找、提取和替换。它不是独立的软件；真正执行它的是宿主工具或编程语言的正则引擎。

本文使用多数引擎都能理解的常见语法。正则并没有一套完全统一的标准：执行前应明确引擎（如 JavaScript、Java、PCRE、.NET、Python）、模式选项（如大小写忽略、多行、单行）以及替换字符串语法。需要匹配整段输入时，优先使用宿主 API 的 `full match`/`fullmatch`；只写搜索模式很容易把“包含”误当成“等于”。

在线测试工具适合验证公开的样例，不要把密码、令牌、生产日志或个人信息粘贴到第三方网站。

## 概述：先确定引擎和匹配范围

同一个模式可能经过两层转义：正则引擎要看到 `\d`，而宿主语言的普通字符串可能还要写成 `"\\d"`；支持原始字符串的语言则可以写成 `r'\d'`。因此排查“模式看起来对但匹配不到”时，先打印传给引擎的实际字符串。

还要区分三种操作：

| 操作 | 含义 | 典型风险 |
|---|---|---|
| 搜索 | 文本中出现一段匹配即可 | `123` 可能匹配到 `abc123xyz` |
| 逐行匹配 | 在每一行中搜索或匹配 | 多行模式会改变 `^`、`$` 的含义 |
| 全量匹配 | 整个输入必须符合模式 | 适合校验，但仍要处理换行和 Unicode 边界 |

## 匹配单个字符

`.` 匹配一个任意字符，但默认通常不匹配换行；是否包含换行由 `dotall`/`singleline` 选项决定。要匹配字面量点，应写 `\.`。正则是否区分大小写也由引擎默认值和模式选项决定。

```text
模式：C.C2018
文本：My name is CyC2018.
结果：CyC2018
```

不要把“任意字符”理解成“任意字节”：Unicode 字符、代理对和规范化形式的处理取决于引擎。涉及多语言文本时，用目标引擎的文档确认“字符”的定义。

## 匹配一组字符

字符组用 `[...]` 表示，组内匹配一个字符：`[abc]` 匹配 `a`、`b` 或 `c`；`[0-9]` 匹配一个 ASCII 数字。`-` 放在组首尾或写成 `\-` 时表示字面量；`^` 只有放在组开头（紧跟 `[`）时才表示取非。

例如，匹配一行中以 `abc` 开头且最后一个字符不是 ASCII 数字的文本：

```text
模式：^abc.*[^0-9]$
匹配：abcd
不匹配：abc1、xabc9
```

这个例子面向单行文本；若输入允许换行，应明确使用逐行模式或改用 `[\s\S]` 等由目标引擎支持的写法。`[^0-9]` 表示“不是 ASCII 数字”，并不等价于“不是任意 Unicode 数字”。

## 元字符与转义

### 空白与控制字符

常见转义如下：

| 写法 | 含义 |
|---|---|
| `\n` | 换行（LF） |
| `\r` | 回车（CR） |
| `\t` | 制表符 |
| `\f` | 换页符 |
| `\v` | 垂直制表符，支持范围以引擎为准 |
| `\x0A` | 用十六进制表示 LF；比 `\xA` 更明确 |

Windows 文本通常使用 `\r\n`，Unix/Linux 通常使用 `\n`。`\r?\n` 可兼容两者。`\b` 在字符组外通常是单词边界，但在 `[...]` 内很多引擎把它解释为退格字符，不能写成“回退一个字符”。

### 数字、单词和空白

| 写法 | 常见含义 | 可移植提醒 |
|---|---|---|
| `\d` / `\D` | 数字 / 非数字 | 是否包含 Unicode 数字依引擎和选项而变；只要 ASCII 时用 `[0-9]` |
| `\w` / `\W` | 单词字符 / 非单词字符 | 有的引擎只含 ASCII，有的会随 Unicode 选项扩展 |
| `\s` / `\S` | 空白 / 非空白 | 各引擎对 Unicode 空白的范围可能不同 |

八进制和十六进制转义的长度、语法也存在差异。要匹配协议中的固定字节，优先写出明确的 `\xNN`，并用目标引擎测试，不要把 `\0`、`\xA` 当成跨语言约定。

## 重复匹配

| 写法 | 含义 |
|---|---|
| `+` | 至少 1 次 |
| `*` | 0 次或多次 |
| `?` | 0 次或 1 次 |
| `{n}` | 恰好 n 次 |
| `{m,n}` | m 到 n 次 |
| `{m,}` | 至少 m 次 |

量词默认通常是贪婪的，会尽量多匹配；在量词后加 `?` 常表示懒惰匹配，例如 `a.+?c` 会在满足条件的前提下尽早遇到 `c`。懒惰并不等于高效，复杂的嵌套量词仍可能造成灾难性回溯；面对不可信输入，要限制长度并做性能测试。

```text
模式：a.+c
文本：abcabcabc
贪婪结果：abcabcabc
```

一个常见的邮箱示例是 `^[\w.]+@\w+\.\w+$`，它只适合演示量词和转义，不是完整的邮箱校验规则。真实校验应以业务允许的格式为准，通常还要做长度限制和后续验证。

## 位置匹配

### 单词边界

`\b` 匹配位置，不消耗字符；它通常表示 `\w` 与 `\W` 或字符串边界之间的位置，`\B` 表示非单词边界。因此 `\babc\b` 匹配的是文本中的三个字母 `abc`，但不会把边界本身放进结果。

### 字符串边界和多行模式

`^` 匹配输入开头，`$` 匹配输入结尾；开启 multiline 后，它们通常还会匹配每个换行的两侧。某些引擎的 `$` 还会在末尾换行前匹配。需要严格的绝对开头/结尾时，使用引擎提供的 `\A`、`\z` 或全量匹配 API，并确认语法是否支持。

例如，在 multiline 模式下查找以 `//` 开始的整行注释：

```text
模式：^[ \t]*//[^\r\n]*$
```

它不理解字符串、注释嵌套和语言语法，因此不能可靠地解析“代码中的所有注释”；处理源代码应优先使用对应语言的解析器。

## 分组与或运算

圆括号 `( ... )` 默认会捕获匹配内容，并可配合量词；不需要捕获时优先使用非捕获组 `(?: ... )`，减少无意的组编号变化。`|` 的范围由分组决定：`cat|dog` 等价于“cat 或 dog”，而 `gr(a|e)y` 匹配 `gray` 或 `grey`。

### 日期和 IP 示例

`(19|20)\d{2}` 可匹配 1900 或 2010，但不匹配 1020。匹配 IPv4 的一个常见模式如下，它不允许 `00` 这样的前导零：

```text
^(?:(?:25[0-5]|2[0-4]\d|1\d{2}|[1-9]?\d)\.){3}(?:25[0-5]|2[0-4]\d|1\d{2}|[1-9]?\d)$
```

该模式只检查 IPv4 的十进制文本形式，不处理 IPv6、端口、空白或 CIDR；网络地址应尽量交给标准库解析。

## 回溯引用与替换

回溯引用（backreference）要求后面的文本再次等于捕获组的内容，常见写法是 `\1`、`\2`。例如，匹配成对且级别相同的简单标题标签：

```text
模式：^<(h[1-6])>[^<]*</\1>$
匹配：<h1>x</h1>、<h2>x</h2>
不匹配：<h3>x</h1>
```

这只能处理很有限的标签形状，不能替代 HTML 解析器。

### 替换

替换字符串的组引用语法也不是统一的。多数编辑器、JavaScript、Java 和 .NET 常用 `$1`；Python 的 `re.sub` 常用 `\g<1>` 或 `\1`。先查宿主 API，不要把“查找模式语法”和“替换字符串语法”混为一谈。

```text
查找：  (\d{3})-(\d{3})-(\d{4})
替换：  ($1) $2-$3       （适用于使用 $n 语法的工具）
结果：  (313) 555-1234
```

`\l`、`\u`、`\L...\E`、`\U...\E` 等大小写转换通常属于特定编辑器或引擎的替换扩展，不是通用正则语法；不支持时应由代码显式转换大小写。

## 前后查找

前后查找（lookaround）只检查位置，不把检查内容放进匹配结果：

| 写法 | 含义 |
|---|---|
| `(?=...)` | 正向前查找：后面必须是 `...` |
| `(?!...)` | 负向前查找：后面不能是 `...` |
| `(?<=...)` | 正向后查找：前面必须是 `...` |
| `(?<!...)` | 负向后查找：前面不能是 `...` |

例如，提取 `@` 前的单词而不包含 `@`：

```text
模式：\w+(?=@)
文本：abc@qq.com
结果：abc
```

后查找的支持和限制差异较大；固定长度模式通常更容易跨引擎迁移，带不定长量词的后查找可能无法编译。若目标引擎不支持后查找，可以改用捕获组（如 `@(\w+)`）后取组内容。

## 条件表达式：非通用语法

条件表达式不是 JavaScript 等通用引擎都支持的能力。部分 PCRE、Perl 或 .NET 引擎支持根据捕获组是否成功来选择分支，例如下面的模式允许 `abc` 或 `(abc)`：

```text
模式：^(\()?abc(?(1)\))$
匹配：(abc)、abc
不匹配：(abc、abc)
```

基于前后查找的条件语法（例如 `\d{5}(?(?=-)-\d{4})`）同样是引擎扩展。若只是匹配“5 位数字或 5 位数字加连字符和 4 位数字”，更可移植的写法是：

```text
^\d{5}(?:-\d{4})?$
```

遇到条件语法时，先查目标引擎的文档；如果普通分组、或运算和宿主代码已经足够表达，就优先选更可移植的方案。

## 常见误区

- 把 `\d`、`\w`、`\s` 当成跨引擎完全相同；需要稳定字符集时显式写范围。
- 忘记区分搜索和全量匹配；校验输入时使用 `fullmatch` 或可靠的首尾边界。
- 把 `\b` 当成退格；它在字符组内外含义可能不同。
- 用正则解析 HTML、JSON 或编程语言；嵌套结构应交给解析器。
- 复制网上的复杂邮箱、IP 或 URL 正则却没有长度限制和测试；规则应从业务约束出发。
- 直接启用 `.*` 和多层贪婪量词处理不可信长文本；先限制输入，再检查回溯复杂度。
- 把 `\1` 当成所有替换工具的写法；替换语法要以宿主 API 为准。
